## Пример реального запроса и ответа

Пусть у нас есть модель `UserCreate`:

    class UserCreate(BaseModel):
        name: str
        age: int
        email: str

И маршрут:

    @app.post("/users")
    def create_user(user: UserCreate):
        return {
            "message": "User created successfully",
            "user": user
        }

### Корректный запрос

    {
      "name": "Charlie",
      "age": 28,
      "email": "charlie@example.com"
    }

### Ответ

    {
      "message": "User created successfully",
      "user": {
        "name": "Charlie",
        "age": 28,
        "email": "charlie@example.com"
      }
    }

### Ошибка валидации

Если один из ключей отсутствует или имеет неверный тип:

    {
      "name": "Charlie",
      "email": "charlie@example.com"
    }

Тогда вернётся:

    {
      "detail": [
        {
          "loc": ["body", "age"],
          "msg": "field required",
          "type": "value_error.missing"
        }
      ]
    }

Это означает, что поле `age` не было найдено, хотя в модели оно обязательное.

Теперь вы знаете, как создавать модели данных в FastAPI, которые описывают структуру запросов, и почему это так важно для организации качественного и безопасного API. Экспериментируйте с расширенными возможностями Pydantic: добавляйте вложенные поля, используйте регулярные выражения и кастомные валидаторы — всё это сделает вашу разработку эффективнее и надёжнее.
