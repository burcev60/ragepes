## Вложенные модели и наследование

### Вложенные модели

    class Address(BaseModel):
        street: str
        city: str
        zip_code: str

    class User(BaseModel):
        name: str
        address: Address

Pydantic проверяет корректность каждого уровня.

### Наследование моделей

    class BaseUser(BaseModel):
        name: str
        email: EmailStr

    class AdminUser(BaseUser):
        admin_level: int

Полезно, когда у нескольких моделей много общих полей.

## Параметры конфигурации моделей

В Pydantic есть класс `Config`, позволяющий менять поведение валидации и сериализации.

    class MyModel(BaseModel):
        name: str

        class Config:
            anystr_strip_whitespace = True  # убирает лишние пробелы
            min_anystr_length = 1           # минимальная длина любой строки

### Полезные опции Config:

- `allow_mutation`: разрешать ли изменение полей после создания экземпляра.

- `use_enum_values`: при использовании `Enum` брать строковое значение вместо имени.

- `extra`: контролировать приём дополнительных полей — `forbid`, `ignore` или `allow`.

## Пример реальной модели

Представим, что вы разрабатываете API для e-commerce. Нужно описать заказ:

    from typing import List, Union
    from pydantic import BaseModel, HttpUrl, conint, confloat

    class Product(BaseModel):
        name: str
        price: confloat(gt=0)  # цена > 0

    class Discount(BaseModel):
        description: str
        amount: confloat(gt=0, lt=1)  # скидка: от 0 до 1 (процент)

    class CartItem(BaseModel):
        product: Product
        quantity: conint(ge=1)

    class Order(BaseModel):
        items: List[CartItem]
        discount: Union[Discount, None] = None
        promo_url: Union[HttpUrl, None] = None

        def total(self) -> float:
            subtotal = sum(item.product.price * item.quantity for item in self.items)
            if self.discount:
                return subtotal * (1 - self.discount.amount)
            return subtotal

    # Пример использования
    item1 = CartItem(product=Product(name="Book", price=10.0), quantity=2)
    order = Order(items=[item1])
    print(order.total())  # 20.0

В этом примере мы:

- Используем `confloat` и `conint` для указания ограничений на float и int.

- Применяем `Union` для опциональной скидки.

- Проверяем корректность URL, если он передан.

- Пишем метод `total()` внутри модели, чтобы вычислять итоговую сумму.

## Итоги

1. **Расширенная типизация** помогает описывать структуру данных более точно и защищённо.

2. **Специализированные типы** (EmailStr, HttpUrl, SecretStr и др.) упрощают валидацию.

3. **Коллекции** (`List`, `Dict`, `Set`) дают возможность описывать сложные структуры.

4. **Вложенные модели** и **наследование** облегчают повторное использование кода.

5. Класс **Config** позволяет тонко настраивать поведение валидации.

Используйте эти возможности, чтобы создавать более надёжные и понятные модели данных, что сделает ваш код и API эффективнее и удобнее для сопровождения.
