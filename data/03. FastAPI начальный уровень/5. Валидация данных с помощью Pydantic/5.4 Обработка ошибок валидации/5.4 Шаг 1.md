В FastAPI основная валидация данных осуществляется через библиотеку Pydantic. Если входные данные не соответствуют ожидаемым типам и правилам, приложение автоматически возвращает ошибку **422 (Unprocessable Entity)**. В этом уроке мы разберём, как обрабатываются ошибки валидации и как можно настраивать ответы.

## 1. Как работают ошибки валидации?

Когда FastAPI получает запрос к маршруту, в котором используется модель Pydantic (или параметры, описанные через Path, Query и т.д.), он:

1. Извлекает данные из тела запроса, URL-параметров, заголовков.

2. Пытается преобразовать их в соответствующие типы (int, str, BaseModel и т.д.).

3. Если что-то не совпадает с описанной моделью или нарушается правило валидации, выбрасывается `ValidationError`.

4. FastAPI перехватывает эту ошибку и возвращает клиенту JSON-ответ формата:

    {
      "detail": [
        {
          "loc": ["body", "field_name"],
          "msg": "field required",
          "type": "value_error.missing"
        }
      ]
    }

Этот ответ содержит список полей, которые не прошли валидацию, и описывает, почему.
