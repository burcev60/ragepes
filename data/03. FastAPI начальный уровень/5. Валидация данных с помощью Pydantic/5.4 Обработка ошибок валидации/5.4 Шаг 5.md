## Пример полного кода

    from fastapi import FastAPI, Request
    from fastapi.exceptions import RequestValidationError
    from fastapi.responses import JSONResponse
    from starlette.status import HTTP_422_UNPROCESSABLE_ENTITY
    from pydantic import BaseModel

    app = FastAPI()

    class User(BaseModel):
        name: str
        age: int

    @app.exception_handler(RequestValidationError)
    async def validation_exception_handler(request: Request, exc: RequestValidationError):
        return JSONResponse(
            status_code=HTTP_422_UNPROCESSABLE_ENTITY,
            content={
                "error": "Validation Failed",
                "details": exc.errors()
            },
        )

    @app.post("/users")
    def create_user(user: User):
        return {"message": "User created", "user": user}

### Как работает:

1. Если пользователь отправляет корректные данные:

    {
      "name": "Alice",
      "age": 30
    }

  Ответ:

    {
      "message": "User created",
      "user": {
        "name": "Alice",
        "age": 30
      }
    }

2. Если пользователь пропустил поле `age` или ввёл неверный тип:

    {
      "name": "Alice"
    }

  Ответ:

    {
      "error": "Validation Failed",
      "details": [
        {
          "loc": ["body", "age"],
          "msg": "field required",
          "type": "value_error.missing"
        }
      ]
    }

1. **Стандартное поведение** FastAPI при валидационных ошибках (код 422) уже весьма информативно.

2. При необходимости вы можете **переопределить исключение** `RequestValidationError`, чтобы возвращать данные в нужном формате.

3. **Логируйте** ошибки валидации для анализа действий пользователей.

4. Соблюдайте баланс: слишком подробные ошибки могут раскрывать внутренние детали системы, что иногда нежелательно с точки зрения безопасности.

Таким образом, работа с валидационными ошибками в FastAPI гибкая: вы можете оставаться на уровне дефолтных ответов или настроить всё под конкретные требования.
