#### Переопределение зависимостей при тестировании

В реальных проектах вы, скорее всего, захотите модифицировать некоторые зависимости, когда тестируете свой код. Например, использовать тестовую БД вместо реальной. В FastAPI есть специальный словарь `app.dependency_overrides`, куда вы можете положить «замену» для зависимости.

    from fastapi.testclient import TestClient

    client = TestClient(app)

    def fake_dependency():
        return "Fake data"

    def test_my_endpoint():
        app.dependency_overrides[simple_dependency] = fake_dependency

        response = client.get("/items")
        assert response.json() == {"data": "Fake data"}

        app.dependency_overrides.clear()  # Убираем после тестов

#### 7. Middleware vs Dependencies

Иногда новички путают зависимости с мидлварами. Оба механизма позволяют выполнять некоторый код «до» или «после» обработки запроса. Различия:

- **Middleware**: пишется на уровне приложения; общий код, срабатывающий абсолютно для всех запросов. Обычно используется для логгирования, CORS, gzip-сжатия и т.д.

- **Dependencies**: подключаются к определённым маршрутам или группам маршрутов, могут возвращать значения (например, объект пользователя), которые потребуются в обработчике. Нередко завязаны на валидации входных данных.

#### 8. Порядок разрешения зависимостей

FastAPI автоматически определяет порядок выполнения зависимостей, анализируя, какие из них требуют другие (вложенные зависимости). Порядок примерно такой:

1. Вызвать все зависимости, не имеющие входных параметров (или имеющие только простые параметры запроса).

2. Если у зависимостей есть параметры, являющиеся другими зависимостями, сначала вызвать эти зависимости.

3. После того, как все результаты собраны, вызвать сам обработчик.

Если в какой-то зависимости возникает ошибка (например, выбрасывается `HTTPException`), дальнейшая цепочка прерывается, и пользователь получит соответствующий ответ.
