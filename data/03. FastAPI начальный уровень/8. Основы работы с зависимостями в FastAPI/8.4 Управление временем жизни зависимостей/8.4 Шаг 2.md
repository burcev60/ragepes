## Краткосрочные (per-request) vs долгоживущие ресурсы

Не всегда нужно создавать ресурс при каждом запросе. Иногда разумнее создавать его глобально (например, один пул подключений к БД на всё приложение) и переиспользовать. В таких случаях можно:

- Инициализировать ресурс на этапе `startup_event` приложения,

- Сохранять его в `app.state` (или другом контейнере),

- И возвращать уже созданный ресурс в зависимости.

Например:

    from fastapi import FastAPI, Request, Depends

    app = FastAPI()

    class GlobalDBConnection:
        # Singleton-like connection
        pass

    @app.on_event("startup")
    async def startup_event():
        app.state.db = GlobalDBConnection()

    def get_db(request: Request):
        return request.app.state.db

    @app.get("/")
    def read_root(db=Depends(get_db)):
        # Здесь db уже синглтон из app.state
        return {"message": "Using global DB"}

В этом примере `get_db` просто возвращает глобальный объект из `app.state`. Нет необходимости освобождать что-то в `finally`, потому что ресурс живёт во время всего приложения.

Однако такой подход имеет минусы:

- Труднее тестировать (приходится переопределять состояние приложения).

- Риск утечек ресурсов, если что-то неправильно сконфигурировано.

Поэтому для большинства случаев всё же популярнее (и безопаснее) работать с ресурсами на уровне запроса.

## 5. Управление несколькими ресурсами

Нередко бывает, что в одном запросе нужно использовать несколько ресурсов, каждый из которых требует отдельного `yield`. FastAPI умеет "раскручивать" вложенные зависимости с `yield`. Например, если ваша зависимость `dep_a` при работе сама зависит от `dep_b`, в которой используется `yield`, то всё будет корректно освобождаться в обратном порядке.

Пример (упрощённый):

    def dep_b():
        resource_b = SomeResourceB()
        try:
            yield resource_b
        finally:
            resource_b.close()

    def dep_a(b = Depends(dep_b)):
        resource_a = SomeResourceA(b)
        try:
            yield resource_a
        finally:
            resource_a.close()

    @app.get("/")
    def root(a = Depends(dep_a)):
        # Имеем ресурс А, который зависит от ресурса B
        return {"detail": "Using A and B"}

Когда запрос завершается, сначала будет вызван `finally` для `dep_a` (закрываем ResourceA), затем `finally` для `dep_b` (закрываем ResourceB)
