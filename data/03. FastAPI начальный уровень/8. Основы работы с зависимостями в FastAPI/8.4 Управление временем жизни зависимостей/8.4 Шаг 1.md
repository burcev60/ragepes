### Управление временем жизни зависимостей в FastAPI

В FastAPI под "управлением временем жизни" (lifecycle management) зависимостей обычно понимают то, как создаются и освобождаются ресурсы, используемые в цепочке зависимостей, и какой "срок жизни" (scope) у этих зависимостей. Типичные примеры: подключение к базе данных, файлы, сетевые соединения, сессии и т.д.

## 1. Уровни времени жизни

### 1.1. "Запрос" (per-request)

По умолчанию зависимости в FastAPI имеют область видимости "на запрос":

1. Когда приходит запрос, зависимости вызываются.

2. По завершении запроса (или при возникновении ошибки) можно освободить ресурсы.

3. При следующем запросе зависимости будут вызваны заново.

Это означает, что каждая зависимость, объявленная через `Depends(...)`, обрабатывается заново при новом запросе.

### 1.2. "Глобальный" (application-wide)

Если вы хотите, чтобы зависимость создавалась лишь один раз на всё время работы приложения, то используйте механизмы вроде "startup events" и "shutdown events" или объявляйте соответствующие объекты глобально. Однако в большинстве случаев, для взаимозаменяемости и тестируемости, предпочтительнее создавать ресурсы per-request, чтобы избегать состояния между запросами.

## 2. Использование `yield` для управления временем жизни

FastAPI предоставляет специальный синтаксис с ключевым словом `yield`, когда нужно создать ресурс, "отдать" его для использования, а затем освободить:

    from fastapi import FastAPI, Depends

    app = FastAPI()

    # Предположим, это класс для управления подключением к БД
    class DBSession:
        def __init__(self):
            print("Session created")
        def close(self):
            print("Session closed")

    # Зависимость с использованием yield

    def get_db():
        db = DBSession()  # создаём ресурс (подключение, сессию и т.д.)
        try:
            yield db       # передаём resource вызывающему коду
        finally:
            db.close()    # освобождаем ресурс

    @app.get("/")
    def read_data(db: DBSession = Depends(get_db)):
        return {"info": "Data from DB"}

Как это работает:

1. При каждом запросе к эндпоинту `/`, сначала вызывается `get_db()`, создаётся объект `DBSession`.

2. Код внутри `yield db` отдаёт ресурс вызываемой функции (`read_data`).

3. После того, как запрос обработан, управление возвращается в блок `finally`, и вызывается `db.close()`, освобождая ресурс.

Таким образом, `DBSession` живёт в течение всего одного запроса.

## 3. Ситуации, когда `yield` особенно полезен

1. **Соединения с базой данных**: Создать подключение к БД и закрыть его по завершении запроса.

2. **Файловые операции**: Открыть файл, вернуть файловый дескриптор или контент, а затем закрыть файл.

3. **Сетевые соединения**: Установить соединение с внешним сервисом (FTP, SMTP, AMQP и т.д.), а затем разорвать его.

4. **Временные директории/файлы**: Создать временную директорию, а после запроса удалить.
