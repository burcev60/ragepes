## Тестирование, совмещение с Path parameters и результат в документации

В реальном приложении нередко требуется использовать и Path parameters (для идентификаторов ресурсов), и query-параметры (для дополнительных настроек и фильтрации). Например:

    @app.get("/users/{user_id}/items")
    def get_user_items(
        user_id: int,
        limit: int = 10,
        skip: int = 0
    ):
        return {"user_id": user_id, "limit": limit, "skip": skip}

Здесь `user_id` передаётся как часть пути, а `limit` и `skip` — query-параметры, задающие параметры пагинации. Запрос может выглядеть так: `/users/5/items?limit=20&skip=40`, и сервер вернёт `{"user_id": 5, "limit": 20, "skip": 40}`.

Чтобы проверить корректность работы query-параметров, используйте встроенную документацию:

- **Swagger UI** доступна по адресу `/docs`.

- **ReDoc** — `/redoc`.

В них вы найдёте все описания параметров, их типы, статус обязательности, а также сможете запускать тестовые запросы непосредственно из браузера. Если параметры имеют ограничения или регулярные выражения, при нарушении условий появится подробное сообщение об ошибке.

Таким образом, FastAPI обеспечивает мощный и гибкий механизм работы с query-параметрами, позволяя настраивать как простые, так и сложные сценарии фильтрации, валидации и поиска. В сочетании с понятной автодокументацией и типизацией это делает разработку веб-приложений быстрой, безопасной и удобной.
