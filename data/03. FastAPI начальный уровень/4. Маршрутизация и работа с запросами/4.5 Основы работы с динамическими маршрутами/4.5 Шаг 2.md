## Простейший пример динамического маршрута

Допустим, у нас есть метод, который возвращает информацию о пользователе:

    from fastapi import FastAPI

    app = FastAPI()

    @app.get("/users/{user_id}")
    def get_user(user_id: int):
        return {"user_id": user_id, "info": "User details here"}

- Часть `{user_id}` — это **динамический сегмент**. При обращении к `/users/5` `user_id` станет равным 5.

- Типизация `user_id: int` указывает FastAPI, что ожидается целое число. Если в URL попадёт строка, которая не может быть преобразована в int (например, `/users/notanumber`), сервер автоматически вернёт ошибку 422 (Unprocessable Entity) и оповестит, что данные не соответствуют типу.

Таким образом, маршрут будет «подхватывать» разные значения, сохраняя одинаковый формат.

## 3. Типы данных и автоконвертация

FastAPI умеет автоматически преобразовывать входные данные к нужному типу, что облегчает разработку и сокращает объём проверок:

- **int** — целочисленные значения. Пример: `/posts/{post_id}`, где `post_id: int`.

- **float** — числа с плавающей точкой. Пример: `/measure/{temperature}`, где `temperature: float`.

- **str** — строковые значения. Это используется, если параметр не помечен типом, или явно указан `str`.

- **UUID** — уникальные идентификаторы. Пример: `/items/{item_uuid}`, где `item_uuid: UUID`.

### Пример с UUID

    from uuid import UUID

    @app.get("/documents/{doc_id}")
    def read_document(doc_id: UUID):
        return {"document": str(doc_id), "status": "Retrieved"}

Если клиент передаст невалидный UUID (например, `/documents/12345`), снова произойдёт автоматическая валидация и возврат соответствующей ошибки.
