## Кастомизация схемы ответов

Иногда вам нужно указать несколько возможных кодов статуса и связанных с ними моделей:

    from pydantic import BaseModel

    class ErrorResponse(BaseModel):
        error: str
        detail: str

    class Item(BaseModel):
        name: str
        price: float

    @app.get("/items/{item_id}", responses={
        200: {"model": Item},
        404: {"model": ErrorResponse, "description": "Item not found"}
    }, summary="Получить товар")
    def get_item(item_id: int):
        # ...
        return Item(name="Book", price=9.99)

- `responses` — словарь, где ключи — коды ответов, а значения — описание, модель, пример.

- `"model": Item` говорит, что при коде 200 ожидается JSON, соответствующий `Item`.

- При 404 — `ErrorResponse`.

Swagger UI отобразит две разные схемы ответов.

## 6. Переопределение метода `openapi()`

Если вам нужно **прямо модифицировать** структуру генерируемой схемы, можно переопределить метод `app.openapi()`:

    from fastapi.openapi.utils import get_openapi

    @app.get("/custom")
    def custom_data():
        return {"data": "sample"}

    def custom_openapi():
        if app.openapi_schema:
            return app.openapi_schema
        openapi_schema = get_openapi(
            title="Custom title",
            version="2.5.0",
            description="Custom description",
            routes=app.routes,
        )
        # Допустим, добавим поле x-logo
        openapi_schema["info"]["x-logo"] = {
            "url": "https://fastapi.tiangolo.com/img/logo-margin/logo-teal.png"
        }
        app.openapi_schema = openapi_schema
        return app.openapi_schema

    app.openapi = custom_openapi

Здесь:

1. `get_openapi(...)` генерирует базовую схему.

2. Мы **встраиваем** дополнительные данные (например, `x-logo`).

3. `app.openapi` переопределяем, чтобы в дальнейшем FastAPI возвращал эту модифицированную схему.

Любые поля, которые стандарт OpenAPI не покрывает, можно добавлять как `x-...`, например, `x-organization` или `x-logo`.
