## Авторизация через браузер

При использовании аутентификации (например, **Bearer Tokens** или **Basic Auth**) в Swagger UI можно ввести токен в специальном поле Authorize.

Но если вы тестируете напрямую из адресной строки (**GET** + токен), то придётся либо вручную добавлять заголовок в консоли разработчика `fetch()`, либо полагаться на Swagger.

**Basic Auth** можно проверить, введя URL вида:

    http://username:password@127.0.0.1:8000/protected

Но это не всегда безопасно, а некоторые браузеры не поддерживают такой синтаксис.

## 7. Просмотр заголовков ответа в браузере

При ответе приложения вы можете посмотреть заголовки (Headers) через инструменты разработчика:

1. Откройте вкладку **Network**.

2. Сделайте запрос (перейдите по URL или обновите страницу).

3. Выберите соответствующий запрос в списке.

4. Во вкладке **Headers** увидите Request и Response Headers.

Это полезно, чтобы убедиться, что сервер правильно устанавливает, например, `Set-Cookie`, `Cache-Control`, `Content-Type`.

## 8. Быстрые советы

1. **Используйте Swagger UI** для методов, отличных от GET, так как нативный браузерный GET не позволяет отправлять тело JSON.

2. **Consoles** разработчика в браузере + `fetch()` — хороший способ проверить POST/PUT/DELETE.

3. **Query-параметры** можно указывать напрямую в адресной строке: `?param=value`.

4. Следите за **CORS**, если обращаетесь к API с другого домена. Может понадобиться CORSMiddleware.
