## Как задавать коды ошибок в FastAPI

### Явное использование `HTTPException`

    from fastapi import FastAPI, HTTPException

    app = FastAPI()

    @app.get("/resource/{item_id}")
    def get_resource(item_id: int):
        if item_id < 1:
            raise HTTPException(status_code=400, detail="Item ID must be positive.")
        # ...
        raise HTTPException(status_code=404, detail="Item not found")

- `status_code` — любой HTTP-код.

- `detail` — сообщение об ошибке.

### Выбрасывание более конкретных исключений

FastAPI также предоставляет Shortcut-исключения, например:

- `fastapi.exceptions.RequestValidationError` (код 422) — при ошибке валидации.

- `starlette.exceptions.HTTPException` — базовый класс.

Но обычно `HTTPException` — основной способ.

## Когда использовать 422 Unprocessable Entity, а когда 400 Bad Request?

- **400 Bad Request**: чаще применяется, когда запрос содержит фундаментально неверные данные (некорректный синтаксис JSON, неправильный формат полей или параметры).

- **422 Unprocessable Entity**: удобен, когда синтаксис запроса формально корректен, но данные не соответствуют бизнес-логике или правилам валидации. В FastAPI по умолчанию, если Pydantic отбрасывает ошибку валидации, возвращается 422.

Например:

- Пользователь отправил JSON, но пропущена закрывающая скобка — `400 Bad Request`.

- JSON синтаксически верный, но поле `age` содержит строку "hello" вместо числа — `422 Unprocessable Entity`.
