## Ответы с дополнительными заголовками и статусами

Вместо простого возвращения данных можно более явно управлять ответом с помощью `Response` или `JSONResponse`:

    from fastapi import FastAPI, Response, status
    from fastapi.responses import JSONResponse

    app = FastAPI()

    @app.get("/custom_response")
    def custom_response():
        data = {"msg": "Hello"}
        return JSONResponse(content=data, status_code=status.HTTP_202_ACCEPTED, headers={"X-Custom-Header": "CustomValue"})

### Разбор:

- `content=data` — данные для сериализации.

- `status_code` — устанавливаем свой код ответа.

- `headers` — дополнительные заголовки.

## Сжатие JSON (преобразование Python-объекта)

FastAPI использует `ORJSON` (если доступен) или `json` модуль из стандартной библиотеки Python для сериализации. Обычно формат достаточно компактный, но если нужно уменьшить размер, можно использовать `ORJSONResponse` с настройками.

    from fastapi.responses import ORJSONResponse

    @app.get("/orjson", response_class=ORJSONResponse)
    def orjson_example():
        return {"items": ["apple", "banana"], "count": 2}

ORJSON известен высокой скоростью и эффективным сжатием.

## Пример разного формата ответов для разных случаев

FastAPI даёт возможность определять разные модели ответов в зависимости от кода ответа. Например:

    from fastapi import HTTPException
    from pydantic import BaseModel

    class SuccessResponse(BaseModel):
        detail: str
        data: dict

    class ErrorResponse(BaseModel):
        error: str

    @app.get("/mixed", responses={
        200: {"model": SuccessResponse},
        404: {"model": ErrorResponse}
    })
    def mixed_response(item_id: int):
        if item_id == 1:
            return SuccessResponse(detail="OK", data={"item_id": item_id})
        else:
            raise HTTPException(status_code=404, detail="Item not found")

Здесь мы:

- Указываем, что при `200 OK` ответ должен соответствовать `SuccessResponse`.

- При `404 Not Found` — `ErrorResponse`.

Это помогает сделать спецификацию более понятной для клиентов API и документировать разные варианты ответа.
