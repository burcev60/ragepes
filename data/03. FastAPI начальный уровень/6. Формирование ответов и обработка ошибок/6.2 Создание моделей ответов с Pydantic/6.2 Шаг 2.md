## Базовый пример: модель ответа

Создадим модель `ItemResponse`, которая описывает, что возвращает сервер. Допустим, мы хотим выдавать `id`, `name` и `price`:

    from pydantic import BaseModel
    from fastapi import FastAPI

    app = FastAPI()

    class ItemResponse(BaseModel):
        id: int
        name: str
        price: float

    @app.get("/items/{item_id}", response_model=ItemResponse)
    def get_item(item_id: int):
        return {"id": item_id, "name": "Book", "price": 9.99}

- `response_model=ItemResponse` говорит FastAPI, что этот маршрут вернёт JSON, соответствующий модели `ItemResponse`.

- FastAPI проверяет соответствие возвращаемых данных полям `ItemResponse` и, если есть несоответствия, выбросит исключение (или при необходимости "подрежет" данные).

Попробуйте вернуть из функции лишние поля, например, `{"id": 1, "name": "Pen", "price": 1.99, "secret": "some_secret"}`, — поле `secret` в итоговый JSON не попадёт.

## Конфигурация модели ответа

Через класс `Config` в Pydantic можно настраивать поведение при сериализации:

    class ItemResponse(BaseModel):
        id: int
        name: str
        price: float

        class Config:
            # Запретить любые дополнительные поля
            extra = "forbid"

Если вернуть лишние поля, будет вызвано исключение валидации. Это полезно, когда нужно жёстко контролировать структуру ответа.
