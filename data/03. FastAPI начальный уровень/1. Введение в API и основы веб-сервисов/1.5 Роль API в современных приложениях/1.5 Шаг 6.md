## Влияние API на архитектуру и разработку

### 6.1 Микросервисная парадигма

- API — связующее звено между микросервисами, каждый из которых может быть написан на своём языке и развёрнут на отдельной платформе.
- Такая гибкость ускоряет развитие каждого сервиса и повышает отказоустойчивость системы (при сбое одного микросервиса остальные продолжают работать).


### 6.2 CI/CD (непрерывная интеграция и доставка)

- API-контракты позволяют заранее описать взаимодействие сервисов. Тесты на уровне API помогают гарантировать, что обновление одного микросервиса не «сломает» работу остальных.
- Автоматизированные пайплайны (например, Jenkins, GitLab CI) могут запускать интеграционные тесты и проверять совместимость версий.


### 6.3 Архитектурные паттерны

- **Event-driven** (событийная модель): часть сервисов может взаимодействовать посредством событий (Webhook, очереди сообщений), но основной «точкой входа» для клиентских систем всё равно остаётся API.
- **Serverless**: функции в облачных провайдерах (AWS Lambda, Azure Functions и др.) оборачиваются в API-ендпоинты для внешнего доступа.
