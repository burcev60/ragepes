## Краткое сравнение «лицом к лицу»

| Критерий | Синхронный подход | Асинхронный подход |
| --- | --- | --- |
| **Принцип** | Запрос → ожидание ответа (блокировка) | Запрос (или сообщение) → нет немедленного ожидания ответа |
| **Простота** | Реализуется легко, обычно достаточно HTTP | Требует дополнительной логики (очереди, колбэки) |
| **Производительность** | При высоких нагрузках может тормозить | Более эффективно использует ресурсы, лучше при больших нагрузках |
| **Управление ошибками** | Простое: ошибка приходит сразу | Сложнее: возможны задержки и отдельные механизмы retry |
| **Отладка и трассировка** | Довольно проста, «запрос—ответ» | Сложнее, так как поток выполнения «разрывается» |
| **Пользовательский опыт** | Пользователь может дожидаться ответа | Можно не блокировать UI, возвращать «промежуточные» ответы или уведомления |
| **Типичные примеры** | Чтение/запись данных в БД, получение страницы | Генерация отчётов, обработка видео, долгие вычисления |
