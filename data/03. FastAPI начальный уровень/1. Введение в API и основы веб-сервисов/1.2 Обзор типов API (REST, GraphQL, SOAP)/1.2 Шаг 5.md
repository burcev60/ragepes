## Сравнение основных видов веб-API

| Характеристика | REST | SOAP | GraphQL | RPC (gRPC) |
| --- | --- | --- | --- | --- |
| **Формат данных** | JSON (или XML) | XML | JSON | Специальный (Protocol Buffers) |
| **Сложность** | Относительно прост | Сложнее из-за WSDL и XML | Может быть сложен на сервере | Средняя (требует генерации кода) |
| **Гибкость запросов** | Стандартные HTTP-методы | Жёсткая структура сообщений | Высокая (запрос именно нужных полей) | Высокая (зависит от реализации процедур) |
| **Типизация** | Слабее выражена | Чёткая в WSDL | Схема (Schema) с жёсткой типизацией | Прото-типизация в `.proto` файлах |
| **Использование** | Большинство веб-приложений | Корпоративные системы, банки | Facebook, Instagram, GitHub | Микросервисы (Netflix, Google, Uber) |

## Практические примеры

### REST в веб-разработке

- **Пример**: Создание блога. Для управления постами есть эндпоинты:

  - `GET /posts` (получить список постов)

  - `GET /posts/{id}` (получить конкретный пост)

  - `POST /posts` (создать новый пост)

  - `PUT /posts/{id}` (обновить пост)

  - `DELETE /posts/{id}` (удалить пост)

### SOAP для банковских операций

- **Пример**: Банковская система, где строго определён формат сообщений для перевода средств, запроса баланса и т.д.

- Часто используется сложная схема WSDL, которая описывает все операции.

### GraphQL в соцсетях

- **Пример**: Запрос для получения профиля пользователя вместе со списком последних постов за один раз.

- Клиент может задать, какие поля нужны: `id`, `username`, `email`, `posts(title, createdAt)` — и сервер вернёт ровно это.

### gRPC в микросервисах

- **Пример**: Внутри крупного приложения микросервисы вызывают методы друг друга (регистрация пользователя, заказ товара). Всё это скомпилировано из `.proto`-файлов.

- Позволяет добиться высокой скорости и эффективности.
