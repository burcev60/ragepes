## Когда какой подход выбрать?

1. **REST**: когда нужно быстро создавать типичное веб-приложение; хорошо подходит для публичных API.

2. **SOAP**: когда важны стандарты, сложные транзакции, безопасность на уровне WS-* стандартов; часто корпоративный сектор.

3. **GraphQL**: когда есть сложная структура данных и потребность в гибком получении только нужных данных за один запрос.

4. **RPC (gRPC)**: когда приоритет — высокая производительность и низкий трафик; обычно для микросервисов.

## Итоги

1. **Веб-API** строятся на базе стандартных протоколов (HTTP/HTTPS) и форматов данных (JSON/XML).

2. **REST**, **SOAP**, **GraphQL** и **RPC** — ключевые парадигмы, каждая из которых решает свои задачи:

  - REST — простой и широко используемый.

  - SOAP — формализованный, чаще в крупных корпоративных средах.

  - GraphQL — гибкий для сложных структур и клиентоцентричного подхода.

  - RPC (gRPC) — высокопроизводительный и эффективный для микросервисных архитектур.

3. У каждого подхода есть преимущества и недостатки, выбор зависит от **требований** проекта: безопасности, скорости разработки, объёмов данных и пр.
