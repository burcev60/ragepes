## Основные архитектурные стили и протоколы веб-API

### REST (Representational State Transfer)

#### Определение

- REST — не протокол, а архитектурный стиль взаимодействия в распределённых системах.

- Упрощённо говоря, это набор принципов проектирования API, которые широко применяются в веб-приложениях.

#### Ключевые принципы REST

1. **Клиент-сервер**: Клиент (обычно фронтенд) и сервер (бэкенд) чётко разделены.

2. **Отсутствие состояния (Stateless)**: Сервер не хранит состояние клиента между запросами.

3. **Единообразие интерфейсов**: Предпочтение стандартным методам HTTP (GET, POST, PUT, DELETE и т.д.) для управления ресурсами.

4. **Кэширование**: Возможность кэшировать ответы на запросы для оптимизации.

5. **Слои (Layered System)**: Возможность выстраивать промежуточные слои (балансировщики, прокси-серверы).

#### Преимущества и распространённость

- **Простота и гибкость**: Подходит для большинства веб-сервисов.

- **Широкая поддержка**: Практически все фреймворки и языки программирования имеют инструменты для работы с REST.

- **Стандартные методы HTTP**: Легко отлаживать (много готовых инструментов вроде Postman).

### SOAP (Simple Object Access Protocol)

#### Определение

- SOAP — это протокол обмена сообщениями на основе XML.

- Часто используется в крупных корпоративных решениях, где важна формальность спецификаций и строгая типизация.

#### Отличительные особенности

1. **Сообщения в формате XML**: SOAP-сообщение чётко описано в WSDL (Web Services Description Language).

2. **Наличие обширного стандарта**: Поддерживает сложные типы данных, интеграцию с WS-Security и другими расширениями.

3. **Более формализованный**: SOAP-сообщения имеют строгую структуру (Envelope, Header, Body).

#### Применение

- Традиционные корпоративные системы (например, банк, госучреждения), где важны соглашения о безопасности, транзакции, надёжная доставка.

- Более редок в современной веб-разработке из-за сложности и громоздкости.

### GraphQL

#### Определение

- GraphQL — это язык запросов и среда выполнения запросов, разработанная Facebook.

- Клиент сам описывает структуру и поля, которые ему нужны, а сервер возвращает ровно то, что запрошено.

#### Отличительные особенности

1. **Гибкость запросов**: Не нужно получать «лишние» данные; можно выборочно запрашивать только нужные поля.

2. **Единая конечная точка** (обычно `/graphql`), но сложный «тело» запроса.

3. **Схема** (Schema) описывает все доступные типы и их поля.

#### Преимущества

- **Оптимизация трафика**: Один запрос может заменить несколько REST-запросов.

- **Подробная типизация**: Чётко прописываются типы в схеме.

- **Активное сообщество** и широкое распространение во фронтенд-разработке.

### RPC (Remote Procedure Call)

#### Определение

- RPC — это модель удалённого вызова процедур, где клиент вызывает методы на удалённом сервере, как будто они локальные.

- Пример: gRPC от Google (использует Protocol Buffers).

#### Применение

1. **Высокопроизводительные распределённые системы**: Взаимодействие микросервисов.

2. **Низкое потребление трафика**: ProtoBuf (протокол сериализации) обычно даёт меньший объём данных, чем JSON.
