### Пример 3: RESTful API (PUT и DELETE)

#### Сценарий

У нас есть RESTful API для управления списком товаров. Клиент (например, JavaScript-фреймворк на фронтенде или мобильное приложение) хочет **обновить** информацию о товаре и **удалить** товар.

#### Обновление (PUT)

Запрос:

    PUT /api/products/123 HTTP/1.1
    Host: api.example.com
    Content-Type: application/json
    Content-Length: 54

    {
      "name": "New Product Name",
      "price": 999.0
    }

- **Метод**: `PUT` (заменить данные товара `id=123`).

- **Тело**: JSON с новыми данными.

Ответ (при успехе):

    HTTP/1.1 200 OK
    Content-Type: application/json
    Content-Length: 55

    {
      "id": 123,
      "name": "New Product Name",
      "price": 999.0
    }

- Сервер возвращает обновлённый объект (по желанию).

- Статус `200 OK` или `204 No Content` (если тело не возвращается).

#### Удаление (DELETE)

Запрос:

    DELETE /api/products/123 HTTP/1.1
    Host: api.example.com
    Content-Length: 0

- **Метод**: `DELETE`.

- Обычно тело не требуется.

Ответ:

    HTTP/1.1 204 No Content

- Статус `204` означает, что всё прошло успешно, но **нет тела** (здесь и не нужно).

- Иногда может быть `200 OK` и краткое сообщение, но `204` очень распространён для удаления.
