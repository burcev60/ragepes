Оптимизация касается не только скорости, но и памяти. Python-программы могут потреблять много памяти, особенно если хранят большие объекты или структуры.

**memory_profiler** – внешняя библиотека (устанавливается через pip), позволяющая измерять использование памяти построчно. Она может замерять RSS процесса до и после выполнения каждой строки отмеченной функции.

Пример:

    from memory_profiler import profile

    @profile
    def create_structures():
        data = [0] * 1000000  # список из 1e6 нулей
        squares = [x*x for x in range(1000000)]
        return data, squares

    if __name__ == "__main__":
        create_structures()

Запуск `python -m memory_profiler script.py` даст вывод:

    Line #    Mem usage    Increment  Line Contents
    ================================================
         3   4.0 MiB    4.0 MiB   @profile
         4                             def create_structures():
         5   4.0 MiB    0.0 MiB       data = [0] * 1000000
         6  11.6 MiB    7.6 MiB       squares = [x*x for x in range(1000000)]
         7  11.6 MiB    0.0 MiB       return data, squares

Видно, что строка 5 (создание списка data) увеличила память на ~0 MiB (поскольку список из миллионов одинаковых элементов мог оптимизироваться, или 4 MiB уже было выделено на интерпретатор и прочее), а строка 6 – на 7.6 MiB (создание списка квадратов).

**tracemalloc** – встроенный модуль (с 3.4) для отслеживания выделений памяти объектами Python. Он не показывает фактическое использование памяти процесса, а именно аллокации Python-объектов и их размер в байтах.

Пример:

    import tracemalloc
    tracemalloc.start()
    # ... код ...
    current, peak = tracemalloc.get_traced_memory()
    print(f"Текущее потребление: {current/1024:.1f} KiB, пик: {peak/1024:.1f} KiB")
    tracemalloc.stop()

Также можно получить срез snapshot и выяснить, где больше всего памяти выделено:

    snapshot = tracemalloc.take_snapshot()
    top_stats = snapshot.statistics('filename')
    for stat in top_stats[:5]:
        print(stat)

Выведет топ-5 мест в коде (файлы и строки) по объему выделенной памяти.

**Понимание потребления памяти**:

- Объекты Python имеют накладные расходы (объект пустого int занимает 28 байт примерно).

- Списки хранят элементы как ссылки на объекты. Список из 1000 int занимает 1000 * (размер ссылки) + накладные 8 байт на элемент = ~8кБ плюс сами объекты int (~28кБ) итого ~36кБ, не считая выравнивания.

- Большое потребление могут вызвать крупные структуры (список миллионов элементов) или удерживание ненужных объектов (например, глобальный кэш, который не очищается).

Оптимизация памяти:

- Использовать генераторы вместо списков, если нужен только итератор (не храня весь список).

- Использовать более компактные структуры: модуль `array` или `numpy.ndarray` для массивов чисел (они хранятся компактно).

- Удалять ненужные переменные (del) или реинициализировать крупные списки, чтобы освободить память, если уверены, что они не нужны.

- Использовать `__slots__` в классах, чтобы избежать overhead на `__dict__` для множества объектов (это экономит память, но делает класс менее гибким).

- Если нужно освобождать память, можно вызывать `gc.collect()` чтобы убрать циклические ссылки пораньше.

- Следить за тем, чтобы большие объекты не оставались в области видимости без необходимости (например, большие списки внутри функций лучше вернуть или удалить перед выходом, иначе они могут остаться в стеке вызовов).
