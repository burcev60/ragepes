Прежде чем оптимизировать программу, нужно понять, где она тратит время. Для этого служат **профилировщики**. В стандартной библиотеке есть модуль `cProfile` (написан на C для минимального overhead), который может собирать статистику по вызовам функций: сколько раз вызвана каждая функция, сколько времени заняла суммарно и в среднем, сколько времени внутри себя vs внутри подвызывов и т.д.

Использование cProfile:

- В программе можно вызвать `cProfile.run("<код>")` для быстрого профиля.

- Или, более гибко, использовать:

    import cProfile, pstats
    profiler = cProfile.Profile()
    profiler.enable()
    # ... код, который хотим профилировать ...
    profiler.disable()
    stats = pstats.Stats(profiler).sort_stats("cumtime")
    stats.print_stats(10)  # печатаем 10 самых "тяжелых" по времени функций

- Или запустить скрипт из командной строки с профилированием:

    python -m cProfile -o stats.dat myscript.py

Это запустит `myscript.py` и запишет результат профилирования в файл `stats.dat` для последующего анализа.

Простой пример:

    import cProfile, time

    def slow_function():
        time.sleep(0.5)
        total = 0
        for i in range(1000000):
            total += i
        return total

    def fast_function():
        return sum(range(1000000))

    def main():
        slow_function()
        fast_function()

    cProfile.run('main()')

Результат (примерно):

    5 function calls in 0.506 seconds

       Ordered by: cumulative time

       ncalls  tottime  percall  cumtime  percall filename:lineno(function)
            1    0.004    0.004    0.506    0.506 <string>:1(<module>)
            1    0.003    0.003    0.502    0.502 script.py:4(slow_function)
            1    0.494    0.494    0.494    0.494 script.py:7(<listcomp>)
            1    0.005    0.005    0.005    0.005 script.py:12(fast_function)
            1    0.000    0.000    0.000    0.000 {built-in method builtins.sum}

Пояснение:

- `ncalls`: число вызовов (1 раз main, он вызывает slow_function и fast_function по 1 разу, плюс listcomp – это списковое включение внутри slow_function).

- `tottime`: "own time", время, затраченное внутри этой функции, без учета подвызываемых функций.

- `cumtime`: cumulative time, суммарное время работы функции (включая подвызываемые). Для slow_function cumtime 0.502, в том числе 0.494 ушло на listcomp, значит собственное время slow_function 0.008 (видно в tottime 0.003, видимо остальное на sleep).

- `percall`: среднее время за вызов (tottime/ncalls и cumtime/ncalls).

- Имя функции: файл, строка, имя.

Из примера видно, что медленная часть – listcomp (в нем происходит суммирование миллиона чисел на Python). Fast_function использует builtins.sum, почти все время ушло внутри встроенной функции (которая на C, и не детализируется).

Анализ профиля: определяем "узкие места" – функции с большим cumtime или часто вызываемые (большой ncalls) с заметным tottime. В примере slow_function явно "тормоз".

Далее можно оптимизировать, например, заменить Python-цикл на использование sum.

Для визуализации профилей можно использовать внешние инструменты: например, библиотека `snakeviz` строит интерактивную диаграмму, или `gprof2dot` для создания графа вызовов.
