### FAQ

*Задавайте вопросы в комментариях — мы будем расширять раздел.*

1. **Зачем `__enter__` возвращает `self` (или другой объект)?**  
Возвращённое значение привязывается к имени после `as ...` в конструкции `with`. Если нужен доступ к данным менеджера внутри блока, обычно
 возвращают `self` (`with Timer() as t:`).
 Если ничего не нужно — можно вернуть `None`.
2. **Что будет, если в `__exit__` вернуть `True`?**  
Исключение, возникшее в блоке `with`, будет подавлено и не
 «уйдёт» выше по стеку. Возврат `False` (или `None`)
 оставляет исключение активным.
3. **Можно ли использовать `print` в `__exit__` вместо логирования?**  
Технически можно, но для реального кода лучше применить `logging` — так сообщения можно фильтровать и перенаправлять.
4. **Что произойдёт, если в `__exit__` само возникнет новое исключение?**  
Оно заменит (затрёт) исходное исключение блока. Чтобы сохранить исходное
 стек-трейс, перехватывайте ошибки внутри `__exit__` или используйте `contextlib.ExitStack`.
5. **Нужно ли явно вызывать `Timer.__exit__` вне `with`?**  
Нет, интерпретатор сделает это автоматически.
 Ручной вызов допустим (например, при тестировании), но редко нужен.
6. **Как сделать менеджер, который только подавляет исключения определённого типа?**  
Проверяйте `exc_type` и возвращайте `True` только для
 нужных исключений:

    def __exit__(self, exc_type, exc_val, tb):
        return exc_type is FileNotFoundError
  

7. **Можно ли написать менеджер без класса?**  
Да, с помощью `@contextlib.contextmanager`:

    from contextlib import contextmanager
    @contextmanager
    def timer():
            start = time.perf_counter()
            try:
                yield
            finally:
                print(time.perf_counter() - start)
  

Всё до `yield` работает как `__enter__`, всё после —
 как `__exit__`.

8. **Будет ли `ChangeDir` безопасен при вложенных вызовах?**  
Если одновременно используется несколько экземпляров («матрёшка»), каждый
 запоминает свою `old_path`, поэтому восстановление происходит
 корректно. Главное — не мутировать глобальное состояние вне менеджера.
