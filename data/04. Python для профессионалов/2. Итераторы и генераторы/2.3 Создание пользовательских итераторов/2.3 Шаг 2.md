### FAQ:
> Этот шаг‑шпаргалка будет пополняться новыми вопросами из комментариев.

#### 1. **Нужно ли обязательно делать сам объект итератором (`__iter__ → self`), как в `OddRange`?**

Нет. Такой вариант удобен, когда вы не планируете иметь два независимых прохода по одним и тем же данным. Если же параллельные итерации возможны (как у `list`), лучше вернуть отдельный объект‑итератор:

    class OddRange:
        ...
        def __iter__(self):
            return OddRangeIter(self.start, self.end)

    class OddRangeIter:
        ...

Каждый вызов `iter(odd_range)` будет давать «свежий» курсор.

#### 2. **Как “сбросить” итератор, чтобы начать обход заново?**

Перезапустить **тот же** объект‑итератор нельзя — он уже исчерпал данные. Создайте новый:

    odds = OddRange(1, 10)
    for x in odds: ...
    for x in odds:         # не начнёт с 1 — объект уже исчерпан!
        ...
    odds = OddRange(1, 10) # новый экземпляр

Именно поэтому в большинстве случаев отделяют контейнер (`OddRange`) и курсор (`OddRangeIter`).

#### 3. **Что будет, если забыть выбросить `StopIteration` в `__next__`?**

Цикл `for` никогда не завершится — получится бесконечный цикл.  
Совет: тестируйте итераторы в небольшом `for`‑цикле или вызывайте `next()` вручную, чтобы убедиться, что исключение действительно выбрасывается.

#### 4. **Можно ли в `__next__` возвращать `None`, чтобы сигнализировать об окончании?**

Нет. Протокол явно требует исключения `StopIteration`. Значение `None` может быть законным элементом последовательности, поэтому «магическое значение» приведёт к багам.

#### 5. **Как обеспечить несколько “живых” итераций одновременно без дублирования данных?**

Храните **данные** в контейнере, а каждый итератор пусть содержит только *ссылку* и текущий указатель. Пример:

    class Buffer:
        def __init__(self, data): self._data = data
        def __iter__(self):       return BufferIter(self._data)

    class BufferIter:
        def __init__(self, data):
            self._data = data
            self._idx = 0
        def __iter__(self): return self
        def __next__(self):
            if self._idx >= len(self._data):
                raise StopIteration
            val = self._data[self._idx]
            self._idx += 1
            return val

#### 6. **Стоит ли использовать `__getitem__`‑обход вместо явного `__iter__`?**

Только для поддержки **старого** кода. У современных классов лучше определять `__iter__`, потому что:

- работает быстрее (один вызов вместо цепочки `__getitem__` + обработка `IndexError`),

- код очевиднее для читателей и статических анализаторов,

- гибче (можно вернуть ленивый генератор).

#### 7. **Чем генератор‑функция лучше “ручного” класса‑итератора?**

- **Код короче** — часто 2‑3 строки против десятка.

- **Автоматически создаётся** правильный объект‑итератор с `__iter__` и `__next__`.

- **Поддерживает возврат значения** через `return` (доступно из `StopIteration.value`).

Однако генератор не даёт удобного места хранить дополнительные методы или свойства; в таких случаях класс‑итератор предпочтительнее.

#### 8. **Как сделать итератор потокобезопасным (thread‑safe)?**

    import threading
    class SafeCounter:
        ...
        def __next__(self):
            with self._lock:
                ...

Но учтите — это снижает производительность; зачастую проще отдавать разные диапазоны потокам вместо разделения одного итератора.
