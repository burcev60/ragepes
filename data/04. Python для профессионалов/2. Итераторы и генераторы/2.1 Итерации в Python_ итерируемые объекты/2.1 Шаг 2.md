### FAQ:
> Шаг‑справочник, куда мы будем добавлять новые вопросы по мере их появления в комментариях к уроку.

#### 1. **Можно ли узнать длину любого итерируемого объекта через `len()`?**

Только если объект **является последовательностью** (`list`, `tuple`, `str`, `range`, …) и реализует метод `__len__`. Итераторы и генераторы длину «не знают» — они потенциально бесконечны и не хранят все элементы в памяти.  
Если вам критично узнать размер потока, придётся:

- либо пройтись по нему и посчитать (`sum(1 for _ in iterable)`),

- либо материализовать в список (`items = list(iterable)`) с ценой O(n) памяти.

#### 2. **Чем `iterable` отличается от `iterator` на практике?**

- **Iterable** ― объект, у которого есть метод `__iter__`, возвращающий ** iterator**. Он может создавать **сколько угодно** независимых итераторов.

- **Iterator** ― объект, у которого есть `__next__` (и само `__iter__`, возвращающее `self`). Итератор **одноразовый** и хранит текущую позицию обхода.  
Пример: список — iterable; вызов `iter(spisok)` вернёт итератор‑обходчик списка.

#### 3. **Почему опасно изменять список (или словарь) во время обхода?**

Итератор запоминает индексы/ячейки, а изменение контейнера смещает их и приводит к пропускам или неожиданным результатам.  
Безопасные варианты:

    for item in list(items):    # копия
        if need_remove(item):
            items.remove(item)

    for key, value in dict(data).items():  # «замороженный» снимок
        ...

CPython не бросит исключение, но логика будет нарушена.

#### 4. **Как создать бесконечный итератор и всё‑таки уметь его остановить?**

Используйте генератор с `while True` или функцию из `itertools` (`itertools.count()`, `cycle()`, `repeat()`). Управляйте остановкой через `break`, таймауты или условия в вызывающем коде.

    from itertools import count

    for i in count(1):          # 1, 2, 3, …
        if i > 1000:
            break               # вручную останавливаем

В асинхронном контексте применяйте `async for` и ловите `asyncio.CancelledError`, если нужно завершить задачу.

#### 5. **Что произойдёт, если вызвать `iter()` на объекте без `__iter__`, но с `__getitem__`?**

CPython «наследием» времён Python 2 попытается итерироваться, начиная с индекса 0, пока не получит `IndexError`. Такой способ считается устаревшим; для новых классов реализуйте явный `__iter__`, так код понятнее и работает быстрее.
