### FAQ

*Спрашивайте в комментариях — пополним список.*

1. **Насколько быстрее Python 3.11 по сравнению с 3.10?**  
Средний прирост — 10-30 % (проект **Faster CPython**).
 Конкретный выигрыш зависит от кода: расчётные циклы и вызовы функций ускоряются сильнее, чем I/O-сценарии.
2. **Что делает «адаптивный байткод» (PEP 659)?**  
При первом выполнении опкод «обучается» на типах операндов и
 заменяется на специализированную версию
 (например, `BINARY_OP` → `BINARY_ADD_INT`).
 Если типы меняются, происходит «деоптимизация» обратно.
3. **Как работают `ExceptionGroup` и `except*`?**  
Несколько исключений объединяются в один объект.
 Блок `except*` «раскрывает» группу и перехватывает *подмножество* по типу; оставшиеся ошибки летят дальше.
 Полезно в `asyncio.gather()`, где сразу возвращается
 несколько ошибок от разных задач.
4. **Нужно ли обновлять код для новых сообщений об ошибках?**  
Нет. Улучшенные SyntaxError и Traceback работают «из коробки»,
 показывая стрелки ^ точно на проблемный токен.
5. **Как использовать новый тип `typing.Self` (PEP 673)?**  

    from typing import Self
    class Builder:
        def set_x(self, x: int) -> Self:
            self.x = x
            return self
  

Статический анализатор понимает, что метод возвращает *тот же* тип,
 включая наследников.

6. **Что нового в 3.12?**  
• Дальнейшее ускорение (укрупнение опкодов, мелкие JIT-инновации).  
• **PEP 701** — гибкие f-строки (вложенные выражения, удобный `=`).  
• **PEP 692** — точные типы для `**kwargs`: `def func(**kw: Unpack[TypedDict]) → ...`.  
• Подготовка почвы к изолированным подинтерпретаторам без общего GIL (PEP 684).
7. **Когда действительно исчезнет GIL?**  
Рабочий прототип «nogil» (PEP 703) обсуждается, но официального
 решения пока нет. Ближайшие релизы сохраняют GIL, улучшая подинтерпретаторы.
8. **Изменился ли минимальный требуемый gcc/clang для сборки CPython?**  
Начиная с 3.12 — GCC ≥ 9 / Clang ≥ 10, что позволяет использовать
 современные оптимизации (vector-builtins, C11 atomics).
9. **Что даёт `@dataclass(slots=True)` (3.10+)?**  
Автоматически добавляет `__slots__` к dataclass, снижая
 оверхед памяти и ускоряя доступ к атрибутам.
10. **Как мигрировать код под новые возможности аннотаций (`|`, `list[int]`)?**  
Добавьте `from __future__ import annotations` для старых версий,
 обновите mypy/pyright, замените `typing.Union` → `|`, `typing.List` → `list`, и прогоните тесты.
