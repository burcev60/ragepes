**Python 3.11** (выпущен в 2022) фокусировался на производительности и ряде улучшений:

- **Ускорение**: Проект Faster CPython (PEP 659) внедрил адаптивный специализированный интерпретатор. Байткод JIT-оптимизируется на лету: например, если операция `+` видит, что оба операнда int, она может заменить себя на более оптимизированную инструкцию. В итоге 3.11 может быть на 10-30% быстрее 3.10 на ряде задач.

- **Exception Groups (PEP 654)**: введена возможность объединять несколько исключений в одно (`ExceptionGroup`) и перехватывать их частично через `except*`. Это продвинутая функциональность, в основном для библиотек, которые выполняют много параллельных действий и могут выдать несколько ошибок одновременно.

    eg = ExceptionGroup("Множество ошибок", [ValueError("x"), TypeError("y")])
    try:
        raise eg
    except* ValueError as e:
        print("ValueErrors:", e.exceptions)  # поймает подгруппу ValueError
    except* Exception as e:
        print("Остальные ошибки:", e.exceptions)

- **Улучшенные сообщения об ошибках**: у SyntaxError теперь показывается стрелочка на конкретное место в строке, где обнаружена проблема (примерно, как уже делал Friendly-tracebacks).

- **PEP 673 – typing.Self**: добавлен тип Self для аннотации методов, возвращающих экземпляр класса (для лучшей поддержки фабричных методов в Generic контекстах).

- Внутренние оптимизации: frame-объекты создаются ленивее, ускорена работа `deepcopy` для dict, у list сортировка для простых случаев быстрее и т.д.

**Python 3.12** (выпущен в 2023) и будущее:

- Улучшение интерпретатора: продолжение проекта ускорения.

- **PEP 692**: улучшенная типизация `**kwargs` (возможность указать типы ключей).

- **PEP 701**: улучшения f-строк (в 3.12 f-строки позволят использовать в выражении `=` без проблем с пробелами и {...}).

- Работа над изоляцией GIL на уровне субинтерпретаторов (PEP 684): теоретически в будущем можно будет запускать несколько подинтерпретаторов в рамках одного процесса без общей GIL, но это пока экспериментально.

**Другие современные возможности**:

- **Dataclasses (PEP 557, Python 3.7)** – уже упомянуто, но стоит закрепить: являются стандартным способом создавать простые классы для хранения данных.

- **Context Variables (PEP 567, Python 3.7)** – для асинхронного кода, переменные контекста, которые передаются по цепочке вызовов, но изолированы между разными асинхронными задачами (решение проблемы глобальных переменных в async среде).

- **importlib.metadata (Python 3.8)** – позволяет читать метаданные пакетов (версии установленных, entry points).

- **Новое в синтаксисе**: оператор `|` уже упоминали для dict, `@` оператор матричного умножения (PEP 465, Python 3.5) – используется в numpy и подобных.

Современный Python постоянно развивается через процесс PEP. Некоторые PEP не входят в язык, но используются в сообществе (например, PEP 8 – стиль кода).
