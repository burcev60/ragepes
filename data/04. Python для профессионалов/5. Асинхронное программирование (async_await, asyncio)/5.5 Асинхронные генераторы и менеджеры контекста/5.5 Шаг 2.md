### FAQ

*Если у вас возникнут дополнительные вопросы — напишите их в комментариях к шагу!*

1. **Чем асинхронный генератор отличается от обычного?**  
  - Объявляется через `async def`, а не `def`.
  - Использует `yield` (не `yield from`) для выдачи значений и может содержать `await` внутри тела.
  - Итерируется конструкцией `async for`; попытка обычного `for` вызовет `TypeError`.
2. **Почему в асинхронном генераторе запрещён `yield from`?**  
Конструкция `yield from` относится к синхронному протоколу.
 В асинхронном мире ей соответствует `async for`, который
 сам выполняет необходимое ожидание и передачу значений.
3. **Как корректно закрыть асинхронный генератор досрочно?**  
У объекта есть метод `aclose()`:

    agen = countdown(10)
    await agen.__anext__()   # получили первое значение
    await agen.aclose()      # остановили и освободили ресурсы
  

Если генератор использует `try/finally`, секция `finally` гарантированно выполнится.

4. **Можно ли использовать `async for` внутри синхронной функции?**  
Нет. `async for` допустим только внутри `async def`.
 В синхронном коде оберните логику в корутину и выполните через `asyncio.run()`.
5. **Как работает `async with` под капотом?**  
`async with mgr as x:`  
1) `x = await mgr.__aenter__()`  
2) выполняется блок;  
3) `await mgr.__aexit__(exc_type, exc_val, tb)` – если метод вернул `True`, исключение подавляется.
6. **Можно ли комбинировать `async with` и обычный `with` в одной строке?**  
Да: сперва идут асинхронные менеджеры, затем синхронные
 (или наоборот) через запятую. Пример:

    async with aiohttp.ClientSession() as s, open("out.txt", "w") as f:
            ...
  

Порядок закрытия — обратный объявлению.

7. **Нужно ли всегда возвращать `self` из `__aenter__`?**  
Нет, верните любой объект, который удобно использовать в блоке `async with`. Если ничего не нужно, можно вернуть `None`.
8. **Как обрабатывать исключения внутри `__aexit__`?**  
Параметры метода — это `(exc_type, exc_val, traceback)`.
 Проверьте `exc_type` и верните `True`, чтобы подавить
 конкретное исключение, либо `False`/`None`, чтобы
 позволить ему «всплыть».
9. **Поддерживает ли Python comprehension-синтаксис для асинхронных генераторов?**  
Да, начиная с 3.6: `[i async for i in agen]` или `{i async for i in agen if i % 2}`.
 Такой comprehension нужно `await` внутри корутины,
 если он использует `await` в теле.
10. **Можно ли сочетать асинхронные генераторы и `yield` из обычных генераторов?**  
Нельзя «скрестить» напрямую: асинхронный итератор должен реализовать `__anext__`, а синхронный — `__next__`.
 Если нужно обобщить, напишите адаптер: синхронный генератор,
 который `await`-ит асинхронный источник и выдаёт значения
 через `yield`, или наоборот.
