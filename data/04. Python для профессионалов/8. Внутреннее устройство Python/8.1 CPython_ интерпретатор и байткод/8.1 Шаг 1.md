Python – язык с динамической типизацией и высокоуровневыми абстракциями, но под капотом у основной реализации (CPython) происходит немало действий для исполнения вашего кода.

**CPython** – наиболее распространенная реализация Python, написанная на C. Когда мы запускаем скрипт или интерпретатор, CPython выполняет следующие шаги:

1. **Парсинг (синтаксический анализ)**: исходный код `.py` преобразуется в абстрактное синтаксическое дерево (AST).

2. **Компиляция в байткод**: AST транслируется в последовательность **байткода** – низкоуровневых инструкций для виртуальной машины Python. Байткод – это коды операций (опкоды) плюс аргументы. Например, загрузить значение, сложить, сделать условный переход и т.д.

3. **Выполнение байткода**: виртуальная машина (интерпретатор) читает байткод и исполняет каждую инструкцию. В CPython 3.x используется стековая виртуальная машина: большинство операций берут операнды из стека и кладут результат обратно на стек.

Каждый `.py` файл при импорте компилируется в байткод, и CPython может сохранять байткод в файлы `.pyc` (в папке **pycache**). Это ускоряет повторный запуск, минуя стадию парсинга/компиляции, если исходник не изменился.

Пример:

    x = 1
    y = 2
    print(x + y)

Этот код при компиляции превратится во что-то вроде (псевдокод байткода):

    LOAD_CONST 1
    STORE_NAME x
    LOAD_CONST 2
    STORE_NAME y
    LOAD_NAME print
    LOAD_NAME x
    LOAD_NAME y
    BINARY_ADD
    CALL_FUNCTION 1

Где BINARY_ADD сложит два верхних элемента стека, CALL_FUNCTION вызовет функцию print с одним аргументом (результатом сложения).

Можно посмотреть байткод функции, используя модуль `dis` (дизассемблер):

    import dis
    def example():
        x = 1
        y = 2
        return x + y

    print(dis.dis(example))

Это выведет инструкции байткода для функции example, например (комментарии поясняют этапы):

    2           0 LOAD_CONST               1 (1)
                  2 STORE_FAST               0 (x)
      3           4 LOAD_CONST               2 (2)
                  6 STORE_FAST               1 (y)
      4           8 LOAD_FAST                0 (x)
                 10 LOAD_FAST                1 (y)
                 12 BINARY_ADD
                 14 RETURN_VALUE

Строки слева – номер строки в исходнике, далее байтовый адрес, операция, аргумент и пояснение аргумента.

**Стековая виртуальная машина**: CPython VM управляет стеком, на который кладет промежуточные результаты. Например, чтобы сложить x и y, VM кладет x, затем y, выполняет BINARY_ADD, который убирает оба и кладет результат.

**Цикл выполнения (eval loop)**: реализован на Си (файл `ceval.c`). По сути, это бесконечный цикл: получить следующую инструкцию -> выполнить -> повторить. В реальности он сложнее, т.к. должен проверять многие вещи (например, сигналы ОС, события дебаггера, переключение потоков по GIL и т.п.).

**GIL**: (подробнее в следующем уроке) CPython использует глобальную блокировку интерпретатора, поэтому одновременно исполняется только один поток байткода, даже если потоков несколько.

**Альтернативные реализации**:

- **PyPy** – реализация Python на Python (с JIT-компиляцией, ускоряющей выполнение).

- **Jython** – Python на JVM (байткод Python -> байткод Java).

- **IronPython** – Python на .NET CLR.

- **MicroPython** – облегчен для микроконтроллеров.

Каждая реализация может иметь свои особенности. Мы фокусируемся на CPython.
