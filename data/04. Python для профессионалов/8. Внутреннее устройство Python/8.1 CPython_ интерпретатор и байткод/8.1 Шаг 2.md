### FAQ

*Задавайте дополнительные вопросы в комментариях — мы расширим раздел.*

1. **Что такое файлы `__pycache__/module.cpython-311.pyc` и можно ли их удалить?**  
Это скомпилированный байткод. При следующем импорте, если дата/хэш
 исходника совпадает, CPython пропустит стадию парсинга.
 Удаление безопасно: интерпретатор просто пересоздаст кеш.
2. **Как посмотреть байткод функции?**  

    import dis
    dis.dis(my_func)
  

Для подробностей (offset, line-number table) используйте `dis.Bytecode(my_func).dis()`.

3. **Почему VM стековая, а не регистровая?**  
Стековые инструкции компактнее, легче генерировать из AST и
 упрощают передачу промежуточных результатов.
 Недостаток — больше операций «толкать/поп»; PyPy/JIT могут
 оптимизировать их до регистров на лету.
4. **Как цикл `ceval.c` решает, когда переключать потоки (GIL)?**  
У CPython 3.x «квант» ≈ 5 мс (кроме 3.12, где «per bytecode tick»).
 Счётчик уменьшается на каждую выполненную инструкцию; когда
 достигает нуля, поток пытается освободить GIL.
5. **Можно ли «оптимизировать» байткод руками?**  
Только для экспериментов. Стабильный способ —
 писать понятный Python-код: большинство микровыигрышей исчезнут
 после обновления версии. Для серьёзного ускорения: C-расширения, `cython`, PyPy, Numba.
6. **Почему `assert` исчезает при запуске с `-O`?**  
Флаг `-O` (optimize) убирает опкод `ASSERT_OP` при
 компиляции, экономя время выполнения. Используйте `assert` только для проверок разработчика, а не бизнес-логики.
7. **Что произойдёт, если изменить байткод и исполнить его?**  
Можно создать новый объект code через `types.CodeType`,
 но это нестабильно: форматы bytecode меняются межрелизно.
 Для «инъекций» проще использовать декораторы/метапрограммирование.
8. **PyPy быстрее CPython всегда?**  
Для долгоживущих CPU-нагруженных программ — да (JIT оптимизирует).
 Для коротких CLI-скриптов старт JIT > 0.5 с, поэтому CPython выигрывает.
 Совместимость C-расширений у PyPy ограничена.
9. **Как посмотреть размер/число инструкций функции?**  
`code = my_func.__code__;`  
• `code.co_code` — байтовая строка;  
• `len(code.co_code)` — байты;  
• `code.co_stacksize` — максимальный размер стека.
10. **Что нового в байткоде Python 3.12+ (PEP 659, adaptive interpreter)?**  
CPython теперь *адаптирует* некоторые опкоды во время работы
 (specialization), заменяя «универсальную» инструкцию на
 более узкую (например, `LOAD_GLOBAL` → `LOAD_GLOBAL_MODULE`),
 сокращая количество проверок типов и ускоряя до 10-35 %.
