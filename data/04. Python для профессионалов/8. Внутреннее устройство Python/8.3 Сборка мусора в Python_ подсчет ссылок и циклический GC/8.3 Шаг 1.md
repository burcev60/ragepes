Python управляет памятью автоматически, удаляя неиспользуемые объекты – это называется **сборкой мусора** (garbage collection). В CPython используется комбинация:

- **Подсчет ссылок (reference counting)** – каждый объект хранит счетчик ссылок (сколько других объектов и переменных ссылаются на него). Когда счетчик становится нулевым, объект сразу удаляется и освобождается память.

- **Дополнительный сборщик циклов** – периодически обнаруживает группы объектов, которые ссылаются друг на друга, образуя цикл, недостижимый извне, и удаляет их.

Подсчет ссылок работает постоянно. Пример:

    a = []       # создали список, счетчик ссылок = 1 (переменная a)
    b = a        # еще одна ссылка, счетчик = 2
    del a        # удалили одну ссылку, счетчик = 1
    del b        # удалили вторую ссылку, счетчик = 0 -> объект удаляется

Большинство объектов освобождается сразу, как только на них не остается ссылок.

Но проблема – если объекты ссылаются друг на друга, образуя цикл:

    class Node:
        def __init__(self):
            self.ref = None

    n1 = Node()
    n2 = Node()
    n1.ref = n2
    n2.ref = n1
    del n1
    del n2

Здесь два Node ссылаются друг на друга. Когда мы удаляем `n1` и `n2`, их внутренние ссылки друг на друга не дают счетчику ссылок упасть до нуля (каждый из них ещё имеет по ссылке). Если бы не было дополнительного GC, получилась бы утечка памяти.

CPython решает это с помощью периодического запуска алгоритма обнаружения циклов. Модуль `gc` управляет этим:

- `gc.collect()` – принудительно запускает сборщик циклов.

- `gc.get_threshold()` и `gc.set_threshold()` – настройки, контролирующие частоту запуска сборщика (основаны на количестве созданных и освобожденных объектов).

Обычно разработчикам не нужно явно вызывать `gc.collect()`, Python сам запускает его по мере необходимости (например, после создания определенного количества объектов).

**Деструкторы (**`__del__`**)**: Если в классе определен метод `__del__`, он вызывается при уничтожении объекта (точнее, когда сборщик решит удалить объект). Полагаться на `__del__` нужно осторожно: если объект с `__del__` вовлечен в циклическую ссылку, сборщик поместит такие объекты во "временное" хранилище (gc.garbage), т.к. не знает, в каком порядке вызывать **del**, и не удалит автоматически. Это может привести к утечке, если не чистить gc.garbage. В общем, `__del__` усложняет работу сборщика.

**Weak references**: Модуль `weakref` позволяет создавать слабые ссылки на объекты, которые не увеличивают счетчик ссылок. Полезно для кэшей или обратных ссылок, когда не хотим препятствовать сборке объекта. Например, `weakref.ref(obj)` возвращает слабую ссылку, которая станет None, когда obj удалится.

**Выделение памяти**: CPython для маленьких объектов использует собственный аллокатор (pymalloc), распределяя память большими блоками (аренами) и отдавая маленькими частями. Поэтому освобождение объекта может не сразу вернуть память ОС, а пометить ее как свободную для будущих объектов Python. Память может "пилиться" между аренами, вызывая фрагментацию (но это уже детали реализации).

Резюме:

- Python автоматически очищает объекты с нулевым счетчиком ссылок.

- Циклические структуры тоже очищаются (кроме случаев с `__del__`).

- Неиспользуемые объекты не текут (утечки обычно возникают только если есть внешние ссылки или `__del__` сложные).

- Иногда полезно знать про `gc` (например, `gc.disable()` можно временно выключить сборщик в особо критичных по времени участках, если уверены, что памяти хватит и циклов нет).
