### FAQ

*Задавайте вопросы в комментариях — мы будем пополнять раздел.*

1. **Получит ли декорированный метод всё ещё `self` первым аргументом?**  
Да. Декоратор получает несвязанный метод (обычную функцию), но когда
 результат помещается в класс, дескрипторный механизм Python превращает её
 в «bound-method» и при вызове передаёт экземпляр как `self`.
2. **Нужно ли использовать `functools.wraps` в декораторах методов?**  
Обязательно, если хотите сохранить имя метода, docstring, аннотации
 — точь-в-точь как при декорировании функций.  

    from functools import wraps
    def log_method(fn):
        @wraps(fn)
        def wrapper(self, *a, **kw):
            ...
        return wrapper
  

3. **В каком порядке применяются несколько декораторов над методом?**  
Так же, как у функций: верхний оборачивает результат нижнего.

    @d1
    @d2
    def m(self): ...
    # → m = d1(d2(m))
  

4. **Чем «декоратор класса» отличается от метакласса?**  
`@decorator` — пост-обработка *уже готового* объекта класса.  
Метакласс вмешивается во время создания (пример — меняет атрибуты до
 финального объекта). В 90 % случаев декоратор проще и достаточен.
5. **Можно ли с помощью декоратора изменить базовые классы (MRO)?**  
Да, но осторожно:

    def add_mixin(cls):
        class New(cls, ExtraMixin):
            pass
        return New
  

Изменение MRO влияет на разрешение методов и должен быть хорошо
 протестирован.

6. **Как работают встроенные `@staticmethod`, `@classmethod`, `@property`?**  
Это *дескриптор-объекты* (не простые функции): они перехватывают
 доступ к атрибуту и меняют способ вызова.  
– `staticmethod` — не передаёт ни `self`, ни `cls`.  
– `classmethod` — первым аргументом даёт класс (`cls`).  
– `property` — делает метод «вычислимым атрибутом».
7. **Можно ли сделать параметризованный декоратор класса?**  
Да, схема та же:

    def register(name):
        def decorator(cls):
            REGISTRY[name] = cls
            return cls
        return decorator
  

`@register("plugin")` — сначала вызывается фабрика, затем
 полученный декоратор получает класс.

8. **Что произойдёт, если декоратор класса вернёт `None`?**  
Имя класса будет заменено на `None`; попытка создать экземпляр
 вызовет `TypeError: 'NoneType' object is not callable`.
 Декоратор обязан вернуть вызываемый класс или совместимый объект.
