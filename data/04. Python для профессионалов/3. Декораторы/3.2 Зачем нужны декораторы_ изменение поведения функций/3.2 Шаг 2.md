### FAQ

*Справочник пополняется новыми вопросами из комментариев к уроку.*

1. **Зачем вообще нужны декораторы, если можно просто вызвать обёртывающую функцию вручную?**  
Декоратор позволяет *одной строкой* «приклеить» дополнительное поведение к множеству функций,
 не меняя их тело. Это снижает дублирование кода и делает дополнительную логику (логирование, кеш,
 измерение времени) явно видимой рядом с объявлением функции.
2. **Чем декоратор отличается от функции-обёртки (wrapper)?**  
  - `декоратор` — функция `decorator(func) → new_func`, которая получает
 оригинальную функцию и возвращает модифицированную.
  - `wrapper` — функция **внутри** декоратора, непосредственно вызывающая `func()` и выполняющая дополнительный код «до» и «после».
3. **Почему в примере используется `*args, **kwargs`?**  
Это универсальный способ принять любой набор позиционных и именованных аргументов, чтобы
 декоратор работал с любыми сигнатурами функций, не ограничивая их.
4. **Как сохранить оригинальные метаданные функции (`__name__`, `__doc__`)?**  
Используйте `functools.wraps(func)`:  

    from functools import wraps
    def debug_decorator(func):
        @wraps(func)
        def wrapper(*a, **kw):
            ...
        return wrapper
  

`@wraps` копирует метаданные из `func` в `wrapper`.

5. **Можно ли передавать параметры самому декоратору?**  
Да, создайте «фабрику» декораторов: функция, принимающая параметры и возвращающая настоящий
 декоратор. Пример — декоратор `@retry(times=3)` из популярного паттерна повторных попыток.
6. **Что произойдёт, если декоратор не вернёт функцию?**  
Python заменит исходную функцию тем, что вернул декоратор.
 Если это будет `None` или объект другого типа, вызов декорированной функции
 приведёт к ошибке «object is not callable».
7. **Можно ли применить несколько декораторов к одной функции?**  
Да, они выполняются «снизу вверх» (ближайший к функции вызывается первым):

    @dec_outer
    @dec_inner
    def f(): ...
    # порядок: dec_outer(dec_inner(f))
