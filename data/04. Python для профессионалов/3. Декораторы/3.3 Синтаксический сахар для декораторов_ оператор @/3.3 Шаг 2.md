### FAQ

*Справочник пополняется вопросами из комментариев.*

1. **Как работает порядок применения при нескольких `@decorator`?**  
Декораторы читаются сверху вниз, а вызываются внутрь-наружу:  

    @d1
    @d2
    def f(): ...
    # эквивалентно:  f = d1(d2(f))
  

Поэтому ближний к функции (`@d2`) выполняется первым.

2. **Можно ли использовать параметры в декораторе с синтаксисом `@`?**  
Да — через фабрику:  

    def log(level):
        def decorator(func):
            ...
            return wrapper
        returndecorator

        @log(level="INFO")
    def foo(): ...
  

Вызывается фабрика → возвращается настоящий декоратор → он оборачивает функцию.

3. **Зачем нужен `functools.wraps` и что будет, если его забыть?**  
Без `@wraps` у обёртки (`wrapper`) будет имя «wrapper», пустой
 docstring, потеряются аннотации и атрибут `__module__`. `@wraps(func)` копирует эти метаданные, сохраняя корректные `help()`, `inspect.getsource()` и дружбу с IDE.
4. **Можно ли декорировать методы классов тем же синтаксисом?**  
Да, правила те же. Если декоратор возвращает *функцию*, она автоматически превращается в
 дескриптор-метод (получит `self` первым аргументом).
5. **Что произойдёт, если декоратор вернёт не функцию, а например число?**  
Имя функции будет заменено этим числом — дальнейшие вызовы вызовут `TypeError: 'int' object is not callable`.
 Декоратор обязан возвращать *вызываемый* объект.
6. **Как задекорировать функцию только при определённом условии (например, в debug-режиме)?**  
Используйте «пустой» декоратор-передатчик:

    def maybe_debug(func):
        if DEBUG:
            return debug_decorator(func)
        return func
  

`@maybe_debug` применит логирование лишь при включённом DEBUG.

7. **Декоратор с `@` можно применять к классу?**  
Да. Если декоратор принимает класс и возвращает модифицированный
 (или новый) класс, используйте его так же: `@dataclass`, `@singleton` и т.д.
