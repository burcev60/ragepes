### FAQ

*Дополняем по вашим вопросам в комментариях.*

1. **Как правильно применять `functools.wraps` в собственном декораторе?**  
Разместите `@wraps(original_func)` непосредственно над обёрткой:

    from functools import wraps
    def my_decorator(func):
            @wraps(func)  
            def wrapper(*a, **kw):
                ...
            return wrapper
  

Это сохраняет метаданные, что важно для отладки, автодокументации и IDE.

2. **Чем `partial` лучше `lambda`?**  
`partial`:
  - поддерживает атрибуты `__name__`, `__doc__`;
  - хранит ссылку на исходную функцию (`.func`) и зафиксированные аргументы;
  - корректно работает с `pickle` (при условии, что оригинальная функция сериализуема).
`lambda` быстрее написать, но лишается этих плюсов.
3. **Почему `reduce()` спрятали в `functools`, а не оставили встроенной?**  
В Python 3 авторы решили, что большинство задач может решить `sum`, `min`, `max`, comprehension-ы и `for`-циклы. `reduce()` оставили, но «убрали с глаз» в модуль, чтобы не перегружать namespace начинающих.
4. **Как очистить кэш у функции с `@lru_cache`?**  
У декорированной функции есть метод `.cache_clear()`: `fib.cache_clear()`.
 Статистику попаданий/промахов смотрите через `fib.cache_info()`.
5. **Можно ли кэшировать методы класса с `lru_cache`?**  
Да, но декоратор должен стоять после `@staticmethod`/`@classmethod` (чтобы кэш был общим) или внутри `__init__` указывать `self` как часть ключа. Сигнатура должна быть hash-able.
6. **Чем `singledispatch` отличается от `total_ordering`?**  
– `singledispatch` динамически выбирает реализацию функции по типу первого аргумента (Generic Functions).
 – `total_ordering` генерирует недостающие методы сравнения внутри класса, опираясь на уже определённые `__eq__` + один
 из операторов (`__lt__/__le__/__gt__/__ge__`).
7. **Какой предел кэша использовать в `lru_cache`?**  
Зависит от задачи. Типичные значения:
  - `None` — бесконечный кэш (осторожно с памятью);
  - 128 / 256 — дефолт, подходит для большинства CPU-связанных расчётов;
  - 1000+ — для I/O-функций с большим повторением запросов.
8. **Можно ли комбинировать `singledispatch` с
 типовыми аннотациями `@overload`?**  
Да. `@overload` из модуля `typing` описывает для
 статического анализатора «виртуальные» сигнатуры, а `singledispatch` определяет реальные рантайм-имплементации.
9. **Когда пригодится `cmp_to_key`?**  
При миграции старого кода Python 2 → 3, где сортировка принимала `cmp(x, y)`. Теперь нужно:

    seq.sort(key=cmp_to_key(old_cmp))
  

или переписать на `key=` и сохранить производительность.

10. **Есть ли ещё полезные «скрытые» функции в functools?**  
– `cached_property` (ленивый property с кэшированием);  
– `partialmethod` — частичное применение для методов;  
– `singledispatchmethod` — диспетчеризация по типу `self`/`cls` в методах класса.
