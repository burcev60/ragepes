### FAQ

*Не нашли ответ? Задавайте вопросы в комментариях — добавим!*

1. **ThreadPool или ProcessPool — что выбрать?**  
  - **I/O-bound** (ожидание сети, диска, БД) → `ThreadPoolExecutor`; GIL освобождается во время I/O.
  - **CPU-bound** (числовые расчёты, сжатие, ML-инференс) → `ProcessPoolExecutor`; каждый процесс получает собственный GIL и ядро.
2. **Почему в `ProcessPoolExecutor` функция должна быть «на уровне модуля»?**  
Под капотом используется `pickle`. Лямбды, вложенные функции и объекты,
 которые нельзя сериализовать, вызовут `PicklingError`.
3. **Как ограничить время ожидания результата?**  
Используйте `future.result(timeout=5)`.
 При превышении времени будет `concurrent.futures.TimeoutError`,
 задачу можно отменить через `.cancel()`.
4. **Что делает `executor.map()` по сравнению с `submit()`?**  
`map(func, *iterables)` планирует все вызовы сразу и возвращает
 ленивый итератор результатов в порядке входных данных. `submit()` + `as_completed()` даёт контроль: можно обрабатывать
 результаты по мере готовности и отменять отдельные фьючерсы.
5. **Надо ли вручную вызывать `shutdown()`?**  
Если используете контекст-менеджер `with Executor(...) as ex:` —
 нет, `shutdown(wait=True)` вызовется автоматически.
 В противном случае вызов обязателен, чтобы корректно закрыть потоки/процессы.
6. **Можно ли изменить число рабочих потоков/процессов после создания пула?**  
Нет. Создайте новый `Executor` с нужным `max_workers`.
 Старый пул завершите (`shutdown()`).
7. **Как передать «большой» объект в `ProcessPoolExecutor` без лишнего копирования?**  
Никак полностью избежать копий: данные сериализуются в канал межпроцессного
 взаимодействия. Используйте:
  - общую память (`multiprocessing.shared_memory`),
  - мэп-файл `mmap`,
  - храните данные в файле/БД и передавайте только ключи/смещения.
8. **Почему в Windows нужно писать `if __name__ == "__main__":`?**  
`ProcessPoolExecutor` (как и `multiprocessing`)
 перезапускает процесс через импорт текущего модуля; без защиты возникнет
 бесконечное создание новых процессов.
9. **Можно ли использовать пул в асинхронном (asyncio) коде?**  
Да:

    loop = asyncio.get_running_loop()
    result = await loop.run_in_executor(ThreadPoolExecutor(), blocking_func, arg)
  

Это «мост» между синхронной блокирующей функцией и async-циклом.

10. **Как мониторить загрузку пула и количество активных задач?**  
Базовый API не показывает метрик.
 Варианты:
  - хранить собственный счётчик отправленных/завершённых задач,
  - использовать `concurrent.futures.thread._threads_queues` (не-public),
  - переходить на `multiprocessing.pool` или сторонние lib-monitor’ы.
