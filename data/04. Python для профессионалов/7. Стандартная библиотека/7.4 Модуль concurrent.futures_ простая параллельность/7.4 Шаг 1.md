Модуль `concurrent.futures` предоставляет высокоуровневый интерфейс для параллельного выполнения задач с использованием потоков (ThreadPoolExecutor) или процессов (ProcessPoolExecutor).

Основные компоненты:

- **Executor** – базовый класс исполнителя (не используется напрямую, только через подклассы).

- **ThreadPoolExecutor** – исполнитель, который выполняет задачи в пуле потоков.

- **ProcessPoolExecutor** – исполнитель, который выполняет задачи в пуле процессов.

**Когда использовать:**

- ThreadPoolExecutor – хорош для I/O-bound задач (сетевые запросы, файловые операции), которые могут параллельно выполняться несмотря на GIL, так как GIL освобождается при ожидании I/O (встроенные операции ввода-вывода освобождают GIL внутри).

- ProcessPoolExecutor – хорош для CPU-bound задач (вычисления), т.к. обходит GIL путем использования нескольких процессов (каждый со своим интерпретатором Python на отдельном ядре).

Пример использования ThreadPoolExecutor:

    import time
    from concurrent.futures import ThreadPoolExecutor, as_completed

    def work(x):
        print(f"Начало работы {x}")
        time.sleep(1)
        print(f"Конец работы {x}")
        return x * x

    # Создаем пул из 3 потоков
    with ThreadPoolExecutor(max_workers=3) as executor:
        futures = [executor.submit(work, i) for i in range(5)]
        for fut in as_completed(futures):
            result = fut.result()
            print("Результат:", result)

В этом коде мы запускаем 5 задач, которые имитируют работу (спят 1 секунду) параллельно в 3 потоках. `executor.submit(func, arg)` возвращает объект Future (будущего результата). `as_completed` – генератор, который итерируется по завершившимся задачам в порядке их завершения. Мы получаем результаты по мере готовности.

Вывод может быть:

    Начало работы 0
    Начало работы 1
    Начало работы 2
    Конец работы 0
    Начало работы 3
    Результат: 0
    Конец работы 1
    Начало работы 4
    Результат: 1
    Конец работы 2
    Результат: 4
    Конец работы 3
    Результат: 9
    Конец работы 4
    Результат: 16

(Порядок немного зависит от планировки потоков, но видно, что работы переплетаются, а результаты получаем по мере готовности).

Для CPU-bound задач можно заменить на ProcessPoolExecutor:

    from concurrent.futures import ProcessPoolExecutor
    with ProcessPoolExecutor() as executor:
        results = list(executor.map(lambda x: x*x, range(5)))
    print(results)

Здесь `executor.map` запускает вычисление `x*x` для 0..4 в разных процессах параллельно и возвращает результаты. Процессы имеют изолированную память, поэтому функции, передаваемые в ProcessPoolExecutor, должны быть сериализуемы через pickle. Также данные, возвращаемые из процесса, копируются (то есть для очень больших данных могут быть накладные расходы).

Также concurrent.futures позволяет:

- Отменять задачи: `future.cancel()`.

- Проверять состояние: `future.done()`, `future.running()`, `future.result(timeout)` – получить результат или исключение.

- Использовать context manager `with` для автоматического shutdown() у пула, как показано в примере.

Модуль concurrent.futures объединяет под единый интерфейс многопоточность и многопроцессность. Под капотом, ThreadPoolExecutor использует `threading` и `queue`, а ProcessPoolExecutor – `multiprocessing`.
