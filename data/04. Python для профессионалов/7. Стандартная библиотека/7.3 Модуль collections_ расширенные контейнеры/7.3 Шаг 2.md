### FAQ

*Если не нашли нужного ответа — задавайте вопросы в комментариях!*

1. **Зачем нужен `namedtuple`, если есть `@dataclass(frozen=True)`?**  
  - namedtuple создаётся быстрее и занимает меньше памяти (это по-сути `tuple` + имена полей).
  - dataclass даёт больше гибкости: типы, дефолты, методы, валидация.
Для лёгких «структур-записей» — берите `namedtuple`;
 для «богатых» объектов — `@dataclass`.
2. **Когда использовать `deque` вместо списка?**  
  - Нужны частые `appendleft/pop` — у списка это O(n), у `deque` O(1).
  - Реализовать фиксированный буфер последних N элементов (параметр `maxlen`).
Срезы и случайный доступ у `deque` работают медленнее — в этом случае лучше список.
3. **Можно ли использовать `Counter` для арифметики множеств?**  
Да: поддерживаются операции `+`, `-`, `&`, `|` (для Py 3.10+).
 Нулевые и отрицательные счётчики автоматически отбрасываются методом `Counter += Counter()`.
4. **Чем `defaultdict(list)` лучше `setdefault`?**  
`setdefault` каждый раз создаёт новый список, даже если ключ уже есть. `defaultdict` вызывает фабрику только при первом обращении,
 поэтому быстрее и чище по синтаксису.
5. **Нужен ли `OrderedDict` после Python 3.7?**  
Обычный `dict` гарантирует порядок вставки,
 но `OrderedDict` всё ещё полезен:
  - `move_to_end(key, last=True)` — быстро менять позицию;
  - `popitem(last=False)` — вынуть первый вставленный элемент (FIFO-кеш).
6. **Как работает `ChainMap` и чем отличается от `{**d1, **d2}`?**  
`ChainMap(a, b)` ищет ключи последовательно без копирования
 данных. Изменения в первом мапе отражаются сразу.
 Оператор `{**a, **b}` создаёт *новый* словарь (копия),
 занимает память и время.
7. **Можно ли сделать собственный неизменяемый словарь/список, унаследовав `UserDict`/`UserList`?**  
Да: переопределите методы изменения (`__setitem__`, `append` …)
 и выбросите `TypeError`.
 Класс-обёртка уже реализует большинство «клейкой» логики.
8. **Как быстро посчитать «скользящее окно» последних N элементов?**  
Используйте `deque(maxlen=N)`.
 При каждом `append` сверх лимита старый элемент удаляется автоматически.
9. **Зачем `collections.abc`? Чем проверка `isinstance(x, Iterable)` лучше `try: iter(x)`?**  
`collections.abc` даёт *формальный* интерфейс:
 – Можно объявить класс наследником, чтобы он «официально» считался `Mapping`, `Sequence` и т.д.;
 – Статические анализаторы/IDE поймут тип;
 – `isinstance` быстрее, чем ловить исключение.
10. **Как объединить два `Counter` «по максимуму» значений?**  

    from collections import Counter
    c1 = Counter(a=3, b=1)
    c2 = Counter(a=1, b=4)
    c_max = c1 | c2   # Python 3.10+: Counter({'a': 3, 'b': 4})
  

Оператор `|` оставляет максимальное значение для каждого ключа.
