### Разрешения файлов и управление пользователями (chmod, chown, sudo)

Теперь о безопасности. В многопользовательских системах Linux важно, кто что может делать. За это отвечают **права доступа (permissions)** файлов и папок, а также механизм привилегий (например, команда sudo).

Каждый файл в системе имеет **владельца** и **группу**, а также набор прав для трёх категорий: *владелец*, *группа*, *остальные*. Права обозначаются буквами:

- `r` (read) — разрешение на чтение,

- `w` (write) — разрешение на запись (изменение, удаление),

- `x` (execute) — разрешение на выполнение файла как программы.

Посмотрим на пример вывода `ls -l`:

    -rw-r--r-- 1 alice alice 1024 Jan 1 12:34 report.txt

В начале мы видим строку `-rw-r--r--` — это код прав доступа. Разобьём её: первый символ `-` означает, что это файл (для директории была бы буква `d`). Далее идёт три группы символов:

- `rw-` – права владельца (владелец может читать и писать, но не выполнять файл);

- `r--` – права группы (члены группы владельца могут только читать);

- `r--` – права остальных (все остальные пользователи тоже могут только читать).

После прав указано, что владельцем файла *report.txt* является пользователь `alice`, а группа владельца тоже `alice`. Размер файла 1024 байта, дата изменения и имя файла.

**Изменение прав (chmod):** Команда `chmod` (change mode) используется для изменения этих прав. Сделать файл исполняемым для владельца: `chmod u+x script.sh` (`u` = user, владелец; `+x` = добавить право выполнения). Забрать право на чтение у группы: `chmod g-r secret.txt`. Можно задавать права и числовым кодом, который складывается из сумм 4 (r) + 2 (w) + 1 (x) для каждой категории. Например:

- 7 = r+w+x,

- 5 = r + x,

- 4 = r.

Так, `chmod 750 myprog` установит права `rwxr-x---` (7 для владельца = rwx, 5 для группы = r-x, 0 для остальных = ---). Если видишь код `644`, это `rw-r--r--` (владелец читает и пишет, остальные только читают). А код `777` – полный доступ всем (rwxrwxrwx) — обычно так делать не нужно, это небезопасно.

**Смена владельца (chown):** Команда `chown user:group file` меняет владельца и/или группу файла. Требует прав суперпользователя (или чтобы вы сами были владельцем файла). Например, `sudo chown bob:users report.txt` сделает пользователя bob владельцем файла *report.txt*, а группу изменит на *users*. Если группу не указывать (`sudo chown bob report.txt`), поменяется только владелец, группа останется прежней.

**Повышение привилегий (sudo):** В Linux обычные пользователи не имеют права выполнять многие системные действия (например, открывать порт 80, менять системные файлы, устанавливать софт). `sudo` позволяет временно выполнить одну команду от имени суперпользователя (root), если ваш пользователь включён в список доверенных (обычно это группа sudo или wheel). Синтаксис простой: `sudo <команда>`. При первом использовании в сессии вас спросят пароль (пароль вашего пользователя, не root). Пример:

    sudo apt update

    sudo apt install nginx

Эти команды обновят списки пакетов и установят веб-сервер nginx, используя привилегии суперпользователя. Без sudo вы получили бы отказ в доступе. Важно: будьте аккуратны с sudo, ведь запуская что-то с правами root, можно случайно навредить системе. Помни фразу: *"с большой силой приходит большая ответственность"*. Кстати, забавный факт: в мире Linux есть шутка-команда `sudo make me a sandwich` (из комикса XKCD). Если просто попросить "make me a sandwich" (сделай мне бутерброд), терминал ответит "что, сам себе сделай?". А вот с `sudo` — бутерброд *магически* появится (на самом деле, конечно, это просто шутка, реальной команды такой нет, но демонстрирует идею о силе sudo).

Резюмируем: используй chmod и chown, чтобы настраивать доступ к файлам, и sudo – чтобы выполнять административные задачи, когда это необходимо. Всегда проверяй права (`ls -l`), если получаешь неожиданный отказ или, наоборот, хочешь убедиться, что конфиденциальный файл не прочитают лишние люди.
