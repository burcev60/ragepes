**Практическое задание:** Выполните небольшие упражнения:

1. **Сеть:** Проверьте подключение до известного сайта. Выполните `ping -c 4 google.com` и посмотрите статистику (4 пакета отправлены и получены). Затем попробуйте скачать содержимое веб-страницы. Например, командой `curl http://example.com > example.html` вы можете сохранить HTML-код страницы example.com в файл *example.html*. Проверьте, создался ли файл и просмотрите его содержимое через `less example.html` или откройте в редакторе – вы увидите исходный код страницы. Попробуйте аналогично команду `wget http://example.com` (она сама сохранит страницу в файл).

2. **Права:** Создайте файл `secret.txt` командой `touch secret.txt`. Выполните `ls -l secret.txt` и посмотрите текущие права доступа (например, `rw-rw-r--`). Теперь ограничьте доступ к файлу: выполните `chmod 600 secret.txt` и снова `ls -l` — права должны измениться на `rw-------` (только владелец может читать и писать). Попытайтесь прочитать файл от имени другого пользователя (если у вас есть такая возможность, либо мысленно представьте) — доступ будет запрещён. Верните права обратно командой `chmod 644 secret.txt` (чтение для всех, запись только для владельца). Затем измените владельца файла (потребуются права суперпользователя): `sudo chown root secret.txt`. Теперь владельцем значится root (проверьте через `ls -l`). Верните себе владение файлом командой `sudo chown $USER secret.txt` (переменная `$USER` содержит ваше имя пользователя).

Подумайте, для чего нужны такие ограничения. Например, файл с правами 600 гарантирует, что кроме вас его никто не прочитает. А `sudo` понадобится, чтобы делать системные вещи (попробуйте, кстати, создать файл в директории `/root` без sudo – система запретит, потому что у вашего пользователя нет прав на каталог root).
