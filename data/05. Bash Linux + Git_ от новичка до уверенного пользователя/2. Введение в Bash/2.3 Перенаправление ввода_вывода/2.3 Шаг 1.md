### Перенаправление ввода/вывода

Одно из самых мощных свойств Bash — умение перенаправлять потоки ввода и вывода. Что это значит? Обычно команды выводят текст в терминал (stdout) или читают ввод с клавиатуры (stdin). Перенаправление позволяет "связать" команды друг с другом или с файлами, как трубы в сантехнике:

- Символ `>` перенаправляет вывод команды в файл, **перезаписывая** этот файл. Например, `ls > files.txt` возьмёт всё, что команда ls обычно выводит на экран, и запишет в файл *files.txt*. Если файл существовал, его содержимое будет заменено.

- Символ `>>` тоже перенаправляет вывод в файл, но в **конец** файла, дописывая новые данные. Полезно для ведения журналов. Например, `echo "Новая запись" >> log.txt` добавит строку "Новая запись" в конец файла log.txt.

- Символ `|` (пайп, "вертикальная черта") перенаправляет вывод одной команды напрямую на **вход** другой команды. Это как конвейер: первая команда производит данные, вторая их потребляет. Например, `ls /bin | grep bash` возьмёт список файлов из /bin и передаст его на вход команде grep, которая отфильтрует и покажет только строки, содержащие "bash". Таким образом, с помощью пайпов можно строить целые цепочки обработки данных.

- Символ `<` перенаправляет **вход** команды из файла. То есть вместо клавиатуры команда прочитает данные из указанного файла. Например, если у тебя есть файл *list.txt*, ты можешь передать его содержимое как ввод команде sort: `sort < list.txt` и получить отсортированный список строк на экране.

Перенаправления можно комбинировать. Пример посложнее: `grep "ERROR" app.log | sort > errors_sorted.txt` — эта конструкция найдёт все строки с "ERROR" в файле *app.log*, отсортирует их и сохранит результат в файл *errors_sorted.txt*. Попробуй представить, как данные текут через пайп, словно вода по трубе, и оказываются в файле.

Теперь, когда мы освоили основы управления файлами и вывода, самое время перейти к инструментам для работы с текстом и файлами более глубоко.
