## **Основные стратегии ветвления**

### **1. Git Flow**

**Git Flow** — одна из самых популярных стратегий для проектов с долгосрочной разработкой и периодическими релизами.

#### **Основные ветки:**

- **`main`** — основная ветка с последними стабильными версиями.
- **`develop`** — ветка для текущей разработки.
- **`feature/*`** — ветки для разработки новых функций.
- **`release/*`** — ветки для подготовки релиза.
- **`hotfix/*`** — ветки для исправления критических ошибок.


#### **Процесс работы:**

1. Создание новой функциональности в ветке `feature/feature-name`. `git checkout develop git checkout -b feature/new-feature `

2. Слияние ветки `feature` в `develop` после завершения работы. `git checkout develop git merge feature/new-feature `

3. Подготовка релиза в ветке `release`.

4. Быстрое исправление ошибок через ветку `hotfix`.

#### **Когда использовать Git Flow?**

- Для больших проектов с чёткими этапами разработки и релизами.
- При разработке сложных приложений с долгими циклами разработки.


### **2. GitHub Flow**

**GitHub Flow** — более простая и гибкая стратегия, подходящая для проектов с непрерывной интеграцией и быстрыми релизами.

#### **Основные принципы:**

- Всегда работайте в ветке `main`.
- Для каждой новой задачи создавайте временную ветку (`feature-branch`).
- Создавайте Pull Request для слияния изменений в `main`.
- После прохождения код-ревью выполняйте слияние.


#### **Пример:**

1. Создайте новую ветку для задачи. `git checkout -b feature/task-123 `

2. Внесите изменения и создайте коммит. `git add . git commit -m "Добавлена новая функция" `

3. Запушьте изменения и создайте Pull Request. `git push origin feature/task-123 `

#### **Когда использовать GitHub Flow?**

- Для стартапов и небольших команд.
- При непрерывной интеграции и доставке (CI/CD).


### **3. Trunk-based Development**

**Trunk-based Development** — это подход, при котором все разработчики работают в одной ветке (`trunk` или `main`), а изменения интегрируются очень часто.

#### **Основные принципы:**

- Минимальное использование временных веток.
- Короткие жизненные циклы изменений.
- Интеграция с CI/CD для автоматического тестирования и деплоя.


#### **Пример:**

1. Работайте напрямую в ветке `main`.
2. Все изменения должны проходить через CI для автоматического тестирования.
3. Проводите частые небольшие релизы.


#### **Когда использовать Trunk-based Development?**

- Для проектов с высокой скоростью разработки.
- При использовании DevOps-подходов и CI/CD.
