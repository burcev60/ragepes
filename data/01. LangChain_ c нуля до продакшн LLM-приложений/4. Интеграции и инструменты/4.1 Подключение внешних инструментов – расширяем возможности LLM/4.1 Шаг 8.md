## 🔹 Практическое задание: Базовый набор инструментов

**Цель:** собрать модуль `tools.py` с базовой библиотекой инструментов для ассистента. Реализовать несколько примеров tools, настроить обработку ошибок, таймауты и ретраи, а также подготовить список инструментов для последующего подключения в агента.

### 🔸 Что требуется сделать

В рамках задания вам нужно подготовить модуль `tools.py`, содержащий полноценный набор инструментов. Каждый инструмент оформляется функцией с декоратором `@tool`, имеет строковое описание и надёжную обработку ошибок. Итоговый модуль должен включать несколько примеров инструментов. Например:

### **1) CalculatorTool**

Инструмент выполняет арифметические выражения:

- использует безопасную оценку выражений через AST;

- разрешены только базовые операции и функции из `math`;

- обрабатывает ошибки (например, деление на ноль);

- имеет встроенный ограниченный таймаут.

### **2) WebSearchTool (скелет с ретраями)**

Инструмент должен:

- принимать поисковый запрос;

- обращаться к API (например, DuckDuckGo);

- возвращать top-k результатов поиска;

- выполнять несколько попыток при сбоях, используя экспоненциальный backoff.

### **3) WeatherTool**

Инструмент определяет погоду по названию города:

- использует Open-Meteo (геокодинг + текущая погода);

- повторяет запросы при ошибках сети;

- корректно обрабатывает ситуацию, когда город не найден.

### **4) FileTool**

Инструмент читает файлы с диска:

- доступ ограничен конкретной папкой;

- разрешены только определённые расширения;

- встроены проверки размера и безопасности пути.

### **5) CurrencyTool**

Инструмент запрашивает курсы валют через `api.fxratesapi.com` или аналоги:

- принимает хотябы пару валют;

- возвращает стоимость 1 единицы базовой валюты;

- выполняет ретраи и корректно обрабатывает ошибки API.

## 🔸 Требования к реализации

1. **Каждый инструмент** должен быть оформлен через `@tool`.

2. Сетевые операции — с ретраями.

3. В нижней части модуля должен быть определён список инструментов, например:  


    def make_tools():
        return [calculator, web_search, weather, read_file, fx_rate]

   

## 🔸 Что нужно протестировать

Перед подключением инструментов к агенту проверьте их работу напрямую (без LLM):

- корректные аргументы → успешный результат;

- невалидные входные данные → понятная ошибка;

- сетевые инструменты → действительно выполняют несколько попыток (проверьте по логам/счётчику);

- проверка файлового инструмента для разных расширений, размеров и путей.

## 🔸 Результат шага

После выполнения задания у вас должен быть готовый модуль `tools.py`, содержащий:

- набор надёжных инструментов;

- контроль ошибок и таймаутов;

- ретраи для сетевых операций;

- безопасное чтение файлов;

- единый список зарегистрированных инструментов.

Этот набор станет фундаментом, на котором вы далее сможете строить ассистента, расширять функциональность инструментов, добавлять новые API и подключать всё это к агенту.
