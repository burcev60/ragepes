## 🔹 Концепция tool‑вызовов

В модуле про RAG мы уже немного касались темы инструментов, когда рассказывали про агентную архитектуру и там мы как инструмент использовали ретривер. Но это лишь один вариант использования инструментов в langchain. Давайте подробнее разберёмся в том, как работать с инструментами, как большие языковые модели могут взаимодействовать с ними и как LLM решает, когда вызывать их вместо прямого ответа.

### 🔸 Что такое tool‑вызов?

LLM по своей природе ограничены текстовым вводом‑выводом и знаниями из обучающих данных. Подключение инструментов даёт модели “руки и глаза” – возможность выполнить действие (например, сделать вычисление, вызвать веб‑API, выполнить поиск) и затем использовать результат в своём ответе. В langchain инструмент — это обёртка вокруг функции или API, который модель может вызвать по имени. У каждого инструмента есть описание того, для чего он нужен и как им пользоваться.

### 🔸 Что это даёт?

LLM становится координатором, принимающим решение о том, когда и какой инструмент применить. Благодаря этому ассистент может получать свежие данные (через web‑поиск), совершать транзакции (вызывать API), работать с форматами (генерировать и запускать код). Это открывает путь к созданию **агентов** – интеллектуальных сущностей, которые решают сложные задачи пошагово.

### 🔸 Создание инструмента в LangChain?

Как же создаются такие инструменты? импортируем метод: `from langchain.tools import tool`, с помощью которого мы можем создать объект `Tool` , обернув некую функцию этим методом как декоратором. Этот объект имеет имя (`name`), описание (`description`), схему входных аргументов (`args_schema`) и собственно саму функцию / метод, который выполняется.

    # Пример: инструмент Calculator
    from langchain.tools import tool

    @tool("Calculator", args_schema=some_schema)
    def calculate(a: str, b: str) -> str:
        """Складывает два числа."""
        return str(int(a) + int(b) + 1)
    # считаем неправильно, специально, чтобы убедиться что модель не сама считала, а использовала именно инструмент

В этом примере:

- имя инструмента это `name="Calculator"`
- `args_schema` — это класс схемы (обычно на базе **Pydantic** `BaseModel`) или JSON-схема, описывающая, какие аргументы инструмент принимает, их типы, описание, обязательность и т.п.
> 💡 Для нашего простого примера этот аргумент не обязателен, разберём его позже

- строка `"""Складывает два числа."""`, это `description` и тут это не просто для удобства программиста, этот пункт обязателен при создании инструмента, агент берёт для себя описание отсюда и без него будет ошибка.
> 💡 альтернативный вариант задания описания инструмента в аргументе у декоратора:
>
> @tool("Calculator", description="Складывает два числа")

 

### 🔸 Интеграция в агентов

Для использования этих инструментов нам нужен `Agent`. Агенту, чтобы он мог использовать инструменты в системном промпте необходимо перечислить доступные инструменты и формат ответа.

    import os
    from dotenv import load_dotenv
    from langchain.agents import create_agent
    from langchain_openai import ChatOpenAI

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")
    model = ChatOpenAI(model_name=MODEL, temperature=0)

    system_prompt = """
    Ты агент-помощник.
    Если пользователь просит посчитать что-либо — ты ВСЕГДА вызываешь инструмент Calculator.
    Тебе нужно извлечь из текста два числа:
     - первое число — аргумент a
     - второе число — аргумент b
    Всегда отвечай пользователю тем, что получил из инструмента калькулятор - не считай сам
    """

    agent = create_agent(
        model=model,
        system_prompt=system_prompt,
        tools=[calculate],
    )

Во время генерации ответа, если модель руководствуясь системным промптом может решить что в этом вопросе нужен инструмент, вместо ответа пользователю, она посылает ответ с необходимыми аргументами в инструмент, от него получает ответ и интерпретирует его. Далее она может опять решать, нужен ли инструмент или можно отвечать пользователю.
> 💡 Тут необходимо помнить про бесконечные циклы, которые мы уже разбирали в уроке про агентный RAG

Далее, если мы вызовем нашего агента с вопросом:

    response = agent.invoke({"messages": [{"role": "user", "content": "посчитай сумму 2 плюс 2"}]})

То в ответ мы получим словарь в котором за ключом `messages` список сообщений,  
часть из которых — это обращение к инструментам, ответы инструментов, а последний это ответ пользователю

    HumanMessage(content='посчитай сумму 2 плюс 2', ...)
    AIMessage(..., tool_calls=[{'name': 'Calculator', 'args': {'a': '2', 'b': '2'}, 'id': '514820312', 'type': 'tool_call'}], ...),
    ToolMessage(content='5', name='Calculator', ...),
    AIMessage(content='5', ...)

И мы можем взяв последнее сообщение, получить готовый ответ:

    print(response['messages'][-1].content) # '5'

### **🔸** Формат аргументов `args_schema`

В нашем примере модель сама правильно поняла какие аргументы передать в инструмент и всё сработало. Но это простой пример, а в более сложных ситуациях всё может быть не так тривиально и поэтому агенту может понадобиться дополнительная инструкция, как пользоваться аргументами функции. Оформляются они, например при помощи **pydantic** import `BaseModel`:

    from pydantic import BaseModel, Field

    class CalcArgs(BaseModel):
        a: int = Field(description="Первое число")
        b: int = Field(description="Второе число")

    @tool("Calculator", args_schema=CalcArgs)
    def calculate(a: int, b: int) -> str:
        """Складывает два числа."""
        return str(a + b + 1)

Теперь модель получает JSON-схему:

    {
      "type": "object",
      "properties": {
        "a": {"type": "integer"},
        "b": {"type": "integer"}
      },
      "required": ["a", "b"]
    }

Модели теперь намного проще:

    "args": {"a": 2, "b": 2}

И она всегда заполнит поля правильно.

### **🔸** Метод `bind_tools`

Инструмент можно привязать к уже готовой чат-модели используя метод `.bind_tools()`

    from langchain_openai import ChatOpenAI

    model = ChatOpenAI(model_name="gpt-5", temperature=0)

    model_with_tools = model.bind_tools([calculate])

`ChatOpenAI` в LangChain — это стандартная обёртка вокруг OpenAI Chat Completions API.  
Любая такая модель **поддерживает методы**:

- `bind_tools(...)`

- `with_structured_output(...)`

- `bind(...)`

Потому что они реализованы в базовом классе `BaseChatModel` и работают поверх **function calling**, который есть у всех моделей OpenAI современного формата.

 

### **🔸 Function calling**

Современные модели (например, GPT‑5) поддерживают механизм function calling — формат, позволяющий модели возвращать структурированный вызов функции с заполненными аргументами. LangChain использует этот механизм как основу своих инструментов: через декоратор `@tool`, `args_schema`, метод `bind_tools` и агенты. Принцип одинаковый: мы описываем функцию в виде JSON-схемы, передаём её модели, и она сама выбирает, вызывать инструмент или сформировать обычный текстовый ответ.

Инструменты создаём там, где модель не может выполнить операцию напрямую:

- Калькуляторы
- Веб‑поиск
- Ретриверы
- Интерфейсы к БД
- Работа с файлами
- Внешние сервисы (заказ такси, отправка email)


Наша задача — выделить такие функции и описать их так, чтобы модель могла вызывать их через function calling.
