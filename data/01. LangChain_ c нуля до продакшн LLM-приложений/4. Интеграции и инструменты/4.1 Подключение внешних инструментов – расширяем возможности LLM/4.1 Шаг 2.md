## 🔹 Обёртки над внешними API

Сейчас мы будем учиться превращать обычные вызовы внешних сервисов в инструменты, которые LLM может использовать.

### 🔸 Что нужно сделать?

Чтобы LLM мог пользоваться внешним ресурсом, нам нужно написать функцию для конкретного REST‑API, сделать обёртку и зарегистрировать её как инструмент LangChain.
> 💡 Важно держать интерфейс простым, и в коде обрабатывать ошибки и ограничения безопасности.

### 🔸 Пример: погода

    from langchain.tools import tool
    import requests

    def geocode(city: str):
        '''Получает координаты по названию города'''
        resp = requests.get(
            "https://nominatim.openstreetmap.org/search",
            params={"q": city, "format": "json", "limit": 1},
            headers={"User-Agent": "weather-agent/1.0"}
        )
        data = resp.json()
        if not data:
            return None
        return float(data[0]["lat"]), float(data[0]["lon"])

    @tool("get_weather")
    def get_weather(city: str) -> str:
        """Возвращает текущую температуру в указанном городе."""
        coords = geocode(city)
        if not coords:
            return f"Город «{city}» не найден."
        lat, lon = coords
        resp = requests.get(
            "https://api.open-meteo.com/v1/forecast",
            params={"latitude": lat, "longitude": lon, "current_weather": True},
            timeout=5
        )
        data = resp.json()
        cw = data.get("current_weather")
        if not cw:
            return "Не удалось получить текущую погоду."
        return f"В городе {city} сейчас {cw['temperature']}°C."
> 💡 Нужно дать модели подсказку, как и когда его использовать. Например: `get_weather: предоставляет прогноз погоды в указанном городе. Ввод: название города. Вывод: информация о погоде`

Функция принимает название города и возвращает строку с погодой. Внутри мы для начала получаем координаты города обращаясь к другому API, затем делаем запрос к открытой погодной службе, указав эти координаты и указываем, что нужна погода сейчас, формируем строку ответа получив ответ от API и возвращаем модели ответ.

### 🔸 Пример: конвертация валют

Допустим, нам нужен инструмент конвертации валют: курс рубля к доллару на текущий момент. Пишем функцию `convert_usd_to_rub()` – которая стучится в API курсов, получает текущий курс и возвращает результат умножения. Регистрируем как инструмент с описанием и теперь, когда пользователь спросит: "Сколько будет 50 USD в рублях?", модель, имея этот инструмент, вероятно его вызовет:

    @tool("convert_currency")
    def convert_currency(amount: float, from_currency: str, to_currency: str) -> str:
        """
        Конвертирует сумму из from_currency в to_currency по актуальному курсу.
  
        Пример: amount=10, from_currency='USD', to_currency='RUB'
        """
        from_currency = from_currency.upper()
        to_currency = to_currency.upper()
  
        try:
            resp = requests.get("https://api.fxratesapi.com/latest", timeout=5)
            resp.raise_for_status()
            data = resp.json()
            rates = data.get("rates")
            if not rates:
                return f"Не удалось получить курсы валют: {data}"

            if from_currency not in rates:
                return f"Неизвестная валюта-источник: {from_currency}"
            if to_currency not in rates:
                return f"Неизвестная валюта-назначение: {to_currency}"

            # конвертация через базовую валюту API (USD)
            amount_in_usd = amount / rates[from_currency]  # переводим в USD
            converted_amount = round(amount_in_usd * rates[to_currency], 2)
  
            return f"{amount} {from_currency} ≈ {converted_amount} {to_currency} (курс {to_currency}: {rates[to_currency]}, курс {from_currency}: {rates[from_currency]})"
  
        except Exception as e:
            return f"Ошибка при запросе курса: {e}"

Работает со всеми валютами из списка API `data["rates"]`, конвертирует через базовую валюту (`USD`), так как API возвращает все курсы относительно USD. Сообщает актуальные курсы обеих валют.

Если API недоступен или произошли иные ошибки, функция возвращает строку с указанием ошибки, а агент может перейти к fallback‑логике. Подробнее об ошибках на следующем шаге

### 🔸 Использование

Оба инструмента теперь списком можно дать нашему агенту, прописать их функционал в системный промпт и пользоваться

    system_prompt = """
    Ты агент-помощник. У тебя есть следующие инструменты:

    get_weather: предоставляет прогноз погоды в указанном городе.
    - Ввод: название города.
    - Вывод: информация о погоде

    convert_currency: конвертирует валюты по текущему курсу
    - Ввод: значение, валюта из которой конвертируем, валюта в которую конвертируем.
    - Вывод: результат конвертации
    """

    agent = create_agent(
        model=model,
        system_prompt=system_prompt,
        tools=[get_weather, convert_currency],
    )

    response = agent.invoke({"messages": [{"role": "user", "content": "Подскажи какая сейчас погода в Лос-анджелесе и какой курс доллара к рублю"}]})
    print(response['messages'][-1].content)

 

### 🔸 Рекомендации

- Кроме REST API, обёртки могут быть и над локальными ресурсами: например, инструмент `open_file(path)` – открывает файл и возвращает содержимое, или `run_sql(query)` – выполняет SQL-запрос к БД.
- Важно ограничить список инструментов только теми, которые действительно нужны. Это повышает безопасность и снижает риск выполнения вредоносного кода.
