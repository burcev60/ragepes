## 🔹 Сохранение контекста диалога

На этом этапе мы научимся сохранять контекст, чтобы модель помимо актуального вопроса пользователя, получала в промпте так же как и предыдущие сообщения (и вопросы, и ответы) и могла отвечать более осмысленно.

### 🔸 Современный подход с create_agent

В версии 1.0 радикально изменился подход к работе с памятью:

- Память встроена в агенты через `checkpointer`
- Состояние хранится автоматически между вызовами
- Поддерживаются разные потоки разговоров через `thread_id`


**Пример:**

    import os
    from langchain.agents import create_agent
    from langgraph.checkpoint.memory import InMemorySaver

    agent = create_agent(
        model="gpt-4o-mini",
        checkpointer=InMemorySaver(),  # Сохранение в памяти
    )

    # Конфигурация с уникальным ID потока разговора
    conv_1 = {"configurable": {"thread_id": "conversation_001"}}

    question1 = "Привет! Меня зовут Алиса"
    response1 = agent.invoke(
        {"messages": [{"role": "user", "content": question1}]},
        conv_1
    )
    print("пользователь 1:", question1)
    print("Бот:", response1["messages"][-1].content)

    question2 = "Какое у меня имя?"
    response2 = agent.invoke(
        {"messages": [{"role": "user", "content": question2}]},
        conv_1
    )
    print("пользователь 1:", question2)
    print("Бот:", response2["messages"][-1].content)

    # Новый пользователь с другим thread_id
    conv_2 = {"configurable": {"thread_id": "conversation_002"}}

    question3 = "Какое у меня имя?"
    response3 = agent.invoke(
        {"messages": [{"role": "user", "content": question3}]},
        conv_2
    )
    print("пользователь 2:", question3)
    print("Бот:", response3["messages"][-1].content)

**Ожидаемый вывод:**

### Как это работает:

1. **`create_agent`** — функция для быстрого создания агентов
2. **`InMemorySaver()`** — автоматически сохраняет состояние между вызовами, инициализируется при создании агента в аргументе **`checkpointer`**
3. **`thread_id`** — уникальный идентификатор потока разговора, подаётся в словаре в настраеваемых параметрах **`"configurable"`** при вызове метода **`invoke()`**


 

### 🔸 Альтернативные варианты

Для production-приложений используйте персистентное хранилище, например **SQLite** или **PostgreSQL**:

    # SQLite (для production)
    from langgraph.checkpoint.sqlite import SqliteSaver
    checkpointer = SqliteSaver.from_conn_string("database.db")

    # PostgreSQL (для масштабирования)
    from langgraph.checkpoint.postgres import PostgresSaver
    checkpointer = PostgresSaver.from_conn_string("postgresql://...")
> 💡 Эти и другие дополнительные модули доустанавливаются отдельно `pip install langgraph-checkpoint-sqlite langgraph-checkpoint-postgres` и т.д.

## 🔹 Важные моменты работы с памятью:

**Просмотр истории:**

    # Получить состояние потока
    state = agent.get_state(config)
    print("История сообщений:")
    for msg in state.values["messages"]:
        print(f"{msg.type}: {msg.content}")

**Ограничения по контексту:**  
Если пользователь и бот обменялись десятком длинных сообщений, при каждом новом запросе вся история вставляется в промпт. Это может:

- Выйти за пределы лимита контекста модели

- Сделать ответ медленнее и дороже

**Решения:**

- Ограничить число хранимых сообщений (например, последние 10)

- Использовать суммаризацию старой истории (сворачивать в краткое резюме)

- Применить скользящее окно (только N последних реплик)

В этом курсе мы работаем с короткой историей, поэтому это не критично. Для продвинутого управления памятью есть и другие варианты:

    from langchain.agents.middleware import before_model
    from langchain.agents import AgentState

    @before_model
    def trim_messages(state: AgentState, runtime) -> dict:
        """Оставить только последние 10 сообщений"""
        messages = state["messages"]
        if len(messages) <= 10:
            return None  # Изменений нет
  
        # Сохраняем первое (системное) и последние 9
        return {
            "messages": [messages[0]] + messages[-9:]
        }

    agent = create_agent(
        model="gpt-4o-mini",
        tools=[],
        checkpointer=InMemorySaver(),
        middleware=[trim_messages],  # Добавляем middleware
    )

**Встраивание system-контекста:**  
Чтобы задать поведение бота, используйте system-сообщение:

    agent = create_agent(
        model="gpt-4o-mini",
        tools=[],
        checkpointer=InMemorySaver(),
        system_message="Ты дружелюбный помощник по математике. "
                       "Объясняй концепции просто и с примерами. "
                       "Используй эмодзи для наглядности."
    )
> ⚠️ При использовании прокси ничего менять не нужно – способ соединения не влияет на память . Она только управляет данными, которые мы отправляем. Больше данных в истории = длиннее запрос = немного дороже и медленнее, но на нескольких репликах это не критично.
