## 🔹 LCEL (LangChain Expression Language)

На прошлом шаге мы реализовывали цепочку с помощью объекта **RunnableSequence**, но Langchain в новых версиях сильно поменял свою архитектуру и теперь основной подход по построению цепочек это **LCEL**. Данный способ строит цепочки обработки данных через оператор `|` (pipe). Данные текут слева направо, как в Unix-командах.

## 🔸Базовый синтаксис

    import os
    from dotenv import load_dotenv
    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import ChatPromptTemplate

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")

    prompt = ChatPromptTemplate.from_template("Привет. Меня зовут {name}")
    llm = ChatOpenAI(model=MODEL)

    basic_chain = prompt | llm

    result = basic_chain.invoke({"name": "Вася"})
    print(result)

По сути мы тут реализуем то же самое что и с **RunnableSequence**, промпт форматируется → отправляется в LLM. Но нам не нужно делать дополнительных импортов и код становится чище. Но это конечно не все плюсы по сравнению с использованием отдельного класса.

 

### 🔸Основные компоненты (Runnables)

`Runnables` — это универсальные объекты, которые можно запускать. Они представляют собой отдельные вычислительные шаги или блоки, которые принимают входные данные и возвращают результат. По сути, это замена старой концепции цепочек **(`Chains`)** и отдельных LLM шагов, но с более модульной и гибкой архитектурой.

- `RunnablePassthrough` — передача данных без изменений  
Может показаться что он ничего не делает, но на самом деле полезный объект, дальше это будет видно на практике

    from langchain_core.runnables importRunnablePassthrough

        # Просто передаёт входные данные дальше
    chain = RunnablePassthrough() | llm
    result = chain.invoke("Привет!")  # "Привет!" → llm
    print(result)

- `RunnableLambda` — применяет функцию  
Польза этого объекта очевидна, можно написать костюмную функцию обработки или короткий скрипт с помощью `lambda` прямо в аргументе

    from langchain_core.runnablesimport RunnableLambda

        def uppercase(text):
        return text.upper()

        chain =RunnableLambda(uppercase) | llm
    chain.invoke("hello")  # "HELLO" → llm

- `StrOutputParser` — извлечь текст из ответа LLM  
Простая цепочка выводит нам объект `AIMessage` и для того чтобы нам из него получить только ответ, нам бы приходилось каждый раз доставать его через атрибут `.content`, но мы можем упростить это и сразу парсить только ответ, если остальное нам не нужно. Делается это так:

    from langchain_core.output_parsers importStrOutputParser

        chain_with_parser = prompt | llm | StrOutputParser()
    result_with_parser = chain_with_parser.invoke({"name": "Вася"})

        # С объектом из примере базового синтаксиса
    print(type(basic_chain)) # <class 'langchain_core.messages.ai.AIMessage'>
    print(basic_chain) # content='Привет, Вася! 😊 Как дела?' additional_kwargs={'refusal': None} ...

    # если парсим ответ
    print(type(result_with_parser)) # <class 'str'>
    print(result_with_parser) # Привет, Вася! 😊  Как дела?

- **Работа со словарями**  
Как мы уже убедились, часто приходится передовать в аргументах словарь с переменными, для подстановки этих переменных в шаблоны. LCEL позволяет гибко работать с этими словарями.  
Тут мы **создаём словарь** и аргументы, которые будут переданы при вызове, с помощью класса `RunnablePassthrough` передаём дальше по цепочке уже в словаре:

    # Создать словарь из входных данных
    chain = {"name": RunnablePassthrough()} | prompt | llm

        result = chain.invoke("Ваня") # → {"name": "Ваня"} → prompt → llm
    print(result)

  Тут мы уже **добавляем ключи** в словарь используя метод `.assign()`

    chain = (
        {"name": RunnablePassthrough()}
        | RunnablePassthrough.assign(second_name=lambda x: "Иванов")
    )

        result = chain.invoke("Вася")
    print(result)
    # вывод: {'name': 'Вася', 'second_name': "Иванов"}
> ⚠️ Важно чтобы значением был объект **`runnable`**, `lambda` функция подходит для этого А тут **достаём определённые ключи** из словаря методом `.pick()`

    chain = (
        {"name": RunnablePassthrough(), "age": lambda x: 25, "city": lambda x: "Москва"}
        | RunnablePassthrough().pick(["name", "city"])
    )

        result = chain.invoke("Иван")
    print(result)
    # # вывод: {'name': 'Иван', 'city': 'Москва'}

- Параллельное выполнение — `RunnableParallel`

    from langchain_core.runnables importRunnableParallel

        prompt1 = PromptTemplate.from_template("Плюсы {topic}")
    prompt2 = PromptTemplate.from_template("Минусы {topic}")

        # Выполняются ОДНОВРЕМЕННО
    parallel_chain =RunnableParallel(
        pros=prompt1 | llm | StrOutputParser(),
        cons=prompt2 | llm | StrOutputParser()
    )

        result = parallel_chain.invoke({"topic": "Python"})
    # result = {"pros": "...", "cons": "..."}

- Условная логика — `RunnableBranch`

    from langchain_core.runnables importRunnableBranch

        prompt_for_questions = ChatPromptTemplate.from_template("вопрос: {text}")
    prompt_for_statements = ChatPromptTemplate.from_template("не вопрос: {text}")

        def is_question(x):
        return "?" in x["text"]

        branch = RunnableBranch(
        (is_question, prompt_for_questions | llm),# Если вопрос
        prompt_for_statements | llm  # Иначе (default))

        chain = {"text": RunnablePassthrough()} | branch | StrOutputParser()

        result = chain.invoke({"text": "Какая сегодня погода?"})
    print(result)

### 🔸Шпаргалка по компонентам

| Компонент | Назначение |
| --- | --- |
| `|` | Соединяет компоненты в цепочку |
| `RunnablePassthrough` | Передаёт данные без изменений |
| `RunnableLambda(func)` | Применяет функцию к данным |
| `.assign(key=value)` | Добавляет ключ в словарь |
| `.pick([keys])` | Выбирает только указанные ключи |
| `RunnableParallel` | Параллельное выполнение |
| `RunnableBranch` | Условная логика (if/else) |
| `StrOutputParser()` | Извлекает текст из ответа LLM |

### 🔸Главный принцип

**Думайте о данных как о потоке воды:**

- Оператор `|` — это труба
- Каждый компонент — фильтр или трансформер
- Данные текут слева направо
- Каждый этап получает выход предыдущего


Вместо "**создай объект, вызови метод"** → **"опиши поток данных от входа до выхода"**.
