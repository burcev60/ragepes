**Шаг 3: Чекпойнты между шагами**  
**Цель шага:** Добавить в граф аналитического агента контрольные точки (чекпойнты) в ключевых местах, чтобы можно было возобновить выполнение. Рассмотреть пример использования чекпойнта при отладке или вмешательстве пользователя.

Мы уже поставили checkpoint после PlanCode (генерации кода). Это главное место: если код не работает, у нас сохранён исходный запрос и сгенерированный код:

- Разработчик может взять этот state из saver, вручную поправить `generated_code`, и выполнить `compiled_graph.invoke(state, start_at="ExecuteCode")` – попробовать свою версию.

- Либо, для debug, можно проанализировать код.

Можно ещё добавить checkpoint после ExecuteCode (например, если хотим сохранять результаты выполнения для аудита). Но критично было после PlanCode.

Также, checkpoint после PlanCode можно использовать для **human approval**:  
Вместо сразу Execute, можно:

- Остановить граф (не вызывая Execute).

- Показать код человеку (например, разработчику или продвинутому пользователю) для ревью – особенно, если данные чувствительные.

- Если человек одобрил, продолжить с сохранённого state.

Но в большинстве случаев, мы не будем каждый раз останавливать – это скорее debug-вариант.
