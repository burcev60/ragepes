**Шаг 1: Планер → выполнение шагов как узлы**  
**Цель шага:** Перепроектировать нашего агента для анализа CSV (из урока 5.2) в виде явного графа. Выделить в нём стадии (планирование, выполнение кода, пост-обработка) как отдельные узлы, соединённые последовательностью.

Ранее, CSV-агент осуществлял несколько действий за кулисами:

1. Запрос у пользователя.

2. GPT генерирует код.

3. Выполнение кода.

4. GPT формирует ответ.

Теперь опишем эти этапы как узлы LangGraph. Получится линейный граф (с возможными ответвлениями при ошибках):

- Node "PlanCode": вызывает модель для генерации кода решения.

- Node "ExecuteCode": выполняет сгенерированный код в песочнице.

- Node "DraftAnswer": вызывает модель для формулировки ответа на основе результатов выполнения.

- Node "FinishAnswer": (опционально) финализирует ответ.

И **checkpoints**:

- После "PlanCode" – мы получили код, сохраним state (чтобы можно было отладить или повторно выполнить, если что).

- После "ExecuteCode" – можно сохранить, если хотим, но не обязательно.

**Узел PlanCode:**  
Вызывает GPT-4/5, чтобы тот выдал Python-код. Используем `ChatOpenAI` с настройкой `openai_api_base="https://api.essayai.ru/v1"`. Промпт:  
*"Ты – агент-аналитик. Для запроса ниже напиши только код на Python (pandas, matplotlib) для получения ответа, без пояснений."*.

Реализация:

    from langchain.chat_models import ChatOpenAI
    from langchain.prompts import ChatPromptTemplate

    system_msg = "Ты – аналитик данных. Отвечай, генерируя только Python-код для анализа CSV (pandas, matplotlib)."
    human_template = "{query}"
    prompt = ChatPromptTemplate.from_messages([("system", system_msg), ("user", human_template)])
    llm = ChatOpenAI(model="gpt-5", temperature=0, openai_api_base="https://api.essayai.ru/v1", openai_api_key=ESSAYAI_KEY)

    def plan_code_node(state, runtime):
        query = state["user_input"]
        code = llm.predict(prompt.format(query=query))
        return {"generated_code": code}

(Здесь мы используем LangChain `ChatOpenAI` для простоты. В реальности, можно напрямую `openai.ChatCompletion.create`.)

Добавим checkpoint:

    graph.add_node("PlanCode", plan_code_node)
    saver = InMemorySaver()
    graph.add_checkpoint("PlanCode", saver)

**Узел ExecuteCode:**  
Берёт `state["generated_code"]`, валидирует и выполняет:

    def execute_code_node(state, runtime):
        code = state["generated_code"]
        ok, error = validate_code(code)
        if not ok:
            return {"error": f"Code validation failed: {error}"}
        output, files = run_code_sandbox(code)
        result = {}
        if "Ошибка" in output or "Error" in output:
            result["error"] = output.strip()
        else:
            result["exec_output"] = output.strip()
        for f in files:
            if f.endswith(".png"):
                result["image_path"] = f
        return result

Этот узел возвращает либо `error`, либо `exec_output` и, опционально, `image_path`.

**Узел DraftAnswer:**  
Формирует ответ пользователя. Если была ошибка – можно сразу сформировать из `error`. Иначе – вызвать GPT:

    def draft_answer_node(state, runtime):
        # Если была ошибка при выполнении:
        if "error" in state:
            err = state["error"]
            return {"final_answer": f"Извините, не удалось выполнить анализ данных. Детали: {err}"}
        # Иначе, соберём контекст
        exec_out = state.get("exec_output", "")
        image_note = "График прикреплен." if "image_path" in state else ""
        # Промпт для GPT на оформление ответа
        user_msg = f"Результаты анализа:\n{exec_out}\n{image_note}\nСформулируй ответ для пользователя."
        answer = llm.predict(user_msg)
        return {"final_answer": answer}

Здесь, если выполнению кода сопутствовал график, мы просим GPT упомянуть график (через `image_note`). Если была ошибка – сразу ответим извинением (без второго вызова GPT, хотя можно и через GPT – но модель не нужна, чтобы сказать извините).

**Узел FinishAnswer:**  
Можно не делать отдельный, DraftAnswer уже формирует final_answer. Но если хотим, можно оставить DraftAnswer как черновик, а FinishAnswer – например, добавить какой-то шаблон. Но особой надобности нет, поэтому DraftAnswer сразу записывает `final_answer`.

Теперь строим граф:

    graph = StateGraph(state_schema=DataAgentState)
    graph.add_node("PlanCode", plan_code_node)
    graph.add_node("ExecuteCode", execute_code_node)
    graph.add_node("DraftAnswer", draft_answer_node)
    graph.add_edge("PlanCode", "ExecuteCode")
    graph.add_edge("ExecuteCode", "DraftAnswer")
    graph.set_entry_point("PlanCode")
    graph.set_finish_point("DraftAnswer")
    graph.add_checkpoint("PlanCode", InMemorySaver())

**Обработка ошибок и ветвлений:**  
Обратите внимание, мы не сделали явного условного перехода на случай ошибки, мы обработали ошибку внутри DraftAnswer. То есть, даже если state содержит `error`, DraftAnswer выполнится и вернёт final_answer-извинение.

Альтернативно, могли:

     

    graph.add_conditional_edges("ExecuteCode", {"True": "DraftAnswer"}, condition_key="error")

Но тогда, если `error=False`, тоже надо идти к DraftAnswer. То есть, проще всегда идти к DraftAnswer, а внутри него решить.

**Retry**:  
Если в ExecuteCode возникла ошибка (например, `SyntaxError`), можно попытаться исправить код. Это можно оформить так:

- Добавить узел "FixCode" между ExecuteCode и DraftAnswer:

  - condition: если `error` – идти в FixCode, а потом снова ExecuteCode.

  - Limit attempts to 1-2.

Но мы опустим, т.к. это усложнит граф. Возможно, в prod можно добавить.
