**Шаг 4: Артефакт – аналитический граф-агент**  
**Цель шага:** Свести реализованный граф DataAgent воедино, протестировать его на примерах и убедиться, что он даёт тот же функционал, что и прежний CSV-агент, но с возможностью отслеживания и перезапуска.

Мы получили **DataAgentGraph**, который делает то же, что наш старый csv_agent, но более структурированно:

- Node PlanCode – GPT пишет код.

- Node ExecuteCode – выполнение.

- Node DraftAnswer – GPT пишет ответ.  
(+ Checkpoint, guardrails и т.д.)

Протестируем:

- Запрос: "Посчитай максимальное значение в столбце Sales."

  - PlanCode: GPT выдаёт что-то как `df['Sales'].max()`.

  - ExecuteCode: выполнит, вернёт например `5000`.

  - DraftAnswer: модель скажет "Максимальное значение продаж = 5000."

  - **Ответ пользователю**: "Максимальные продажи составили 5000."

- Запрос: "Построй график тренда продаж по месяцам."

  - PlanCode: GPT код с groupby по month + plot.

  - ExecuteCode: output = (печать средних/сумм?), files = ["output.png"].

  - DraftAnswer: "График продаж по месяцам приложен ниже. Видно, что ...".

  - Пользователь получает текст + график.

- Запрос: "Удалите файл config.cfg". (Проверка безопасности)

  - PlanCode: GPT вероятно `import os; os.remove('config.cfg')`.

  - ExecuteCode: validation fails (os.remove flagged), error.

  - DraftAnswer: "Извините, не удалось выполнить анализ данных. Детали: Code validation failed: Запрещённый вызов: import os".

  - Пользователю можно вывести просто извинение без деталей, чтобы не раскрывать политику.

Видим, функциональность сохранилась. Разница:

- Можно заглянуть внутрь: `compiled_data_graph.get_state_history()` для запроса, и увидеть:

  1. После PlanCode: state содержит user_input и generated_code (можно просмотреть код).

  2. После ExecuteCode: добавляется либо exec_output, либо error.

  3. После DraftAnswer: final_answer.

- Можем даже логировать токены: ChatOpenAI может возвращать usage, мы можем capture и записать, например, `state["plan_tokens"] = usage["prompt_tokens"]+usage["completion_tokens"]`. Но опустим.

Теперь интегрируем DataAgentGraph в ассистента:  
В DataHandlerNode (в маршрутизаторе) вместо вызова csv_agent, можно вызвать подграф:

    def data_handler_node(state, runtime):
        query = state["user_input"]
        out_state = compiled_data_graph.invoke({"user_input": query})
        answer = out_state["final_answer"]
        image_path = out_state.get("image_path")
        result = {"final_answer": answer}
        if image_path:
            result["image_path"] = image_path
        return result

Таким образом, основной граф маршрутизатор не знает деталей, он просто делегирует подграфу. Получается модульность: мы могли бы и RagChain, WebChain тоже как подграфы оформить.

Итак, **Analytical Agent Graph** готов и работает. Его преимущество – прозрачность: если он часто ошибается, мы увидим где – на этапе планирования (плохой код) или исполнения (ошибки).
