**Шаг 1: Вынос Router в узел LangGraph**  
**Цель шага:** Преобразовать логику маршрутизации запросов (из модулей 4–5) в узел графа. Это означает: вместо внешнего if/elif – внутри графа будет узел, определяющий маршрут, и далее граф разветвляется по этому решению.

Ранее наш маршрутизатор (`QueryRouter`) работал, например, как метод, возвращающий строку "RAG"/"Web"/"Data". Теперь мы интегрируем его в граф. Сделаем узел **RouterNode**. Он принимает `state["user_input"]` и на выход выдаёт `state["route"]`.

Реализуем RouterNode двумя способами:

- Через правила (как пример в уроке 6.1: поиск ключевых слов).

- Через модель (GPT), которой даём описание категорий. GPT-4/5 хорошо классифицирует, но это дополнительный API-вызов (дороже). У нас был ранее промпт-маршрутизатор. Для ясности сейчас используем правила, чтобы не отвлекаться на ещё один вызов модели.

Простейшая реализация:

    def router_node(state, runtime):
        query = state["user_input"].lower()
        if any(word in query for word in ["данные", "график", "csv", "таблиц", "файл"]):
            return {"route": "Data"}
        elif any(word in query for word in ["когда", "сколько", "кто", "http", "www", "интернет", "найти"]):
            return {"route": "Web"}
        else:
            return {"route": "RAG"}

Здесь мы на уровне эвристики определяем: если вопрос явно про данные/файлы – Data; если содержит признаки общих вопросов – Web; иначе – RAG. Это не идеально, но как пример.

Добавляем узел:

    graph = StateGraph(state_schema=SupportState)
    graph.add_node("Router", router_node)
    graph.set_entry_point("Router")

Далее добавим ветви.
