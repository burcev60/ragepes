**Шаг 2: Ветви RAG/Web/Track**  
**Цель шага:** Создать в графе три ветви (подграфы) для обработки разных типов запросов – внутренний (RAG), внешний (Web) и аналитический (Data). Соединить их с узлом Router условными рёбрами.

После RouterNode, используем `add_conditional_edges`:

    graph.add_conditional_edges("Router", {
        "RAG": "RagHandler",
        "Web": "WebHandler",
        "Data": "DataHandler"
    }, condition_key="route")

Теперь определим узлы RagHandler, WebHandler, DataHandler. Их задача – сформировать финальный ответ, записав его в `state["final_answer"]`.

**RagHandlerNode:**  
Это фактически вызов RetrievalQA chain. Можно использовать существующую функцию:

    def rag_handler_node(state, runtime):
        query = state["user_input"]
        answer = rag_chain.run(query)  # допустим, rag_chain настроен заранее
        return {"final_answer": answer}

(Можно добавить, например, ссылки на источник в ответ, как в модуле 4 делали.)

**WebHandlerNode:**  
Аналогично:

    def web_handler_node(state, runtime):
        query = state["user_input"]
        answer = web_search_chain.run(query)  # предположим, имеется chain или tool
        return {"final_answer": answer}

(Web chain может внутри сделать поиск и оформить ответ с цитатами.)

**DataHandlerNode:**  
Теперь, самый сложный – интеграция CSV-агента. Мы уже сделали DataAgent, можно его вызвать:

    def data_handler_node(state, runtime):
        query = state["user_input"]
        result = csv_agent.process_query(query)  # возвращает текст ответа, а также может график
        answer_text = result["answer"]
        image_path = result.get("image_path")
        # Сохраним в state
        new_state = {"final_answer": answer_text}
        if image_path:
            new_state["image_path"] = image_path
        return new_state

Допустим, `csv_agent.process_query` реализует весь цикл с GPT и возвращает словарь с ответом и, возможно, именем файла картинки.

Добавляем узлы:

    graph.add_node("RagHandler", rag_handler_node)
    graph.add_node("WebHandler", web_handler_node)
    graph.add_node("DataHandler", data_handler_node)

Теперь, назначим точки завершения. У нас три ветки, каждая даёт final_answer. Можно объявить все три узла конечными:

    graph.set_finish_point("RagHandler")
    graph.set_finish_point("WebHandler")
    graph.set_finish_point("DataHandler")

LangGraph допускает несколько finish-поинтов: граф завершается, когда достигнут любой из них (в зависимости от ветки).

Альтернатива – добавить общий узел "Finish", но для этого надо соединять все ветки в него. Если сделать:

    graph.add_edge("RagHandler", "Finish")
    graph.add_edge("WebHandler", "Finish")
    graph.add_edge("DataHandler", "Finish")
    graph.set_finish_point("Finish")

То нужно, чтобы только одна ветка доходила. Так и будет, т.к. условные рёбра не позволяют выполнить другие ветки. Но тогда на Finish узле можно, например, просто передать ответ дальше (или ничего не делать, он просто как конец).

Возможно, проще оставить каждый ветвевой узел финишем, чтобы не добавлять лишний.
