**Шаг 4: Артефакт – минимальный граф-пайплайн**  
**Цель шага:** Создать простой пример графа с использованием LangGraph – своего рода минимальный конвейер, который продемонстрирует все основные элементы: state, node, edge, checkpoint, event log. Убедиться, что он выполняется как ожидается.

Для освоения принципов сделаем крошечный граф: агент, который получает число и выводит факториал этого числа, разбивая задачу на два шага с checkpoint.

Граф "FactorialAgent":

- Node "ParseInput": читает `user_input` (строка), преобразует в число n, сохраняет `state["n"]`.

- Node "Checkpoint1": (фактически, просто отметим checkpoint после ParseInput).

- Node "ComputeFact": вычисляет факториал `state["n"]`, сохраняет `state["result"]`.

- Node "Finish": формирует ответ `state["final_answer"] = f"{n}! = {result}"`.

Узлы:

        try:
            n = int(state["user_input"])
        except:
            return {"error": "Введите целое число."}
        return {"n": n}

Сборка графа:

    from langgraph.graph import StateGraph
    from langgraph.checkpoint import InMemorySaver

    graph = StateGraph(state_schema=dict)  # Для простоты, используем словарь как schema
    graph.add_node("ParseInput", parse_input_node)
    graph.add_node("ComputeFact", compute_fact_node)
    graph.add_node("Finish", finish_node)
    graph.add_edge("ParseInput", "ComputeFact")
    graph.add_edge("ComputeFact", "Finish")
    graph.set_entry_point("ParseInput")
    graph.set_finish_point("Finish")
    # Добавим checkpoint после ParseInput:
    saver = InMemorySaver()
    graph.add_checkpoint("ParseInput", saver)

    compiled = graph.compile()
    out_state = compiled.invoke({"user_input": "5"})
    print(out_state["final_answer"])  # Ожидается: "Факториал числа 5 равен 120."

Тестируем:

- Для ввода "5" получим вывод "Факториал числа 5 равен 120.".

- Для ввода "abc" (не число) `state["error"]` заполняется, ComputeFact всё равно запустится (т.к. мы не сделали условие), но может в compute_fact_node попытка `state["n"]` вызовет ошибку KeyError. Чтобы этого избежать, можно добавить условное ветвление: после ParseInput, если есть error, сразу на Finish:

    graph.add_conditional_edges("ParseInput", {True: "Finish", False: "ComputeFact"}, condition_key="error")

Но тогда `error` надо сохранить как bool (например, `state["error"] = "..."` и `state["error_flag"] = True`). Опустим, предположим, user вводит корректное число.

**Просмотр логов:** Используем историю состояний:

    history = compiled.get_state_history()
    for i, st in enumerate(history):
        print(f"Step {i}: {st}")

Выведет:

    Step 1: {'user_input': '5', 'n': 5, 'result': 120}

Видно, как state накапливает данные.

**Откат и повтор:** Например, хотим попробовать изменить n и пересчитать без полного запуска:  
Мы можем взять сохранённый state из saver после ParseInput:

    saved_state = saver.load()  # гипотетический метод получить сохранённый state
    saved_state["n"] = 6
    new_state = compiled.invoke(saved_state, start_at="ComputeFact")
    print(new_state["final_answer"])  # Получим факториал 6.

Таким образом, без переразбора ввода мы изменили число и продолжили вычисление. Конечно, здесь это искусственный пример, но принцип применим к большим агентам.

Этот минимальный пайплайн показывает принципы LangGraph: раздельные узлы, состояние, переходы, checkpoint, лог выполнения. Теперь мы готовы перенести эти идеи на нашего ассистента.

Перед продолжением убедимся, что понимаем:

- **State** – разделяемое состояние (данные) между узлами.

- **Node** – функция, изменяющая состояние (выполняющая действие).

- **Edge** – переход, может быть условным (ветвление) или безусловным (последовательность).

- **Checkpoint** – сохранение состояния (для пауз и восстановления).

- **Event log** – запись выполнения узлов.

Вооружившись этими понятиями, мы готовы реализовать графы для конкретных задач нашего ассистента.
