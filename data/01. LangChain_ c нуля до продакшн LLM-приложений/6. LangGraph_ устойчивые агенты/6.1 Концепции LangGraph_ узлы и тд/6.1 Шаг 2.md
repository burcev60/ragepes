**Шаг 2: Узлы, ветвления, условия**  
**Цель шага:** Разобраться, как определяются **узлы (nodes)** в графе, как они соединяются рёбрами (**edges**), в том числе условными, образуя ветвления. Научиться описывать логику if/else и последовательностей внутри графа.

В LangGraph узел – это элементарная операция. Это может быть:

- Вызов LLM (например, генерация ответа GPT).

- Вызов функции или инструмента (например, выполнить код, сделать поиск).

- Логический узел, который ничего не вызывает, а на основе состояния решает, куда идти дальше (ветвление).

- Узел-пустышка (NOP) – иногда нужен для синхронизац.

Чтобы построить граф, мы:

1. **Добавляем узлы** (даем им уникальные имена).

2. **Соединяем узлы рёбрами** – указываем, из какого узла в какой ведёт переход.

3. Обозначаем **стартовый узел** (entry point) и **финишный** (finish point).

В простейшем графе цепочка: A -> B -> C (последовательно). Здесь A после завершения переходит к B, затем к C. Мы укажем:

    graph.add_edge("A", "B")
    graph.add_edge("B", "C")
    graph.set_entry_point("A")
    graph.set_finish_point("C")

LangGraph также имеет удобный метод `add_sequence("A", "B", "C")` для таких цепочек.

**Ветвления и условия:** Иногда нужно разветвить логику. Например, после узла Router, если `route == "Web"`, идти в узел WebHandler, если `route == "RAG"` – в RagHandler, и т.д. В LangGraph это делается условными рёбрами:

    graph.add_conditional_edges("RouterNode", {
        "RAG": "RagBranchNode",
        "Web": "WebBranchNode",
        "Data": "DataBranchNode"
    }, condition_key="route")

Здесь мы говорим: взять значение `state["route"]` после выполнения RouterNode, и в зависимости от него выбрать ветку. Ключи словаря – возможные значения `route`, а значения словаря – имена узлов, куда перейти. В этом примере, если `state["route"] == "RAG"`, исполнение перейдёт к узлу RagBranchNode.

Что если значение не совпало ни с одним ключом? Можно указать default: например, `graph.add_conditional_edges("RouterNode", {...}, default:contentReference[oaicite:23]{index=23}, condition_key="route")` – тогда если `route` имеет неожиданное значение, пойдём в DefaultNode (который может вернуть ответ типа "не знаю"). Если default не указан, граф завершится без ответа.

Другой вид ветвления – **параллельное**. Это не условие, а просто одновременный запуск нескольких узлов из одного. Например, хотим одновременно запустить поиск в базе и в веб. Мы можем нарисовать два ребра от узла Router: одно на RagSearch, другое на WebSearch. По умолчанию граф выполнит их последовательно. Но Langchain поддерживает асинхронный запуск: если определить узлы как асинхронные (например, `async def node_func()`), то с помощью `await compiled_graph.astream(state)` они могут работать параллельно. В уроке 6.4 мы рассмотрим, как настроить параллелизм.

**Пример графа с условиями:** Возьмём наш маршрутизатор:

- Node "Router": на выход пишет `state["route"]`.

- Node "RagBranch": внутри вызывает RAG chain, пишет `final_answer`.

- Node "WebBranch": вызывает веб-поиск, пишет `final_answer`.

- Node "DataBranch": вызывает CSV-агента, пишет `final_answer`.

- Потом объединяем ветви. Можно сделать узел "Finish" – конечная точка.

Схема: Router -> (условно) RagBranch/WebBranch/DataBranch -> Finish. В LangGraph:

     

    graph.add_conditional_edges("Router", {"RAG": "RagBranch", "Web": "WebBranch", "Data": "DataBranch"}, condition_key="route")
    graph.add_edge("RagBranch", "Finish")
    graph.add_edge("WebBranch", "Finish")
    graph.add_edge("DataBranch", "Finish")
    graph.set_entry_point("Router")
    graph.set_finish_point("Finish")

Теперь, во время выполнения:

- RouterNode установит route.

- Только соответствующая ветвь выполнится (другие узлы просто будут пропущены).

- В конце все сходятся в Finish (который можно сделать пустым узлом, или он может, например, просто присутствовать для общей точки завершения).

**Определение узлов:** Узел можно описать через Python-функцию, которая принимает (state, runtime) и возвращает dict (частичный state). Например:

    def router_node(state, runtime):
        user_input = state["user_input"]
        # Простое правило:
        if any(word in user_input.lower() for word in ["данн", "график", "csv", "таблиц"]):
            return {"route": "Data"}
        elif ...:  # другие правила
            ...
        else:
            return {"route": "RAG"}

Добавляем в граф:

     

`graph.add_node("Router", router_node) `

Аналогично для RagBranch, WebBranch, DataBranch – реализуем соответствующие вызовы и добавляем как узлы.

LangGraph также предоставляет готовые узлы для типичных действий. Например, `ToolNode` – узел-обёртка вокруг инструментов LangChai. Также, вероятно, есть интеграция с LangChain LLMChain.

Но ключевое: структура ветвлений явно прописана, вместо того чтобы писать `if/elif` в коде, что делает логику прозрачной.
