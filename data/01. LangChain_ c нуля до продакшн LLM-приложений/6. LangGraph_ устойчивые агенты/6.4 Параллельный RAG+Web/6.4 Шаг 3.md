**Шаг 3: Политика отказов/таймаутов ветвей**  
**Цель шага:** Обозначить, как обрабатывать ситуацию, если одна из параллельных ветвей не отвечает или слишком долго выполняется. Задать таймаут для каждой ветви и решить, что делать, если одна вернула пустой результат.

При параллельном поиске:

- Мы должны установить таймауты для внешнего поиска, чтобы не держать ответ слишком долго. Например, ждать максимум 3 сек.

- В LangChain Tools можно настроить таймаут или использовать asyncio.wait_for.

В псевдокоде WebSearch:

    try:
        results = await web_tool.search(query, timeout=3)
    except TimeoutError:
        results = []
    return {"web_snippets": results}

В RagSearch:  
Внутренняя БД, обычно быстро, но тоже можно ограничить (если векторный поиск, там миллисекунды).

Если одна ветвь не вернулась (timeout), `state` просто не получит её данных (или получит пустой список). Merge-узел должен это учесть:  
Если `internal` пусто, `external` не пусто – ничего, комбинируем что есть.  
Если оба пусты – можно сразу вернуть `final_answer = "Извините, ничего не найдено."`.

Может сделать:

    if not combined:
        return {"final_answer": "Извините, мне не удалось найти информацию по вашему запросу."}
    else:
        return {"combined_context": "\n".join(combined)}

А финальный ответ пусть строится из combined_context.
