**Шаг 2: Слияние результатов, дедуп/реранк**  
**Цель шага:** После получения ответов или контента от обеих ветвей, объединить их: убрать дублирующуюся информацию и отсортировать/ранжировать по важности. Затем подготовить единый контекст для финального ответа.

Когда параллельные ветви завершены, у нас в state, например:

- `state["rag_docs"]` – список топ-документов из базы.

- `state["web_snippets"]` – найденные факты из веб.

Теперь Node "Merge":

    def merge_node(state, runtime):
        internal = state.get("rag_docs", [])
        external = state.get("web_snippets", [])
        # Уберём дубли (например, если оба нашли одно и то же):
        combined = []
        seen = set()
        for doc in internal:
            text = doc['text']
            if text not in seen:
                combined.append(text); seen.add(text)
        for snip in external:
            text = snip['text']
            if text not in seen:
                combined.append(text); seen.add(text)
        # Ограничим размер, если слишком много:
        combined = combined[:5]  # например, не более 5 фрагментов
        # Сохраним для ответа:
        return {"combined_context": "\n".join(combined)}

Здесь мы собираем все найденные тексты, удаляем повторяющиеся (очень простым способом – по точному совпадению; можно улучшить, например, сравнить по ключевым словам). Также ограничиваем, чтобы не перегрузить модель на ответе.

Мы можем также **ранжировать (rerank)**: скажем, сортировать combined по релевантности. Если RagDocs обычно очень релевантны (векторный поиск), а web_snippets могут быть шумнее, можно ставить rag_docs первыми. В коде мы так и делаем – проходим сначала internal, потом external.

Для более продвинутого реранка можно использовать cross-encoder модель, которая по запросу и фрагменту даёт оценку релевантности, но оставим.
