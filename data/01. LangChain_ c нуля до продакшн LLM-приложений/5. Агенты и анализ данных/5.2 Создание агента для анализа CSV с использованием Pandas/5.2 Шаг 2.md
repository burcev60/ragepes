**Шаг 2: Генерация кода и исполнение в песочнице**  
**Цель шага:** Реализовать цикл “модель → код → выполнение → результат”. Обучить модель генерировать корректный код на Python для анализа данных и обрабатывать результат выполнения.

Этот шаг – сердце агента-аналитика. По сути, мы программируем поведение: когда приходит запрос на анализ данных, модель должна выдать не прямой ответ, а код для получения ответа. Наша система это распознает, исполняет, и затем либо сама формирует ответ, либо просит модель его сформировать на основе полученных данных.

Два основных подхода интеграции:

- **Одношаговый (в стиле Code Interpreter):** Модель генерирует сразу и код, и финальный ответ, опираясь на то, что код выполнится. Например, ответ модели может содержать: сначала блок кода, затем объяснение результатов. Наш backend при обнаружении кода, выполнит его, подставит результаты обратно. В ChatGPT Code Interpreter, к примеру, модель может выдавать что-то вроде: *«Вот что я получил:* [код] *… Выполнив, получаем:* [вывод] *… значит, ответ: …»* – и интерфейс ChatGPT делает эти шаги автоматически. Однако реализовать такое требует интерактивного вывода.

- **Двухшаговый (план и выполнение отдельно):** Сначала модель *только код* (или план), затем после выполнения кода – ещё один запрос модели с просьбой оформить ответ, используя результаты. Мы выберем этот путь, так как он понятнее поэтапно. То есть:

  1. **Запрос 1 (анализ)**: “Напиши код для решения задачи”. Модель -> код.

  2. Мы выполняем код, получаем, скажем, текст результата или файл графика.

  3. **Запрос 2 (ответ)**: “Вот результаты выполнения: ... Сформулируй ответ пользователю.” Модель -> финальный ответ.

Во втором подходе можно не бояться, что модель попытается **сама** вставить результат – мы контролируем, что она видит и делает.

Настроим промпт для генерации кода. Например, пользователь спрашивает: *«Построй график продаж по месяцам и укажи средние продажи.»* Мы формируем для модели такой prompt (в контексте, где она уже знает о наличии инструмента Python и названии файла):

**System:** Вы загружены как аналитический агент. У тебя есть доступ к Python (библиотеки: pandas, matplotlib). Данные находятся в файле `sales.csv`. Отвечай, генерируя **только код** на Python для анализа данных и получения ответа. Не пиши пояснений.  
**User:** Построй график продаж по месяцам и укажи средние продажи.

С такой инструкцией GPT-4 или 5 должна вернуть чисто код, например:

    import pandas as pd
    import matplotlib.pyplot as plt

    # Читаем данные
    df = pd.read_csv("sales.csv")
    # Предположим, в данных есть колонка "month" и "sales"
    monthly = df.groupby("month")["sales"].mean()

    # Строим график
    monthly.plot(kind="bar")
    plt.title("Средние продажи по месяцам")
    plt.ylabel("Продажи")
    plt.savefig("output.png")
    print("Средние продажи по месяцам:")
    print(monthly.to_string())

Модель может написать и по-другому, но ключевое: **код входит в тройных кавычках как код-блок** (если мы используем Markdown-стиль), или просто текстом. Мы должны вычленить этот код. Обычно, анализируя ответ, можно искать markdown-делимитры `python ... `. Если их нет, а текст выглядит как код, всё равно трактуем как код.

Теперь **исполнение**. Код надо выполнить в песочнице (о песочнице подробнее в уроке 5.3, но в целом: ограничить возможности). Допустим, мы реализовали функцию `run_code_sandbox(code: str) -> (output: str, files: list)` – она запускает код в отдельном процессе/контейнере и возвращает печать в консоль (`print()` выводы) и список созданных файлов (чтобы получить, например, `output.png`).

В нашем случае, выполнив код, мы ожидаем:

- В `output` строках будет что-то вроде:

    Средние продажи по месяцам:
    month
    1    1234
    2    1100
    ... (и т.д.)

   

- В `files` – будет файл `"output.png"` – сохранённый график.

Если код завершился с ошибкой, мы должны эту ошибку тоже обработать (например, передать модели, что был `Error: ...` – чтобы она поняла и попыталась исправить, либо выдать сообщение об ошибке пользователю). Но предположим, всё прошло гладко.

Далее, **получение ответа**. Теперь у модели есть цифры и сохранённый график. Нам нужно, чтобы она сформулировала человеческий ответ. Формируем второй запрос:

**System:** Ты получил результаты выполнения своего кода. Построй ответ для пользователя, используя эти результаты. Если есть картинка, упомяни, что график построен и приложен.  
**User:** *(здесь вместо пользователя мы подставляем как бы сообщение с результатами)*: Результаты анализа: Средние продажи по месяцам: (тут таблица или краткие данные из `monthly`), график сохранён как файл `output.png`.

Модель (GPT) получает эти данные и возвращает примерно: *«Средние продажи по месяцам показаны на диаграмме. Как видно, максимум в Декабре (1500 единиц), минимум в Феврале (900 единиц). График продаж по месяцам прилагается ниже.»*.

Мы отдаем пользователю текст и сам файл `output.png` (например, если это чат-интерфейс, то изображение отправим). Пользователь видит готовый ответ с графиком.

Заметим, этот подход – **практически реализация Code Interpreter**: модель пишет код, мы выполняем, модель интерпретирует результат. Разница лишь в том, что у нас разбито на два запроса, а в OpenAI Advanced Data Analysis это более динамично (там модель сама решает, когда выполнить код, а когда комментировать). Но принцип тот же: *«LLM + Python = мощный инструмент анализа»*. Как отмечают в обзорах, Code Interpreter (сейчас известный как Advanced Data Analysis) значительно расширяет возможности GPT-4, позволяя работать с файлами, данными, выполнять вычисления. Мы делаем подобное своими руками, контролируя процесс.
