**Шаг 1: Интерфейс к данным (безопасные операции)**  
**Цель шага:** Научиться давать LLM доступ к табличным данным (например, CSV-файлам) и при этом ограничить набор допустимых действий. Спроектировать интерфейс (API) для чтения и анализа данных, безопасный для использования моделью.

Представим, что у нашего ассистента есть некоторая структурированная информация – например, экспорт продаж или заказов в формате CSV. Пользователь может задать вопрос: *«Каков средний объём продаж в этом CSV?»* или *«Построй график продаж по месяцам на основе данных из файла»*. LLM по умолчанию не умеет выполнять вычисления или читать файлы, но мы можем научить его использовать инструменты – в данном случае, Python с библиотекой Pandas для анализа данных.

**Интерфейс к данным** – это контролируемый слой, через который модель получает доступ к файлу. Самый прямолинейный способ: передать содержимое CSV в контекст модели. Но это ограничено объёмом (файл может быть большой) и небезопасно (приватные данные окажутся у модели). Поэтому более правильный путь – **позволить модели выполнять код на Python для чтения файла и вычислений**. По сути, мы делаем мини-«кодовый интерпретатор» как в ChatGPT. Модель пишет код – мы его исполняем и возвращаем результат.

Но давать модели полный произвольный Python нельзя – она может по ошибке (или вследствие injection-атаки) сделать что-то опасное. Нужно ограничить операции. Для этого определим политики и **белый список** разрешённых действий:

- Разрешаем: импорт конкретных библиотек, необходимых для задачи (например, `pandas`, `matplotlib` для графиков, возможно `numpy`).

- Запрещаем: любые операции с сетью (`requests` и др.), доступ к системе (`os`, `subprocess`), запись файлов (кроме, может быть, временного сохранения графика), выполнение небезопасных функций (`eval`, `exec` внутри кода).

- Ограничиваем объём данных: например, если CSV огромный, имеет смысл предупредить, что обрабатывать надо агрегировано (но это больше логический уровень; на кодовом уровне можно ограничить, сколько строк читать).

- Ограничиваем время выполнения: код не должен работать бесконечно (введём таймаут на выполнение, допустим 5-10 секунд, иначе прерываем – об этом подробнее в Шаге 3 урока 5.3).

Итак, модель будет взаимодействовать с данными через написание кода. Мы должны спроектировать, как она узнает про данные. Есть варианты:

1. **Встроить данные в промпт.** Если CSV небольшой, можно превратить его в текст (например, первые N строк) и дать модели. Но для больших данных это нереально – контекст переполнится. Лучше дать модели название файла или схему данных.

2. **Документировать интерфейс.** Например, заранее сказать: *«У тебя есть инструмент `Python` с библиотеками pandas и matplotlib. Файл `sales.csv` доступен. Чтобы анализировать данные, пиши код. Не выходи за рамки этих библиотек.»* Так модель будет знать, что можно сделать.

3. **Предоставить функции.** Альтернатива – реализовать *OpenAI function* типа `load_data(file)` и `plot_graph(data)` и т.д. Модель бы вызывала их, а код выполнялся внутри нас. Но для обучения мы пойдём по пути генерации Python-кода, чтобы явно видеть процесс.

Таким образом, интерфейс будет таким: **LLM пишет код на Python, используя pandas для анализа CSV.** Мы этот код перехватываем, проверяем на соответствие политике (белому списку), и если всё ок – запускаем в изолированной среде. Результат (вывод или ошибки) возвращаем модели.
