## «Агент-аналитик: CSV-отчёты и графики для e-commerce»

**Бизнес-цель:** научить бота поддержки Shoply отвечать на аналитические запросы «на лету»: считать метрики продаж по CSV и строить графики (тренды, сезонность, топ-товары), возвращая **и числа, и изображения**. Агент должен **сам планировать шаги** (парсить вопрос → выбрать инструменты → выполнить код → собрать вывод), работать безопасно и объяснять ход решения.

## Что сделать (за 1 спринт)

1. **Многошаговый агент** (LangChain/аналог) с инструментами:

  - **CSV-анализатор**: чтение/агрегации в pandas.

  - **Построение графиков**: сохранение `.png` в `reports/plots/`.

  - (опц.) **Описательная статистика**: корреляции, сезонность (по неделям/месяцам).

2. **Безопасная песочница**: белый список библиотек/функций, лимиты CPU/времени, запрет файловых/сетевых операций, кроме чтения предоставленных `data/*.csv` и сохранения в `reports/`.

3. **Структурированный ответ**:

    {
      "answer": "<краткое резюме в стиле бренда>",
      "plan": ["шаг 1 ...", "шаг 2 ..."],
      "metrics": {"kpi": значения},       # машиночитаемые числа
      "artifacts": ["reports/plots/....png"],
      "warnings": ["если были ограничения/допущения"]
    }

   

4. **CLI-чат**: единый вход, сохраняет историю и логи инструментов.

5. **Автооценка**: скрипт, который гоняет 12 запросов, сверяет числа и наличие графиков, считает метрики качества.

## Данные

1. **Основной датасет** `data/orders.csv` (минимум 10k строк). Обязательные колонки:

  - `order_id` (str), `date` (YYYY-MM-DD), `sku` (str), `category` (str),  
`qty` (int), `price` (float), `revenue` (float = qty*price с учётом скидок),  
`city` (str), `region` (str), `channel` (one of: web, app, retail),  
`is_returned` (0/1), `payment_method` (card, sbp, gift).

2. **Генератор данных** `src/gen_orders.py`: детерминированный (фиксация seed), описать логику в README.

3. (опц.) `data/returns.csv` для раздельного учёта возвратов — если используете, опишите формат.

## Ограничения и требования

### Агент и инструменты

- Планы и действия должны быть **прозрачными** (логируйте последовательность шагов).

- Агент обязан валидировать входные вопросы: если просят несуществующую колонку — вежливо сообщить и предложить доступные поля.

- **Безопасность**:

  - Таймаут выполнения кода/шага: ≤ 5 сек.

  - Память на шаг: ≤ 512 МБ (опишите, как ограничиваете).

  - Запрещены: `open()` вне `data/` и `reports/`, сеть, `os.system`, `subprocess`, чтение `.env`.

- **Формат графиков**: PNG 1280×720, читаемые подписи осей, название графика, авто-сохранение в `reports/plots/`.

### Интерфейсы (контракты проверки)

- **CLI**: `python app_agent.py` — обычный диалог. Команда `/debug on|off` включает печать плана и используемых инструментов.

- **Функция**: `run_agent(question) -> dict` возвращает структуру, как в разделе «Структурированный ответ».

- **Конфиги**:

  - `tools.yaml` — белый список функций/методов pandas и правил построения графиков.

  - `policy.md` — кратко о безопасной песочнице и лимитах.

### Производительность

- Средняя латентность ответа для аналитических запросов ≤ 4 сек (на вашей машине).

- Кэшируйте повторные чтения CSV (по пути и checksum).

## Набор обязательных запросов (для автооценки)

Сформируйте файл `data/eval_prompts.jsonl` с **12** запросами. Обязательно включите следующие **минимум 8** (оставшиеся 4 — свои, с метками для проверки):

1. «ТОП-10 SKU по выручке за последний квартал. Построй столбчатую диаграмму.» → ожидается график `top_sku_qX.png`, таблица топ-10.

2. «Выручка по месяцам за последний год. Линия. Покажи также сезонность по неделям.» → `rev_by_month.png`, `rev_by_week.png`.

3. «Доля возвратов (share) по категориям. Круговая или столбцы.» → `returns_share.png`.

4. «Сравни выручку web vs app vs retail по кварталам. График с группировкой.» → `channel_quarters.png`.

5. «ТОП-5 городов по выручке и их сезонность по месяцам.» → `top_cities.png`, `top_cities_seasonality.png`.

6. «Средний чек по каналам и категориям (pivot).» → артефакт: CSV/HTML `avg_check_pivot.csv|html`.

7. «Пиковые дни заказов (top-7).» → `peak_days.png`.

8. **Негативный кейс:** «Покажи распределение по колонке `customer_age`» (её нет). → корректный отказ + список доступных колонок.
> Для **числовых** кейсов добавьте в `eval_prompts.jsonl` поле `expected` с формулой/правилом сверки (например, сумма по фильтрам) или эталонными числами, полученными вашим генератором.

## Автооценка (обязательная)

Создайте `src/agent_eval.py`. Выход — `reports/agent_eval.json`:

    {
      "calc_accuracy": 0..100,          # доля корректных числовых ответов (±2% толеранс по суммам, ±1 день по датам)
      "chart_completeness": 0..100,     # доля обязательных графиков, которые реально созданы
      "robustness": 0..100,             # доля запросов без исключений (вкл. негативный кейс)
      "safety_score": 0..100,           # штрафы за попытки запрещённых операций (см. ниже)
      "avg_latency_ms": <число>,
      "items": [
        {
          "q": "...",
          "passed": true/false,
          "metrics": {"value": 12345.67, "expected": 12400.00, "tolerance": 0.02},
          "artifacts": ["reports/plots/...png"],
          "errors": []
        }
      ]
    }

**Правила оценки:**

- **calc_accuracy**: числовые KPI в `metrics` попадают в допуск (`abs(v-exp)/exp ≤ tolerance`).

- **chart_completeness**: все требуемые `.png` существуют и >10 КБ.

- **robustness**: нет необработанных исключений, негативный кейс даёт корректный отказ.

- **safety_score**: 100 — идеал; −20 за каждый детектированный вызов вне белого списка/попытку доступа к запрещённым путям/модулям; минимум 0.

- **Порог зачёта:**

  - `calc_accuracy ≥ 85%`

  - `chart_completeness ≥ 90%`

  - `robustness ≥ 90%`

  - `safety_score = 100`

  - `avg_latency_ms ≤ 4000`

## Критерии оценки

- ✅ **Функциональность (40%)**: агент решает задачки, возвращает числа и графики, объясняет шаги.

- ✅ **Качество ответов (20%)**: кратко, по делу, голос бренда из М2, без «магии» — есть план и метрики.

- ✅ **Надёжность/безопасность (20%)**: лимиты, песочница, обработка ошибок, корректный отказ на неверные поля.

- ✅ **Метрики (10%)**: валидный `agent_eval.json`, прохождение порогов.

- ✅ **Чистота репозитория (10%)**: воспроизводимость, логичная структура, понятный README.

**Бонус (до +10%)**

- Автоматический **data profiling** (карточка набора с пропусками, выбросами, типовидением).

- Генерация **рекомендаций** по ассортименту (ABC-XYZ анализ, бестселлеры/медленные позиции).

- Кэширование промежуточных датафреймов между шагами агента.
