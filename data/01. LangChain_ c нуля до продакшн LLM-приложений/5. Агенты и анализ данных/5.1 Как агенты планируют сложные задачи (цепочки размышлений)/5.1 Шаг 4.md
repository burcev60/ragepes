**Шаг 4: Артефакт – планировщик шагов для задач**  
**Цель шага:** Разработать модуль (функцию или класс) “планировщика”, который на вход получает сложный запрос и выдаёт упорядоченный список шагов для его решения. Этот артефакт послужит основой для построения более сложных агентов в дальнейшем.

Мы реализуем простой планировщик с использованием модели OpenAI. По сути, это будет оболочка вокруг GPT-4/5, которая возвращает не финальный ответ, а список действий. Например, создадим функцию `plan_query(query: str) -> list[str]` – она будет обращаться к модели с инструкцией составить пошаговый план:

     

    def plan_query(user_query: str) -> list[str]:
        system_msg = "Ты – ассистент-планировщик. Разбери запрос на последовательность действий для решения, не давая конечного ответа."
        prompt = f"Запрос: {user_query}\nПланируй шаги решения задачи:"
        resp = openai.ChatCompletion.create(
            model="gpt-5",  # предположительно доступен, иначе gpt-4
            messages=[{"role": "system", "content": system_msg},
                      {"role": "user", "content": prompt}],
            temperature=0
        )
        plan_text = resp['choices'][0]['message']['content']
        # Предполагаем, что модель вернула шаги нумерованным списком или с префиксом "Шаг 1", "Шаг 2", ...
        steps = [line for line in plan_text.split("\n") if line.strip()]
        return steps

Здесь мы ориентируемся на строгий и детерминированный ответ (temperature=0). В переменной `steps` получим список строк – шагов плана. Этот планировщик можно протестировать на разных примерах, например:

     

`print(plan_query("Сравни динамику продаж 2023 года по регионам и выдели топ-2 региона.")) `

Ожидаемый вывод – список шагов, например:

    1. Загрузить данные о продажах по регионам за 2023 год.
    2. Рассчитать сумму или индекс динамики продаж для каждого региона.
    3. Отсортировать регионы по полученному показателю.
    4. Выбрать топ-2 региона с наибольшей динамикой.
    5. Сформировать вывод с названиями этих регионов и соответствующими цифрами.

Таким образом, мы получаем первый артефакт: **планировщик сложных задач**. Он сам по себе ещё не решает вопрос, но выдаёт дорожную карту для агента. В дальнейших уроках мы воспользуемся им, когда будем строить графы действий в LangGraph.

Стоит отметить, что наш планировщик – довольно простой. В продакшене можно усложнить: например, добавить в него knowledge base о том, какие инструменты у агента есть (чтобы он в план включал вызовы конкретных инструментов: “выполнить SQL запрос”, “построить график” и т.д.). Но на данном этапе курса достаточно и общего плана.
