**Шаг 1: Сшиваем RAG + Web + CSV-агент**  
**Цель шага:** Объединить созданные компоненты (поиск по базе знаний, веб-поиск, анализ CSV) в единого ассистента, который может гибко решать разные задачи. Настроить маршрутизатор запросов, чтобы он направлял вопрос пользователя в нужный модуль (RAG, Web или CSV).

К этому моменту у нас есть:

- **RAG-модуль** (из модулей 3-4): ретривер по внутренней базе знаний, который по запросу находит релевантные документы и формирует ответ с цитатами.

- **Web Search tool** (модуль 4): инструмент для поиска информации в интернете, с выдачей ссылки/цитат, чтобы отвечать на общие вопросы.

- **Tracking/CSV агент** (модуль 5): инструмент для анализа данных (например, заказов или продаж) – мы его только что разработали.

Наша примерная сюжетная линия – ассистент поддержки “Shoply”. Можно представить, что:

- Внутренняя база (RAG) содержит сведения о продуктах, инструкциях, FAQ – для ответов на вопросы о товарах, политике компании и т.д.

- Web-поиск нужен, когда клиент спрашивает что-то об общеизвестных фактах (например, сравнение с конкурентами, или новостей).

- CSV/Tracking нужен, когда клиент спрашивает о **своих данных** – скажем, о статусе заказа, статистике покупок, либо менеджер запрашивает отчёт по продажам.

Наш *маршрутизатор запросов* (делали в модуле 4) – это логика выбора между режимами. Ранее он, возможно, различал “RAG vs Web vs Track” по ключевым словам и модельному предсказанию. Теперь мы интегрируем CSV-агент как реализацию режима “Track” (возможно, Track означал отслеживание заказов).

Как настроить? Самый простой способ – по ключевым словам или формату запроса:

- Если запрос содержит слова типа “данные”, “график”, “CSV”, “таблица”, “файл”, цифры, или названия известных нам полей (например “продажи”, “доход”, “заказы”) – вероятно, нужен CSV-агент.

- Если упоминается «мой заказ», «номер заказа» – может быть тоже CSV (если у нас CSV с заказами).

- Если спрашивают про справочную информацию (“что такое X?”, “как вернуть товар?”) – скорее RAG.

- Если про внешние факты (“когда будет черная пятница в этом году?”) – Web.

Также, в модуле 4 мы, вероятно, делали ML-модель или использовали LLM для маршрутизации. Можно продолжить: дать GPT список категорий запросов, он выберет. Например, промпт:  
*«Категории: 1) Внутренняя база (RAG), 2) Интернет (Web), 3) Анализ данных (Data). К какой категории относится запрос: "{user_query}"?»* – Модель GPT-4 способна классифицировать. На основе ответа выбираем маршрут.

Итак, **соединяем**:

- Если маршрут = RAG, запускаем нашу цепочку RetrievalQA (из мод.3).

- Если маршрут = Web, используем инструмент веб-поиска (из мод.4) и формируем ответ с цитатами.

- Если маршрут = Data (CSV), запускаем нашего `csv_agent`.

Для последовательности:

    route = router.route(user_input)  # пусть вернет "RAG", "Web" или "Data"
    if route == "RAG":
        answer = answer_from_rag(user_input)
    elif route == "Web":
        answer = answer_from_web(user_input)
    elif route == "Data":
        answer = answer_from_csv(user_input)
    else:
        answer = "Извините, я не знаю как это обработать."

Где `answer_from_csv` реализует ту логику: с помощью GPT спланировать/сделать анализ. Мы уже её, по сути, описали.

Например, пользователь спрашивает: *«Какой средний чек заказа за последний месяц?»*  
Маршрутизатор видит слова *средний чек, последний месяц* – это явно что-то из данных продаж. Рекомендует “Data”. CSV-агент:

1. GPT: генерирует код, чтобы фильтровать за последний месяц, вычислить средний чек.

2. Выполняем (CSV содержит транзакции, с колонками Price, Date, etc.).

3. GPT: формирует ответ: *“Средний чек за последний месяц – 820 руб.”*.

Другой пример: *«Расскажите о продуктах, похожих на X у конкурентов»*.  
Маршрутизатор: слово “конкурентов” – скорее, внешняя инфа -> Web. Запускается веб-поиск, ответит с данными из сети.

Ещё: *«Как вернуть товар в Shoply?»*  
Маршрутизатор: “вернуть товар” – это политика возврата, должна быть во внутренней базе -> RAG. Бот найдет в базе статью о возвратах и ответит ссылкой на правила.

Так мы получаем универсального ассистента, понимающего различные типы запросов и адресующего их соответствующим “агентам”.
