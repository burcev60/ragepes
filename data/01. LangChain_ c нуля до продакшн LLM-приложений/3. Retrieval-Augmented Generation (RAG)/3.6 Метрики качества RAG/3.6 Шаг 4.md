## 🔹 Оценка качества ответа в RAG-системах

Оценка ответа — более сложная задача, чем оценка `retriever`, потому что требуется проверить:

- **Правильность содержания (Correctness)** — соответствие эталонному ответу
- **Соответствие источникам (Faithfulness)** — нет ли галлюцинаций
- **Релевантность вопросу (Relevance)** — отвечает ли система на вопрос
- **[опционально] Наличие корректных ссылок (Citation Quality)**


Современные системы RAG используют **LLM-based evaluation**, так как классические метрики схожести текста (BLEU, ROUGE) плохо работают для свободных ответов.

 

### 🔸 **Простая оценка через LLM (без сторонних фреймворков)**

Рассмотрим простую реализацию оценки ответов LLM с помощью ещё одного обращения к LLM на примере метрики **Correctness** (сравнение с эталонным ответом).

Если есть `ground truth` ответ, то можно измерить:

- Насколько ответ совпадает по смыслу
- Насколько полно он раскрывает информацию
- Есть ли противоречия правильному ответу

    import os
    from dotenv import load_dotenv
    load_dotenv()
    from langchain_openai import ChatOpenAI

    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")
    llm = ChatOpenAI(model_name=MODEL, temperature=0)

    examples = [{"query": "Когда основана компания?", "answer": "1999 год."},
                {"query": "Кто основатели?", "answer": "Иван Иванов и Мария Петрова."}]

    predictions = [{"query": "Когда основана компания?", "result": "Компания создана в 1999 году."},
                   {"query": "Кто основатели?", "result": "Иван Иванов и Мария Петрова."}]

    def evaluate_qa_with_llm(query: str, prediction: str, reference: str) -> dict:
        prompt = f"""Ты эксперт по оценке качества ответов.

    Вопрос: {query}
    Ожидаемый ответ: {reference}
    Полученный ответ: {prediction}

    Оцени, насколько полученный ответ соответствует ожидаемому по смыслу.
    Ответь ТОЛЬКО одним словом: CORRECT или INCORRECT"""

        response = llm.invoke(prompt)
        verdict = response.content.strip().upper()
        score = 1.0 if verdict == "CORRECT" else 0.0
  
        return score, verdict

    print("=== Оценка с помощью LLM ===\n")
    scores_llm = []
    for example, prediction in zip(examples, predictions):
        score, verdict = evaluate_qa_with_llm(
            query=example["query"],
            prediction=prediction["result"],
            reference=example["answer"]
        )
        scores_llm.append(score)
        print(f"Вопрос: {example['query']}")
        print(f"Полученный ответ: {prediction['result']}")
        print(f"Ожидаемый ответ: {example['answer']}")
        print(f"Оценка: {score} ({verdict})\n")

    avg_score_llm = sum(scores_llm) / len(scores_llm)
    print(f"Средняя оценка (LLM): {avg_score_llm:.2f}")

Аналогичным образом можно изменив системный промпт просить модель оценивать и другие метрики и ставить разные оценки в удобном для вас формате.

 

### 🔸 **Использование RAGAS**

Специализированный под оценку RAG систем фреймворк с большим набором готовых метрик

**Для установки фреймворка:** `pip install ragas`

    import os
    from dotenv import load_dotenv
    from ragas import evaluate
    from ragas.metrics import Faithfulness, AnswerRelevancy, ContextRecall
    from ragas.llms import llm_factory
    from openai import OpenAI
    from datasets import Dataset
    load_dotenv()

    # Настройка LLM для оценки
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")
    ragas_llm = llm_factory(MODEL, client=OpenAI())

    # Подготовка данных для оценки
    data = {
        "user_input": [
            "Когда основана компания?",
            "Кто основатели?"
        ],
        "response": [
            "Компания основана в 1999 году Иваном Ивановым и Марией Петровой.",
            "Основатели — Иван Иванов и Мария Петрова."
        ],
        "retrieved_contexts": [
            ["Компания основана в 1999 году основателями: Иван Иванов и Мария Петрова."],
            ["Основатели компании — Иван Иванов и Мария Петрова, 1999 год."]
        ],
        "reference": [
            "1999 год.",
            "Иван Иванов и Мария Петрова."
        ]
    }

    dataset = Dataset.from_dict(data)

    # Оценка с помощью RAGAS
    result = evaluate(
        dataset=dataset,
        metrics=[
            Faithfulness(),           # Соответствие контексту (нет галлюцинаций)
            AnswerRelevancy(),        # Релевантность ответа вопросу
            ContextRecall()           # Полнота извлеченного контекста
        ],
        llm=ragas_llm
    )

    print("=== Результаты RAGAS ===")
    print(f"Faithfulness: {result['faithfulness']:.3f}")
    print(f"Answer Relevancy: {result['answer_relevancy']:.3f}")
    print(f"Context Recall: {result['context_recall']:.3f}")

**Основные метрики**

- **`Faithfulness`** — измеряет, насколько ответ опирается исключительно на предоставленный контекст и не содержит галлюцинаций.

- **`AnswerRelevancy`** — оценивает соответствие ответа исходному вопросу и его информативность.

- **`ContextRecall`** — определяет, насколько извлечённый `retriever` контекст покрывает все необходимые факты, содержащиеся в эталонном ответе.

- **`ContextPrecision`** — измеряет долю действительно полезной информации среди извлечённых документов (насколько `retriever` не приносит “лишние” куски текста).

- **`AnswerCorrectness`** — сравнивает фактическую корректность ответа с эталонным ответом.

- **`ContextUtilization`** — определяет, насколько ответ реально использует информацию из контекста, а не опирается на внешние знания.

- **`AnswerSimilarity`** — измеряет степень совпадения ответа с эталонным, не требуя буквального совпадения.

## 🔸 DeepEval

**DeepEval** — это фреймворк в стиле pytest для тестирования LLM-приложений.

**Преимущества DeepEval:**

- Интеграция с pytest для CI/CD
- Самообъясняющие метрики (показывает почему оценка такая)
- Поддержка 60+ метрик
- Генерация синтетических тестовых данных


Можно интегрировать проверку в pipeline разработки. Допустим, вы обновили модель эмбеддинга – стоит запустить eval на контрольном наборе, и если **precision** или **faithfulness** упали ниже порога – бить тревогу.

 

### 🔸 Citation Quality (правильность ссылок)

Если ответы содержат определённый формат ссылок, например `факт [1], факт [2]`, можно измерить долю предложений с цитатами и правильность сопоставления ссылки и документа с помощью функций с определёнными под формат ссылок условиями. Например:

    import re

    def citation_rate(answer: str) -> float:
        """Вычисляет долю предложений с цитатами"""
        sentences = re.split(r'[.!?]\s+', answer.strip())
        sentences = [s for s in sentences if s]  # Убираем пустые
  
        if not sentences:
            return 0.0
  
        cited = sum(1 for s in sentences if re.search(r'\[\d+\]', s))
        return cited / len(sentences)

    # Пример
    ans = "Основана в 1999 году [1]. Основатели — Иванов и Петрова [1]. Компания быстро росла."
    rate = citation_rate(ans)
    print(f"Citation Rate: {rate:.2%}")  # => 66.67%

**Цель:** ключевые факты должны сопровождаться ссылками (≥60%).

### 🔸 **Как интерпретировать результаты**

| Метрика | Что оценивает | Если низкая |
| --- | --- | --- |
| **Correctness** | совпадение с эталоном | модель путает факты |
| **Faithfulness** | соответствует ли ответ источникам | галлюцинации |
| **Relevance** | отвечает ли на вопрос | уход в сторону |
| **Citation rate** | корректность ссылок | ссылки недостоверны |

Типичные хорошие значения:

- Faithfulness ≥ 0.85
- Correctness ≥ 0.85
- Relevance ≥ 0.90
- Citation rate ≥ 0.60 (если требуются обязательные ссылки)


Низкая **faithfulness** (т.е. модель галлюцинирует) – тогда:

- Усилить инструкцию (как мы сделали: `не отвечай, если нет в тексте`)
- Уменьшить `temperature`
- Использовать более фактоориентированную модель (GPT-4 обычно надежнее GPT-3.5 в этом)


Низкая **citation rate** – можно добавлять строже правило. Иногда модель может забыть ставить ссылку, даже если ответ опирается на источник. Тогда просто приучите её: в chain prompt добавить `Обязательно указывай источник для каждого факта`. И проверить на нескольких примерах. Если всё равно забывает – возможно, нужно разбиение ответа: можно попросить в ответе сначала дать сам ответ, а потом отдельно список источников. Но пользователю приятнее inline-ссылки.

**В заключение:** построение RAG-системы – это итеративный процесс. Метрики дают вам компас. Например, вы видите `faithfulness = 0.9` – хорошо, но `citation rate = 0.5` – надо подтянуть, чтобы больше ссылок было. Исправляете промпт, тестируете снова – метрика выросла, отлично. Или обнаруживаете, что `recall = 0.6` – система пропускает инфу – вы решаете добавить вторую стадию поиска или увеличить `k`, потом видите, как поменялись `precision` и `recall`. Так, постепенно, вы доводите систему до нужных показателей баланса между ***находим все нужное*** и ***отвечаем только правду***.

### 🔸 Рекомендации

- **Для быстрого прототипирования:** используйте простую оценку через LLM-промпты (первый пример)

- **Для серьезной RAG-оценки:** используйте [**RAGAS**](https://stepik.org/lesson/2036087/step/docs.ragas.io) — это стандарт индустрии с проверенными метриками

- **Для интеграции в CI/CD:** используйте [**DeepEval**](https://deepeval.com/docs/getting-started) с pytest

- **Если нужна платформа с UI:** рассмотрите **LangSmith** (хорошо интегрируется с langchain, но платно) или **Confident AI** (платформа для DeepEval)

- **Логируйте запросы** и какие документы выбраны (LangChain `retriever` позволяет получить `source`, логируйте `answer +ссылки`)

- Можно организовать **получение пользовательской обратной связи** (лайк/дизлайк, или если в ответе что-то не так – сбор фидбэка). Это поможет собрать новые тест-кейсы.

- **Никакие автоматические метрики не заменят человеческого оценивания** для тонких вещей. Поэтому хорошей практикой является периодически делать ручную выборку: взять 20 случайных ответов системы и критически их просмотреть (или дать экспертам). Особенно это касается того, насколько ответ понятен, полезен ли стиль изложения. Автоматически это сложно измерить.
