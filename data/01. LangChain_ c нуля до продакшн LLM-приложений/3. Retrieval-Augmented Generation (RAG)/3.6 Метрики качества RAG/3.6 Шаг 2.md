## 🔹 Сбор данных для оценки (тестовый набор)

Чтобы посчитать метрики, нужен **тестовый набор**, по которому заранее известны:

- какие документы релевантны вопросу,

- каким должен быть корректный, фактический ответ,

- какие аспекты знания должен покрывать retrieval.

Современные RAG-системы почти всегда используют **комбинированный датасет**, состоящий из:

1. **Ручных контрольных вопросов** (gold questions)

2. **Синтетически сгенерированных Q&A пар**

3. **Тестов на устойчивость и проверку границ возможностей retrieval**

4. **Списков ground truth документов** (для расчёта recall/precision)

### 🔸 Gold-набор (ручные контрольные вопросы)

Если у вас есть внутренняя база знаний, FAQ, база статей — начиная именно с неё вы создаёте небольшой ручной набор (10–30 вопросов):

**Пример:**

- Вопрос: «Когда основана компания?»

- Ответ: «1999 год»

- Ground truth documents: [`history_002.md`]

Этот набор нужен как «эталон»: он показывает реальный формат вопросов и реальные ожидания пользователей. Такие вопросы особенно важны для продуктов в производстве — они помогают ловить регрессии.

### 🔸 Синтетический тест

Можно сделать и по-другому: **синтетический тест**. Идея: сгенерировать “фейковый ответ” или вопросы на основе документа. Например, взять каждый документ из базы и попросить LLM: "Сформулируй вопрос, на который отвечается в этом тексте, и дай правильный ответ." Так вы получите набор Q&A пар, заведомо ответ есть в документе. Их можно использовать для теста.

1. **HYDE-2 (Hypothetical Document or Answer Generation)**  
Генерирует не просто вопрос и ответ, а также:
  - альтернативные формулировки,
  - distractors (похожие, но неверные факты),
  - список фактов, которые должен найти retriever.
2. **QAGen++ (Многофакторная генерация)**
  - модель читает документ,
  - генерирует *несколько уровней вопросов*: простые, сложные, уточняющие,
  - создаёт краткие и расширенные ответы,
  - выделяет факты, которые должны присутствовать в `retrieved_docs`,
  - маркирует уровень гранулярности вопроса (факт → абзац → документ).
> 💡 QAGen++ встроен в RAGAS 2025, EncouRAGe и DeepEval 2.x.

### 🔸 **Пример генерации тестов**

Используем формат JSON для удобства парсинга и автоматизации.

    import os
    from dotenv import load_dotenv
    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import ChatPromptTemplate
    from langchain_core.documents import Document
    load_dotenv()

    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")
    llm = ChatOpenAI(model_name=MODEL, temperature=0)

    documents = [Document(page_content="Фирма ООО 'Одуванчик' основана в 2015 году", metadata={'id': 1}),
                 Document(page_content="Директор ООО 'Одуванчик' Смирнов Иван Петрович", metadata={'id': 2}),
                 Document(page_content="Адрес ООО 'Одуванчик' ул.Ленина д.5", metadata={'id': 3})]

    prompt = ChatPromptTemplate.from_template("""
    Ты – помощник, который придумывает вопросы по тексту.
    Прочитай текст и сформулируй вопрос, на который этот текст отвечает. Затем дай короткий точный ответ на этот вопрос.

    Формат:
    {{
      "questions": [...],
      "answers": [...],
      "facts": [...],
      "ground_truth_doc_id": "{doc_id}"
    }}

    Требования:
    - Сгенерируй 2–3 вопроса разной сложности по тексту.
    - Дай точные ответы, опираясь только на факты из текста.
    - Выдели список ключевых фактов, которые должен найти retriever.
    - Не придумывай информацию вне текста.

    Текст:
    {content}
    """)

    gen_chain = prompt | llm

    examples = []
    for doc in documents:
        ex = gen_chain.invoke({"content": doc.page_content, "doc_id": doc.metadata["id"]})
        examples.append(ex.content)

**Что важно:**

- Модель **явно просим** перечислить факты — это нужно для автоматической проверки **faithfulness/hallucination**.

- В ответ включается *ID документа*, используя метаданные.

- Генерируются вопросы разной сложности — это улучшает распределение сложности датасета.

 

### 🔸 Ground Truth Documents (метки релевантности)

Для каждой Q&A пары фиксируем:

    ground_truth[q] = [doc_id, ...]

Многие фреймворки поддерживают **мягкую разметку**, когда документ оценивается по шкале 0–2:

- 2 — содержит прямой ответ

- 1 — содержит частичную информацию

- 0 — нерелевантен

Это улучшает оценку методов reranking.

Фреймворки, поддерживающие graded relevance:

- **Open-RAG-Eval**

- **EncouRAGe**

- **LangSmith**

### 🔸 Робастность: тесты на устойчивость

Современные датасеты обязательно включают **stress tests**:

- **Paraphrase robustness**  
Перефразированные вопросы (QAGen++ генерирует автоматически).
- **Distractor documents**  
В индекс добавляют документы с похожей лексикой, но неправильными фактами. Проверяется, путается ли retriever.
- **Missing Evidence Test**  
Проверяем, что модель не выдумывает ответ, если фактов нет.
- **Multi-hop test**  
Вопросы, требующие нескольких фактов из разных документов. Нужен для проверки `Context Recall`.
> 💡 RAGAS и DeepEval умеют генерировать такие тесты автоматически

### 🔸 Итоговая структура датасета

    [ { "question": "...", "answer": "...", "facts": [...], "ground_truth_docs": ["doc_12"], "difficulty": "medium", "type": "paraphrase | multi-hop | direct | distractor" }, ... ]

**Это позволяет:**

- Оценивать **faithfulness** на уровне фактов,

- Измерять **recall/precision**

- Анализировать ошибки модели по категориям.
