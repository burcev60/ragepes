## 🔹 **Интеграция в LangChain**

Интегрируем гибридный поиск и реранк в инструментальный стек LangChain. Настроим кастомный ретривер, который под капотом выполняет два вида поиска, и использует кросс-энкодер для сортировки.

### 🔸Свой Retriever

В экосистеме LangChain модуль извлечения знаний представлен интерфейсом `BaseRetriever`. Ретривер – это компонент, который по входному вопросу возвращает список релевантных документов. Обычно это оболочка над одной техникой поиска (например, вызов векторной базы или запрос в SQL-базу знаний). Однако, LangChain позволяет создавать составные ретриверы, объединяющие несколько источников данных или этапов обработки.

В LangChain есть обёртка `BaseRetriever`, которая позволяет легко реализовать свои ретриверы, внутри неё мы можем реализовать свою логику:

    from langchain_core.retrievers import BaseRetriever
    import hashlib

    class HybridRerankerRetriever(BaseRetriever):
        first_retriever: BaseRetriever
        second_retriever: BaseRetriever
        reranker: SimpleReranker
        k: int = 3

        def _dedup_docs(self, docs):
            '''объединение результатов с дедупликацией'''
            seen = set()
            result = []
            for d in docs:
                content = d.page_content
                uid = hashlib.md5(content.encode("utf-8")).hexdigest()
                if uid not in seen:
                    seen.add(uid)
                    result.append(d)
            return result
  
        def _get_relevant_documents(self, query):
            first_docs = self.first_retriever.invoke(query)
            second_docs = self.second_retriever.invoke(query)
            merged = self._dedup_docs(first_docs + second_docs)

            return self.reranker.rerank(query, merged, self.k)

Этот кастомный ретривер может объединять результаты поиска других ретриверов, но мы будем использовать в нашем примере комбинацию поиска BM25 с векторным поиском, как и описывали в теории ранее.

метод `_get_relevant_documents()`:

- Вызывает два других ретривера
- Объединяет их результаты, удаляя дубликаты методом `_dedup_docs()`
- Вызывает реранкер, который возвращает топ `k` выдачи
> 💡 Всю эту логику можно было бы проделать и вне класса обёртки, но с ней пользоваться таким ретривером будет удобнее, так как его можно будет легко встраивать в цепочки как обычный ретривер

 

**Пример использования:** 

    # создаём документы для теста
    from langchain_core.documents import Document
    docs = [
        Document(page_content="Python - язык программирования для машинного обучения", metadata={"source": "0"}),
        Document(page_content="Машинное обучение использует Python и математику", metadata={"source": "1"}),
        Document(page_content="JavaScript работает в браузере", metadata={"source": "2"}),
        Document(page_content="Deep learning - подраздел машинного обучения", metadata={"source": "3"}),
        Document(page_content="React - библиотека для JavaScript", metadata={"source": "4"}),
        Document(page_content="PyTorch - фреймворк для глубокого обучения", metadata={"source": "5"}),
        Document(page_content="Node.js - среда выполнения JavaScript", metadata={"source": "6"}),
        Document(page_content="Нейронные сети в deep learning", metadata={"source": "7"}),
    ]

Тут **BM25** реализован как просто ретривер, немного упрощенный подход, нежели как на первом шаге

    from langchain_community.vectorstores import FAISS
    from langchain_huggingface import HuggingFaceEmbeddings
    from langchain_community.retrievers import BM25Retriever

    emb = HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2")
    vector_store = FAISS.from_documents(docs, emb)

    # инициализация гибридного retriever+reranker
    retriver = HybridRerankerRetriever(
        first_retriever=vector_store.as_retriever(search_kwargs={"k": 5}),
        second_retriever=BM25Retriever.from_documents(docs, k=5),
        reranker=SimpleReranker("BAAI/bge-reranker-base"),
        k=3
        )

    # проверяем
    results = retriver.invoke("расскажи про машинное обучение")

    print("=== Гибридный BM25 + Vector + Rerank ===")
    for i, doc in enumerate(results, 1):
        score = doc.metadata.get("rerank_score", 0)
        print(f"{i}. {score:.4f} | {doc.page_content}")

Тут мы во время инициализации сразу в аргументах нашего кастомного ретривера объявляем два других ретривера с нужными нам `k` (могут быть и разные, если хотим искать больше каким либо способом), реранкер и параметр `top_k` передаются в `top_n` реранкера

### 🔸 **Векторной базы с гибридным поиском**

Некоторые современные векторные базы данных (Weaviate, Elastic, Qdrant) поддерживают **гибридные запросы** напрямую. Например, в Qdrant Query API можно одним запросом указать и фильтр по ключевому поиску, и векторный скор, получив взвешенную комбинацию. LangChain-интеграция таких хранилищ позволяет задавать параметры hybrid search. Если используемый стор (например, ElasticSearch) умеет сразу возвращать cмешаный результат BM25+Vector, можно обойтись без двух отдельных ретриверов – достаточно правильно сконфигурировать запрос.

 

### 🔸 Советы по оптимизации

1. Чем больше настройка `k` у изначальных ретриверов, тем больше пар из которых гибридный ретривер будет выбирать и соответственно медленнее его работа. При этом настройка `k` у гибридного ретривера передаётся в `top_n` реранкера, которая влияет лишь на итоговый срез выдачи релевантных документов, а на скорость работы не повлияет. Таким образом мы можем выбирать в итоговую выдачу например, 3 лучших документа, но в составных ретриверах под капотом нашего кастомного ставить k больше, тем самым улучшая поиск, но замедляя процесс:
  - `k=20`, `top_n=3`: быстрее, но хуже качество
  - `k=50`, `top_n=3`: медленнее, лучше качество
2. GPU-ускорение:
  - Установите PyTorch с поддержкой CUDA, если ваша GPU поддерживает это. Модель автоматически будет использовать её мощности
