## 🔹 C**ross-encoder reranking**

Помимо расчёта рангов простыми формулами, вроде тех, что были описаны на прошлом шаге, определить новые ранги из обеих выдач можно с помощью **cross-encoder** модели для повторного ранжирования найденных документов. Посмотрим, в чём отличие кросс-энкодера от **bi-encoder** (векторного поиска) и почему дополнительный этап повторного ранжирования повышает качество выдачи.

### 🔸 C**ross-encoder**

Это модель (обычно на базе трансформера), которая принимает на вход пару «запрос–документ» и выдаёт степень их релевантности. В отличие от **bi-encoder**, где запрос и документ превращаются в эмбеддинги раздельно, кросс-энкодер совместно обрабатывает оба текста, что позволяет учесть более тонкие взаимосвязи. Благодаря этому **cross-encoder** способен более точно оценить, отвечает ли конкретный фрагмент документа на вопрос пользователя.

В pipeline гибридного поиска **cross-encoder** используется для **повторного ранжирования (reranking)**:

1. Сначала, гибридный поиск (**BM25** + **embeddings**) извлекает расширенный список кандидатов – например по 50 документов от каждого метода, итого до ~100 уникальных чанков.

2. Затем **cross-encoder** прогоняется для каждой пары «запрос–документ» из этого списка и присваивает каждому документу новую оценку релевантности (как правило, вероятность того, что документ содержит ответ).

3. Кандидаты сортируются по этому новому скору и отбираются топ N (например, топ-5 или 10), для подачи в LLM.

Таким образом, **cross-encoder** выступает как высокоточный фильтр *после* первичного поиска. Он часто ловит нюансы, которые были упущены при одном лишь косинусном сравнении эмбеддингов. Например, **bi-encoder** мог дать высокий балл документу, просто имеющему схожую тематику, но не отвечающему на конкретный вопрос. **Cross-encoder**, «прочитав» одновременно и вопрос, и текст документа, способен снизить ранг такого нерелевантного фрагмента и повысить в списке действительно полезный. Это показано в экспериментах: добавление этапа rerank к семантическому поиску увеличивает метрику **MRR@10** на ~7%.

Однако у **cross-encoder** есть цена – они требуют гораздо больше ресурсов, ведь нужно прогнать полную модель для каждой пары запрос–документ. Поэтому оптимально применять их на **ограниченном пуле кандидатов** (например, 50–100 документов), полученных более дешевым методом. В итоге достигается баланс: быстрые методы (**BM25** / **bi-encoder**) дают охват, а медленный **cross-encoder** на малом множестве обеспечивает точность.

### 🔸 Готовые модели для повторного ранжирования

Для реранка можно использовать готовые модели, натренированные на задаче поискового ранжирования. Существуют публичные **cross-encoder** модели(например, из библиотеки `sentence-transformers`), возвращающие скор релевантности.

Оформить реранкер удобно в виде простого класса:

    from sentence_transformers import CrossEncoder

    class SimpleReranker:
        def __init__(self, model_name):
            """
            Args:
                model_name: Название модели cross-encoder
            """
            self.model = CrossEncoder(model_name)
  
        def rerank(self, query, documents, top_n=3):
            """  
            Args:
                query: Поисковый запрос
                documents: Список документов для переоценки
                top_n: Сколько документов возвращает
            Returns:
                Список топ-N документов после rerank
            """

            if not documents:
                return []
  
            # Подготавливаем пары (query, document)
            pairs = [[query, doc.page_content] for doc in documents]
  
            # Получаем скоры релевантности
            scores = self.model.predict(pairs)
  
            # Сортируем документы по скору
            doc_score_pairs = list(zip(documents, scores))
            doc_score_pairs.sort(key=lambda x: x[1], reverse=True)
  
            # Отбираем топ-N документов (score записываем в метаданные)
            result = []
            for doc, score in doc_score_pairs[:top_n]:
                doc.metadata = doc.metadata or {}
                doc.metadata["rerank_score"] = float(score)
                result.append(doc)
  
            return result

Примеры моделей (больше моделей на сайте Hugging Face по тегу [Text Reranking](https://huggingface.co/models?pipeline_tag=text-ranking)):

- `BAAI/bge-reranker-base` – универсальная, хороший баланс скорости и качества. Поддержка 70+ языков
- `BAAI/bge-reranker-large` – более точная версия, требует больше ресурсов. Лучшее качество при увеличенной латентности
- `cross-encoder/ms-marco-MiniLM-L-6-v2` – быстрая и лёгкая модель для английского языка
- `cross-encoder/ms-marco-electra-base` – более мощная модель для английского
- `Qwen/Qwen3-Reranker-0.6B` – компактная модель от Qwen, 100+ языков
- `Qwen/Qwen3-Reranker-4B`, `Qwen/Qwen3-Reranker-8B`– более мощные версии Qwen3, 8B модель занимает №1 в MTEB multilingual leaderboard
