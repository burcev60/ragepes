## 🔹 Что происходит после загрузки?

Загрузчики возвращают объекты `Document`. Каждый объект имеет два основных атрибута:

- `page_content` – текстовое содержимое (строка)
- `metadata` – словарь с метаданными (источник, страница и т.д.)

    # Структура Document
    doc = docs[0]
    print(type(doc))  # <class 'langchain_core.documents.base.Document'>
    print(doc.page_content)  # текст
    print(doc.metadata)  # {'source': '...', 'page': 0, ...}
> 💡 Для больших документов текст может быть слишком объёмным для обработки LLM. Поэтому обычно сразу применяют **Text Splitter**, чтобы разбить документ на чанки (об этом в следующих уроках)

 

### 🔸 Объединение разных типов документов

База знаний порой состоит не только из одного типа документов. Например у нас есть PDF и HTML документы. Их логко можно объединить:

    from langchain_community.document_loaders import PyMuPDFLoader, WebBaseLoader
    import bs4

    # Загрузка PDF
    pdf_loader = PyMuPDFLoader("docs/document.pdf")
    pdf_docs = pdf_loader.load()
    print(f"Загружено {len(pdf_docs)} страниц из PDF")

    # Загрузка HTML
    html_loader = WebBaseLoader(
        web_paths=("https://docs.langchain.com/oss/python/langchain/overview",),
        bs_kwargs={
            "parse_only": bs4.SoupStrainer(id="content")
        }
    )
    html_docs = html_loader.load()
    print(f"Загружено {len(html_docs)} документов из HTML")

    # Объединение всех документов
    all_docs = pdf_docs + html_docs
    print(f"Всего документов: {len(all_docs)}")

    # Просмотр структуры
    for i, doc in enumerate(all_docs[:3]):  # первые 3 документа
        print(f"\n--- Документ {i+1} ---")
        print(f"Источник: {doc.metadata.get('source', 'N/A')}")
        print(f"Первые 150 символов: {doc.page_content[:150]}...")

Теперь у нас есть общий объект `all_docs,` Каждый отдельный документ в нём имеет свойства `.page_content` (текст) и `.metadata` (словарь).

 

## 🔹 Разбиение на чанки

Тексты в документах могут быть длинные, поэтому их следует разбивать на более мелкие фрагменты (чанки). Представьте, у нас есть документ из 10 страниц. Если оставить его одним большим куском, поиск может вернуть весь документ даже если только один абзац релевантен, а LLM не сможет прочитать все 10 страниц (слишком большой контекст). Поэтому принято **резать документ на кусочки** — чанки. Обычно чанком называют фрагмент текста размером нескольких сотен слов или символов (например, 500 слов с небольшим перекрытием).

 

### 🔸 **Как разбивать**

LangChain предлагает классы **TextSplitter**. Они делят текст по разделителям (параграфам, предложениям) до заданной длины. Например `RecursiveCharacterTextSplitter` сначала пытается разрезать по параграфам, если они слишком длинные – по предложениям и т.д., чтобы не разорвать слова или связанные фразы без нужды:

    from langchain_text_splitters import RecursiveCharacterTextSplitter

    text_splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=100)

    splitted_docs = text_splitter.split_documents(all_docs)

    print(f"Было документов: {len(all_docs)}, стало фрагментов: {len(splitted_docs)}")

Здесь:

- `chunk_size=1000` – каждый фрагмент не длиннее 1000 символов
- `chunk_overlap=100` – последние 100 символов предыдущего фрагмента будут дублироваться в начале следующего


Это позволяет сохранить информацию на границе разреза.

Если PDF 10 страниц, ~3000 символов каждая – 30 000 символов. При `chunk_size=1000`, `chunk_overlap=100`, уникальных символов на кусок ≈900 – получается около 34‑38 чанков.

 

### 🔸Разбиение по токенам

Ограничения провайдеров LLM идёт по токенам, поэтому логичнее будет и чанки делить по ним. для этого есть **TokenTextSplitter**, измеряющий длину в токенах

    from langchain_text_splitters import TokenTextSplitter

    text_splitter = TokenTextSplitter(encoding_name="cl100k_base", chunk_size=200, chunk_overlap=20)
    splitted_docs = text_splitter.split_documents(all_docs)

    print(f"Было документов: {len(all_docs)}, стало фрагментов: {len(splitted_docs)}")

Здесь:

- `encoding_name="cl100k_base"` – это кодировка (token‑encoder) из пакета tiktoken, разработанного OpenAI.
- `chunk_size=200` – означает примерно 200 токенов GPT‑4/5, а
- `chunk_overlap=20` – обеспечивает плавность перехода.
> ⚠️ Важно учитывать лимит токенов конкретной модели LLM и выбирать размер чанка соответственно.

 

### 🔸 **Метаданные при разбиении**

TextSplitter, когда принимает `Document` с метаданными, автоматически переносит их в новые куски, при использовании `split_documents()` вы получите список `Document` с теми же метаданными. Источник не потеряется, что важно. Можно добавить собственные поля, например номер чанка.

 

### 🔸 **Рекомендации**

- Иногда можно резать по логической структуре – например, по главам, но общий подход – разделять на небольшие одинаковые куски, чтобы унифицировать процесс. Retrieval будет работать эффективнее с большим числом маленьких записей.
- Код, списки, таблицы и формулы обычно не разрушаются TextSplitter’ом, но при необходимости можно настроить специальные разделители. Если в документе есть сложные структуры, их сохранить может быть полезно.
