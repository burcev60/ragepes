## 🔹 Стратегии дедупликации и фильтрации

Научимся выявлять и удалять **повторяющиеся** или **малозначимые** фрагменты текста, чтобы они не засоряли базу знаний.

**Дедупликация** в контексте RAG — это удаление дубликатов на уровне чанков (фрагментов).  
​​Дубли возникают, если один и тот же раздел встречается в нескольких документах или если при разбивке текста чанки сильно пересекаются и повторяют содержание. Такие повторы стоит удалить. Зачем:

1. Экономия места и ускорение поиска (меньше векторов для индексации).

2. Модель не должна получать один и тот же текст несколько раз — это может приводить к избыточным или повторяющимся ответам. Иногда дубликат — точный текст, иногда — почти одинаковый по смыслу.

**Фильтрация** касается удаления слишком коротких или бесполезных чанков например:

- пустые строки,

- очень короткие фрагменты (например, заголовок «Глава 1» без контекста),

- куски с большим количеством ошибок (например, результат OCR),

- фрагменты, состоящие в основном из символов, цифр, пунктуации.

 

### 🔸**Стратегии удаления**

- **Точное совпадение**  
Если после очистки два чанка имеют абсолютно одинаковый текст — удалить дубликат (например, с помощью хэша).

- **Почти полное совпадение**  
Использовать более гибкие методы — например, **simhash**, **MinHash** или эмбеддинги для оценки схожести.

- **Частичный дубль**  
Когда один фрагмент является подмножеством другого (например, из-за overlap после разбиения).
> ⚠️ overlap (намеренный перекрывающийся контекст) **не стоит удалять**, так как это полезно для семантики.
> Пример: если чанки разделены с overlap=200 символов, конец чанка *N* и начало чанка *N+1* могут дублироваться — это ок.

- **По длине**  
Удалять чанки, короче некоторого порога.  
Например, если после очистки осталось менее чем **30 символов**, такой фрагмент, скорее всего, бесполезен.

- **По составу символов**  
Если в тексте преобладают цифры или знаки, а букв очень мало — возможно, это неинформативная часть (номер страницы, таблица и т.п.). Тут стоит здраво оценивать природу ваших данных, что для них нормально.  
Пример функции:

    def is_meaningful(text: str, threshold: float = 0.5) -> bool:
        if not text:
            return False
        ratio = sum(ch.isalpha() for ch in text) / len(text)
        return ratio > threshold  # по умолчанию — хотя бы половина букв

- **Стоп-слова доменные**  
Фрагменты навигации или меню можно убрать, если они содержат определённые слова (например: «Главная», «Контакты», «Поиск») **и** слишком короткие или повторяющиеся

 

### 🔸**Особенности фильтрации табличных данных**

Иногда фрагменты разбиваются таким образом, что части таблиц оказываются разделены. Лучше их объединить, если это возможно:

    import re
    from typing import List
    from langchain_core.documents import Document

    table_example1 = """| Продукт | Цена | Количество | Статус |
    | Ноутбук | 10000 | 1 | В наличии |
    | Монитор | 15000 | 1 | Ограничено |
    | Клавиатура | 1000 | 10 | В наличии |"""

    table_example2 = """| Продукт | Цена | Количество | Статус |
    | Ноутбук | 20000 | 2 | В наличии |
    | Монитор | 25000 | 2 | Ограничено |
    | Клавиатура | 2000 | 20 | В наличии |"""

    pages = [table_example1, table_example2]

    docs = []
    for page_num, page_text in enumerate(pages, start=1):
        doc = Document(page_content=page_text, metadata={"source": 'file_name', "page": page_num})
        docs.append(doc)

    def is_table_fragment(text: str) -> bool:
        return bool(re.search(r'\|.*\|.*\|', text)) or \
               bool(re.search(r'\t.*\t.*\t', text))

    def merge_metadata(docs: List[Document]) -> dict:
        merged = {}
        for doc in docs:
            for key, value in doc.metadata.items():
                merged.setdefault(key, []).append(value)

        final_md = {}
        for key, values in merged.items():
            unique = list({v for v in values})  # оставляем только уникальные
            if len(unique) == 1:
                final_md[key] = unique[0]       # если одно значение — делаем скаляр
            else:
                final_md[key] = sorted(unique)  # иначе — список
        return final_md

    def merge_docs(docs: List[Document]) -> Document:
        return Document(
            page_content="\n".join(doc.page_content for doc in docs),
            metadata=merge_metadata(docs),
        )

    def merge_table_fragments(docs: List[Document]) -> List[Document]:
        merged = []
        current_table = []
        for doc in docs:
            if is_table_fragment(doc.page_content):
                current_table.append(doc)
            else:
                if current_table:
                    merged.append(merge_docs(current_table))
                    current_table = []
                merged.append(doc)
        if current_table:
            merged.append(merge_docs(current_table))
        return merged

    merged = merge_table_fragments(docs)
    print(merged[0].page_content)
    print(merged[0].metadata)

 

### 🔸Технические **приёмы**

- **Хэширование для точных дублей**  
Вычислить хэш каждого чанка (например, MD5 или SHA1 строки). Затем найти дубли по совпадению хэша. Это быстрый способ и займет O(n) памяти для хэшей.

    import hashlib
    hash = hashlib.md5(text.encode('utf-8')).hexdigest()

- **Simhash / MinHash**  
Библиотеки типа `simhash` работают хорошо, если нужно обнаружить почти одинаковые тексты с небольшими изменениями.

- **Embedding similarity**  
Когда вы уже имеете эмбеддинги фрагментов, можно при добавлении нового чанка проверять его схожесть с уже индексированными. Если косинусное сходство выше порога (например, 0.95), можно не добавлять.  
В стандартной библиотеке LangChain нет готовой функции «авто-дедупликация эмбеддингов», но можно сделать так вручную: делать similarity search на векторном индексе и проверять ближайший сосед.
> ⚠️ Сравнивать каждые эмбеддинг со всеми уже существующими может быть очень расурсозатратным процессом, особенно при большом количестве данных. Возможно это того не стоит

 

### 🔸Реализация в langchain

Допустим, у нас уже есть список документов `docs` после предыдущих шагов (с метаданными, текст очищен). Реализуем простую дедупликацию по точному совпадению и фильтр по длине:

    import re
    import hashlib
    from typing import List
    from langchain_core.documents import Document

    def is_table_row(text: str) -> bool:
        return bool(re.search(r'\|.*\|', text)) or \
               bool(re.search(r'\t{2,}', text)) or \
               bool(re.search(r'^\s*[\w\s]+\s{2,}[\w\s]+', text))

    def filter_and_dedup(docs: List[Document], min_length: int = 30) -> List[Document]:
        unique_hashes = set()
        filtered = []
        stats = {'duplicates': 0, 'too_short': 0, 'empty': 0}
        for doc in docs:
            text = doc.page_content.strip()
            if not text:
                stats['empty'] += 1
                continue
            if len(text) < min_length and not is_table_row(text):
                stats['too_short'] += 1
                continue
            h = hashlib.md5(text.encode('utf-8')).hexdigest()
            if h in unique_hashes:
                stats['duplicates'] += 1
                continue
            unique_hashes.add(h)
            filtered.append(doc)
        print(f"Первоначально: {len(docs)} чанков")
        print(f"Удалено дубликатов: {stats['duplicates']}, слишком коротких: {stats['too_short']}, пустых: {stats['empty']}")
        print(f"Осталось: {len(filtered)} чанков")
        return filtered

Здесь `unique_hashes` хранит хэши уже включённых текстов. Если встречается точный дубль, не добавляем его повторно. Кроме того, мы отбрасываем любые куски короче 30 символов. В итоге, `filtered` – наш очищенный от дублей список. Вывод покажет статистику. Например:

    Первоначально: 120 чанков
    Удалено дубликатов: 5, слишком коротких: 8, пустых: 0
    Осталось: 107 чанков

 

### 🔸 Пример сравнения эмбеддингов

    import numpy as np
    from typing import List
    from langchain_core.documents import Document
    from langchain_core.vectorstores.in_memory import InMemoryVectorStore
    from langchain_huggingface import HuggingFaceEmbeddings

    def cosine_similarity(v1: np.ndarray, v2: np.ndarray) -> float:
        return float(np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2)))

    def dedupe_by_embedding(docs: List[Document], embedding_model, threshold: float = 0.95) -> List[Document]:
        # создаём векторное хранилище
        vector_store = InMemoryVectorStore(embedding=embedding_model)
        kept_docs = []
        embeddings = []

        for doc in docs:
            text = doc.page_content.strip()
            if not text:
                continue

            emb = embedding_model.embed_documents([text])[0]

            if not embeddings:
                vector_store.add_documents([doc])
                embeddings.append(emb)
                kept_docs.append(doc)
                continue

            # делаем similarity search вручную: можно просто сравнить со всеми
            sims = [cosine_similarity(np.array(emb), np.array(e)) for e in embeddings]
            max_sim = max(sims)
            if max_sim < threshold:
                vector_store.add_documents([doc])
                embeddings.append(emb)
                kept_docs.append(doc)
            else:
                print(f"Пропускаем дубликат (по embedding): '{text[:50]}...' с sim = {max_sim}")

        return kept_docs

    # Пример использования
    pages = [
        "abcd1234",
        "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ",
        "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYabcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXY"
        ]

    docs = []
    for page_num, page_text in enumerate(pages, start=1):
        doc = Document(page_content=page_text, metadata={"source": 'file_name', "page": page_num})
        docs.append(doc)

    embed_model = HuggingFaceEmbeddings(model_name="all-MiniLM-L6-v2")
    filtered = dedupe_by_embedding(docs, embed_model, threshold=0.95)

    print(filtered)

Этот код:

1. Создаёт `InMemoryVectorStore` (в оперативной памяти), он поддерживает вычисление косинусной близости.

2. Для каждого документа вычисляет эмбеддинг.

3. Сравнивает эмбеддинг нового чанка с уже сохранёнными — находит максимальное косинусное сходство.

4. Если самая высокая похожесть ниже порога, добавляет новый документ. Иначе — считает, что это дубликат.

 

### 🔸**Рекомендации**

- **Не переусердствуйте**. Лучше пускай в базе будет немного шума, чем вы удалите что-то и ответ не найдется. Например, удалять все короткие фрагменты может быть плохо, если в некоторых документах действительно короткие ответы или термины. Будьте консервативны: удаляем только то, что точно мусор.

- **Желательно логировать** **удаляемые фрагменты** на этапе разработки, чтобы понимать что удаляется. Если таких фрагментов много, вероятно эти проблемы решаемы на этапе парсинга данных или эту проверку не проходит полезная информация и тогда стоит повысить порог или отказаться от такой фильтрации

- **Логируйте так же и количество удалённого.** Это показатели качества данных. Например: “после фильтрации осталось 95% исходных чанков, 5% удалено (3% дубликаты, 2% слишком короткие)” – такие данные можете включить в финальный отчёт препроцессинга.
