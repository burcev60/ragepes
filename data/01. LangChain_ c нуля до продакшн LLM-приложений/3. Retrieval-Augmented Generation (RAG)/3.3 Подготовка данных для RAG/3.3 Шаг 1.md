## 🔹 Очистка и нормализация текста

Сейчас мы научимся превращать сырые документы в чистый, удобный для поиска формат. Это включает удаление лишних символов, неинформативных частей и нормализацию текста. Хорошая очистка повышает качество последующего поиска и генерации ответов, потому что модель получает более релевантный контент.

Документы из реального мира (PDF, HTML, сканы) часто содержат артефакты: номера страниц, колонтитулы, стоп‑слова, неравномерный регистр, опечатки OCR, код или разметку.

 

### 🔸Нормализация

**Нормализация** – это приведение текста к единому стилю:

- **Приведение регистра:** `text = text.lower()` – классика, но иногда регистр важен (имена собственные).

- **Единые разделители:** Точки в конце предложений, `\n` для переносов, формат заголовков новой темы и т.д.

- **Нормализация пробелов и переносов:** Замените последовательности пробелов/переводов строк на единичные: `re.sub(r"\s+", " ", text)`. Будьте аккуратны – между абзацами можно оставить двойной перевод строки.

- **Унификация представления данных:** Цифры в одном формате, даты в ISO и т.д.

- **Если данные мультиязычные**, можно оставить язык или перевести. Чаще на этапе препроцессинга просто не трогаем естественный язык, а чистим только форму.

 

### 🔸**Очистка**

**Очистка** – удаление того, что не нужно индексировать: содержание, рекламные блоки, boilerplate (типовое сноски, ссылки на лицензии), повторяющиеся на каждой странице заголовки. Чем чище текст, тем точнее будут эмбеддинги и меньше риск получить мусорный фрагмент.

- **Удаление спецсимволов и невидимых символов:** Часто в текст попадают неразрывные пробелы, скрытые переносы. Используйте `.encode('utf-8', 'ignore').decode('utf-8')` или библиотеку `ftfy` для устранения мусора. `unidecode` может транслитерировать странные символы в ASCII.

- **Регулярные выражения для вырезания шаблонов:** Например, если каждая страница PDF имеет строку “Company Confidential”, можно сделать `text = re.sub(r"Company Confidential\s*\d+\s*", " ", text)`.

- **Удаление стоп‑слов или лемматизация:** В RAG обычно не удаляют stop words и не делают лемматизацию перед эмбеддингом. Лучше сохранить исходный текст.

- **Коррекция OCR ошибок:** Можно использовать `LanguageTool`, `PyEnchant` для проверки орфографии, но будьте осторожны – автоматическое исправление может внести ошибки. Лучший вариант – брать более качественный OCR или обучить модель справляться с мелкими опечатками.

 

### 🔸**Лучшие практики**

- **Не переусердствовать:** Удаляйте шум, но не содержательную информацию. Ошибка новичков – вырезать все цифры или текст в скобках.

- **Проверять на образцах:** Напишите функцию очистки и прогоните её на 2‑3 разных документах, внимательно сравните до/после.

- **Универсальность:** Если корпус разнородный (PDF, HTML, markdown), делайте очистку модульной: сначала специфичная (например, убрать `<script>` из HTML), потом общая.

- **Логи изменений:** При сильной очистке логируйте количество символов до/после и замены по каждому правилу.

 

### 🔸**Пример очистки текста**

    import re

    raw_text = """Статья 1.  Общее положение

    Company Confidential 2024. Все права защищены.
    Введение:   Данный документ...
    ...Содержание...
    1.1. Определения.

    Статья 2. Следующий раздел"""

    def clean_text(text: str) -> str:
        # Удаляем упоминания "Company Confidential ..."
        text = re.sub(r"Company\s+Confidential\s+\d{4}\.\s+Все права защищены\.", " ", text)
        # Убираем 'Содержание...' как пример ненужного раздела
        text = re.sub(r"\.{3,}Содержание\.{3,}", " ", text)
        # Удаляем лишние переводы строк (больше 2 подряд превращаем в 1, одиночные в пробел)
        text = re.sub(r"\n{3,}", "\n\n", text)   # больше двух \n -> два \n
        text = re.sub(r"[ \t]+\n", "\n", text)   # убираем пробелы в конце строк
        text = re.sub(r"\n", " ", text)          # заменяем оставшиеся переводы строк пробелом
        # Убираем двойные пробелы
        text = re.sub(r"\s{2,}", " ", text)
        return text.strip()

    cleaned = clean_text(raw_text)
    print(cleaned)
    # Вывод: Статья 1. Общее положение Введение: Данный документ 1.1. Определения. Статья 2. Следующий раздел

В примере удалены лишние строки, «Company Confidential» и «Содержание…». После очистки получаем связный текст без мусора.

Финальный пайплайн препроцессинга должен быть документирован. Если вы решили привести всё в нижний регистр, упомяните это. Можно сравнить до/после очистки на примерах – например, вывести сырой и очищенный текст в notebook.

 

### 🔸 Специальная обработка таблиц

Когда база знаний состоит из табличных данных, стандартная текстовая очистка недостаточна. Таблицы требуют особого подхода:

- Структура часто ломается при извлечении – объединённые ячейки, многострочные заголовки.
- Традиционные методы превращают таблицы в хаотичные строки текста.
- CSV/JSON теряют контекст и связи между элементами.


**Пример гибридного подхода – текст + структура:**
> 💡 Для работы кода, необходимо установить в окружении библиотеку pandas `pip install pandas`

    import pandas as pd

    def extract_table_as_dataframe(table_text: str) -> pd.DataFrame:
        """Преобразуем таблицу в DataFrame."""
        lines = table_text.strip().split('\n')
        rows = []
        for line in lines:
            if '|' in line:
                row = [cell.strip() for cell in line.split('|') if cell.strip()]
            else:
                row = [cell.strip() for cell in line.split('\t') if cell.strip()]
            if row:
                rows.append(row)
        if not rows:
            return pd.DataFrame()
        df = pd.DataFrame(rows[1:], columns=rows[0])
        return df

    def table_as_string(df: pd.DataFrame) -> str:
        """Создаём описательный текст для каждой строки."""
        if df.empty:
            return ""
        descriptions = []
        for _, row in df.iterrows():
            desc = ". ".join([f"{col}: {row[col]}" for col in df.columns])
            descriptions.append(desc)
        return "\n".join(descriptions)


    table_example = """
    | Продукт | Цена | Количество | Статус |
    | Ноутбук | 50000 | 5 | В наличии |
    | Монитор | 15000 | 3 | Ограничено |
    | Клавиатура | 5000 | 10 | В наличии |
    """
    df = extract_table_as_dataframe(table_example)

    print("📊 Структурированные данные:")
    print(df.to_dict(orient='records'))
    print("\n📝 Описательный текст:")
    print(table_as_string(df))

**Объяснение функций:**

- `extract_table_as_dataframe()` – парсит таблицу в DataFrame.
- `table_as_string` – конвертирует каждый ряд в читаемую строку и объединяет в один текст.


 

### 🔸Интеграция в пайплайн Langchain

Написанные функции нормализации и очистки текста можно удобно интегрировать в цепочку от чтения документа до помещения в векторное хранилище. При этом загрузку и обработку разных типов данных можно делать параллельно и даже асинхронно если надо:

    from langchain_core.runnables import RunnableLambda, RunnableParallel
    from langchain_community.document_loaders import PyMuPDFLoader, WebBaseLoader
    from langchain_text_splitters import TokenTextSplitter
    import bs4

    # 1. СОЗДАНИЕ RUNNABLE ЗАГРУЗЧИКОВ
    class LoaderRunnable(RunnableLambda):
        def __init__(self, loader):
            super().__init__(lambda _: list(loader.lazy_load()))
            self.loader = loader

    load_pdf = LoaderRunnable(PyMuPDFLoader("docs/document.pdf"))
    load_html = LoaderRunnable(WebBaseLoader(
        web_paths=("https://docs.langchain.com/oss/python/langchain/overview",),
        bs_kwargs={"parse_only": bs4.SoupStrainer(id="content")}))


    # 2. СОЗДАНИЕ RUNNABLE ОБРАБОТЧИКОВ (Функции обработки тут - это просто заглушки)
    def clean_pdf_text(text: str) -> str:
        return text

    def clean_html_text(text: str) -> str:
        return text

    def normalize_text(text: str) -> str:
        return text.lower()

    def apply_func_to_all_docs(func):
        def process_docs(docs):
            for doc in docs:
                doc.page_content = func(doc.page_content)
            return docs
        return process_docs

    clean_pdf = RunnableLambda(apply_func_to_all_docs(clean_pdf_text))
    clean_html = RunnableLambda(apply_func_to_all_docs(clean_html_text))
    normalize_all = RunnableLambda(apply_func_to_all_docs(normalize_text))


    # 4. КОМПОЗИЦИЯ ЦЕПОЧКИ
    chain = (
        RunnableParallel(pdf=load_pdf | clean_pdf,
                         html=load_html | clean_html)
        | RunnableLambda(lambda x: x["pdf"] + x["html"])
        | normalize_all
    )

    # 5.1 ПРОСТОЙ ВЫЗОВ
    result = chain.invoke(None)

    # # 5.2 АСИНХРОННЫЙ ВЫЗОВ
    # import asyncio
    # async def load_and_split_all_docs():
    #     return await chain.ainvoke(None)
    # result = asyncio.run(load_and_split_all_docs())

    # 6. Смотрим результат
    for doc in result:
            print(doc.page_content[:50])
            print('Источник:', doc.metadata['source'], '\n')

Эти обработки можно сделать и попроще, но данный подход демонстрирует архитектуру для масштабируемых RAG-систем. У этого есть ряд преимуществ:

1. **Модульность и переиспользование**
  - Каждый компонент (загрузчик, очиститель, сплиттер) - независимый `Runnable`
  - Можно создать библиотеку переиспользуемых пайплайнов:
  - Легко комбинировать для разных задач
2. **Параллельная обработка**
  - `RunnableParallel` реально загружает источники параллельно
  - Критично для production систем с множеством источников:  
10 PDF файлов последовательно: ~10 секунд  
10 PDF файлов параллельно: ~1-2 секунды
  - Особенно важно для медленных источников (API, веб-скрейпинг, большие файлы)
3. **Декларативный стиль**
  - Код читается как описание того, ЧТО делать, а не КАК: `chain = load | clean | normalize | split` и т.д.
  - Легко понять `flow` данных даже новичку
  - Меньше вложенности и императивной логики
4. **Расширяемость**
  - Добавить новый источник = добавить одну строку:

    RunnableParallel(
        pdf=pdf_pipeline,
        html=html_pipeline,
        docx=docx_pipeline,  # <-- новый источник
        api=api_pipeline     # <-- ещё один
    )

  - Не нужно переписывать существующую логику
5. **Тестируемость**
  - Каждый Runnable можно тестировать изолированно:  
`assert len(load_pdf.invoke(None)) > 0`  
`assert all(doc.page_content for doc in clean_pdf.invoke(docs))`
  - Легко мокировать отдельные компоненты
6. **Прозрачная асинхронность**
  - **LangChain** автоматически управляет `thread pool`
  - Не нужно вручную писать run_in_executor
  - Одна и та же цепочка работает синхронно и асинхронно:  
`result = chain.invoke(None)        # синхронно`  
`result = await chain.ainvoke(None) # асинхронно`


**Когда использовать простой подход:**

- Один источник данных
- Прототипирование / разовые скрипты
- Файлы маленькие (<1MB) и на локальной машине


**Когда использовать асинхронный подход:**

- Множественные источники данных.
- Production RAG система
- Медленные источники (API, веб, большие файлы)
- Нужна расширяемость и поддерживаемость
- Команда разработчиков работает над кодом
