**Реализация стриминга ответов**  
Сейчас наше API выдаёт ответ только после того, как он полностью получен от модели. Для длинных ответов это может занимать значительное время (несколько секунд или даже десятки секунд). Стриминг позволяет начать отправку частей ответа сразу, как только модель их генерирует, не дожидаясь окончания. В HTTP это реализуется через **сервер-отправляемые события (Server-Sent Events, SSE)** или просто через **поддержку потокового ответа**. В FastAPI есть специальный класс `StreamingResponse` для этих целей.

 

Как это работает: мы должны предоставить генератор (итератор), который по мере готовности данных будет выдавать куски (байты/строки), а FastAPI будет держать соединение открытым и пересылать эти куски клиенту. Браузер (или другой HTTP-клиент) получит несколько частей данных в одном ответе, воспринимая их как поток.

 

В случае LLM OpenAI API поддерживает параметр `stream=True`, при котором возвращается итератор с частичными результатами. Мы можем использовать либо SDK OpenAI напрямую, либо встроенный функционал LangChain. Чтобы не усложнять, воспользуемся напрямую `openai` библиотекой в нашем обработчике стриминга. Не забудьте установить `openai` (`pip install openai`), и важный момент – указать `openai.api_base` 

 

Пример эндпоинта со стримингом:

    import openai
    from fastapi.responses import StreamingResponse

    # Настраиваем OpenAI SDK на использование proxy
    openai.api_base = "ВАШ_ПРОКСИ"
    openai.api_key = "ВАШ_API_КЛЮЧ"

    @app.get("/ask_stream")
    def ask_stream(question: str):
        # Проверка вопроса
        if not question or question.strip() == "":
            raise HTTPException(status_code=400, detail="Question cannot be empty")
        # Создаем генератор ответа
        def stream_answer():
            response = openai.ChatCompletion.create(
                model="gpt-5", messages=[{"role": "user", "content": question}],
                stream=True
            )
            for chunk in response:
                # Каждый chunk - это часть ответа
                chunk_message = chunk["choices"][0].get("delta", {}).get("content", "")
                if chunk_message:
                    # Формируем строку в формате SSE: префикс "data: " и два переноса строки
                    yield f"data: {chunk_message}\n\n"
        # Возвращаем StreamingResponse с медиа-типом text/event-stream (SSE)
        return StreamingResponse(stream_answer(), media_type="text/event-stream")

Этот код добавляет эндпоинт `GET /ask_stream`, который принимает параметр `question` в строке запроса (например: `/ask_stream?question=Привет, как тебя зовут?`). Мы инициализируем глобально `openai.api_base` и `openai.api_key` один раз (в боевом коде это лучше сделать в конфигурации). В обработчике определяем генератор `stream_answer()`, который внутри вызывается `openai.ChatCompletion.create` с параметром `stream=True`. Это вернёт генератор `response`, дающий частичные **чанки** ответа модели. В цикле `for chunk in response` мы извлекаем из каждого чанка `delta.content` – это часть текста, которую модель генерирует. Если content не пустой, отправляем его клиенту через `yield`. Мы добавляем префикс `"data: "` и суффикс `\n\n` – это формат Server-Sent Events (каждое событие начинается с data: и отделяется пустой строкой).

 

Наконец, оборачиваем генератор в `StreamingResponse`, указываем `media_type="text/event-stream"`. Это подскажет клиенту (и браузеру), что соединение будет *потоком событий*. На стороне клиента (например, в браузере) можно использовать объект `EventSource` для подписки на поток. Если мы откроем в браузере напрямую URL `/ask_stream?question=Once upon a time` (пример с английским запросом), мы увидим поток данных, который постепенно появляется (в консоли браузера или в network можно отследить). В терминале curl тоже можно запустить `curl http://localhost:8000/ask_stream?question=Привет` – он будет выводить части ответа по мере генерации.

 

**Примечание:** здесь мы использовали GET для стриминга просто потому, что так легче тестировать через браузер. В реальном API можно сделать и `POST /ask_stream` (тогда вопрос передавать в теле JSON). Однако для SSE удобнее иногда GET, чтобы из браузера можно было просто подключиться через `EventSource(url)`.
