Теперь, когда у нас есть два LLM, реализуем простейшую схему **автоматического переключения**. Идея: пробуем получить ответ от основной модели; если возникает ошибка (например, исключение по таймауту, перегрузке API или иная), тогда используем запасную. Это можно сделать с помощью конструкции `try/except` в Python:

    def ask_with_fallback(question: str) -> str:
        try:
            # Пытаемся получить ответ от основной (мощной) модели
            result = chain_primary.run(question)
            return result
        except Exception as e:
            print(f"Primary model failed: {e}. Using backup model.")
            # Если произошла ошибка – задействуем запасную модель
            return chain_backup.run(question)

    # Пример использования
    query = "В чем разница между списком и кортежем в Python?"
    answer = ask_with_fallback(query)
    print(answer)

В этом коде функция `ask_with_fallback` инкапсулирует логику: если `chain_primary.run()` выбросил исключение, мы перехватываем его и вызываем `chain_backup`. Таким образом, пользователю вернётся ответ либо от GPT-5, либо, в случае сбоя, от GPT-3.5. **Важно**: предусмотреть логирование или метрики, чтобы вы знали о таких случаях (в примере мы выводим в консоль сообщение, но в продакшене лучше записать в лог). По факту, такая стратегия **повышает надёжность приложения**, ведь при проблемах с основным провайдером пользователи все равно получат ответ, пусть и возможно чуть менее точный или детальный. Как отмечают специалисты, fallback повышает отказоустойчивость AI-сервисов: приложение автоматически переключается на резервную модель, благодаря чему пользователи могут вообще не заметить проблем с основным провайдером.

 

Можно усложнить схему: например, при не критических ошибках пробовать повторно тот же провайдер (retry), а уже при серьёзных – переключаться. В LangChain есть поддержка *fallback на уровне Runnable компонентов* – метод `with_fallbacks()`, позволяющий обернуть LLMChain с списком резервных вариантов. Но если не вдаваться в детали, `try/except` реализует ту же логику явно.
