Рассмотрим небольшой пример, демонстрирующий описанное: будем выбирать модель в зависимости от длины вопроса, а также иметь fallback на случай ошибки. Код может выглядеть так:

    from langchain.chat_models import ChatOpenAI

    # Инициируем 2 модели: быструю и мощную (используем proxy)
    fast_model = ChatOpenAI(model_name="gpt-3.5-turbo", openai_api_key="KEY",
                            openai_api_base="ВАШ_ПРОКСИ")
    smart_model = ChatOpenAI(model_name="gpt-5", openai_api_key="KEY",
                             openai_api_base="ВАШ_ПРОКСИ")

    def smart_answer(user_query: str) -> str:
        # Правило: если запрос короткий (<100 символов), используем более быструю модель
        llm = fast_model if len(user_query) < 100 else smart_model
        try:
            return llm.predict(user_query)  # метод predict доступен у ChatOpenAI для одиночного ввода
        except Exception as e:
            # Если выбранная модель дала ошибку, пробуем другую
            print(f"Error with {'fast' if llm==fast_model else 'smart'} model, switching. Err: {e}")
            other_llm = smart_model if llm == fast_model else fast_model
            return other_llm.predict(user_query)

    # Тестируем функцию
    queries = ["Привет, как дела?",  # короткий запрос, пойдет в fast_model
               "Объясни, пожалуйста, концепцию капсул в нейронных сетях и почему они лучше привычных нейронных сетей?"]  # длинный, пойдет в smart_model
    for q in queries:
        print(smart_answer(q))

Здесь функция `smart_answer` выбирает модель на основе длины вопроса. Мы использовали метод `predict` класса `ChatOpenAI`, который удобен для единственного сообщения (не нужно явно создавать список сообщений). Если модель, на которую пришёлся запрос, выбросит исключение – мы ловим его и переключаемся на другую модель. Таким образом, если вдруг GPT-5 недоступен для длинного вопроса, сразу попробуем GPT-3.5, и наоборот.

 

Стоит отметить, что при мульти-модельной схеме нужно **следить за консистентностью опыта пользователя**. К примеру, если пользователь общается с чат-ботом и на разные вопросы получает ответы разного стиля (потому что модели-то разные), это может быть заметно. По возможности, выравнивайте стиль (например, можно подсказать младшей модели имитировать стиль старшей через system-промпт). Также мониторьте, как часто происходит fallback и какова разница в качестве – возможно, имеет смысл в будущем заменить менее надёжную модель или добавить третью.
