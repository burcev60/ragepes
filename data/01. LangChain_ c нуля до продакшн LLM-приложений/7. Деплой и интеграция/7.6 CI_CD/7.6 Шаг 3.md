**Continuous Deployment (CD) – непрерывное развёртывание**  
CD – это автоматическое развертывание кода на окружения (стейдж, прод). Предположим, после мерджа в main мы хотим деплоить на прод. Процесс может выглядеть так:

1. Триггер: новый коммит в main-ветке (после прохождения CI).

2. Сборка Docker-образа (если не собирали на CI) – например, `docker build -t myapp:${GIT_SHA}`.

3. Публикация образа в регистри (Docker Hub, GitHub Container Registry, AWS ECR и т.д.).

4. Развёртывание на сервер: в зависимости от инфраструктуры. Если простой сервер – можно SSH-подключением обновить контейнер. Если Kubernetes – применить `kubectl apply` нового образа (Deployment манифест с новым тегом) или использовать CD-систему типа ArgoCD. Если PaaS – возможно, просто `git push` туда или API вызов.

5. После деплоя – возможно, прогнать smoke-тесты (проверить, что /health возвращает ok, что базовый запрос возвращает что-то разумное). Можно автоматизировать: workflow ждёт, пока новый контейнер поднимется, стучится к нему.

При настройке CD, тоже обеспечьте секреты: например, доступ для пуша образов, доступ для деплоя (SSH ключ или kubeconfig). Храните их в CI/CD системе безопасно.
