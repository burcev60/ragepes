## 🔹 Подбор и порядок примеров

Подбор примеров для few-shot — ключевой фактор, влияющий на результат. Это одновременно творческая и инженерная задача.

### 🔸Критерии выбора примеров

1. **Покрытие задачи.** Примеры должны охватывать все типичные и сложные случаи. Если нужно, чтобы модель справлялась и с простыми, и со сложными запросами — включайте разнообразные по сложности примеры.

2. **Желаемое поведение.** Каждый пример должен демонстрировать целевой стиль: форматирование, структуру ответа, вежливость и т. д. Например, если ассистент должен всегда начинать с приветствия — покажите это в примере.

3. **Единообразие.** Все примеры должны следовать одному шаблону. Это помогает модели улавливать паттерны.

### 🔸Порядок расположения

Последовательность примеров также влияет на поведение модели.

- Оптимально выстраивать их **от простого к сложному** или **от типичного к редкому**, это формирует «лестницу» понимания.

- Особенность архитектуры трансформеров такова, что **последний пример** запоминается лучше (эффект недавности), поэтому в конец стоит ставить пример, наиболее похожий на ожидаемый реальный запрос.

### 🔸Динамический подбор примеров в **LangChain**

Если пользователи задают вопросы на разные темы (техника, искусство, история, код и т.д.), то статические 2–3 примера просто не покроют всё.  
Механизм **dynamic few-shot** подбирает похожие примеры из большой библиотеки, чтобы модель каждый раз училась «на лету» на самых релевантных случаях.

Библиотека **LangChain** предоставляет инструменты для автоматического подбора примеров.

- **ExampleSelector** может выбирать примеры динамически — по семантическому сходству с текущим запросом.

- При поступлении нового вопроса вычисляется эмбеддинг запроса, выбираются N наиболее близких примеров и добавляются в промпт.

- Это создаёт **динамический few-shot**, где каждый запрос получает наиболее релевантный контекст.

    import os
    from dotenv import load_dotenv

    from langchain_core.prompts import PromptTemplate, FewShotPromptTemplate
    from langchain_core.example_selectors import SemanticSimilarityExampleSelector
    from langchain_community.vectorstores import Chroma
    from langchain_openai import ChatOpenAI

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")
    llm = ChatOpenAI(model=MODEL, temperature=0)

    # Локальные эмбеддинги без OpenAI
    from langchain_huggingface import HuggingFaceEmbeddings
    embeddings = HuggingFaceEmbeddings(model_name="all-MiniLM-L6-v2")

    # # эмбеддинги OpenAI (раскомментируйте если решили использовать их)
    # from langchain_openai import OpenAIEmbeddings
    # embeddings = OpenAIEmbeddings()

    example_prompt = PromptTemplate.from_template("Вопрос: {question}\nОтвет: {answer}")
    examples = [
        {"question": "Что делать, если опоздал на работу?",
         "answer": "Притворись, что это спецплан компании по тестированию терпения коллег."},
        {"question": "Как победить лень?",
         "answer": "Скажи лени, что завтра — её выходной, и действуй, пока она отдыхает."},
        {"question": "Что делать, если забыл день рождения друга?",
         "answer": "Сделай вид, что это сюрприз для него, и улыбайся, когда он удивлённо морщит лоб."}
    ]

    # Создание ExampleSelector (динамический выбор k ближайших примеров)
    example_selector = SemanticSimilarityExampleSelector.from_examples(
        examples=examples,
        embeddings=embeddings,
        vectorstore_cls=Chroma,
        k=2  # выбираем 2 ближайших примера
    )

    # Few-shot шаблон с динамическим ExampleSelector
    prompt = FewShotPromptTemplate(
        example_selector=example_selector,
        example_prompt=example_prompt,
        prefix="Отвечай на вопросы в шутливо-ироничном стиле, как в примерах:",
        suffix="Вопрос: {question}\nОтвет:",
        input_variables=["question"]
    )

    # Новый запрос — ExampleSelector выберет ближайший пример по смыслу
    question = "Как объяснить начальнику, что проект задерживается?"
    formatted_prompt = prompt.format(question=question)
    response = llm.invoke(formatted_prompt)

    print(response.content)
> 💡 Для создания эмбеддингов не нужна очень мощная модель и поэтому на продакшене часто используют локальные модели попроще, чтобы не тратить токены для создания векторных хранилищ. В примере есть оба варианта, можете использовать и **OpenAIEmbeddings()**, но рекомендуем обходиться моделями  с **HuggingFace** для такого рода задач. Саму модель рекомендуется заменить, `all-MiniLM-L6-v2` довольно простенькая дефолтная.
>
> 💡 В импортах данного кода используются модули, которые необходимо устанавливать дополнительно, а именно `pip install -U langchain-community langchain-huggingface sentence_transformers​​​​​​ chromadb`
>
> 💡 Позже, в модуле 3, мы будем более подробно рассматривать работу с эмбеддингами, так что если тут не до конца понятно, можете не переживать

В `SemanticSimilarityExampleSelector.from_examples()` мы указываем**:**

- `examples` — список заранее заданных примеров (вопрос–ответ).

- `embeddings` — модель эмбеддингов, которая превращает текст в числовые векторы.

- `Chroma` — векторное хранилище, куда помещаются эти векторы.

- `k` — число наиболее похожих примеров (по косинусному сходству).

При статической настройке всё зависит от разработчика и он руками должен подобрать хорошие примеры. При динамической же, примеров в хранилище может быть множество, а Selector выберет несколько наиболее подходящих под вопрос.

### 🔹Пример рассуждения при создании few-shot примеров

Задача: создать чат-ассистента для поддержки клиентов сервиса подписки на медиа-контент. Ассистент должен помогать с запросами по подписке, оплате, отмене, апгрейду, при этом быть вежливым, ясным и иногда мягко предлагать апселл.

1. #### Анализ задач и случаев
  - **Типичные запросы:** «Как продлить подписку?», «Почему меня списали дважды?»
  - **Сложные/редкие случаи:** клиенты недовольны, просят отменить подписку и вернуть деньги, спрашивают о политике скидок или новых тарифах
  - **Желаемое поведение:** корректно, информативно, вежливо, иногда с мягкой рекомендацией («может быть интересен новый тариф») без давления
2. #### Подбор примеров (few-shot)
  - **Пример 1 — типичный запрос:**  
*Вопрос:* `Как продлить подписку?`  
*Ответ:* `Вы можете продлить подписку через личный кабинет на сайте или в приложении. Если хотите, я могу отправить прямую ссылку для продления.`
  - **Пример 2 — запрос с проблемой оплаты:**  
*Вопрос:* `Списали дважды, что делать?`  
*Ответ:* `Сожалею за неудобство! Чтобы вернуть лишнее списание, пожалуйста: {refund_steps}`
  - **Пример 3 — редкий/сложный случай:**  
*Вопрос:* `Хочу отменить подписку и вернуть деньги`   
*Ответ*: `Понимаю вас. Отмена подписки доступна в личном кабинете, возврат средств возможен, если обращение в течение 14 дней с момента списания. Могу направить прямую ссылку для ускорения процесса`
  - **Пример 4 — запрос про апгрейд/новые тарифы**:  
Вопрос: `Есть ли тариф с дополнительными бонусами?`  
Ответ: `Да, у нас есть премиум-тариф с расширенными возможностями. Если хотите, могу кратко описать преимущества и предложить попробовать его на 7 дней бесплатно.`
3. #### Расположение примеров
  - Выстраиваем от простого к сложному, от типичного запроса к редкому.
  - Последний пример — наиболее важный для бизнеса (апсейл, предложение нового тарифа) — чтобы эффект недавности усилил вероятность правильного ответа в продакшн‑сценарии.
  - Все примеры единообразны: *Вопрос → Ответ → стиль/тон*.
4. #### Проверка и доработка
  - Тестируем на реальных запросах клиентов.
  - Меняем или убираем примеры, которые дают некорректный тон или не покрывают редкие ситуации.
  - Поддерживаем баланс: достаточно 3–4 точных примеров, чтобы модель не «залипала» на частых фразах, но видела разнообразие кейсов.


### 🔸Рекомендации

- Качество важнее количества: **2 точных примера лучше 5 поверхностных**.

- Каждый пример должен иллюстрировать **один принцип** — формат, стиль или поведение.

- Избегайте дублирования и спорного контента.

- Примеры должны быть **независимы** друг от друга — модель воспринимает их как отдельные случаи.

- Периодически тестируйте: меняйте или убирайте примеры и оценивайте изменение в ответах. Это поможет выявить самые «влиятельные» элементы.
