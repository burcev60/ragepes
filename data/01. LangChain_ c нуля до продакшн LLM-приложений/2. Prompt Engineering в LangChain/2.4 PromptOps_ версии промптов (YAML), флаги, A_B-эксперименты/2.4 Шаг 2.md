## 🔹 Версионирование промптов в YAML

Разберёмся как удобнее хранить тексты промптов во внешнем YAML-файле с указанием версий, а также программно загружать нужную версию в приложение. Иными словами, реализуем базовую систему управления версиями промптов с конфигурацией в YAML.

 

**YAML** – это удобный формат для хранения конфигураций, читаемый человеком. Мы можем описать наши промпты в YAML-структуре: ключ будет именем промпта, а значение – текст. Чтобы поддерживать версии, можно структурировать так, что у каждого промпта есть под-ключи как номера версий:

    prompts:
      support_answer:
        v1: |
          Ты – помощник техподдержки. Ответь пользователю лаконично...
        v2: |
          Ты – помощник техподдержки высокого уровня. Всегда обращайся по имени...

Здесь мы определили промпт с именем `support_answer` и две версии текста: `v1` и `v2`. Обратите внимание, YAML воспринимает числа в ключах как, собственно, числа, поэтому принято добавлять префикс `v` , чтобы не было недоразумений. Вы можете придумать свою схему версий, например`v1.0`, `v1.1`. Главное – согласованность.
> 💡 Использование конструкции `|` в YAML позволяет хранить многострочный текст с переносами (очень удобно для длинных промптов с правилами)

 

### 🔸**Загрузка в код**

Чтобы использовать такой YAML, понадобится его загрузить. В Python с этим поможет библиотека `pyyaml`.
> 💡 Эта библиотека ставится отдельно с помощью `pip install pyyaml`

    import yaml

    with open("prompts.yaml", "r", encoding="utf-8") as f:
        data = yaml.safe_load(f)
    prompt_text = data["prompts"]["support_answer"]["v2"]
    print(prompt_text)

Теперь `prompt_text` содержит строку с нашим промптом версии 2. Далее мы можем подставлять переменные либо через `PromptTemplate`, либо просто форматированием строки.

 

### 🔸**Выбор версии**

В реальном приложении нужно определить, какую версию использовать. Один из вариантов — хранить в YAML отдельное поле `current`:

    prompts:
      support_answer:
        current: v2
        versions:
          v1: ...текст...
          v2: ...текст...

Тогда в коде нужно будет доставать в переменную `current` и затем брать текст по её значению:

    import yaml

    with open("prompts.yaml", "r", encoding="utf-8") as f:
        data = yaml.safe_load(f)
    current = data["prompts"]["support_answer"]["current"]
    prompt_text = data["prompts"]["support_answer"]["versions"][current]

    print(prompt_text)

Это удобный способ переключать версию, просто поменяв `current` в файле конфигурации без изменений кода.

Однако можно поступать и иначе: хранить только версии, а выбор делать вне YAML (например, через переменную окружения или фичефлаг в коде, о чём поговорим на следующем шаге). Обе опции применимы. В обучающем проекте для простоты можно реализовать поле `current` в YAML, чтобы переключать одной строчкой.

Такой YAML-файл необходимо коммитить в **Git**. Изменения в нём легко отслеживать диффами. Вы можете потребовать, чтобы каждое изменение YAML проходило код-ревью, как изменение кода (поскольку это действительно изменение логики бота).

 

### 🔸Структурирование сложных промптов

Когда промпт состоит из нескольких частей, например `system` и `user`, YAML можно структурировать добавляя вложенности:

    prompts:
      my_chain:
        current: v1
        versions:
          v1:
            system: |
              Ты – эксперт...
            user: |
              Вопрос: {question}
              Доп. данные: {context}
          v2:
            system: ...
            user: ...

    import yaml

    with open("prompts.yaml", "r", encoding="utf-8") as f:
        data = yaml.safe_load(f)

    current = data["prompts"]["my_chain"]["current"]
    system_prompt = data["prompts"]["my_chain"]["versions"][current]["system"]
    user_prompt = data["prompts"]["my_chain"]["versions"][current]["user"]

 

### 🔸Интеграция в шаблон LangChain

Такой подход очень просто сочетается с LangChain, всё что нам для этого надо, мы уже проходили. Повторим на примере и заодно рассмотрим ещё один вариант структуры YAML фаила, мы можем переключать не версии, а режимы:

    prompts:
      my_chain:
        modes:
          EN-RU:
            system: |
              Ты — опытный переводчик. Просто переведи текст без лишних комментариев.
            user: |
              Переведи текст с Английский на Русский:
              \"{input_text}\"
          RU-EN:
            system: |
              You are an experienced translator. Answer without any comments.
            user: |
              Translate the text from Russian to English:
              \"{input_text}\"

    import os
    from dotenv import load_dotenv
    import yaml
    from langchain_core.prompts import (
        ChatPromptTemplate,
        SystemMessagePromptTemplate,
        HumanMessagePromptTemplate
    )
    from langchain_openai import ChatOpenAI

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")

    with open("prompts.yaml", "r", encoding="utf-8") as f:
        data = yaml.safe_load(f)

    chat_model = ChatOpenAI(
                model_name=MODEL,
                temperature=0,
                request_timeout=15
            )

    mode = 'EN-RU'
    system_prompt = data["prompts"]["my_chain"]["modes"][mode]["system"]
    user_prompt = data["prompts"]["my_chain"]["modes"][mode]["user"]

    chat_template = ChatPromptTemplate.from_messages([
        SystemMessagePromptTemplate.from_template(system_prompt),
        HumanMessagePromptTemplate.from_template(user_prompt)
    ])

    chain = chat_template | chat_model

    result = chain.invoke('Hello World!')
    print(result.content)

Тут мы создаём чат бота переводчика и с помощью переменной `mode` можем удобно управлять языками перевода. Можно как угодно настраивать под себя структуру YAML файла, подойдя к этому вопросу творчески и исходя из поставленных задач.

 

### 🔸**Преимущества YAML-подхода**

- **Доступность вне кода**  
Разработчики и нетехнические специалисты могут править промпты, не лезя в кодовую базу. Например, лингвист или продакт-менеджер может предложить правку текста промпта и сразу внести её в YAML (в рамках своего доступа).

- **Проще экспериментировать**  
​Хранится параллельно несколько вариантов и оперативно переключаются через `current`. Приложение при старте читает YAML и перезапуск с другим `current`, меняет логику без перекомпиляции/деплоя кода (по сути, конфигурационное переключение).

- **Расширение**  
Можно расширять схему YAML, добавляя туда, например, описание промпта, changelog, автора правки, дату – всё, что полезно. YAML гибок и допускает произвольные поля.

### 🔸**Рекомендации**

- Начните версионировать с самого начала, даже если промптов немного. Привычка фиксировать изменения в тексте избавит от ситуации "вроде вчера было лучше, а что я там поменял?".
- Старайтесь давать версиям осмысленные номера: увеличение номера только когда есть значимая правка. Если правка микроскопическая – можно менять версию в других порядках, например v1.0.1
- Подумайте о наименовании: имя промпта в YAML должно отражать его назначение (например, `email_summary` или `faq_answer`).
- Если приложение небольшое, можно всё сложить в один файл `prompts.yaml`. Если много разных модулей – можно разбить по файлам (например, `prompts_chatbot.yaml`, `prompts_analysis.yaml` и т.п.)
- Старайтесь не хардкодить названия версий в коде (типичная ошибка: `if flag: version="v2" else: "v1"` – лучше хранить эти строки в YAML или env). Тогда при переходе к v3, не придётся менять код, только конфиг.
