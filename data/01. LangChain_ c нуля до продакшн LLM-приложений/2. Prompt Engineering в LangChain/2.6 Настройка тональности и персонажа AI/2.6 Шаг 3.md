## 🔹 Проверка соответствия стилю

На этом шаге мы научимся оценивать, насколько ответы модели соответствуют заданной тональности и персоне, и разберёмся, как корректировать модель, если стиль нарушается.

После того как мы задали голос бренда и персону, важно убедиться, что каждый ответ действительно соответствует этим настройкам. В небольших диалогах это легко проверять вручную, но в масштабируемых системах или при автоматической генерации большого количества ответов нужна автоматизация. **Проверка стиля** — это фактически оценка ответа по ряду критериев.

Основные подходы:

1. **Правила и шаблоны (статический анализ):** Применяем заранее определённые критерии, своего рода **lint для текста**. Например: *`Ответ не должен содержать словосочетание "наша компания"`* или `Должен использоваться термин X хотя бы раз`. Эти проверки можно реализовать через регулярные выражения или функции, которые анализируют текст.

2. **LLM-оценка (self-check):** Традиционные метрики (например, точность совпадения с образцом) плохо подходят для оценки стилистических качеств или тона ответа, поскольку стиль – вещь субъективная. Люди способны оценивать нюансы тона, формальности, дружелюбности, но привлечение человека к проверке каждого ответа не масштабируется. Поэтому мы можем использовать саму модель или отдельную модель для анализа ответа. Например, после генерации можно сделать запрос: *`Проанализируй ответ: соответствует ли он требованиям стиля X? Если нет, перечисли несоответствия.`*   
Модель второго уровня выдаёт вердикт. Такой подход подходит для автоматического контроля качества — мощные модели GPT-4o и GPT-5 способны точно выявлять отклонения стиля.

Чаще всего применяют оба подхода вместе: LLM-оценка проверяет тон и эмоциональный окрас, а статические правила — конкретные формальные ограничения. Например, если бренд-гайд запрещает обращаться на «ты», делаем проверку: если найдено «ты» вне цитат — это нарушение стиля.

 

### 🔸 Реализация в LangChain **с помощью условия:**

В LangChain можно строить цепочки, где после генерации ответа выполняется дополнительный шаг проверки. Например, через лямбду **`RunnableLambda()`**проверяющую критерии. Если найдены нарушения, система может либо **логировать** их, либо перегенерировать ответ с учётом замечаний. Статические проверки реализуются как функции, обрабатывающие текст.

    import os
    from dotenv import load_dotenv
    import re
    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import ChatPromptTemplate
    from langchain_core.output_parsers import StrOutputParser
    from langchain_core.runnables import RunnableLambda

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")

    llm = ChatOpenAI(model_name=MODEL, temperature=0.9)

    def check_style(text: str) -> str:
        """Проверяет наличие слова 'ты' в ответе"""
        if re.search(r'\bты\b|\bтебя\b|\bтвой\b|\bтвоя\b|\bтвоё\b', text, re.IGNORECASE):
            print(f"⚠️ НАРУШЕНИЕ СТИЛЯ: обнаружено обращение на 'ты' в ответе: {text[:100]}...")
        return text

    # Тест 1: правильный стиль
    print("Тест 1: правильный стиль")
    prompt = ChatPromptTemplate.from_messages([
        ("system", "Ты помощник компании. Обращайся к клиенту на 'Вы'. Отвечай кратко, не более 100 символов."),
        ("human", "{question}")
    ])

    chain = prompt | llm | StrOutputParser() | RunnableLambda(check_style)  # ← Проверка стиля
    result = chain.invoke({"question": "Здравствуйте, я не могу разобраться с оплатой, куда нажимать?"})
    print(f"Ответ: {result}\n")

    # Тест 2: неправильный стиль (специально провоцируем)
    print("\nТест 2: провоцируем нарушение")
    bad_prompt = ChatPromptTemplate.from_messages([
        ("system", "Общайся неформально, на 'ты'. Отвечай кратко, не более 100 символов."),
        ("human", "{question}")
    ])

    bad_chain = bad_prompt | llm | StrOutputParser() | RunnableLambda(check_style)
    result = bad_chain.invoke({"question": "Здравствуйте, я не могу разобраться с оплатой, куда нажимать?"})
    print(f"Ответ: {result}")
> 💡`RunnableLambda` выполняется после парсера, т.е. уже над строковым результатом.

В реальности важно избегать ложных срабатываний. Например, слово «ты» может встречаться внутри других слов, таких как `бутыль`. Это легко исправить с помощью регулярного выражения `\bты\b`.

Другие варианты алгоритмов проверки:

- **Преобразование регистра и символов:** для более простой проверки можно приводить текст к одному регистру, удалять знаки препинания временно, чтобы не пропустить вариант написания.

- **Парсинг структуры:** если формат строго структурирован (скажем, JSON или список), можно попытаться распарсить и проверить наличие/отсутствие полей.

- **Подсчёт количества предложений/слов:** можно разбить текст по точкам или пробелам и проверить длину (например, не более 3 предложений, или не менее 50 слов).

- **Словари стоп-слов или нежелательных слов:** составить список фраз, которые не должны встречаться (например, жаргон, неформальные обращения вроде "чувак", эмодзи и т.п.) и проверить вхождение.

- **Ограничение максимального числа восклицательных знаков подряд**

- **Правописание**: можно подключить библиотеку проверки орфографии/грамматики (например, LanguageTool), но это уже динамически, хотя её можно считать частью статических проверок.

 

### 🔸 Реализация в LangChain **проверки с помощью LLM:**

Предположим, у нас есть ответ модели **`answer_text`** и мы хотим проверить, соответствует ли он формальному деловому стилю и не содержит ли личных местоимений от первого лица. Мы формируем системное сообщение с инструкциями для оценщика, а в пользовательское сообщение поместим проверяемый ответ. Модель вернёт оценку и комментарии:

    import os
    from dotenv import load_dotenv
    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import ChatPromptTemplate, HumanMessagePromptTemplate, SystemMessagePromptTemplate

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")
    llm = ChatOpenAI(model_name=MODEL, temperature=0.3,)

    system_message = "Ты – помощник, оценивающий стиль ответа по заданным правилам. \
    Критерии: (1) тон ответа – деловой, вежливый; (2) речь от третьего лица, \
    избегать местоимения 'я'; (3) нет жаргона, только профессиональные термины. \
    Ответь в формате JSON с полями: formality_score (0-10), no_first_person (True/False), comment."

    user_message = "Оцени стиль следующего ответа:\n\"\"\"\n{answer_text}\n\"\"\""

    prompt = ChatPromptTemplate.from_messages([
        SystemMessagePromptTemplate.from_template(system_message),
        HumanMessagePromptTemplate.from_template(user_message)
    ])

    chain = prompt | llm

    response = chain.invoke({"answer_text": 'Проделана работа по улучшению бизнес метрик, клиенты остались довольны'})
    print(response.content)

    # Вывод:
    '''
    {
      "formality_score": 7,
      "no_first_person": true,
      "comment": "Ответ выдержан в деловом стиле, без использования местоимения «я» и жаргона. Тон достаточно формальный, однако фраза может быть чуть более развернутой для усиления профессионального звучания."
    }
    '''

В этом примере мы просим вернуть JSON с оценкой формальности по десятибалльной шкале, флагом нарушения правила про первое лицо и кратким комментарием. Модель читает `answer_text` и генерирует оценку. В выводе (показан пример) видно, что модель присвоила довольно высокий формальный стиль (7 из 10), и флаг `no_first_person: true` (т.е. она не обнаружила местоимение первого лица), но добавила комментарий, что `фраза может быть чуть более развернутой для усиления профессионального звучания.`

 

### 🔸 Актуальные методы проверки стиля (2025)

1. **Classifier-Free Guidance, но для стиля**

  Отдельная небольшая модель оценивает характеристики текста (формальность, дружелюбность, эмоциональность) и даёт **числовые оценки**:

    style_score = style_classifier(text)
    # → {"formality": 0.85, "friendliness": 0.6, "professionalism": 0.9}

  Основная модель корректирует генерацию на основе этих сигналов. Плюс: быстро и дёшево (маленькая модель), можно обучить под свой бренд.

2. **GPT-4o / GPT-5 как Style Evaluator**

  Самый популярный подход — используем мощную модель для оценки:

    evaluation_prompt = """
    Оцени текст по шкале 1-10:
    - Формальность
    - Дружелюбность  
    - Соответствие корпоративному стилю

        Текст: {generated_text}
    """

  **Преимущества**: высокая точность, не нужно обучать отдельную модель.  
**Минус**: дороже, медленнее.

3. **Style Moderation API**

  По аналогии с OpenAI Moderation (проверка токсичности)

    from openai import OpenAI
    client = OpenAI()

        response = client.moderations.create(
        model="omni-moderation-latest",
        input="Твой текст здесь")

        print(response) # → {"flagged": true, "categories": {"hate": true, "violence": false}}

  
Можно создать свой endpoint для проверки стиля:

    # Псевдокод
    response = requests.post("api/style-moderation", {
        "text": generated_text,
        "rules": ["no_informal_you", "corporate_tone"]
    })

        # → {"violations": ["informal_tone_detected"], "score": 0.72}

        Генерация → Проверка → [FAIL] → Генерация с подсказкой"избегай 'ты'"

  Крупные компании (финтех, банки) внедряют такие системы для контроля всех публичных коммуникаций.  
Prompt Chaining с обратной связью — если проверка провалена, то автоматически перегенерируем с учётом замечаний.

**Тренд 2025**: комбинация быстрой статической проверки (regex) + LLM-оценки для сложных случаев + автоматическая коррекция при нарушениях. Всё чаще используют **GPT-4o** как универсальный style judge вместо обучения отдельных моделей.

 

### 🔸 Рекомендации

- **Определите чёткие критерии стиля:** размытые требования сложно проверять автоматически. Например, `быть позитивным` это субъективно, модель и пользователь могут трактовать по-разному.
- **Используйте измеримые показатели:** наличие определённых слов, длина ответа, формат разметки (например, всегда должен быть заголовок).
- **Ограничение субъективности:** попросите модель давать количественную оценку (например, шкала 1–5) или бинарное соответствие по каждому критерию, чтобы упростить автоматическую интерпретацию
- Эмоциональную окраску **проверяйте через LLM-оценку.**
- **Валидация:** периодически проверяйте несколько оценок моделью вручную или с коллегой, чтобы убедиться, что LLM не «съехала» и понимает критерии правильно. Помните, что LLM может быть предвзята или ошибаться, поэтому критически оценивайте её вердикты.
- **Применяйте проверку выборочно**, чтобы контролировать стоимость (например, 10% ответов или только для новичков).
- **Сводите результаты проверки в отчёт** и анализируйте, чтобы корректировать инструкции модели.
- Если видите систематическое отклонение (например, модель часто забывает подписывать ответы нужным образом) — лучше обновить промпт или few-shot примеры, чем редактировать каждый ответ вручную.
