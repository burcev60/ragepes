## 🔹 Параметры и плейсхолдеры

Сейчас мы разберёмся, как вводить динамические параметры в промпты с помощью плейсхолдеров, чтобы один шаблон мог обслуживать разные входные данные. Мы также посмотрим на форматирование шаблонов (в том числе через Jinja2) и безопасную подстановку.

**Объяснение:** Параметризация промпта означает выделение в тексте шаблона мест, куда будут вставляться разные значения при каждом вызове. В примерах ранее мы использовали `{input_text}` – это и есть плейсхолдер (placeholder) для входного текста.

Главная идея: не писать 10 похожих промптов для 10 случаев, а написать один с параметрами. Например, вы делаете бота-переводчика и хотите менять язык перевода в зависимости от пользователя. Вместо копипасты «Переведи на русский/английский/китайский», пишете шаблон *"Переведи текст с {source_lang} на {target_lang}"* и подставляете нужные языки при вызове.

LangChain `PromptTemplate` по умолчанию использует формат f‑строк Python для плейсхолдеров (фигурные скобки {}). Также поддерживается шаблонизацию через Jinja2, что даёт больше возможностей (условия, циклы внутри шаблона и т.д.). Чтобы использовать Jinja2, достаточно при создании PromptTemplate указать параметр `template_format="jinja2"`. Тогда внутри строки можно применять синтаксис Jinja2. Например:

    from langchain_core.prompts import PromptTemplate

    template_str = "Привет, {% if formal %}уважаемый{% else %}дорогой{% endif %} {{ name }}!"
    prompt = PromptTemplate(
        template=template_str,
        input_variables=["name", "formal"],
        template_format="jinja2"
    )

    print(prompt.format_prompt(name="Иван", formal=True).to_string())
    # Вывод: "Привет, уважаемый Иван!"

Здесь мы показали, что условная логика в шаблоне позволяет варьировать обращение (формально/неформально) в зависимости от переменной `formal`. Jinja2 имеет смысл, когда шаблон очень сложный и содержит повторяющиеся части, циклы или условия. Но в большинстве случаев стандартных f‑строк достаточно – они безопаснее и проще.
> ⚠️ **будьте осторожны**: не подставляйте в Jinja‑шаблон данные из непроверенных источников, так как теоретически это может привести к исполнению нежелательных выражений

 

## 🔸 `prompt.partial()`

`PromptTemplate` так же позволяет задавать частичное заполнение переменных (**partial**) — значения, которые вы фиксируете заранее.  
Например, если в большинстве промптов повторяется одна и та же инструкция, её можно вынести в переменную и один раз подставить, чтобы не дублировать текст.  
Или, скажем, вы хотите заранее заполнить часть шаблона и получить новый шаблон:

    from langchain_core.prompts import PromptTemplate

    # Создаём шаблон с двумя переменными
    template = "Привет, {name}! {instruction}"

    prompt = PromptTemplate(
        template=template,
        input_variables=["name", "instruction"]
    )

    # Частично фиксируем одну из переменных
    partial_prompt = prompt.partial(instruction="Пожалуйста, расскажи о себе.")

    # Теперь у нового шаблона осталась только одна незаполненная переменная
    print(partial_prompt.input_variables)  # ['name']

    # Подставляем оставшееся значение
    result = partial_prompt.format(name="Иван")
    print(result) # Привет, Иван! Пожалуйста, расскажи о себе.
> 💡 Частичные переменные удобно использовать для общих инструкций, которые меняются редко.

### 🔸 Технические детали

При параметризации промпта важно учитывать экранирование и использование специальных символов.  
Если параметр может содержать кавычки, переводы строк или фигурные скобки, это способно нарушить шаблон или затруднить его чтение.

**Решение** — оборачивать пользовательские данные в кавычки либо использовать специальные маркеры внутри промпта.

Например, в шаблонах перевода текст заключают в кавычки — `"{input_text}"`. Это помогает визуально и синтаксически отделить его от остальной инструкции.  
Если вы вставляете в шаблон фрагмент кода или JSON, используйте блок с тройными кавычками или текстовые метки вроде `Начало данных` / `Конец данных`. Такие приёмы защищают шаблон от ситуаций, когда пользовательский ввод содержит проблемные последовательности вроде `"}{`, нарушающие формат.
> ⚠️ Всегда экранируйте специальные символы в переменных, чтобы избежать ошибок при рендеринге шаблона.

### 🔸 Пример с цепочками

Покажем, как использовать параметризацию в связке с `RunnableSequence`. Предположим, у нас есть шаблон промпта для приветствия пользователя по имени и должности:

    import os
    from dotenv import load_dotenv
    load_dotenv()

    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import PromptTemplate
    from langchain_core.runnables import RunnableSequence

    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")

    template = "Отвечай как ассистент: Привет, {name}! Рад тебя видеть. Я могу помочь с вопросами по {topic}."
    prompt = PromptTemplate(
        template=template,
        input_variables=["name", "topic"]
    )

    chain = RunnableSequence(prompt, ChatOpenAI(model=MODEL))

    result = chain.invoke({"name": "Анна", "topic": "программированию"})
    print(result)

Здесь мы создали цепочку, передав наш шаблон. Метод **`chain.invoke()`** принимает именованные аргументы для всех переменных шаблона. Он подставит `name="Анна"`, `topic="программированию"` в шаблон, отправит финальный промпт модели и вернёт результат. Таким образом, разделив шаблон и данные, мы легко можем подставлять разные `name` и `topic` без переписывания самого промпта.

### 🔸 Рекомендации

- Когда планируете структуру плейсхолдеров, выбирайте понятные названия переменных – это облегчает сопровождение. Например, `{input}` – слишком общее название, лучше уточнить `{user_question}` или `{text_to_translate}`.
- Следите за тем, чтобы все необходимые переменные передавались в шаблон: LangChain при включённой валидации (`validate_template=True`) предупредит, если какая‑то переменная не используется или лишняя – это можно включить при отладке.
- Если используете Jinja2‑шаблоны, делайте их содержимое как можно проще и тестируйте отдельно, чтобы убедиться, что логика внутри работает.
- И наконец, **не стоит прописывать чувствительные данные в шаблонах** – API‑ключи, персональные сведения или длинные тексты лучше передавать как параметры или загружать из внешних источников, чем вписывать в строку. Это и безопаснее, и гибче для обновлений.
