## 🔹 Чейнинг промптов (многошаговость)

В предыдущем уроке, обсуждая антипаттерны, мы упоминали рекомендацию — разбивать сложные задачи на этапы. Теперь разберём, как реализовать это на практике: как объединить несколько вызовов модели в единую последовательность, где результат одного шага становится входом для следующего.

Такой подход позволяет модели рассуждать поэтапно и комбинировать различные функции. Этот принцип называется **чейнингом** (от англ. *chain* — «цепь») — техникой, при которой задача делится на несколько шагов, и каждый шаг выполняется моделью с собственным промптом.

### 🔸 Когда это нужно?

- Разбить сложный вопрос на подзадачи: сначала определить подзадания, затем ответить по каждому.
- Пост‑обработка ответа: создать черновик, потом попросить модель отредактировать его.
- Комбинировать роли: один промпт генерирует идеи, второй оценивает их или выбирает лучшие.
- Часто применяют схему «размышление → ответ»: сначала просят модель обосновать решение, а затем сформулировать финальный ответ.


### 🔸 Простая реализация в LangChain

Самый простой способ – использовать **LCEL**, который автоматически передаёт вывод одного шаблона на вход следующему.

    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import PromptTemplate
    from langchain_core.runnables import RunnablePassthrough
    from langchain_core.output_parsers import StrOutputParser

    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")

    llm = ChatOpenAI(model=MODEL)

    prompt1 = PromptTemplate.from_template("Назови 5 популярных достопримечательностей в городе {city}.")
    prompt2 = PromptTemplate.from_template("Составь маршрут на 3 дня по городу {city}, включив следующие места: {places_list}.")

    chain = (
        {"city": RunnablePassthrough()}
        | RunnablePassthrough.assign(
            places_list=lambda x: (prompt1 | llm | StrOutputParser()).invoke(x)
        )
        | prompt2
        | llm
        | StrOutputParser()
    )

    # Запуск
    result = chain.invoke({"city": "Париж"})
    print(result)

**Краткое объяснение цепочки:**

1. `{"city": RunnablePassthrough()}` — создает словарь с ключом city, передавая входное значение без изменений. Это инициализация контекста. **`RunnablePassthrough()`** просто **передает входные данные дальше** без изменений
2.  `RunnablePassthrough.assign(places_list=...)` — ключевой момент! Берет словарь из шага 1, выполняет вложенную цепочку (**prompt1** → **llm** → **парсинг**), и добавляет результат как новый ключ `places_list`. Исходный ключ city при этом сохраняется. На выходе получаем словарь с двумя ключами: `city` и `places_list`.
3.  `prompt2` — форматирует второй промпт, подставляя оба значения из словаря (city и places_list). Возвращает готовую строку-запрос.
4.  `llm` — отправляет отформатированный промпт в модель и получает ответ в виде `AIMessage`.
5.  `StrOutputParser()` — извлекает чистый текст из AIMessage и возвращает финальную строку с маршрутом.


**Суть:** Первая подцепочка генерирует список мест и добавляет его к контексту через `assign()`, затем вторая подцепочка использует и город, и список для создания итогового маршрута.

### 🔸 Практические соображения

Многошаговость означает несколько API‑вызовов, что увеличивает время ответа и стоимость. Поэтому цепочки стоит использовать только тогда, когда один запрос не справляется с задачей.

Чейнинг промптов позволяет строить более гибкие и «умные» сценарии работы с LLM. Главное – держать количество шагов минимальным, следить за смысловой связью между ними и тестировать цепочку на разных входных данных.
> 💡 Не забывайте логировать промежуточные результаты – это поможет отследить, где цепочка может сбиться.
