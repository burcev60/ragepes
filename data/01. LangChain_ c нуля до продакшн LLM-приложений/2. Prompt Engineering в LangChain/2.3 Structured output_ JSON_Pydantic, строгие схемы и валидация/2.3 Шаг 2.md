## 🔹 Output Parsers

Сейчас мы познакомимся с инструментами LangChain для обработки **структурированных ответов** — output parser-ами. Вы научитесь использовать встроенные парсеры (например, для **JSON**) и формулировать инструкцию в промпте, чтобы повысить надёжность получения нужного формата. В предыдущем модуле, при кратком описании языка **LCEL**, мы уже упоминали один из подклассов parser-ов — класс, преобразующий объекта `AIMessage` в строку. Однако процесс может идти и в обратную сторону: модель выдаёт строку, а мы преобразуем её в объект и далее обрабатываем.

### 🔸 Что такое Output Parser?

**Output Parser** — это компонент LangChain, отвечающий за преобразование **вывода модели** (обычно объекта `AIMessage` или `LLMResult`) в нужный формат: строку, словарь, JSON, Pydantic-модель и т.д.

Его задача — стандартизировать и упростить работу с результатами моделей.  
В зависимости от конкретного парсера направление преобразования может быть разным:

- **`StrOutputParser`** извлекает текстовое содержимое (`content`) из `AIMessage` и возвращает обычную строку.

- `CommaSeparatedListOutputParser`, **`JsonOutputParser`**, `ListOutputParser`, **`PydanticOutputParser`**, **`XMLOutputParser`** и другие — наоборот, извлекают некую структуру из строки ответа модели и преобразуют её в объект (словарь, JSON, Pydantic-модель и т.д.)

Таким образом, **Output Parser** служит связующим звеном между моделью и последующими этапами обработки данных, обеспечивая единый интерфейс для работы как с текстом, так и со структурированной информацией.

### 🔸 Преобразование ответа в JSON

Разберём на примере JSON, как можно работать с парсерами. Если нужен простой JSON-объект без строгой схемы, можно конечно просто в промпте вручную сформулировать это как запрос:

    Ответь строго в формате JSON. Пример: { "result": ..., "details": [...] }

Но в LangChain есть для этого более гибкие инструменты, как например `JsonOutputParser` и другие парсеры для стандартных случаев. Вот базовый пример как они работают:

    import os
    from dotenv import load_dotenv
    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import PromptTemplate
    from langchain_core.output_parsers.json import JsonOutputParser

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")

    llm = ChatOpenAI(model=MODEL)

    parser = JsonOutputParser()
    format_instructions = parser.get_format_instructions()

    prompt = PromptTemplate(
        template="Пожалуйста, верни данные в формате JSON.\n{format_instructions}\n{question}",
        input_variables=["question"],
        partial_variables={"format_instructions": format_instructions}
    )

    chain = prompt | llm | parser

    result = chain.invoke({"question": "Что такое LangChain?"})
    print(result)  # вывод: {'question': 'Что такое LangChain?', 'answer': 'LangChain — это ...'}

 

### 🔸 Обработка ошибок

Парсинг может дать сбой — например, модель возвращает:

    {"name": "Иван", "age": "двадцать"}

`json.loads` пройдёт, но тип данных неверен. Хотя `JsonOutputParser` проверяет ключи и их наличие, типы могут не соответствовать строгим требованиям. Риск таких ошибок необходимо иметь ввиду и осуществлять проверки типа данных и проходится другими условными операторами в зависимости от типа данных и специфики вашей задачи.
> 💡 Для более строгой проверки можно использовать **Pydantic** через `PydanticOutputParser`, (подробнее об этом на следующем шаге).

### 🔸 JSON-mode

Раз уж как пример работы парсеров мы взяли именно JSON, то стоит отметить что современные версии OpenAI API (и, соответственно, LangChain) позволяют включить нативный режим возврата данных строго в формате JSON.  
Для этого при создании модели достаточно «привязать» параметр `response_format={"type": "json_object"}`:

    import os
    from dotenv import load_dotenv
    from langchain_openai import ChatOpenAI

    load_dotenv()

    json_llm = ChatOpenAI(model="gpt-5").bind(response_format={"type": "json_object"})

    responce = json_llm.invoke("верни JSON объект с ключом 'random_ints' и значением из 10 случайных чисел в диапазоне [0-99]")

    print(responce.content) # вывод: '\n{\n  "random_ints": [23, 87, 45, 12, 78, 34, 56, 90, 11, 67]\n}'

Метод **`.bind()`** передаёт модели параметр `response_format` напрямую в API-вызов. Модель должна вернуть **валидный JSON-объект**, а не просто текст, имитирующий JSON. В отличие от подхода с парсером, здесь не требуется дополнительный парсер — результат уже гарантированно корректен.

Этот способ полезен, если  требуется 100 % структурированный и валидный результат без пост-обработки
> ⚠️ Работает не всегда, необходима модель семейства GPT-4/5 с поддержкой JSON-режима. Если вы работаете с другими провайдерами или моделями, не поддерживающими `response_format`, используйте **OutputParser** он универсален и не зависит от конкретного API

 

### 🔸 Рекомендации по работе с OutputParsers

- Используйте парсеры, когда задача требует фиксированной структуры данных и интеграции с цепочками.

- Всегда ловите исключения парсера (`try/except`), если работаете вне цепочки (`RunnableSequence`).

- Если доступен режим JSON-mode, лучше его использовать — он повышает надёжность.

- В промпте добавляйте уточнение вроде: «Никаких комментариев — только валидный JSON».

- Имейте план на случай ошибки формата: логируйте её, попробуйте исправить или перепросите модель с более жёсткой инструкцией.

- При правильной настройке доля удачных JSON-ответов у современных моделей может быть очень высокой, но всегда готовьте обработку редких ошибок.

- Если вам нужен вывод в определённом формате, имейте ввиду что langchain имеет обширный арсенал парсеров от XML до Markdawn. Описывать их все в рамках курса не имеет смысла, но вы всегда можете найти детальную и актуальную информацию в [документации](https://api.python.langchain.com/en/latest/core/output_parsers.html)
