## 🔹 Pydantic-схемы и валидация

На этом этапе мы научимся описывать ожидаемый формат ответа с помощью **Pydantic-моделей**, использовать их для автоматической проверки и преобразования вывода модели, а также разберём два способа строгой структуризации:  
через `PydanticOutputParser` и через метод `with_structured_output()` у `ChatOpenAI`.

### 🔸 Что такое Pydantic?

**Pydantic** — библиотека Python, которая позволяет определять структуру данных через классы, описывать типы и ограничения полей, и автоматически проверять входящие данные на соответствие этой схеме.  
В контексте LangChain Pydantic используется для строгого контроля структуры вывода LLM.

### 🔸 PydanticOutputParser

LangChain предоставляет `PydanticOutputParser`, который объединяет мощь **Pydantic** и удобство генерации форматирующих инструкций для модели. Этот парсер:

1. генерирует инструкцию `format_instructions` на основе модели,

2. после получения ответа парсит его:  
→ JSON-строка → `dict` → `YourModel(**dict)`  
(при ошибке — выбрасывает `OutputParserException`)

    import os
    from dotenv import load_dotenv
    from langchain_openai import ChatOpenAI
    from langchain_core.prompts import PromptTemplate
    from langchain_core.output_parsers import PydanticOutputParser
    from pydantic import BaseModel, Field

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")

    llm = ChatOpenAI(model=MODEL)

    # Определяем схему данных
    class BookInfo(BaseModel):
        title: str = Field(..., description="Название книги")
        author: str = Field(..., description="Имя автора")
        tags: list[str] = Field(..., description="Список тегов или жанров")

    # Создаём парсер
    output_parser = PydanticOutputParser(pydantic_object=BookInfo)
    format_instructions = output_parser.get_format_instructions()

    # Шаблон промпта
    prompt = PromptTemplate(
        template=(
            "Ответь на вопрос в требуемом формате.\n"
            "{format_instructions}\n"
            "Вопрос: {user_question}\nОтвет:"
        ),
        input_variables=["user_question"],
        partial_variables={"format_instructions": format_instructions},
    )

    # цепочка
    chain = prompt | llm | output_parser

    # Запуск
    result = chain.invoke({"user_question": "Расскажи о книге '1984' Джорджа Оруэлла."})
    print(type(result)) # <class '__main__.BookInfo'>
    print(result) # title='1984', author='Джордж Оруэлл', tags=['антиутопия', 'классика']


### 🔸 Валидация и типизация

Модель `BookInfo` проверяет типы и структуру данных. Если LLM выдаёт `"tags": "антиутопия"`, Pydantic пытается сконвертировать строку в список.  
Если это невозможно — выбрасывается `ValidationError`, который LangChain перехватывает как `OutputParserException`.

Можно задавать строгие правила, например мы хотим добавить некий пункт со строгими рамками. Пускай это будет рейтинг книги по 10-ти бальной шкале и мы хотим быть точно уверены что тип данных будет `int` и лежать в диапазоне от 0 до 10:

    from pydantic import BaseModel, conint

    class BookInfo(BaseModel):
        rating: conint(ge=0, le=10) = Field(description="Оценка книги по десятибалльной шкале")

Если модель реётинг `rating=11`, произойдёт ошибка — это удобно для отлова “галлюцинаций”.

### 🔸 Метод .with_structured_output()

Современные версии LangChain позволяют не использовать `PydanticOutputParser` явно — вместо этого можно создать “структурированную” LLM, которая **сама возвращает Pydantic-объект**:

    import os
    from dotenv import load_dotenv
    from langchain_openai import ChatOpenAI
    from pydantic import BaseModel, Field

    load_dotenv()
    MODEL = os.getenv("OPENAI_API_MODEL", "gpt-5")

    llm = ChatOpenAI(model=MODEL)

    class Profile(BaseModel):
        name: str = Field(description="Имя пользователя")
        age: int = Field(description="Возраст в годах")
        premium: bool = Field(description="Есть премиум-подписка")

    structured_llm = llm.with_structured_output(Profile)

    result = structured_llm.invoke("Создай профиль русского пользователя средних лет")
    print(type(result))   # <class '__main__.Profile'>
    print(result.name)    # Алексей Петрович
    print(result.age)     # 37
    print(result.premium) # False

Ответ модели будет в формате:

    {
      "name": "Алексей Петрович",
      "age": 37,
      "premium": false
    }

LangChain автоматически **преобразует этот JSON в экземпляр Pydantic-модели** `Profile`

То есть метод **`with_structured_output(BaseModel)`** позволяет создать новый вариант модели, который автоматически формирует схему и передаёт её в модель через API. Результат десериализуется прямо в объект `Profile`

**Чем это полезно:**

- **Упрощает логику**: не нужно использовать парсер, модель уже возвращает структурированный ответ.

- **Повышает надёжность**: если схема задана, можно ожидать, что поля присутствуют и типы соответствуют.

- **Хорошо интегрируется с цепочками в LangChain**: можно сразу передать результат дальше как объект, а не текст.
> ⚠️ Метод работает только если модель и API поддерживают режим, когда модель может гарантировать ответ в требуемой структуре. Если LLM не поддерживает эти возможности, метод вернёт текст вместо объекта
>
> ⚠️ Это не заменяет полностью ручное парсирование для сценариев, где нужна специализированная логика преобразования или проверки

 

### 🔸 Рекомендации

- Пишите чёткие описания полей — они попадают в инструкцию модели.

- Современные модели GPT-4o и GPT-5 поддерживают метод **`.with_structured_output()`**, что упрощает код

- Тестируйте схему заранее — неверный тип в одном поле может испортить весь JSON.
