**Настройка индекса HNSW и параметры поиска.**

В основе Qdrant лежит индекс **HNSW** – графовый алгоритм для быстрого поиска ближайших соседей. Qdrant позволяет тонко настроить параметры HNSW для баланса между точностью и скоростью. Главные параметры – это **M** (число связей у каждого узла графа) и **ef** (глубина поиска). Увеличение M делает поиск точнее, но требует больше памяти, а увеличение ef улучшает качество поиска ценой более долгого времени работы индекса. Эти параметры можно задавать при создании коллекции через `hnsw_config` – как глобально, так и отдельно для каждого именованного вектора.

Кроме параметров индекса, Qdrant даёт управлять режимом поиска в запросах. В методе поиска (`search` или `query`) можно указать объект `search_params` с полями: **`hnsw_ef`** – значение параметра ef для данного поиска, и **`exact`** – режим точного поиска. Если `exact=true`, Qdrant выполнит полный перебор по всем векторам без приближений (это гарантирует идеальный результат, но очень медленно на больших массивах). Обычно `exact` оставляют `false` (по умолчанию) – тогда используется ANN-поиск через HNSW. Настройка `hnsw_ef` позволяет повысить точность запроса: например, для более тщательного поиска можно временно увеличить ef до 100–200 на один конкретный запрос, если нужна максимальная полнота результатов. Значение ef по умолчанию равно `ef_construct` заданному при индексации (обычно 100). Таким образом, **`hnsw_ef`** управляет глубиной обхода графа при поиске: выше – точнее, ниже – быстрее. Рассмотрим пример: `results = client.search(collection_name="mycol", query_vector=vec, limit=5, search_params=models.SearchParams(hnsw_ef=128))`. Здесь мы запрашиваем 5 ближайших результатов с более глубоким обходом графа (128 вместо значения по умолчанию). Параметр `hnsw_ef=128` может повысить вероятность нахождения истинно ближайших соседей ценой небольшого увеличения времени запроса.
