**Мультивекторные коллекции.**

В стандартном режиме у каждого объекта (точки) в коллекции Qdrant один вектор. Однако Qdrant поддерживает **мультивекторные записи** – когда один объект имеет сразу несколько векторных представлений. Это полезно, например, если вы хотите хранить для каждого документа два эмбеддинга: один для текста, другой для изображения. Для включения такой возможности при создании коллекции вместо одного размера вектора передаётся словарь именованных векторов. Каждый вектор получает уникальное имя и может иметь свой размерность и метрику сходства. Например, можно создать коллекцию с двумя видами векторов: `"image"` (размер 4, метрика Dot-Product) и `"text"` (размер 8, метрика Cosine). Пример кода на Python с использованием `qdrant-client`:

     

    from qdrant_client import QdrantClient, models
    client = QdrantClient(url="http://localhost:6333")
    client.recreate_collection(
        collection_name="multidata",
        vectors_config={
            "image": models.VectorParams(size=4, distance=models.Distance.DOT),
            "text":  models.VectorParams(size=8, distance=models.Distance.COSINE)
        }
    )

В примере мы создаём коллекцию `"multidata"` с двумя векторами на объект: первый – имя `"image"` (4-мерный, сравнение по dot product), второй – `"text"` (8-мерный, сравнение по cosine). Внутри Qdrant такие коллекции фактически хранят два под-индекса, и при поиске нужно указать, по какому вектору выполнять запрос. Если в коллекции есть несколько векторов, запрос должен содержать параметр `using` с именем векторного поля. Например, чтобы найти ближайших соседей по текстовому эмбеддингу, мы делаем: `client.search(collection_name="multidata", query_vector=q_vec, limit=5, **vector_name="text"**)`. Либо при REST-запросе: `"using": "text"`. Без этого Qdrant не знает, по какому из векторов выполнять поиск и вернёт ошибку. Мультивекторные коллекции особенно удобны для мультимодальных данных, где один и тот же объект имеет различные представления. Стоит помнить, что каждый именованный вектор может иметь **свою размерность и метрику** – например, можно хранить 512-мерные эмбеддинги текста и 128-мерные эмбеддинги изображений вместе, Qdrant будет корректно их индексировать раздельно
