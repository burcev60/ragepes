#### Лабораторная 1 — «Глубокая работа с одиночным узлом»

### Снапшот и восстановление (с сохранением вне контейнера)

**Важное замечание:** если снапшоты остаются внутри файловой системы контейнера, они удаляются вместе с контейнером. Поэтому используем *volume* для `/qdrant/snapshots` или заранее копируем файл снапшота на хост.

*Итог:* снапшот хранится на volume или на хосте и переживает удаление контейнера. Лаба просит именно «восстановиться из снапшота», поэтому мы удаляем старые volumes и поднимаем пустой контейнер, а затем восстанавливаем коллекцию через endpoint `…/snapshots/upload`.

**Обновление и удаление**

 

1. **Запуск Qdrant с volume для хранилища и снапшотов**

    docker run -d --name qdrant -p 6333:6333 \
      -v qdrant_storage:/qdrant/storage \
      -v qdrant_snapshots:/qdrant/snapshots \
      qdrant/qdrant:latest

  Создайте коллекцию `articles` и загрузите ≥ 50 000 векторов.

2. **Снять снапшот коллекции**

    # создать снапшот коллекцииcurl -X POST http://localhost:6333/collections/articles/snapshots

        # посмотреть список снапшотов и имя файла
    curl http://localhost:6333/collections/articles/snapshots

  Файл появится в каталоге контейнера `/qdrant/snapshots/collections/articles/` (у нас он перенаправлен на volume `qdrant_snapshots`).

3. **Экспорт снапшота на хост (если хотите хранить вне volume)**

    # скопировать файл снапшота из контейнера на хост
    docker cp qdrant:/qdrant/snapshots/collections/articles/<SNAPSHOT_NAME>.snapshot ./articles.snapshot

4. **Чистый перезапуск**

    docker rm -f qdrant
    # (опционально удалить volumes, чтобы точно имитировать «пустую» установку)
    docker volume rmqdrant_storage qdrant_snapshots

        # запустить «чистый» контейнер без данных
    docker run -d --name qdrant -p 6333:6333 qdrant/qdrant:latest

5. **Восстановление из снапшота**

  Вариант A — *загрузить файл снапшота* (рекомендуется для «чистого» контейнера):

    curl -X POST "http://localhost:6333/collections/articles/snapshots/upload" \
      -H "Content-Type: multipart/form-data" \
      -F "snapshot=@./articles.snapshot"

  Вариант B — *смонтировать каталог со снапшотом* и восстановить по пути:

    # запустить контейнер, пробросив локальную папку со снапшотом
    docker rm -f qdrant
    docker run -d --name qdrant -p 6333:6333 \
      -v $(pwd)/snapshots:/snapshots_host \
      qdrant/qdrant:latest

        # восстановление по файлу внутри контейнера
    curl -X POST "http://localhost:6333/collections/articles/snapshots/upload" \
      -H "Content-Type: multipart/form-data" \
      -F "snapshot=@/snapshots_host/<SNAPSHOT_NAME>.snapshot"

6. **Проверка**

    # количество точек и общее состояние
    curl http://localhost:6333/collections/articles
