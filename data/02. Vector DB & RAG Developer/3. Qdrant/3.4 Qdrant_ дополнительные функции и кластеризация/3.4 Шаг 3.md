**Обновление и удаление векторов.** 

Векторная база должна уметь не только добавлять, но и удалять или обновлять данные. Qdrant поддерживает **полный CRUD** для объектов. Если вы добавили эмбеддинги и затем получили новые версии некоторых из них – вы можете обновить их, просто повторно добавив с теми же ID (старые значения будут перезаписаны). Можно воспользоваться методом `upsert`, который вставляет новый объект или обновляет существующий, если ID совпадает. Также есть отдельный метод `update_vectors` для замены только векторной части точки без трогания payload (полезно, если например эмбеддинг изменился, а метаданные нет). Удаление объектов происходит либо по ID, либо выборкой по условию. Метод `client.delete(collection, points_selector=...)` принимает либо список конкретных ID для удаления, либо фильтр, по которому будут удалены все подходящие точки. Например: `client.delete("mycol", points_selector=models.PointIdsList(points=[1,2,3]))` удалит три точки с ID 1,2,3. Важно, что удаление в Qdrant **мгновенное и не требует перестройки индекса** – удалённые векторы просто помечаются и больше не участвуют в поиске. Это отличие от некоторых низкоуровневых библиотек: например, изначально Faiss (о котором пойдёт речь далее) не позволял удалять отдельные векторы из HNSW-индекса без полного пересоздания структуры. Qdrant как полноценная БД решает эти вопросы за нас. Помимо удаления точек целиком, Qdrant поддерживает удаление отдельных векторов в мультивекторной коллекции: метод `delete_vectors` позволяет изъять, скажем, только `"image"`-вектор у ряда объектов, оставив их текстовые эмбеддинги нетронутыми. При этом сами точки не удаляются, просто у них больше нет этого под-вектора. Это гибко: можно динамически менять состав данных. Кроме векторов, обновлять можно и **payload** – дополнительную информацию. Для payload (метаданных) есть методы `set_payload`, `overwrite_payload` и т.д., позволяющие изменить или добавить поля у уже существующих точек без перезаписи самого вектора.
