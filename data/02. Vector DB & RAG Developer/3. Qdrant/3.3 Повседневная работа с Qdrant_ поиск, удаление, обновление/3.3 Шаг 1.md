### Быстрый повтор: что такое коллекция и как она устроена в Qdrant
> Этот шаг напомнит ключевые понятия Qdrant, чтобы в следующих шагах мы сразу перешли к практике поиска, обновления и удаления.

#### 1.1 Коллекция = «коробка» для точек-векторов

- **Аналог таблицы** в реляционной БД: у каждой коллекции своё имя, своя конфигурация.

- Фиксируется **размерность** векторов (`vector_size`) и **метрика сходства** (`cosine`, `dot`, `euclid`).

- Внутри коллекции Qdrant автоматически строит индекс (по умолчанию HNSW) и хранит точки в сегментах на диске.

#### 1.2 Структура одной точки

| Поле | Что хранит | Обязательное? |
| --- | --- | --- |
| `id` | 64-битный целочисленный или строковый идентификатор | ✅ |
| `vector` | Массив чисел (`float32`) длиной `vector_size` | ✅ |
| `payload` | Произвольные метаданные в формате JSON (ключ-значение, вложенные структуры, массивы) | ❌ |

 
> **Payload** делает Qdrant «семантической» базой: по этим метаданным можно фильтровать результаты без дополнительной БД.

#### 1.3 Что ещё описывает коллекция

- **HNSW-параметры** — `m`, `ef_construct`, `on_disk` (для крупных индексов).

- **Product Quantization / Scalar Quantization** — опции сжатия векторов.

- **Sharding / Replication** (если база работает в кластере). Эти настройки появляются уже после создания в `cluster_config`.

#### 1.4 Минимальный пример создания коллекции (Python 3.11)

    from qdrant_client import QdrantClient
    from qdrant_client.http import models as rest

    # Поднятый локально Docker-контейнер
    client = QdrantClient("http://localhost:6333")

    # Создаём (или пересоздаём) коллекцию 'articles' под эмбеддинги Sentence-BERT 768d
    client.recreate_collection(
        collection_name="articles",
        vectors_config=rest.VectorParams(
            size=768,
            distance=rest.Distance.COSINE
        )
    )
    print("Коллекция готова! Размерность:",
          client.get_collection("articles").config.params.vectors.size)

*Важно:* `recreate_collection` удалит существующие данные, используйте только при первом запуске или миграции.

#### 1.5 Как Qdrant хранит данные под капотом (кратко)

1. **WAL** (Write Ahead Log) — каждая операция сначала пишется в журнал, что обеспечивает отказоустойчивость.

2. **Сегменты** — большие файлы на диске; Qdrant периодически сливает маленькие сегменты в крупные (compaction).

3. **Индекс HNSW** — строится отдельно для каждого сегмента; при поиске объединённый результат возвращается с учётом `search_params`.

Теперь, когда мы вспомнили, **что** такое коллекция и **из чего** она состоит, перейдём к ежедневным операциям: поиску, выборке, обновлению и удалению точек.
