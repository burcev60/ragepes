### Удаление и обновление точек: ID, фильтры, payload, векторы
> Этот шаг покажет, как **удалять** ненужные данные и **обновлять** существующие записи — как сами векторы, так и их метаданные.

#### 3.1 Удаление по ID

Если вы точно знаете, какие точки больше не нужны:

    client.delete(
        collection_name="articles",
        points_selector=models.PointIdsList(points=[42, 77])
    )
    print("Точки 42 и 77 удалены")

*После удаления* запросы `retrieve` или `search` больше их не вернут.

#### 3.2 Удаление по фильтру (payload-condition)

Например, убрать **все** статьи категории `"obsolete"`:

    flt = models.Filter(
        must=[models.FieldCondition(
            key="category",
            match=models.MatchValue(value="obsolete")
        )]
    )

    client.delete(
        collection_name="articles",
        points_selector=models.FilterSelector(filter=flt)
    )
> ⚠️ Qdrant синхронно помечает точки удалёнными, а фактическое освобождение места
> происходит при фоновом **compaction** сегментов.

#### 3.3 Обновление («перезапись») вектора

Если у объекта изменилось содержимое и нужно заменить эмбеддинг:

    client.upsert(
        collection_name="articles",
        points=[
            models.PointStruct(
                id=123,
                vector=new_vec,          # новый вектор длиной 768
                payload=None             # payload не трогаем
            )
        ]
    )

- `upsert` — «insert или update»: если `id` существует, вектор перезапишется

- Qdrant обновляет индекс на лету, перезапуск сервера не нужен

#### 3.4 Обновление payload (без изменения вектора)

##### 3.4.1 Полная замена / добавление полей

    client.set_payload(
        collection_name="articles",
        payload={"category": "new-tech", "year": 2024},
        points=[123]                    # можно список ID или фильтр
    )

*Неуказанные поля останутся как были; указанные — перезапишутся.*

##### 3.4.2 Удаление отдельных ключей payload

    client.delete_payload(
        collection_name="articles",
        keys=["year"],
        points=[123]
    )

Удалится только поле `year`, остальные метаданные без изменений.

#### 3.5 Полезные команды для контроля

| Операция | Код | Что даёт |
| --- | --- | --- |
| Статистика коллекции | `client.get_collection("articles").points_count` | Сколько точек сейчас |
| Информация о конкретных точках | `client.retrieve("articles", ids=[123], with_payload=True)` | Проверить изменения |
| Очистка всей коллекции | `client.delete_collection("articles")` | Полный сброс (⚠️ необратимо) |

 

#### 3.6 Рекомендации

1. **Батчи крупнее** ≈ 5-10 тыс. точек обрабатываются быстрее, чем по одной.

2. **Удаления по фильтру** выполняй в off-peak, если фильтр затрагивает много точек — в сегментах создаётся tombstone-запись до compaction.

3. После массовых обновлений можно вызвать **POST `/collections/{name}/optimizations`** (или метод `client.optimize(...)`) — ускорит слияние сегментов и уменьшит дисковое пространство.

Готово: теперь ты умеешь искать, удалять и обновлять данные в Qdrant. Следующий шаг — настроить массовую загрузку и посмотреть, как контролировать размер/точность индекса, если нужно.
