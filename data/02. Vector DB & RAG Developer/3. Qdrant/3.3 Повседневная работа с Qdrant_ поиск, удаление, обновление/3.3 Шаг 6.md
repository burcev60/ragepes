## QueryInterface в Qdrant: подробный разбор с примерами

Все запросы выполняются единым эндпоинтом `POST /collections/<name>/points/query`.
Тип запроса выбирается полем `query` (один из вариантов интерфейса Query).
Ниже — что делает каждый тип, когда его использовать, и рабочие примеры на Python (`qdrant-client`).

### 0) Анатомия запроса

    from qdrant_client import QdrantClient, models
    client = QdrantClient("http://localhost:6333")

    res = client.query_points(
        collection_name="products",
        query=...,                       # <== один из типов Query (см. ниже)
        prefetch=[...],                  # <== необязательные подзапросы (для Fusion/Formula)
        using="text_vector",             # <== какой именованный вектор использовать (в мультивекторной коллекции)
        query_filter=models.Filter(...), # <== фильтр по payload
        limit=10,
        offset=0,
        with_payload=True,
        with_vectors=False,
        score_threshold=None,            # отсекаем по порогу схожести (опционально)
        params=models.SearchParams(      # параметры поиска (HNSW ef/search_exact и пр.)
            exact=False, hnsw_ef=128
        ),
    )

- **using** — важно для коллекций с несколькими векторами (например, `image_vector` / `text_vector`).
- **prefetch** — список «подзапросов» для последующего слияния или реранкинга (см. Fusion/Formula).
- **query_filter** — сузьте область поиска (категория, цена, метки и т.д.).
- **params** — тонкая настройка скорости/качества (точный поиск, ef и т.п.).


### 1) NearestQuery — ближайшие соседи (kNN)

*Когда:* базовый векторный поиск по вектору или по ID (вектор берётся из хранилища).

    # По ID (вектор будет извлечён у этой точки)
    by_id = client.query_points(collection_name="products", query="a1b2c3d4-...")

    # По вектору (в мультивекторной коллекции укажите using)
    query_vec = [0.11, 0.35, 0.6, ...]
    by_vec = client.query_points(
        collection_name="products",
        query=query_vec,
        using="text_vector",
        limit=10
    )

**Подводные камни:** убедитесь, что размер вектора совпадает с конфигурацией коллекции; для мультивекторных — не забывайте `using`.

### 2) RecommendQuery — «похоже на X, но не на Y»

*Когда:* нужно учесть несколько положительных/отрицательных примеров. Поддерживаются разные стратегии агрегации.

    from qdrant_client import models

    rec = client.query_points(
        collection_name="products",
        query=models.RecommendQuery(
            recommend=models.RecommendInput(
                positive=["a1b2c3d4-...", [0.11, 0.35, 0.6, ...]],   # можно ID и/или векторы
                negative=[[0.01, 0.45, 0.67, ...]]
            )
            # strategy=models.RecommendStrategy.AVERAGE_VECTOR  # опционально: стратегия
        ),
        limit=10
    )

**Практика:** добавляйте немного «negative», чтобы отталкиваться от нерелевантных кластеров.

### 3) FusionQuery — смешиваем результаты нескольких подзапросов

*Когда:* гибридные сценарии (несколько модальностей, разные векторные поля, dense+sparse). Есть два готовых режима:

- `RRF` — Reciprocal Rank Fusion (устойчив к шкалам скоринга),
- `DBSF` — нормализует скоры и суммирует (удобно при разных метриках/масштабах).

    from qdrant_client import models

    res = client.query_points(
        collection_name="products",
        prefetch=[
            models.Prefetch(query=image_vec, using="image_vector", limit=50),
            models.Prefetch(query=text_vec,  using="text_vector",  limit=50),
        ],
        query=models.FusionQuery(fusion=models.Fusion.DBSF),  # или Fusion.RRF
        query_filter=models.Filter(must=[
            models.FieldCondition(key="category", match=models.MatchValue(value="electronics")),
            models.Range(key="price", lt=500),
        ]),
        limit=5
    )

**Совет:** ставьте `limit` в `prefetch` немного больше, чем итоговый (`limit` Query), чтобы было из чего «смешивать».

### 4) FormulaQuery — реранкинг по формуле (score boosting)

*Когда:* нужно явно «взвесить» модальности, сложить/умножить их скоры, учесть дополнительные сигналы.

    from qdrant_client import models

    img_w, txt_w = 0.6, 0.4
    res = client.query_points(
        collection_name="products",
        prefetch=[
            models.Prefetch(query=image_vec, using="image_vector", limit=50),  # $score[0]
            models.Prefetch(query=text_vec,  using="text_vector",  limit=50),  # $score[1]
        ],
        query=models.FormulaQuery(
            formula=models.SumExpression(sum=[
                models.MultExpression(mult=[img_w, "$score[0]"]),
                models.MultExpression(mult=[txt_w, "$score[1]"]),
            ])
        ),
        limit=5
    )

**Практика:** сделайте мини-«grid search» параметров `img_w`/`txt_w` и выберите комбинацию с лучшим `Recall@K` на вашем эталонном наборе.

### 5) SampleQuery — выборка без близости (инспекция/аудит)

*Когда:* быстро посмотреть случайный (или иной) поднабор точек — для контроля качества данных.

    from qdrant_client import models

    sampled = client.query_points(
        collection_name="products",
        query=models.SampleQuery(sample=models.Sample.RANDOM),
        limit=50
    )

### 6) DiscoverQuery — «найти в заданном контексте»

*Когда:* у вас есть «область интереса», заданная парами (positive, negative), и (опционально) целевая точка/вектор.

    from qdrant_client import models

    res = client.query_points(
        collection_name="products",
        query=models.DiscoverQuery(
            discover=models.DiscoverInput(
                target=[0.2, 0.1, 0.9, 0.7],  # можно ID точки или вектор
                context=[models.ContextExamplePair(positive="id_pos", negative="id_neg")]
            )
        ),
        limit=10
    )

**Идея:** «найди похожее на то, что формирует вот эту область, избегая вот этого подпространства».

### 7) ContextQuery — контекстный поиск без target

*Когда:* хотим найти «зону пересечения» позитивных примеров и оттолкнуться от негативных, не задавая конкретной целевой точки.

    from qdrant_client import models

    ctx = client.query_points(
        collection_name="products",
        query=models.ContextQuery(
            context=[models.ContextExamplePair(positive="id_pos", negative="id_neg")]
        ),
        limit=10
    )

### 8) OrderByQuery — сортировка по payload-полю

*Когда:* вернуть точки, отсортированные по значению в payload (например, `price`), часто в сочетании с фильтром.

    from qdrant_client import models

    by_price = client.query_points(
        collection_name="products",
        query=models.OrderByQuery(order_by=models.OrderBy(
            key="price", direction=models.Direction.ASC
        )),
        query_filter=models.Filter(must=[
            models.FieldCondition(key="category", match=models.MatchValue(value="electronics"))
        ]),
        limit=20
    )

**Практика:** всегда ограничивайте область сортировки фильтром — иначе это может быть дорого.

### 9) Dense + Sparse гибрид (через prefetch)

*Когда:* объединяем нейросемантику (dense) и BM25/спарс (sparse) в одном запросе.

    from qdrant_client import models

    sparse = models.SparseVector(indices=[3, 15, 101], values=[0.9, 0.4, 0.3])

    hybrid = client.query_points(
        collection_name="products",
        prefetch=[
            models.Prefetch(query=dense_vec, using="dense", limit=100),
            models.Prefetch(query=sparse,   using="sparse", limit=100),
        ],
        query=models.FusionQuery(fusion=models.Fusion.DBSF),
        limit=20
    )

### Best practices

- **Фильтры**: задавайте `query_filter` как можно раньше — меньше кандидатов, быстрее итог.
- **prefetch.limit**: держите его выше финального `limit` (например, 50→10) — будет из чего «смешивать».
- **DBSF** хорош, когда шкалы скоринга разных модальностей «плавают»; **RRF** устойчив к выбросам.
- **Formula**: начинайте с простых весов и подберите их по офлайн-метрике (Recall@K / nDCG@K).
- **params**: повышайте `hnsw_ef` для качества, снижайте для скорости; `exact=True` — эталон, но медленно.


### Микро-задания для самопроверки

1. **Baseline:** сделайте `NearestQuery` и задайте `score_threshold`, чтобы отсечь слабые ответы. Сколько результатов остаётся?
2. **Гибрид:** выберите по 10 запросов. Сравните `Fusion.RRF` vs `Fusion.DBSF` по `Recall@5`.
3. **Веса:** для `FormulaQuery` переберите пары весов (например, 0.2/0.8, 0.4/0.6, 0.6/0.4, 0.8/0.2). Где `Recall@5` выше?


*Подсказка:* если коллекция мультивекторная, не забывайте указывать `using` в каждом `prefetch` и/или на верхнем уровне.
