## Задача 4. Память vs качество: IVFFlat против IVFPQ (фиксированный nprobe)

### Цель

Понять компромисс «память ↔ точность ↔ задержка» при замене IVFFlat на IVFPQ. На одинаковом `nprobe` сравнить Recall@10 и размер индекса, подобрать `(m, nbits)`, дающий ≥10× экономию памяти при умеренной потере качества.

### Окружение и данные

- Библиотеки: `numpy`, `faiss` (CPU).

- Данные: синтетические.

  - Рекомендация: `N = 300_000`, `Q = 100`, `d = 96`, `K = 10`.

- Метрика: L2 (без нормализации).

- dtype: `float32`, массивы C-contiguous.

### Что сделать

1. Построить **эталон** `IndexFlatL2` и посчитать для каждого запроса `R=100` ближайших соседей (для расчёта Recall@10).

2. Построить **IVFFlat(L2)** с `nlist = 4096`, обучить на подвыборке (до 200k), добавить базу, установить `nprobe = 64`. Снять:

  - `Recall@10` против эталона;

  - p50/p95 (по желанию);

  - **размер сериализованного индекса** в MB.

3. Построить **IVFPQ(L2)** на тех же данных и с тем же `nlist`, `nprobe`, перебрать:

  - `m ∈ {16, 32}` (требование: `d % m == 0`);

  - `nbits ∈ {6, 8, 10}`.  
Для каждого варианта — обучить, добавить данные, посчитать `Recall@10`, p50/p95 (опционально) и размер индекса.

4. Свести результаты в таблицу и выбрать конфигурацию IVFPQ, которая:

  - даёт **экономию памяти ≥ 10×** относительно IVFFlat;

  - имеет **падение Recall@10 ≤ 0.1** относительно IVFFlat (на синтетике допустим этот порог).

### Критерии зачёта

- Есть таблица: `index_type, nlist, nprobe, m, nbits, Recall@10, size_MB, (p50_ms/p95_ms опц.)`.

- Найдена хотя бы одна конфигурация IVFPQ с `size_ratio = size_IVFPQ / size_IVFFlat ≤ 0.2` и `Recall_IVFFlat − Recall_IVFPQ ≤ 0.1`.

- Краткий вывод (2–4 предложения) о лучшем выборе `(m, nbits)` и его влиянии на размер/точность.

### Подсказки

- Память грубо: IVFFlat ≈ `d·4` байт/вектор; IVFPQ ≈ `(m·nbits/8)` байт/вектор + накладные.

- На больших `m` и `nbits` — точнее, но больше код (медленнее и больше памяти).

- Если обучение долго — сократите `N` или лимит обучающей подвыборки (но не меньше `~30–50 × nlist`).
