**Создание и использование индексов (пример кода).** 

Давайте посмотрим, как работать с FAISS на практике. Предположим, у нас есть набор эмбеддингов в виде NumPy-массива `xb` размером N×d (N векторов, размерности d). Мы хотим построить индекс и выполнить запрос. Начнём с простого – **Flat индекс**:

    import faiss
    d = 128  # размерность эмбеддинга
    index = faiss.IndexFlatL2(d)  # создаём индекс L2 (евклидова метрика)
    # (Для косинусной близости можно использовать IndexFlatIP и нормализовать векторы заранее)
    index.add(xb)  # загружаем все вектора в индекс
    # Проверим количество:
    print(index.ntotal)  # должно вывести N
    # Теперь выполним поиск
    k = 5  # хотим 5 ближайших соседей
    D, I = index.search(x_query, k)  # x_query – матрица запросов, например размер 1×128
    # D – матрица расстояний (1×k), I – матрица индексов найденных векторов (1×k)
    print(I[0])  # индексы 5 ближайших в базе
    print(D[0])  # расстояния до них

Здесь всё просто: IndexFlatL2 не требует обучения (`train` не нужен), мы сразу добавили данные и можем искать. Однако на больших N это будет медленно.

 

Теперь попробуем **IVF**. Нам нужно сначала определить кластеризатор – в FAISS для IVF требуется указать другой индекс как **квантизатор** (coarse quantizer). Обычно используют простой Flat index для этого:

    nlist = 1000  # число кластеров
    quantizer = faiss.IndexFlatL2(d)  # используем плоский индекс для назначения кластеров
    index_ivf = faiss.IndexIVFFlat(quantizer, d, nlist, faiss.METRIC_L2)
    index_ivf.train(xb)   # обучаем квантизатор на наших данных (кластеризация k-means)
    index_ivf.add(xb)     # добавляем базы, они распределяются по кластерам
    index_ivf.nprobe = 10  # будем проверять 10 кластеров при поиске
    D, I = index_ivf.search(x_query, k)

Поясним: мы создали IndexIVFFlat с `nlist=1000`. Метод `train` проводит кластеризацию (найдет 1000 центроидов по нашим данным). После этого `add` распределяет каждый вектор в ближайший из 1000 центров. При поиске мы задаём `nprobe=10`, чтобы просматривать 10 лучших кластеров. Это ключевой параметр: если `nprobe=1`, поиск будет очень быстрый (только один кластер), но может пропустить многие результаты; если `nprobe=1000` (равно nlist), то мы фактически ищем во всех – вернётся точно, но потеряем ускорение. Значение 10 – компромисс. Практически, `nprobe` лучше выбирать экспериментально: увеличить, пока качество результатов (например, средний расстояние или recall на тестовом наборе) не станет приемлемым.

 

**Примечание:** IndexIVFFlat хранит внутри себя копию квантизатора (FlatL2) и массив inverted lists (списки векторов по кластерам). Если данных много, можно экономить память, установив `quantizer` в режим не хранить сами вектора центроидов, но обычно это не критично.

Теперь **PQ (Product Quantization)**. Создавать его ещё проще:

    m = 16        # число суб-векторов
    nbits = 8     # бит на код каждого суб-вектора (8 бит = 256 центроидов на сегмент)
    index_pq = faiss.IndexPQ(d, m, nbits)
    index_pq.train(xb)  # обучаем кодовые слова PQ
    index_pq.add(xb)
    D, I = index_pq.search(x_query, k)

Здесь `train` выполняет обучение квантайзера: находит оптимальные центроиды для каждого из 16 сегментов размером (d/m = 8). После этого при добавлении каждый вектор превращается в 16-байтовый код. Поиск происходит по сжатым кодам. IndexPQ не имеет `nprobe`, т.к. нет кластеров – он всегда рассматривает все точки, но очень быстро вычисляет расстояния между закодированными векторами и запросом (FAISS использует precomputed таблицы для ускорения). IndexPQ даёт приблизительные дистанции: в список I могут вкрасться не абсолютно ближайшие точки, хотя обычно топ-1 попадает правильно.

 

**Комбинированный IVFPQ** – объединяем два подхода:

    index_ivfpq = faiss.IndexIVFPQ(quantizer, d, nlist, m, nbits)
    index_ivfpq.train(xb)   # сперва обучается и кластеризация, и PQ-кодеки на подвыборке
    index_ivfpq.add(xb)
    index_ivfpq.nprobe = 10
    D, I = index_ivfpq.search(x_query, k)

FAISS сам сначала вызывает k-means для кластеров, потом внутри каждого кластера обучает PQ на векторах, попавших в этот кластер (или на всём сразу, в зависимости от реализации). Настройка `nlist`, `m`, `nbits` влияет на компромисс памяти/точности. IndexIVFPQ – мощный, но сложный индекс: много параметров. Часто применяют эвристики или даже автоматический подбор (например, есть утилиты, которые по заданному объёму памяти рассчитывают оптимальные m и nbits).
