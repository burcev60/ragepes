## FAISS на GPU: перенос индексов, мульти-GPU, настройки памяти и точности

В этом шаге разберём, как задействовать видеокарту для ускорения поиска в FAISS. Покажем типовые схемы: перенос готового CPU-индекса на GPU, создание «родных» GPU-индексов, репликация и шардинг на несколько GPU, возврат на CPU для сериализации, а также ключевые настройки памяти и точности (FP32/FP16).

### 1) Когда GPU даёт выигрыш

- **Большие батчи запросов** (`Q` сотни–десятки тысяч): вычисления сводятся к большим матричным операциям, где GPU особенно эффективен.
- **Точные и IVF-индексы** (Flat, IVFFlat, IVFPQ): значительную часть времени занимает вычисление скоров/дистанций, хорошо векторизуемое на GPU.
- **Высокая размерность** (`d` сотни–тысячи): больше работы на одно сравнение ⇒ лучше загрузка ядра.


Обратите внимание: **HNSW** чаще используют на CPU (граф сложно эффективно «распараллелить» на GPU), тогда как Flat/IVF/IVFPQ получают заметный профит.

### 2) Базовый шаблон: перенос готового CPU-индекса на GPU

Наиболее простой путь — собрать индекс на CPU (там же сохранить/загрузить при необходимости) и «склонировать» его на выбранный GPU для быстрого поиска.

    import numpy as np, faiss

    # данные
    xb = np.load("data/xb.npy").astype('float32')
    xq = np.load("data/xq.npy").astype('float32')
    d, k = xb.shape[1], 10

    # 1) CPU-индекс (пример: точный L2)
    index_cpu = faiss.IndexFlatL2(d)
    index_cpu.add(xb)

    # 2) Ресурсы GPU
    res = faiss.StandardGpuResources()          # менеджер временных буферов на устройстве

    # (необязательно) ограничить/увеличить временную память:
    # res.setTempMemory(256 * 1024 * 1024)      # 256 MB во временный пул

    # 3) Перенос на устройство 0
    index_gpu = faiss.index_cpu_to_gpu(res, 0, index_cpu)

    # 4) Поиск
    D, I = index_gpu.search(xq, k)

    # 5) Возврат на CPU для сериализации
    index_back = faiss.index_gpu_to_cpu(index_gpu)
    faiss.write_index(index_back, "flat_l2_gpu_saved.faiss")

Такой подход работает и для IVF/IVFPQ: обучаем/строим на CPU, переносим на GPU для ускоренного поиска. Если строите IVF/IVFPQ полностью на GPU, следите, чтобы train/add и search были в согласованных режимах.

### 3) «Родные» GPU-индексы

Помимо клонирования, есть классы *GpuIndex**, работающие непосредственно на устройстве. Пример для точного поиска по L2:

    # GpuIndexFlatL2 (аналог IndexFlatL2 на GPU)
    res = faiss.StandardGpuResources()
    gpu_index = faiss.GpuIndexFlatL2(res, d)   # данные живут на GPU
    gpu_index.add(xb)                          # FAISS сам копирует xb на устройство
    D, I = gpu_index.search(xq, k)

Для IVF/IVFPQ можно либо использовать «родные» GPU-варианты, либо строить CPU-индекс и переносить его (часто удобнее второе — единый путь сериализации).

### 4) Настройка точности: FP32 ↔ FP16

На GPU часто имеет смысл включать **FP16** для ускорения и экономии памяти (с небольшой потерей точности при суммировании). Это задаётся через настройки «клонирования» CPU-индекса на GPU.

    # Пример: клонирование CPU-индекса с FP16
    co = faiss.GpuClonerOptions()
    co.useFloat16 = True                         # расчёты и хранение на GPU в half precision
    index_gpu = faiss.index_cpu_to_gpu(res, 0, index_cpu, co)

- FP16 уменьшает потребление памяти почти вдвое; выигрыш заметнее на больших `d` и больших батчах `Q`.
- Для IVFPQ есть дополнительные «тонкие» опции (lookup-таблицы в FP16 и т.д.); включайте, если отслеживаете влияние на recall/латентность.


### 5) Мульти-GPU: репликация и шардинг

Две базовые стратегии масштабирования по нескольким GPU:

- **Репликация (IndexReplicas):** копия одного и того же индекса на каждом устройстве. Увеличивает пропускную способность (QPS) при фиксированном объёме данных. Балансировщик распределяет запросы по репликам.
- **Шардинг (IndexShards):** делим базу на части (по ID/хэшу), кладём шард на свой GPU. Уменьшает объём данных на устройство, позволяя хранить «слишком большие» коллекции. При поиске запрос уходит на все шарды, затем результаты объединяются.


#### Репликация

    ngpu = faiss.get_num_gpus()
    # Переносим CPU-индекс на все устройства (реплика)
    replicated = faiss.index_cpu_to_all_gpus(index_cpu)  # под капотом создаст IndexReplicas
    D, I = replicated.search(xq, k)

#### Шардинг

    # Вариант 1: вручную создать шардовые индексы и собрать их
    d = xb.shape[1]
    shards = []
    for dev in range(faiss.get_num_gpus()):
        res = faiss.StandardGpuResources()
        shard = faiss.GpuIndexFlatL2(res, d)
        shards.append(shard)

    # распределяем данные по шардам (по хэшу ID, по диапазонам и т.п.)
    # ... add() в каждый shard ...

    # агрегатор, который объединит top-K из всех шардов
    agg = faiss.IndexShards(d, threaded=True, own_fields=True)
    for sh in shards:
        agg.add_shard(sh)

    D, I = agg.search(xq, k)

Для IVF/IVFPQ шардирование аналогично: каждый шард содержит «кусок» базы и свой IVF; запрос параллелится по устройствам, результаты мерджатся.

### 6) Память и пропускная способность: практические советы

- **Данные:** приводите к `np.float32`, массивы C-contiguous. Это снижает скрытые копии/каст.
- **Размер батча запросов (`Q`):** GPU любит большие матрицы. Объединяйте запросы в чанки (сотни–десятки тысяч) для лучшей загрузки.
- **Временная память GPU:** пул `StandardGpuResources` можно ограничить/увеличить `setTempMemory(...)`, чтобы избежать частых аллокаций.
- **Переносы host↔device:** минимизируйте лишние копирования; если есть поток запросов, держите индекс на устройстве и пересылайте только `xq`. Старайтесь реже «туда-сюда» гонять индекс.
- **Мульти-GPU:** при репликации следите за балансировкой QPS; при шардировании — за равномерным распределением данных и временем мерджа top-K.


### 7) Сохранение/загрузка: всегда через CPU

Бинарные файлы индексов (включая IVF/IVFPQ/OPQ/IDMap) — это **CPU-представление**. Поэтому:

1. Если индекс «живёт» на GPU — *сначала* верните его на CPU: `faiss.index_gpu_to_cpu(...)`.
2. Сохраните: `faiss.write_index(index_cpu, path)`.
3. Для загрузки — читайте с диска в CPU и, при необходимости, снова переносите на GPU.


### 8) Совместимость и диагностика

- **Версии CUDA/драйверов:** GPU-сборки FAISS чувствительны к совместимости. Если есть сомнения — начните с `faiss-cpu`, а затем перейдите на GPU-сборку, собранную под вашу CUDA.
- **Проверка ресурсов:** используйте `faiss.get_num_gpus()` для инвентаризации; убедитесь, что устройство видно системе.
- **Сходимость показателей:** убедитесь, что результаты (например, *Recall@K*) на CPU и GPU совпадают в пределах численной погрешности (особенно при FP16).


### 9) Краткие рецепты

    # (A) CPU → GPU (один девайс)
    res = faiss.StandardGpuResources()
    gpu = faiss.index_cpu_to_gpu(res, 0, index_cpu)

    # (B) CPU → все GPU (репликация)
    replicated = faiss.index_cpu_to_all_gpus(index_cpu)

    # (C) Возврат на CPU для сохранения
    cpu_again = faiss.index_gpu_to_cpu(gpu)
    faiss.write_index(cpu_again, "index.faiss")

    # (D) FP16 на GPU
    co = faiss.GpuClonerOptions(); co.useFloat16 = True
    gpu_fp16 = faiss.index_cpu_to_gpu(res, 0, index_cpu, co)
