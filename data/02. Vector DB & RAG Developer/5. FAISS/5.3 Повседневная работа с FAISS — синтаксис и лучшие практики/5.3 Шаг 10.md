## Шпаргалка синтаксиса FAISS и «карта решений» по выбору индекса

Этот шаг — компактное резюме предыдущих тем: минимально-достаточный синтаксис, типовые шаблоны кода и «карта решений» — как выбирать индекс и параметры под ограничения по памяти, задержке, качеству и частоте обновлений.

### 1) Базовый минимум: импорты, проверки и косинус

    import numpy as np, faiss

    # Проверки
    assert xb.dtype == np.float32 and xq.dtype == np.float32
    assert xb.flags['C_CONTIGUOUS'] and xq.flags['C_CONTIGUOUS']
    d, k = xb.shape[1], 10

    # Косинусная нормализация
    def l2_normalize(a: np.ndarray) -> np.ndarray:
        n = np.linalg.norm(a, axis=1, keepdims=True)
        return (a / np.maximum(n, 1e-12)).astype('float32')

    # Flat L2
    idx_l2 = faiss.IndexFlatL2(d); idx_l2.add(xb); D,I = idx_l2.search(xq, k)

    # Flat IP (косинус: нормализуйте xb/xq!)
    xbn, xqn = l2_normalize(xb), l2_normalize(xq)
    idx_ip = faiss.IndexFlatIP(d); idx_ip.add(xbn); D,I = idx_ip.search(xqn, k)

    # Range search
    radius = 0.7    # L2-порог (квадрат L2)
    lims, D, I = idx_l2.range_search(xq[:10], radius)
  

### 2) IVF (IndexIVFFlat): train → add → search

    # L2-вариант
    nlist = 2048
    quant = faiss.IndexFlatL2(d)
    ivf = faiss.IndexIVFFlat(quant, d, nlist, faiss.METRIC_L2)

    ivf.train(xb[:min(100_000, len(xb))])  # репрезентативная подвыборка
    ivf.add(xb)
    ivf.nprobe = 32
    D,I = ivf.search(xq, k)

    # Правила выбора:
    # nlist ~ √N ... несколько·√N; nprobe ~ 1%...10% nlist (под SLA).
  

### 3) IVFPQ / OPQ: экономия памяти

    # Параметры PQ
    m, nbits = 16, 8          # d % m == 0; 8 бит — базовый компромисс
    nlist = 4096

    # L2-вариант
    quant = faiss.IndexFlatL2(d)
    ivfpq = faiss.IndexIVFPQ(quant, d, nlist, m, nbits)   # residual PQ
    ivfpq.train(xb[:200_000]); ivfpq.add(xb); ivfpq.nprobe = 64
    D,I = ivfpq.search(xq, k)

    # OPQ (улучшение качества без увеличения кода)
    spec = "OPQ16,IVF4096,PQ16x8"
    idx = faiss.index_factory(d, spec, faiss.METRIC_L2)
    idx.train(xb[:200_000]); idx.add(xb); idx.nprobe = 64

    # Оценка памяти:
    # Flat ≈ d·4 байт/вектор; IVFPQ ≈ (m·nbits/8) байт/вектор (+ накладные).
  

### 4) HNSW: высокое качество и низкая латентность (RAM дороже)

    hnsw = faiss.IndexHNSWFlat(d, M)       # по умолчанию METRIC_L2
    hnsw.hnsw.efConstruction = 200
    hnsw.hnsw.efSearch = 64
    hnsw.add(xb)
    D,I = hnsw.search(xq, k)

### 5) Пользовательские ID, удаления и реконструкция

### 8) «Карта решений»: что выбрать под ваши ограничения

#### По размеру коллекции (N) и бюджету памяти

- **N ≤ 200k**, RAM хватает: *IndexFlatL2/IP* (эталон/простой прод), или *HNSW* для низкой латентности.
- **200k…10M**, RAM ок: *IVFFlat* (быстрый, без потерь в ячейках) или *HNSW* (выше recall, дороже по RAM).
- **10M+** или строгий RAM-бюджет: *IVFPQ* (и лучше *OPQ*) — кратная экономия памяти.


#### По SLA по задержке (p95) и качеству

- **Минимальная задержка, высокий recall, RAM допустима** → *HNSW* (M≈32, efSearch 64–128).
- **Баланс скорость/простота** → *IVFFlat* (nlist≈√N…4√N; nprobe 16–64).
- **Память критична** → *IVFPQ/OPQ* (m=16/32, nbits=8; nprobe 32–128; для косинуса IP+нормализация).
- **Большие батчи запросов** → GPU для Flat/IVF/IVFPQ (и подумать о FP16).


#### По частоте обновлений

- **Частые инкрементальные апдейты** → HNSW или IVFFlat + *IndexIDMap*, периодические офлайн-rebuild’ы.
- **Пакетные nightly-релизы** → IVFPQ/OPQ как main + «blue/green» переключение, hot-буфер для свежих данных.


#### Типовые стартовые конфигурации

| Сценарий | Рекомендация | Параметры старта |
| --- | --- | --- |
| Косинус, N≈1M, RAM ок | IVFFlat (IP) | nlist=4096, nprobe=32; нормализовать xb/xq |
| Косинус, N≈50M, строгий RAM | IVFPQ+OPQ (IP) | nlist=8192, m=16, 8b, nprobe=64 |
| Минимальная p95 при высоком recall | HNSW | M=32, efC=200, efS=64–128 |
| Большие батчи Q на GPU | Flat/IVF на GPU | FP16=on, batched Q≈1k–10k |

### 9) Мини-чек-лист «грабли» (напоминание)

- **dtype**: только `float32`; делайте `np.ascontiguousarray`.
- **Косинус**: это IP *на нормализованных* векторах; нормализуйте и *train/add/search* в одном режиме.
- **IVF**: не забыть `train()`; `is_trained` должен быть True.
- **IVFPQ**: `d % m == 0`; храните «сырые» эмбеддинги отдельно для точной доранжировки.
- **GPU I/O**: сохраняйте/грузите через CPU-представление (`index_gpu_to_cpu`).
- **Поиск ≠ модификация**: не делайте `add/remove` в том же объекте, по которому идёт `search`; используйте swap/буфер.
