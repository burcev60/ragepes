## Контроль качества и грид-поиск параметров: Recall@K, nDCG, латентность и размер индекса

В этом шаге систематизируем оценку качества и скорости для разных конфигураций FAISS. Разберём метрики (**Recall@K**, **nDCG@K**, **MRR**), как готовить «эталон» (Flat или поднабор), как корректно измерять латентность (p50/p95), и как запускать *грид-поиск* параметров для IVF/IVFPQ/HNSW (а также FP16 на GPU).

### 1) Зачем нужен эталон и как его получить

- **Эталон** — это «истинные» соседи для каждого запроса. Обычно берут *Flat* (IndexFlatL2/IP) на всей базе и считают top-R (например, R=100) соседей. Если вся база слишком большая, делают эталон на *репрезентативном подмножестве* (например, 100–200k векторов).
- **Метрика сравнения**: с альтернативными индексами (IVF, IVFPQ, HNSW) сравниваем пересечение множеств ответов с эталоном.

    import numpy as np, faiss

    # xb, xq подготовлены ранее; выбираем K_eval и R эталона
    d = xb.shape[1]
    K_eval = 10
    R = 100                    # глубина эталона (должна быть ≥ K_eval)

    # Эталон (пример: L2)
    ref = faiss.IndexFlatL2(d)
    ref.add(xb)
    D_ref, I_ref = ref.search(xq, R)   # I_ref: (Q, R) — списки лучших соседей по Flat

### 2) Метрики качества

#### Recall@K

Доля релевантных (по эталону) объектов, найденных альтернативным индексом среди его top-K: `Recall@K = |retrieved_K ∩ reference_R| / K` (если R ≥ K). Часто усредняют по всем запросам (macro-avg).

#### nDCG@K

Учитывает *позиции* релевантных документов. Если у нас бинарная релевантность «в эталоне/вне эталона», можно взять gain = 1, иначе — использовать веса по расстоянию/оценке. DСG: `DCG@K = Σ (gain_i / log2(2+i))`. Нормируем на *идеальный* DCG из эталона → nDCG ∈ [0,1].

#### MRR (Mean Reciprocal Rank)

Полезно, если важен первый релевантный документ: `MRR = mean(1 / rank_first_relevant)`. При отсутствии релевантных — 0.

### 3) Измерение латентности: p50/p95 и прогрев

- **Прогрев**: перед замером сделайте 1–2 «холостых» прохода поиском, чтобы прогреть страницы/кэш/ядра BLAS.
- **Повторы**: собирайте 20–30 измерений, агрегируйте p50/p95, фиксируйте число потоков: `faiss.omp_set_num_threads(T)`.
- **Батчи**: меряйте для разных размеров Q (например, 1, 32, 256, 1000) — результаты сильно зависят от батчинга.

    import time, numpy as np, faiss

    def time_search(index, xq, k, warmup=2, runs=10):
        # прогрев
        for _ in range(warmup):
            index.search(xq[:min(32, len(xq))], k)
        times = []
        for _ in range(runs):
            t0 = time.perf_counter()
            D, I = index.search(xq, k)
            times.append((time.perf_counter() - t0) * 1000.0)  # ms
        times = np.array(times)
        return np.percentile(times, [50, 95])  # p50, p95

### 4) Измерение размера индекса

- Для сравнения используйте *размер файла* сериализованного индекса (`write_index` → `os.path.getsize`).
- Это хорошо коррелирует с RAM-потреблением для IVFPQ/OPQ; для HNSW/Flat — размер на диске ≈ размер векторов + граф/метаданные.

    import os, faiss, tempfile

    def serialized_size_bytes(index) -> int:
        with tempfile.NamedTemporaryFile(delete=False) as f:
            path = f.name
        faiss.write_index(index, path)
        size = os.path.getsize(path)
        os.remove(path)
        return size

### 5) Реализация Recall@K и nDCG@K

    import numpy as np

    def recall_at_k(I_ref, I_alt, K=10, R=None):
        """
        I_ref: (Q, R) индексы эталона (Flat)
        I_alt: (Q, K) индексы альтернативного индекса
        """
        if R is None: R = I_ref.shape[1]
        Q = I_alt.shape[0]
        # множество эталона на глубине min(R, K) (часто достаточно K)
        Ruse = min(R, K)
        hits = 0
        for q in range(Q):
            ref_set = set(I_ref[q, :Ruse])
            alt = I_alt[q, :K]
            hits += sum(1 for i in alt if i in ref_set)
        return hits / (Q * K)

    def ndcg_at_k(I_ref, I_alt, K=10):
        """
        Бинарный gain: 1 если элемент ∈ эталоне (на глубине K), иначе 0
        """
        Q = I_alt.shape[0]
        def dcg(g):
            return sum(g[i] / np.log2(2 + i) for i in range(len(g)))
        scores = []
        for q in range(Q):
            ref_set = set(I_ref[q, :K])
            gains_alt = [1 if i in ref_set else 0 for i in I_alt[q, :K]]
            gains_ideal = sorted(gains_alt, reverse=True)  # идеальный DCG из того же «набора релевантности»
            dcg_alt = dcg(gains_alt)
            dcg_ideal = dcg(gains_ideal) or 1.0
            scores.append(dcg_alt / dcg_ideal)
        return float(np.mean(scores))

### 6) Экспериментальные гриды параметров

#### IVF / IVFFlat

- **nlist**: {√N, 2√N, 4√N, …} (округлять до степени 2/ближайшего удобного значения).
- **nprobe**: {8, 16, 32, 64, 128} (для больших nlist — шире диапазон).


#### IVFPQ / OPQ

- **m** (субвекторы): {16, 24, 32} при d≈768; условие d % m == 0.
- **nbits**: {6, 8, 10} (8 — базовый компромисс).
- **OPQ**: on/off (даёт ощутимый прирост качества при той же длине кода).
- Плюс **nlist/nprobe** как у IVFFlat.


#### HNSW

- **M**: {16, 24, 32, 48}
- **efConstruction**: {100, 200, 300, 400} (влияет только на построение)
- **efSearch**: {16, 32, 64, 96, 128}


#### GPU

- **FP16**: on/off (через `GpuClonerOptions.useFloat16`), проверять влияние на Recall@K.
- **Batch size Q**: {32, 256, 1024, 10000} — важнейший фактор времени.


### 7) Каркас кода для грид-поиска (пример IVF)

    import numpy as np, faiss, math

    def build_ivf(xb, metric, nlist):
        d = xb.shape[1]
        q = faiss.IndexFlatL2(d) if metric == faiss.METRIC_L2 else faiss.IndexFlatIP(d)
        idx = faiss.IndexIVFFlat(q, d, nlist, metric)
        # train на репрезентативной подвыборке
        tr = min(200_000, xb.shape[0])
        idx.train(xb[:tr])
        idx.add(xb)
        return idx

    def evaluate(index, xq, k, I_ref, nprobe):
        index.nprobe = nprobe
        D, I = index.search(xq, k)
        rec = recall_at_k(I_ref, I, K=k)
        nd = ndcg_at_k(I_ref, I, K=k)
        p50, p95 = time_search(index, xq, k)
        size = serialized_size_bytes(index)
        return {"Recall@K": rec, "nDCG@K": nd, "p50_ms": p50, "p95_ms": p95, "size_mb": size/1024/1024}

    N = xb.shape[0]
    sqrtN = int(round(math.sqrt(N)))

### 8) Методология эксперимента: чтобы цифры были честными

- **Фиксируйте сиды** генераторов (numpy/к-means/OPQ), чтобы конфигурации были сравнимы.
- **Одинаковая предобработка**: для косинуса — нормализуйте xb/xq *для всех* конфигураций (ref/alt) одинаково.
- **Согласованная метрика**: ref и alt должны работать в одной метрике (L2/IP). Косинус → IP+нормализация.
- **Стабильность времени**: фиксируйте `faiss.omp_set_num_threads(T)`, отключайте «шумные» процессы, меряйте несколько прогонов.
- **Размер батча** и **K_eval** держите одинаковыми для сравниваемых конфигураций.

### 10) Статистическая надёжность

- **Бутстрэп** по запросам: перему sample запросов с возвращением, пересчитывайте метрики, оценивайте доверительные интервалы.
- **Парные сравнения**: для двух конфигураций сравнивайте метрики для одних и тех же запросов; используйте парный t-тест/пермутационный тест.
- **Стабильность по сид-ам** (для IVF/OPQ): прогоняйте 2–3 разных сида k-means — метрики не должны «плавать» сильно.
