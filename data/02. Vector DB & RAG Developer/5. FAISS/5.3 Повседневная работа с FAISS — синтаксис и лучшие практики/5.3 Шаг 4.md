## Сжатие памяти и ускорение: IndexIVFPQ (Product Quantization)

В этом шаге поверх идеи IVF добавляем сжатие векторов с помощью **Product Quantization (PQ)**. Индекс `IndexIVFPQ` существенно уменьшает потребление памяти и ускоряет поиск на больших коллекциях, платя небольшой ценой точности (recall). Это «рабочая лошадка» FAISS для продакшена на миллионах и десятках миллионов векторов.

### 1) Зачем нужен IVFPQ

- **Память:** Flat/IVFFlat хранят исходные векторы как `float32` ⇒ `N · d · 4` байт. При `N=10M` и `d=768` это ≈ 28.6 GB только на данные.
- **IVFPQ:** вместо хранения всего вектора хранится компактный *PQ-код* фиксированной длины (обычно 8–32 байта на вектор), а сравнение делается по этим кодам.
- **Итог:** многократная экономия RAM (в 10–50 раз и более) и высокая пропускная способность, особенно при больших `N`.


### 2) Как работает Product Quantization

1. **Разбиение признаков:** исходный вектор `x ∈ ℝ^d` делится на `m` равных подпространств (субвекторов) размерности `d/m` (важно: `d` кратно `m`).
2. **Кодбуки:** для каждого подпространства строится свой маленький словарь из `ksub = 2^{nbits}` центроидов (обычно 256 при `nbits=8`).
3. **Кодирование:** каждый субвектор заменяется индексом ближайшего центроида (число от 0 до `ksub−1`). Итого на вектор уходит `m · nbits` бит.
4. **Сравнение:** расстояние между запросом и кодированным вектором оценивается по таблицам предрассчитанных расстояний (ADC — Asymmetric Distance Computation).


В `IndexIVFPQ` PQ применяется к **остаткам** («residuals») относительно центроида ячейки IVF: `r = x − c`. Это обычно даёт меньшую ошибку квантования, чем кодировать исходные векторы целиком.

### 3) Параметры IVFPQ: что выбирать

- **nlist** — число ячеек IVF (см. шаг 3). Чем больше, тем меньше средний размер ячейки.
- **nprobe** — число просматриваемых ячеек на запрос. Главный рычаг «скорость ↔ recall».
- **m** — число субвекторов PQ. Должно делить `d` (например, `d=768` удобно делится на 16, 24, 32).
- **nbits** — бит на субвектор. Часто 8 (256 кодовых слов на подпространство). 6–10 — рабочий диапазон.


*Правила большого пальца:* начните с `m=16` или `m=32` при больших `d`, `nbits=8`, `nlist≈(√N … несколько·√N)`, `nprobe` подберите по метрикам качества/задержки.

### 4) Базовый пример: L2 с IVFPQ

    import numpy as np, faiss

    xb = np.load("data/xb.npy").astype('float32')
    xq = np.load("data/xq.npy").astype('float32')
    d, k = xb.shape[1], 10

    # параметры IVF и PQ
    nlist = 4096      # число ячеек
    m = 16            # число субвекторов (d должно делиться на m)
    nbits = 8         # бит на субвектор (256 кодовых слов)

    # квантайзер и сам индекс
    quantizer = faiss.IndexFlatL2(d)
    index = faiss.IndexIVFPQ(quantizer, d, nlist, m, nbits)  # METRIC_L2 по умолчанию для L2-quantizer

    # обучение: и центроиды IVF, и кодбуки PQ
    train_sz = min(200_000, xb.shape[0])
    index.train(xb[:train_sz])

    # добавление базы и настройка поисковых параметров
    index.add(xb)
    index.nprobe = 32

    # поиск
    D, I = index.search(xq, k)

Здесь хранится не сам `xb`, а его сжатые коды. Сравнение выполняется по предрасчитанным таблицам, что сильно ускоряет поиск.

### 5) Косинусная близость с IVFPQ (через IP)

Для косинуса — нормализуем векторы и используем IP-режим (как и в шаге 2), но уже с PQ-кодированием:

    import numpy as np, faiss

    def l2_normalize(a: np.ndarray) -> np.ndarray:
        n = np.linalg.norm(a, axis=1, keepdims=True)
        n = np.maximum(n, 1e-12)
        return (a / n).astype('float32')

    xb = np.load("data/xb.npy").astype('float32')
    xq = np.load("data/xq.npy").astype('float32')
    xbn, xqn = l2_normalize(xb), l2_normalize(xq)
    d, k = xbn.shape[1], 10

    nlist, m, nbits = 4096, 16, 8
    quantizer = faiss.IndexFlatIP(d)
    index = faiss.IndexIVFPQ(quantizer, d, nlist, m, nbits, faiss.METRIC_INNER_PRODUCT)

    # ВАЖНО: train/add на НОРМАЛИЗОВАННЫХ данных
    train_sz = min(200_000, xbn.shape[0])
    index.train(xbn[:train_sz])
    index.add(xbn)
    index.nprobe = 64

    D, I = index.search(xqn, k)  # больше — лучше (косинус)

### 6) Улучшение качества: OPQ (Rotation-optimized PQ)

**OPQ** применяет обучаемое ортогональное преобразование к векторам перед PQ, чтобы лучше распределить информацию по субвекторам. В FAISS это делается через предтрансформацию (`IndexPreTransform`) или фабричную строку (`index_factory`).

#### Вариант A — вручную

    import faiss

    d, m, nbits, nlist = 768, 16, 8, 4096
    opq = faiss.OPQMatrix(d, m)                  # обучаемая матрица d×d с m блоками
    quantizer = faiss.IndexFlatL2(d)
    ivfpq = faiss.IndexIVFPQ(quantizer, d, nlist, m, nbits)

    index = faiss.IndexPreTransform(opq, ivfpq)  # OPQ → IVFPQ как единый индекс

    # train применит и OPQ, и IVF/PQ
    index.train(xb[:200_000])
    index.add(xb)
    index.nprobe = 32

#### Вариант B — index_factory

    # строка-фабрика: "OPQ{m},IVF{nlist},PQ{m}x{nbits}"
    spec = "OPQ16,IVF4096,PQ16x8"
    index = faiss.index_factory(d, spec, faiss.METRIC_L2)
    index.train(xb[:200_000]); index.add(xb)
    index.nprobe = 32

OPQ обычно повышает recall при той же длине кода, особенно на высокомерных представлениях с коррелированными признаками.

### 7) Сколько памяти на самом деле экономим

Приближённая оценка памяти на вектора:

- **Flat/IVFFlat:** `d · 4` байт.
- **IVFPQ:** `m · nbits / 8` байт (сам код) + небольшие накладные на структуру IVF и кодбуки.


Пример: `d=768`, `m=16`, `nbits=8` ⇒ код = 16 байт/вектор. Сравните с `768·4=3072` байт/вектор у Flat: экономия ≈ **192×** на сами данные (без учёта метаданных и центроидов).

### 8) Качество и латентность: как подбирать параметры

- **nprobe:** главный параметр качества/скорости. Увеличение `nprobe` повышает recall, но растит латентность.
- **m и nbits:** больше код (больше байт) — лучше точность, но больше память и чуть медленнее поиск. 8 бит на субвектор — хороший базовый компромисс.
- **OPQ:** улучшает точность практически «бесплатно» по памяти, добавляя матрицу преобразования и обучающий шаг.
- **Эталон:** держите под рукой Flat (или небольшой поднабор), чтобы считать `Recall@K` и сравнивать конфигурации честно.


### 9) Ограничения и практические тонкости

- **Кратность:** `d % m == 0` обязательно для классического PQ.
- **Reconstruct:** у PQ реконструкция «приближённая» (по кодам + центроиду). Если нужна точная переранжировка — храните исходные векторы отдельно (например, в колонночном хранилище) и делайте доранжировку top-R кандидатов.
- **Обновления:** как и в IVF — нет «update». Делайте *delete+add*, периодически переобучайте индекс, если распределение сильно изменилось.
- **Метрика:** для косинуса обязательно нормализуйте и используйте IP-режим (и при `train`, и при `add`, и при `search`).
- **Стабильность обучения:** увеличивайте размер обучающей выборки (десятки или сотни тысяч), чтобы k-means дал устойчивые центроиды и кодбуки.
