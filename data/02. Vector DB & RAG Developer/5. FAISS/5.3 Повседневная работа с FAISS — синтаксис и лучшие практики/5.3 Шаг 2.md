## Точный поиск в FAISS: IndexFlatL2 и IndexFlatIP, косинусная близость

Этот шаг — фундамент для всех следующих индексов. Мы разберём, как устроен **точный** kNN-поиск в FAISS на плоских индексах `IndexFlatL2` и `IndexFlatIP`, чем отличаются метрики, как корректно считать косинусную близость, что возвращает FAISS в массиве `D`, как работает батч-поиск, и как контролировать многопоточность на CPU.

### 1) Два базовых плоских индекса

- `IndexFlatL2(d)` — точный поиск ближайших соседей по **L2** (евклидовой) метрике.
- `IndexFlatIP(d)` — точный поиск по **inner product** (скалярному произведению), максимум — лучше.


Плоский индекс ничего «умного» не строит: он хранит исходные векторы и при поиске сравнивает запрос со *всеми* векторами коллекции. Это даёт 100% точность (по выбранной метрике), но время запроса растёт линейно с размером базы.

#### API-минимум

- `index = faiss.IndexFlatL2(d)` *или* `faiss.IndexFlatIP(d)`
- `index.add(xb)` — добавить базу векторов `xb` формы `(N, d)`
- `D, I = index.search(xq, k)` — найти `k` соседей для запросов `xq` формы `(Q, d)`
- `index.ntotal` — сколько векторов хранится
- `index.reset()` — очистить индекс
- `index.is_trained` — у `IndexFlat*` всегда `True` (тренировка не требуется)

    import numpy as np, faiss

    d = 768
    xb = np.load("data/xb.npy").astype('float32')  # (N, d)
    xq = np.load("data/xq.npy").astype('float32')  # (Q, d)
    k  = 10

    # L2
    index_l2 = faiss.IndexFlatL2(d)
    index_l2.add(xb)
    D_l2, I_l2 = index_l2.search(xq, k)   # D_l2 — МЕНЬШЕ лучше (квадрат L2)

    # Inner Product
    index_ip = faiss.IndexFlatIP(d)
    index_ip.add(xb)
    D_ip, I_ip = index_ip.search(xq, k)   # D_ip — БОЛЬШЕ лучше (скалярное произведение)

### 2) Что такое «расстояния» в FAISS и почему это важно

- **L2:** `IndexFlatL2` возвращает *квадрат* евклидовой дистанции: `D = ||x - y||^2`. Это быстрее и не меняет порядок соседей. При постобработке помните, что это не «корень из суммы квадратов».
- **Inner Product:** `IndexFlatIP` возвращает само скалярное произведение `x·y`. Здесь **больше — лучше** (в отличие от L2, где меньше — лучше).


На практике это влияет на пороги фильтрации и интерпретацию качества: не сравнивайте значения из `D_l2` и `D_ip` между собой как «одинаковые расстояния» — это разные величины и разные шкалы.

### 3) Косинусная близость правильно

В FAISS нет отдельного «косинусного индекса». Корректный способ — использовать IP на **L2-нормализованных** векторах:

    def l2_normalize(a: np.ndarray) -> np.ndarray:
        norms = np.linalg.norm(a, axis=1, keepdims=True)
        norms = np.maximum(norms, 1e-12)          # защита от деления на 0
        return (a / norms).astype('float32')

    xbn = l2_normalize(xb)
    xqn = l2_normalize(xq)

    index_cos = faiss.IndexFlatIP(d)              # IP + нормализация => косинус
    index_cos.add(xbn)
    D_cos, I_cos = index_cos.search(xqn, k)       # БОЛЬШЕ — лучше (cosine similarity)

#### Почему это работает

Для единично-нормированных векторов `||x||=||y||=1` верно: `||x - y||^2 = ||x||^2 + ||y||^2 - 2(x·y) = 2(1 - cosθ)`. Значит, упорядочение по **максимальному** `x·y` эквивалентно упорядочению по **минимальному** L2, и эквивалентно максимуму косинуса. Поэтому IP на нормализованных векторах — это именно косинусная близость.

#### Частые ловушки

- Нулевые векторы: добавляйте эпсилон к норме (см. код выше).
- Смешивание нормализованных и ненормализованных данных в одном индексе — это некорректно.
- Не «нормализуйте ещё раз» запросы, если база уже нормализована (и наоборот, нормализация должна быть симметричной).


### 4) Батч-поиск и форма входов

`search` принимает сразу много запросов `xq` формы `(Q, d)`. FAISS эффективно векторизует вычисления, поэтому 512 запросов за один вызов часто быстрее, чем 512 вызовов по одному запросу.

    Q = 512
    xq_many = xq[:Q]               # (Q, d)
    D, I = index_l2.search(xq_many, k)
    assert D.shape == (Q, k) and I.shape == (Q, k)

Если память ограничена — разбивайте `xq` на разумные чанки (например, по 1–10 тыс. запросов). На CPU FAISS использует BLAS-ядра и OpenMP-параллелизм.

### 5) Скорость, память и масштабируемость

#### Временная сложность

- **Добавление:** `add` — линейное по числу векторов, приблизительно `O(N·d)`.
- **Поиск:** для каждого запроса точный flat-kNN — `O(N·d)`. Для `Q` запросов — `O(Q·N·d)`.


#### Память

Плоский индекс хранит вектора как `float32`: ровно `N·d·4` байта (без учёта накладных). Пример: `N=100k`, `d=768` → ~293 MB. Это важно при выборе железа и при миграции к IVF/IVFPQ.

#### Когда flat уместен

- **Небольшие коллекции** (до сотен тысяч векторов) и/или щедрые CPU/GPU.
- **Эталон качества**: используйте flat для оценки `Recall@K` у приближённых индексов.
- **Онлайновые** сценарии с малым N или большим Q (батчи) — благодаря векторизации и потокам.


### 6) Многопоточность на CPU

FAISS обычно собирают с поддержкой OpenMP. Количество потоков можно управлять:

    import faiss
    faiss.omp_set_num_threads(8)   # подберите под вашу машину

- Чем больше потоков, тем выше пропускная способность, но следите за конкуренцией ресурсов (кэш/память).
- Для воспроизводимости бенчмарков фиксируйте число потоков.


### 7) Семантика индексов в выдаче и соответствие объектам

Массив `I`, который возвращает `search`, содержит **позиционные индексы** в вашей матрице `xb` (0…N−1). Если вам нужны «внешние» ID (например, UUID документов) — оборачивайте индекс в `IndexIDMap`. Мы подробно разберём это в отдельном шаге (ID и операции удаления).

### 8) Range Search (по порогу), когда нужен не kNN

Помимо k-ближайших соседей, можно искать по порогу расстояния/похожести:

    # для L2 (меньше - лучше): порог по квадрату L2
    radius = 0.75
    lims, D, I = index_l2.range_search(xq[:10], radius)
    # для IP (больше - лучше): порог по скалярному произведению
    tau = 0.6
    lims_ip, D_ip, I_ip = index_ip.range_search(xq[:10], tau)

Возврат `range_search` — сжатый формат списков: для запроса `q` релевантные элементы — срез `D[lims[q]:lims[q+1]]` и `I[lims[q]:lims[q+1]]`. Это удобно для постановок типа «верни всех ближе порога».

### 9) Типичные ошибки при работе с плоскими индексами

- **Неправильный dtype:** массивы должны быть `np.float32`; иначе — ошибки или лишние копии.
- **Не-contiguous память:** используйте `np.ascontiguousarray` для `xb` и `xq`.
- **Смешение метрик:** не интерпретируйте `D` от L2 и IP одинаково; у них разные смыслы и шкалы.
- **Косинус без нормализации:** `IndexFlatIP` без нормализации — это *не* косинус.
- **«Пропали ID»:** помните, что `I` — это позиции; внешние идентификаторы требуют `IndexIDMap`.
