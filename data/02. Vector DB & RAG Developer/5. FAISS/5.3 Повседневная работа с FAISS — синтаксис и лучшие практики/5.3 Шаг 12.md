## Итоговый мини-проект: end-to-end пайплайн (индексация → поиск → гибрид → re-rank → метрики)

В этом шаге собираем целостную систему вокруг FAISS: офлайн-индексация (IVF/IVFPQ/HNSW), снапшоты и «blue/green» переключение, онлайновый поиск с фильтрами и гибридным скориングом, доранжировка top-кандидатов и подсистема метрик. Ниже — архитектура, рекомендации по параметрам, кодовые скелеты и чек-листы эксплуатации (без самопроверок).

### 1) Архитектура мини-проекта

- **Embeddings**: модуль генерации эмбеддингов (батчи, нормализация для косинуса).
- **FAISS Index**: IVFFlat/IVFPQ/OPQ/HNSW + *IndexIDMap*, сериализация/снапшоты.
- **Metadata Store**: внешняя БД/kv-хранилище (по ключу = внешний `int64/uuid` ID).
- **Search API**: сервис, который принимает запрос, делает векторный retrieve с запасом (K′), фильтры/ACL, гибрид с BM25, re-rank, отдаёт документы.
- **Evaluator**: офлайн-каркас метрик (Recall@K, nDCG@K, p50/p95), грид-поиск параметров.
- **Ops**: снапшоты, blue/green swap, логирование/метрики, CI для регрессий качества.

### 3) Офлайн-индексация: пайплайн build → snapshot

1. **Чанкинг и эмбеддинг**: разбейте длинные тексты на фрагменты (например, 256–512 токенов), приведите к `float32`, *C-contiguous*.
2. **Нормализация** (если косинус/IP): одинаково для *train/add/search*.
3. **Выбор индекса**: IVFPQ/OPQ для экономии RAM, IVFFlat для простоты/качества, HNSW для минимальной задержки.
4. **Train → Add**: IVF/IVFPQ обучите на репрезентативной подвыборке (≥ 30–50× `nlist`), затем `add_with_ids`.
5. **Снапшот**: `write_index()` + JSON-манифест параметров и метрик билда; версионирование по времени.

    import faiss, json, time, numpy as np, os

    def build_ivfpq(xb, ids, d, nlist=8192, m=16, nbits=8, metric=faiss.METRIC_INNER_PRODUCT):
        quant = faiss.IndexFlatIP(d) if metric==faiss.METRIC_INNER_PRODUCT else faiss.IndexFlatL2(d)
        idx = faiss.IndexIVFPQ(quant, d, nlist, m, nbits, metric)
        tr = min(200_000, xb.shape[0])
        idx.train(xb[:tr])
        idmap = faiss.IndexIDMap(idx)
        idmap.add_with_ids(xb, ids.astype("int64"))
        return idmap

    def snapshot(index, path_dir, manifest):
        os.makedirs(path_dir, exist_ok=True)
        ts = time.strftime("%Y%m%d_%H%M%S")
        pidx = f"{path_dir}/index_{ts}.faiss"
        faiss.write_index(index, pidx)
        with open(f"{path_dir}/manifest_{ts}.json", "w", encoding="utf-8") as f:
            json.dump(manifest|{"snapshot": ts}, f, ensure_ascii=False, indent=2)
        return pidx

### 4) Blue/Green переключение

- **Green** грузится параллельно, прогревается тестовыми запросами.
- **Swap**: атомарная замена ссылки в сервисе; старую версию удаляете после дренажа соединений.

    class FaissHolder:
        def __init__(self, idx): self._idx = idx
        def search(self, xq, k): return self._idx.search(xq, k)
        def swap(self, new_idx): self._idx = new_idx  # атомарная замена ссылки

### 6) Конфигурирование и воспроизводимость

- **Единый конфиг** (YAML/JSON): *d, metric, nlist, nprobe, m, nbits, efSearch*, флаги нормализации, размеры K/K′/R, веса гибрида.
- **Сиды**: фиксируйте RNG (numpy/к-means/OPQ) при билде; сохраняйте сид в манифесте.
- **Манифест снапшота**: параметры индекса, дата/версия эмбеддера, количество документов, базовые метрики (Recall@K, p95).


### 7) Подсистема метрик и регрессии качества

- **Офлайн-метрики**: Recall@K, nDCG@K против эталона (Flat на поднаборе).
- **Онлайн-метрики**: p50/p95 поиска, длина очередей, доля отфильтрованных, тайм-ауты БД.
- **CI**: прогон набора «контрольных» запросов на старом/новом индексах, проверка, что раскладка по метрикам не деградировала > заданного порога.


### 8) Масштабирование: шардинг/репликация

- **Репликация** — для роста QPS (несколько копий индекса на разных узлах/ГПУ).
- **Шардинг** — для роста N (разделение базы; *IndexShards* или уровень сервиса; merge top-K на агрегаторе).
- **Смешанные схемы** — «R×S»: S-шардов × R-реплик по каждому шару.


### 9) Надёжность и ошибки

- **Fail-safe загрузка**: два пути снапшотов (current / previous), быстрый откат.
- **Атомарное I/O**: писать во временный путь, затем *rename*.
- **Контроль памяти**: оцените RAM для выбранного индекса + графов/кодбуков; мониторьте OOM.
- **Тайм-ауты**: лимиты на этапах *search → hybrid → rerank → metadata*, возврат частичного результата при нужде.
