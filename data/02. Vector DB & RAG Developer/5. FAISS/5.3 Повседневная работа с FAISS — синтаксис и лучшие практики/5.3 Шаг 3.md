## IVF с нуля: IndexIVFFlat — кластеризация, nlist, nprobe, train → add → search

В этом шаге переходим от точного flat-поиска к ускоренным индексам семейства **IVF** (Inverted File). Базовая идея: мы заранее «грубо» разбиваем пространство на *nlist* ячеек (кластеров), а при запросе ищем не по всей базе, а только в *nprobe* ближайших ячейках. Это резко снижает число сравниваемых векторов и ускоряет поиск в обмен на небольшое падение полноты (recall).

### 1) Архитектура IVF по шагам

1. **Квантайзер (coarse quantizer).** Это плоский индекс (обычно `IndexFlatL2` или `IndexFlatIP`), который хранит центроиды кластеров и умеет быстро находить ближайшие центроиды к любому вектору.
2. **Кластеризация.** Алгоритм k-means на обучающих примерах строит *nlist* центроидов. Каждому базовому вектору сопоставляется ближайший центроид → он попадает в соответствующий «инвертированный список» (ячейку).
3. **Поиск.** Для запроса ищем ближайшие *nprobe* центроидов и сравниваем запрос только с векторами, лежащими в выбранных ячейках.


Конструктивно это класс `IndexIVFFlat`: «IVF» — инвертированные списки, «Flat» — в ячейках лежат оригинальные векторы без сжатия (точные расстояния внутри выбранных ячеек).

### 2) Ключевые параметры: `nlist` и `nprobe`

- **nlist** — число ячеек (кластеров). Чем больше, тем тоньше разбиение: меньше средний размер ячейки, выше потенциальная скорость при фиксированном *nprobe*, но дороже обучение и метаданные. На практике часто берут порядок *~√N* до *нескольких × √N* (уточняйте под задачу и железо).
- **nprobe** — сколько ячеек просматривать при поиске. Чем больше *nprobe*, тем выше recall (и медленнее). Значения от ~1% до 10–20% от *nlist* — частый стартовый диапазон; подбирается эмпирически.


В пределе `nprobe = nlist` вы приближаетесь к полному перебору (как Flat), а при очень малом `nprobe` можете сильно потерять полноту. Баланс определяется требованиями к задержке/качеству.

### 3) Жизненный цикл IVF-индекса

1. **Создать квантайзер.** Обычно `IndexFlatL2(d)` для L2 или `IndexFlatIP(d)` для IP.
2. **Сконструировать IVF-индекс.** `IndexIVFFlat(quantizer, d, nlist, metric)`.
3. **Обучить** на подвыборке: `index.train(train_vectors)`. Без обучения поиск невозможен.
4. **Добавить** базу: `index.add(xb)` (или `add_with_ids` через `IndexIDMap`).
5. **Настроить** `nprobe` и выполнять `search`.


### 4) Обучающая выборка: сколько и какие векторы брать

- **Размер.** Чем больше данных — тем устойчивее k-means. Правило практики: хотя бы *~30–50 × nlist* обучающих векторов (минимум — не меньше *10 × nlist*), верхняя планка часто в районе 100–200k.
- **Репрезентативность.** Семплируйте равномерно из всей базы (или по сегментам/классам пропорционально), чтобы не получить «пустые» или перегруженные ячейки.
- **Предобработка.** Для косинуса нормализуйте обучающую и базовую выборки одинаково.


### 5) Пример: L2-поиск с `IndexIVFFlat`

    import numpy as np, faiss

    # данные из предыдущих шагов
    xb = np.load("data/xb.npy").astype('float32')
    xq = np.load("data/xq.npy").astype('float32')
    d  = xb.shape[1]
    k  = 10

    # 1) квантайзер и IVF-индекс
    nlist = 1024
    quantizer = faiss.IndexFlatL2(d)
    index = faiss.IndexIVFFlat(quantizer, d, nlist, faiss.METRIC_L2)

    # 2) обучение (обязательно!)
    # берём репрезентативную подвыборку; если N невелико, можно train на всей базе
    rng = np.random.default_rng(42)
    train_sz = min(100_000, xb.shape[0])
    train_idx = rng.choice(xb.shape[0], size=train_sz, replace=False)
    index.train(xb[train_idx])

    # 3) добавление базы и настройка nprobe
    index.add(xb)
    index.nprobe = 32  # попробуйте 8, 16, 32, 64 — дальше подберём в метриках

    # 4) поиск
    D, I = index.search(xq, k)

### 6) Пример: косинусная близость через IP-режим

Для косинуса используем **нормализацию** + `METRIC_INNER_PRODUCT` и квантайзер `IndexFlatIP`.

    import numpy as np, faiss

    def l2_normalize(a: np.ndarray) -> np.ndarray:
        n = np.linalg.norm(a, axis=1, keepdims=True)
        n = np.maximum(n, 1e-12)
        return (a / n).astype('float32')

    xb = np.load("data/xb.npy").astype('float32')
    xq = np.load("data/xq.npy").astype('float32')
    xbn, xqn = l2_normalize(xb), l2_normalize(xq)
    d, k = xbn.shape[1], 10

    nlist = 2048
    quantizer = faiss.IndexFlatIP(d)
    index = faiss.IndexIVFFlat(quantizer, d, nlist, faiss.METRIC_INNER_PRODUCT)

    # train на НОРМАЛИЗОВАННЫХ векторах!
    train_sz = min(150_000, xbn.shape[0])
    index.train(xbn[:train_sz])

    index.add(xbn)
    index.nprobe = 64

    D, I = index.search(xqn, k)  # БОЛЬШЕ — лучше (cosine similarity)

### 7) Производительность, память и формулы «на салфетке»

- **Сложность поиска.** Приблизительно `O(nprobe · (N / nlist) · d)` сравнений вместо `O(N·d)` у Flat. Рост *nlist* уменьшает средний размер ячейки (ускоряет), но увеличивает накладные расходы обучения и выбора ячеек.
- **Память.** `IVFFlat` хранит исходные векторы (как и Flat) плюс лёгкие метаданные списков и центроиды — потребление похоже на Flat с небольшой надбавкой. Если RAM — узкое место, переходите к IVFPQ (сжатие).
- **Latency/Recall-trade-off.** Главный «рычаг» — *nprobe*. Двигайте его и оценивайте Recall@K. *nlist* подбирайте реже (это архитектурный параметр; слишком маленький — медленно, слишком большой — долго train и «пустые» листы).


### 8) Полезные приёмы и мелочи синтаксиса

- **Проверка статуса обучения:** `index.is_trained` должно быть `True` перед `add`/`search`.
- **Тонкая настройка параметров:** через `faiss.ParameterSpace()` можно задавать параметры по имени:

    ps = faiss.ParameterSpace()
    ps.set_index_parameter(index, "nprobe", 32)

- **Стабильность k-means:** для больших *d* и «острых» распределений увеличивайте обучающую выборку; при необходимости задавайте число итераций/перезапусков (через расширенный API кластеризации).
- **Смешение метрик:** метрика квантайзера и метрика индекса должны соответствовать вашей постановке: L2 → `IndexFlatL2` + `METRIC_L2`; косинус → нормализация + `IndexFlatIP` + `METRIC_INNER_PRODUCT`.


### 9) Типичные ошибки и как их избежать

- **Забыли train.** `IndexIVFFlat` не будет работать без `train` — проверяйте `is_trained`.
- **Слишком маленький train-набор.** Получаются «пустые» или пере-заполненные ячейки → слабый recall. Увеличьте размер и репрезентативность.
- **Не тот квантайзер/метрика.** Для косинуса нужен IP-режим и нормализация; L2 и IP взаимозаменяемы только при строжайшей нормализации.
- **Слишком маленький nprobe.** Видите сильное падение recall — увеличьте *nprobe* (начните с 8→16→32→64).
- **Сравнение «скоростей» без батчей.** На CPU/GPU батч-поиск (много запросов сразу) существенно эффективнее одиночных вызовов.


### Итог шага

Вы разобрали концепцию IVF, связь параметров `nlist` и `nprobe` со скоростью и полнотой, корректные схемы для L2 и косинуса, и получили готовые шаблоны кода *train → add → search*. На следующем шаге мы добавим **квантование продукта** (IVFPQ), чтобы радикально уменьшить потребление памяти при приемлемой точности.
