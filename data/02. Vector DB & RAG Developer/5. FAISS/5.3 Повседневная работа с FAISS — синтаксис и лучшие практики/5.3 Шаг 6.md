## Пользовательские ID и связка с внешними данными: IndexIDMap, remove_ids, reconstruct

По умолчанию FAISS возвращает *позиционные* индексы (0…N−1) — это удобные «внутренние» номера строк в вашей матрице `xb`. В продакшене почти всегда нужен собственный идентификатор (документа, объекта, записи в БД). В этом шаге разберём, как правильно работать с пользовательскими ID, удалениями и реконструкцией векторов.

### 1) Зачем нужны пользовательские ID

- **Связь с метаданными.** Индекс хранит только вектор (или его код). Заголовок, текст, ссылка, payload — лежат во внешнем хранилище (БД/объектное хранилище) и выбираются по вашему ID.
- **Стабильные ссылки.** Порядок векторов в индексе может меняться при перезагрузке/слиянии. Внешние ID гарантируют неизменность логических ключей.
- **Удаления/обновления.** Вы удаляете/переиндексируете по своим ID, не зная «внутренних» позиций.


### 2) Базовая схема: IndexIDMap поверх индекса

Оборачиваем любой «векторный» индекс в `IndexIDMap` и используем `add_with_ids`/`remove_ids`. Обёртка хранит биекцию «ID → положение».

    import numpy as np, faiss

    # 1) базовый индекс (любой: Flat, IVFFlat, IVFPQ, HNSW)
    d = 768
    base = faiss.IndexFlatL2(d)

    # 2) обёртка с ID
    index = faiss.IndexIDMap(base)

    # 3) данные
    xb = np.load("data/xb.npy").astype('float32')
    xq = np.load("data/xq.npy").astype('float32')
    ids = np.arange(xb.shape[0], dtype='int64')  # ваши внешние ID (int64)

    # 4) добавление с ID
    index.add_with_ids(xb, ids)

    # 5) поиск: вернутся ваши ID
    k = 10
    D, I = index.search(xq[:5], k)
    print(I[0][:5])  # например: [123 987  42 ...]

Если вы используете IVF/IVFPQ/HNSW — оборачивайте именно «боевой» индекс; логика `search` не меняется, но теперь выдача — ваши ID.

### 3) Удаление по ID: IDSelectorBatch и IDSelectorRange

Метод `remove_ids(selector)` принимает селектор. В Python удобно использовать батч-селектор из массива ID.

    # удалить произвольный набор ID
    to_remove = np.array([10, 42, 99, 123456789], dtype='int64')
    sel = faiss.IDSelectorBatch(to_remove)
    num_removed = index.remove_ids(sel)
    print("removed:", num_removed)

    # удалить диапазон [first, last)
    sel_range = faiss.IDSelectorRange(0, 1000)
    num_removed2 = index.remove_ids(sel_range)

- **Идемпотентность:** удаление не упадёт, если ID отсутствует; просто не удалит ничего.
- **Массовые удаления:** для больших списков используйте батч; это быстрее, чем удалять по одному.
- **IVF и «дырки»:** удаления помечают элементы как «deleted» внутри ячеек; объём индекса не уменьшается. При большом числе удалений планируйте периодическое переобучение/пересборку.


### 4) Реконструкция векторов: reconstruct / reconstruct_n / search_and_reconstruct

Иногда нужно получить исходный (или приближённый) вектор по ID — для отладки, переранжировки или валидации.

    # реконструкция по позиционному индексу (для IDMap — сначала найдите позицию)
    # для удобства используйте IDMap: поиск вернёт ваши ID, но reconstruct принимает внутренний индекс
    # поэтому чаще используют reconstruct_n над "пачкой" позиций

    # Для Flat/HNSW/IVFFlat:
    vec = index.reconstruct(0)            # 1D np.array(dtype=float32), если позиция существует

    # Сразу несколько
    first, n = 0, 5
    mat = index.reconstruct_n(first, n)   # shape: (n, d)

    # Для приближённых (PQ): вектор восстанавливается приблизительно по кодам (residual PQ/OPQ)
    # Если нужна "точная" доранжировка — храните исходные эмбеддинги отдельно.

- **Flat/HNSW/IVFFlat:** реконструкция эквивалентна исходному вектору (без потерь).
- **IVFPQ/OPQ:** реконструкция приблизительна; годится для быстрой дооценки, но не заменяет хранение «оригиналов».


### 5) Прямое отображение (direct map) для IVF

Для индексов семейства IVF существует «прямая карта» (ID → (ячейка, смещение)), ускоряющая удаление и реконструкцию. Её можно включить после построения индекса.

    # пример для IVFFlat
    d = 768
    quantizer = faiss.IndexFlatL2(d)
    ivf = faiss.IndexIVFFlat(quantizer, d, 2048, faiss.METRIC_L2)

    # ... train/add как обычно ...
    ivf.train(xb[:100_000])
    ivf.add(xb)

    # включаем direct map
    ivf.make_direct_map()      # теперь remove_ids/reconstruct работают быстрее

Помните, что direct map — это дополнительные структуры в памяти; включайте её там, где реально нужны быстрые удаления/реконструкции.

### 6) Дублирующиеся ID и политика уникальности

- **FAISS не навязывает уникальность ID.** Вы можете добавить одинаковый ID к нескольким векторам. При поиске они вернутся как «разные элементы с одинаковым ключом».
- **Практика:** в большинстве приложений ID должен быть уникальным. Следите за уникальностью на уровне вашего пайплайна индексации.
- **Удаление дублей:** `remove_ids` удалит все элементы с указанным ID.


### 7) Поток обновлений: шаблон delete+add

«Обновить» вектор по ID напрямую нельзя. Принятый шаблон:

1. Удалить старую версию по ID.
2. Добавить новую версию (`add_with_ids` с тем же ID).


При очень интенсивных апдейтах IVF-гистограммы могут деградировать (несбалансированные ячейки). Планируйте периодическую переиндексацию: заново *train → add* на свежем срезе данных.

### 8) Сериализация: сохраняем/загружаем вместе с ID

`faiss.write_index`/`faiss.read_index` сохраняют/восстанавливают всю структуру, включая ID-карту и «deleted flags». Для GPU-индексов перед сохранением перенесите их на CPU (`index_gpu_to_cpu`), затем пишите на диск.

    # сохранить
    faiss.write_index(index, "faiss_with_ids.faiss")

    # загрузить
    index2 = faiss.read_index("faiss_with_ids.faiss")

### 9) Организация внешних метаданных

- **Отдельное хранилище.** Документы/поля (title, url, текст) храните в БД/kv-хранилище (PostgreSQL, SQLite, DuckDB, LMDB, RedisJSON, S3-объекты).
- **Ключ — ваш ID.** FAISS возвращает список ID — по ним делаете batched lookup метаданных.
- **Консистентность.** Индекс и БД должны обновляться атомарно (или с журналированием транзакций). При падении процесса у вас должен быть «реплей» (лог операций индексации: *upsert* / *delete* по ID).
- **Доранжировка.** Частая схема: FAISS выдаёт кандидатов K′ (например, 100–1000), дальше точная доранжировка по «сырым» векторам или доп. признакам (BM25, время, клики).


### 10) Диагностика и отладка

- **Проверка покрытий:** выберите случайные ID, проверьте, что `search` по их векторам находит самих себя в top-1.
- **Проверка целостности:** после массовых удалений сравните `index.ntotal` и число «живых» элементов по вашей БД.
- **Реконструкция vs оригинал:** на IVFPQ измеряйте L2-ошибку реконструкции; это поможет понять, нужен ли OPQ/другие параметры.
