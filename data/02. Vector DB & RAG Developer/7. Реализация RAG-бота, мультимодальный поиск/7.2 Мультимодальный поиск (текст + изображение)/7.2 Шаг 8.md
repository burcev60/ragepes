### Смешивание сигналов (fusion) — объединяем текст и картинку

**Задача.** У запроса могут быть сразу два канала: текст *qt* и картинка *qi*.
У документа (или экрана) тоже несколько представлений: `image_vector`, `ocr_text_vector`, `caption_vector`.
Нужно объединить их сходства в *один* скор, по которому ранжировать кандидатов.

#### 1) Какие сигналы смешиваем

- `cos_ti` = cos(*qt*, *dimage*) — текст запроса vs вектор изображения;
- `cos_it` = cos(*qi*, *dtext*) — картинка запроса vs текст документа (или caption);
- `cos_to` = cos(*qt*, *docr*) — текст запроса vs OCR-текст;
- (опц.) `cos_tc` = cos(*qt*, *dcaption*).


Все эмбеддинги предполагаются L2-нормированными; метрика индекса — `Cosine`.

- Стартовые веса: `w_t=0.5`, `w_i=0.3`, `w_o=0.2` (если OCR есть), `w_c=0` (если caption не используем).
- **Отсутствующий канал** (например, нет OCR) → соответствующий вес и/или сигнал = 0.
- **Динамическое взвешивание:** если у запроса есть картинка, увеличьте `w_i`; если в тексте видны редкие токены (regexp), поднимите `w_o`.


#### 4) Реранк и диверсификация после fusion

- **Late rerank:** примените к топ-K кросс-энкодер (если есть текстовые поля) или пересчёт CLIP на полном разрешении.
- **MMR (разнообразие):** уберите дубликаты и доминирование одного источника:
  `argmaxd∉S λ·sim(q,d) − (1−λ)·maxe∈S sim(d,e)`,
где `S` — уже выбранные документы, `λ≈0.7`.

#### 5) Мини-пример (на 3 кандидатах)

Дан набор кандидатов с cos-баллами (до нормализации):

| d1 |
| d2 |

Нормализуем min–max отдельно по каждому столбцу (ε=1e−9). Получаем, например, для `cos_to`:
min=0.12, max=0.88 → norm(d1)=1.00, norm(d2)=0.00, norm(d3)=0.39.
При весах wt=0.5, wi=0.3, wo=0.2 суммируем и сортируем — чаще всего топ-1 будет **d1** (сильный OCR-сигнал вытянул его вверх).

#### 6) Псевдокод (склейка + MMR)

    def minmax_norm(xs, eps=1e-9):
        lo, hi = min(xs), max(xs)
        return [(x - lo) / (hi - lo + eps) for x in xs]

    def fuse(scores_ti, scores_it, scores_to=None, scores_tc=None,
             w_t=0.5, w_i=0.3, w_o=0.2, w_c=0.0):
        # scores_*: список из K чисел по кандидатам в одинаковом порядке
        K = len(scores_ti)
        ti = minmax_norm(scores_ti)
        it = minmax_norm(scores_it)
        to = minmax_norm(scores_to) if scores_to is not None else [0.0]*K
        tc = minmax_norm(scores_tc) if scores_tc is not None else [0.0]*K
        return [w_t*ti[k] + w_i*it[k] + w_o*to[k] + w_c*tc[k] for k in range(K)]

    def mmr_rerank(cands, fused_scores, emb_docs, emb_query, lam=0.7, topn=10):
        # cands: список doc_id в порядке кандидатов
        # emb_docs: словарь {doc_id: вектор}, emb_query: вектор
        selected = []
        remaining = set(range(len(cands)))
        # предварительно нормируем emb_docs/emb_query (если нужно)
        def cos(a,b): return (a @ b) / ( (np.linalg.norm(a)+1e-9) * (np.linalg.norm(b)+1e-9) )
        while remaining and len(selected) < topn:
            best, best_score = None, -1e9
            for k in list(remaining):
                d = cands[k]
                rel = fused_scores[k]                      # релевантность по fusion
                div = 0.0 if not selected else max(cos(emb_docs[d], emb_docs[cands[j]]) for j in selected)
                score = lam*rel - (1-lam)*div
                if score > best_score:
                    best, best_score = k, score
            selected.append(best)
            remaining.remove(best)
        return [cands[k] for k in selected]

#### 8) Типичные ошибки

- **Складывают «как есть» без нормализации:** один канал доминирует → перекос. *Фикс:* min–max/z-score или rank-fusion.
- **Суммируют скоры на разных наборах кандидатов:** нарушен порядок соответствий. *Фикс:* сначала *объедините* кандидатов и выровняйте списки.
- **Нет MMR:** в топе — близнецы. *Фикс:* примените MMR с λ≈0.7.
