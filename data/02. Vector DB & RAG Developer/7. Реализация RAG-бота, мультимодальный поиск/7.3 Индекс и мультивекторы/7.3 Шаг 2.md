### Шаг 2. Схема коллекции и параметры индекса

**Цель.** Спроектировать коллекцию под мультимодальные данные: именованные векторы, метрики, индексацию (HNSW), квантование и индексы по payload-полям.

#### 1) Какие векторы храним (имена и размерности)

- `text_vector` — основной текст (SBERT/инстр. эмбеддинги), *384/768*, `Cosine`.
- `title_vector` — заголовки/анкоры (малый энкодер), *384*, `Cosine`.
- `image_vector` — визуальный (CLIP/SigLIP), *512/768*, `Cosine`.
- `ocr_text_vector` — OCR-текст, та же модель, что и для `text_vector`, *384/768*, `Cosine`.
- `caption_vector` — короткое описание картинки, тот же текстовый энкодер, *384*, `Cosine`.


*Важно:* все эмбеддинги L2-нормируем перед записью; размеры могут отличаться между каналами — это ок.

#### 2) Быстрый старт: `schema.json`

Минимальная схема коллекции (Qdrant) с HNSW и возможностью квантования:

    {
      "vectors": {
        "text_vector":   {"size": 384, "distance": "Cosine"},
        "title_vector":  {"size": 384, "distance": "Cosine"},
        "image_vector":  {"size": 512, "distance": "Cosine"},
        "ocr_text_vector":{"size": 384, "distance": "Cosine"},
        "caption_vector":{"size": 384, "distance": "Cosine"}
      },
      "hnsw_config": {"m": 16, "ef_construct": 128},
      "optimizers_config": {"memmap_threshold": 200000},
      "quantization_config": null
    }

- **M** — степень связности графа (память/скорость поиска). Типично `16–32`.
- **ef_construct** — качество индекса при построении (время/память). Типично `64–256`.
- **memmap_threshold** — порог для выноса сегментов на диск (экономия RAM на больших коллекциях).
- **quantization_config** — начните с `null`. Включите позже точечно (см. ниже).


#### 3) Создание коллекции: Python (qdrant-client)

    from qdrant_client import QdrantClient
    from qdrant_client.http.models import Distance, VectorParams, ScalarQuantization, ScalarType

    client = QdrantClient(url="http://localhost:6333", api_key=None)
    COLL = "kb_multivector"

    client.recreate_collection(
        collection_name=COLL,
        vectors_config={
            "text_vector":    VectorParams(size=384, distance=Distance.COSINE),
            "title_vector":   VectorParams(size=384, distance=Distance.COSINE),
            "image_vector":   VectorParams(size=512, distance=Distance.COSINE),
            "ocr_text_vector":VectorParams(size=384, distance=Distance.COSINE),
            "caption_vector": VectorParams(size=384, distance=Distance.COSINE),
        },
        hnsw_config={"m":16, "ef_construct":128},
        optimizers_config={"memmap_threshold":200000},
        # quantization_config можно добавить позже точечно (см. ниже)
    )

    # Индексы по payload-полям для быстрых фильтров (ACL/язык/раздел/даты)
    client.create_payload_index(COLL, field_name="org_id",     field_schema="keyword")
    client.create_payload_index(COLL, field_name="lang",       field_schema="keyword")
    client.create_payload_index(COLL, field_name="section",    field_schema="keyword")
    client.create_payload_index(COLL, field_name="created_at", field_schema="datetime")

*curl (REST) вариант опционален — используйте, если нет Python-клиента.*

#### 4) ef_search: качество ↔ латентность

`ef_search` задаётся на этапе запроса (не в схеме). Чем больше — тем ближе к «точному» k-NN (выше Recall@K), но дольше ответ.

- Стартовые значения: `64` для текста, `32` для image/OCR; поднимайте точечно на «критичном» канале.
- Тюнинг: бенчмаркуйте p50/p95 латентности и Recall@K на валид-наборе (см. урок 6).


#### 5) Квантование (точечно, когда память давит)

Включайте только на «тяжёлых» каналах (`image_vector`) и после замера падения качества:

    from qdrant_client.http.models import ScalarQuantizationConfig

    client.update_collection(
        collection_name=COLL,
        quantization_config={
            "image_vector": ScalarQuantizationConfig(
                type=ScalarType.INT8, quantile=0.99, always_ram=True
            )
        }
    )

- **Scalar INT8**: экономия памяти ~4×, малое падение качества; хороший «первый шаг».
- **PQ** (если используете): ещё сильнее экономит, но чувствительнее к падению Recall — применяйте с осторожностью.
- Квантование разных векторов независимо: можно квантовать `image_vector` и оставить «как есть» `text_vector`.


#### 6) Payload и ACL (многоарендность)

Минимум для продового фильтра:

- `org_id` (организация), `is_public` (флаг), `lang` (язык), `section` (раздел), `created_at/updated_at` (свежесть).
- Индексы по этим полям уже создали выше: фильтры будут <10 мс на больших данных.


#### 7) Проверка схемы и «здоровья» индекса

- После ingest проверьте распределения скорингов (Cosine) по каждому каналу: нет ли перекоса?
- Логи/трассировка: сохраняйте *каким вектором искали*, *каким ef_search*, размер кандидатов, сколько попало в финальный промпт.


#### Мини-практика (2 минуты)

1. Создайте коллекцию с `text_vector`, `image_vector`, `ocr_text_vector`. Индексы по payload: `org_id`, `lang`, `created_at`.
2. Включите *scalar INT8* только на `image_vector`. Зафиксируйте, какой прирост даёт это по RAM (оценочно) и как меняется Recall@10 на вашем валид-наборе.


#### Чек-лист перед переходом к Шагу 3

- Именованные векторы и их размерности определены; метрика — `Cosine`, L2-нормализация включена в ingest.
- Коллекция создана; полезные payload-индексы (ACL/язык/даты) добавлены.
- Стартовые параметры HNSW: `M=16`, `ef_construct=128`; план тюнинга `ef_search` по каналам.
- Понимаете, когда и на какой вектор включать квантование; договорились мерить ΔRecall/латентность.
