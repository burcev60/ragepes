### Шаг 4. Поиск по именованным векторам и межвекторная агрегация (fusion)

**Цель.** Научиться искать по любому каналу (`text_vector`, `image_vector`, `ocr_text_vector`, `caption_vector`) и объединять сигналы в один финальный скор. Сделаем удобный «тонкий» слой: запрос → несколько поисков → нормализация → fusion → (опц.) MMR → JSON-трейс.

#### 1) Режимы запроса

- **Text→Text**: спрашиваем текстом, ищем по `text_vector` (и/или `title_vector`).
- **Text→Image**: текст → `image_vector` (CLIP/SigLIP).
- **Image→Text**: картинка → `text_vector`/`ocr_text_vector`/`caption_vector`.
- **Mixed (text+image)**: одновременно несколько каналов, затем fusion.


*Подсказка:* выставляйте `ef_search` отдельно по каналам (выше для текста, ниже для image) и применяйте фильтры payload (`org_id`, `lang`, `section`).

#### 3) Мини-пример (ручной расчёт)

Имеем трёх кандидатов, сырые cosine по каналам:

| doc | text | image | ocr |
| --- | --- | --- | --- |
| d1 |
| d2 |
| d3 |

Нормализуем min–max в каждом столбце (ε=1e−9):

- text: min=0.55, max=0.74 → d1=0.37, d2=1.00, d3=0.00
- image: min=0.28, max=0.44 → d1=0.19, d2=0.00, d3=1.00
- ocr: min=0.12, max=0.88 → d1=1.00, d2=0.00, d3=0.39


При весах `w_t=0.5`, `w_i=0.3`, `w_o=0.2`:

- d1 = 0.5·0.37 + 0.3·0.19 + 0.2·1.00 = 0.185 + 0.057 + 0.200 = **0.442**
- d2 = 0.5·1.00 + 0.3·0.00 + 0.2·0.00 = **0.500**
- d3 = 0.5·0.00 + 0.3·1.00 + 0.2·0.39 = 0.000 + 0.300 + 0.078 = **0.378**


Топ-3 по fusion: **d2** → **d1** → **d3**. Если поднять вес OCR (например, `w_o=0.35`), топ-1 станет d1.

#### 4) Псевдокод клиента: поиск и fusion

    from qdrant_client import QdrantClient
    import numpy as np

    def minmax(xs):
        lo, hi = min(xs), max(xs)
        return [(x - lo) / (hi - lo + 1e-9) for x in xs]

    def fuse(scores, weights):
        # scores: dict{name -> dict{doc_id -> score}}
        # weights: dict{name -> w}
        # 1) объединяем множество кандидатов
        all_docs = sorted({d for ch in scores.values() for d in ch.keys()})
        # 2) нормализуем по каждому каналу
        norm = {}
        for name, d in scores.items():
            arr = [d.get(doc, float("-inf")) for doc in all_docs]
            # заменим -inf на min наблюдаемого, чтобы нормализация не сломалась
            finite = [x for x in arr if x != float("-inf")]
            fill = min(finite) if finite else 0.0
            arr = [x if x != float("-inf") else fill for x in arr]
            norm[name] = minmax(arr)
        # 3) считаем взвешенную сумму
        fused = {doc: 0.0 for doc in all_docs}
        for name, w in weights.items():
            for i, doc in enumerate(all_docs):
                fused[doc] += w * norm.get(name, [0]*len(all_docs))[i]
        # 4) сортируем
        return sorted(fused.items(), key=lambda kv: kv[1], reverse=True)

    def search_named(client: QdrantClient, coll: str, vector_name: str, vec, k=50, ef_search=64, flt=None):
        return client.search(
            collection_name=coll,
            query_vector=(vector_name, vec),
            with_payload=True, limit=k,
            params={"hnsw_ef_search": ef_search},
            query_filter=flt
        )

    # пример пайплайна:
    # 1) считаем вектор текста запроса q_t, вектор картинки q_i (если есть)
    # 2) делаем 2-3 поиска: ("text_vector", q_t), ("image_vector", q_t) для Text-»Image в CLIP и ("ocr_text_vector", q_t)
    # 3) собираем scores[name][doc_id] = score из выдач
    # 4) выдаём fuse(scores, weights) + (опц.) MMR-постобработку

*Фильтры:* передавайте `query_filter` (например, `org_id == "acme"`, `lang == "ru"`, `created_at >= ...`) для ACL и свежести.

#### 5) Пост-обработка: MMR и ограничение «не более N фрагментов с одного doc_id»

- **MMR** добавьте после fusion для диверсификации (λ≈0.7).
- **max_per_doc**: при построении финального списка ограничьте количество фрагментов от одного `doc_id` (например, ≤2), чтобы не было «залипания» одного источника.

#### Чек-лист готовности

- Для каждого режима (Text→Text, Text→Image, Image→Text) выполнены отдельные поиски по нужным векторам.
- Есть нормализация скорингов *внутри списка* и корректное объединение кандидатов.
- Веса каналов конфигурируемы; предусмотрена отключаемость «шумных» каналов.
- Пост-обработка: MMR и лимит на количество фрагментов на `doc_id` включены.
- Формируется подробный JSON-трейс для отладки и экспорта в модуль 8 (оценка).
