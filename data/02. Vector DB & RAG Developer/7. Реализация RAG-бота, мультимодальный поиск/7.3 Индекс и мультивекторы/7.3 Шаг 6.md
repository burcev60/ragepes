### Шаг 6. Производительность и экспорт для оценки

**Цель.** Настроить индекс на нужные SLA (латентность/память/качество), зафиксировать рабочие параметры и выгружать результаты поиска в формат для оффлайн-оценки (модуль 8).

#### 1) Рычаги тюнинга: что крутить и чем это платится

| Параметр | Влияние | Когда менять |
| --- | --- | --- |
| `ef_search` (на запрос) | ↑Recall@K, ↑латентность (p50/p95) | Поднимайте точечно на «узких» каналах (часто текст), держите ниже на image |
| `M`, `ef_construct` (на построение HNSW) | ↑качество/скорость на чтение, ↑время/память на построение | Поднимать при стабильном корпусе, когда ingest не в критическом пути |
| Квантование (INT8 / PQ) | ↓RAM (вплоть до ×4 и более), ↘ Recall@K | Включать точечно (например, только `image_vector`), после замера Δметрик |
| `memmap_threshold` | ↓RAM, возможный ↑p95 | Для очень больших коллекций, если RAM ограничена |
| Размеры векторов/модели | ↑↓ качество/вес; ↓↑ скорость | Выбирайте минимально достаточный размер (384/512) по валид-набору |

*Рекомендация:* фиксируйте «профили» на канал: `text: ef=64`, `image: ef=32`, `ocr: ef=48` (пример), и держите их конфигурируемыми.

#### 2) Мини-бенч: p50/p95 и Recall@K

Быстрый скрипт, который гоняет поиски по каналам, меряет латентность и оценивает Recall@K по валид-набору (если есть qrels):

    #!/usr/bin/env python3
    import time, json, numpy as np
    from statistics import median
    from qdrant_client import QdrantClient

    def p95(xs):
        xs = sorted(xs);
        return xs[int(0.95*(len(xs)-1))]

    def bench(client, coll, queries, enc_text, k=50, ef=64, channel="text_vector", flt=None):
        lat = []; runs = []
        for q in queries:
            qv = enc_text.encode(q["text"], normalize_embeddings=True)
            t0 = time.perf_counter()
            res = client.search(coll, query_vector=(channel, qv), limit=k, with_payload=False,
                                params={"hnsw_ef_search": ef}, query_filter=flt)
            dt = (time.perf_counter()-t0)*1000
            lat.append(dt)
            runs.append({"query_id": q["id"], "ranking":[{"doc_id":str(p.id), "score":float(p.score)} for p in res]})
        return {"p50_ms": median(lat), "p95_ms": p95(lat), "runs": runs}

    def recall_at_k(run, qrels_for_q, K=10):
        rels = {d for d,r in qrels_for_q if r>0}
        topk = [d["doc_id"] for d in run["ranking"][:K]]
        return 1.0 if any(d in rels for d in topk) else 0.0

    # пример использования:
    # queries = [{"id":"q1","text":"ошибка ERR_1201"}, ...]
    # qrels = {"q1":[("kb-42#img0",1), ...], ...}  # опционально

*Что смотреть:* p50 (типичная задержка), p95 (хвост), средний Recall@K. Делайте сравнение «до/после» изменения ef/квантования *по каналам отдельно*.

#### 3) Кэширование и прогрев

- **Нормализация запросов:** приведите регистр, удалите стоп-символы, стабилизируйте пробелы — повысит кэш-хитрейт.
- **Кэш кандидатов:** кешируйте топ-*K* doc_id/score для частых запросов (ключ = нормализованный запрос + фильтры ACL).
- **Кэш «пассажей» после реранка:** если используете cross-encoder — кешируйте top-R итогов.
- **Прогрев:** загрузите FAQ/популярные запросы в кэш на старте сервиса.
- **Инвалидация:** при обновлении корпуса инвалидируйте ключи по `section/lang/org_id` (простая стратегия: версионный суффикс в ключе).

#### 5) Экспорт для модуля 8: `runs.jsonl` (+ `queries.csv`)

Экспортируйте результаты поиска в формат, ожидаемый уроками оценки (8.1–8.3):

- `queries.csv`: *query_id,text* (или путь к картинке для Image→Text).
- `runs.jsonl`: по строке на запрос — `{"query_id": "...", "ranking":[{"doc_id":"...", "score": ...}, ...]}`

    import csv, json
    from qdrant_client import QdrantClient
    from sentence_transformers import SentenceTransformer

    def export_runs(queries_csv, out_jsonl, client: QdrantClient, coll: str, enc_text,
                    k=100, ef=64, channel="text_vector", flt=None):
        with open(queries_csv, newline="", encoding="utf-8") as f, \
             open(out_jsonl, "w", encoding="utf-8") as w:
            reader = csv.DictReader(f)
            for row in reader:
                qid, qtext = row["query_id"], row["text"]
                qv = enc_text.encode(qtext, normalize_embeddings=True)
                res = client.search(coll, query_vector=(channel, qv), limit=k, with_payload=False,
                                    params={"hnsw_ef_search": ef}, query_filter=flt)
                ranking = [{"doc_id": str(p.id), "score": float(p.score)} for p in res]
                w.write(json.dumps({"query_id": qid, "ranking": ranking}, ensure_ascii=False) + "\n")

#### 6) Быстрые правила принятия решения

- **Если p95 > SLA** и Recall@10 норм — снижайте `ef_search` на «дорогом» канале, включайте кэш, подумайте о квантовании именно этого канала.
- **Если Recall@10 низкий, а p95 ок** — поднимайте `ef_search` на тексте, включайте гибрид (добавьте OCR/caption в fusion), проверьте чанкинг.
- **Если RAM не хватает** — поднять `memmap_threshold`, включить INT8 на image, сократить размер векторов/модель.
