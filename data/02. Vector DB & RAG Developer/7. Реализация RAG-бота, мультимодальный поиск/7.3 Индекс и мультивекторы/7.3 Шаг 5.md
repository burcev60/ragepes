### Шаг 5. Фильтры и ACL: многоарендность без дубликатов

**Цель.** Научиться ограничивать выдачу по метаданным (язык, раздел, «свежесть», организация), изолировать данные арендаторов (ACL) и контролировать «залипание» одного источника в топ-выдаче.

#### 1) Многоарендность: варианты дизайна

- **Одна коллекция, поле `org_id`** (рекомендуемый по умолчанию): простая эксплуатация, общий кэш индекса; фильтруем по `org_id` в каждом запросе.
- **Отдельные коллекции на арендатора**: полная изоляция и масштабирование по коллекциям; сложнее эластично распорядиться RAM/CPU.
- **Гибрид**: общий «публичный» индекс + частные индексы арендаторов; ищем в обоих и сливаем (late fusion).


*Практический совет:* начинайте с одной коллекции и строгих фильтров по `org_id` + `is_public`. При росте трафика выведите «тяжёлых» арендаторов в отдельные коллекции.

#### 2) Базовые фильтры payload (язык, раздел, свежесть)

Добавим индексы по полям (мы сделали это в шаге 2) и используем `query_filter` в поиске:

    from qdrant_client import QdrantClient
    from qdrant_client.http.models import Filter, FieldCondition, MatchValue, Range

    client = QdrantClient("http://localhost:6333")
    COLL = "kb_multivector"

    flt = Filter(
        must=[
            FieldCondition(key="org_id",   match=MatchValue(value="acme")),
            FieldCondition(key="lang",     match=MatchValue(value="ru")),
            FieldCondition(key="section",  match=MatchValue(value="install")),
            FieldCondition(key="created_at", range=Range(gte="2025-01-01T00:00:00Z")),
        ],
        must_not=[
            FieldCondition(key="is_deleted", match=MatchValue(value=True))
        ]
    )

    res = client.search(
        collection_name=COLL,
        query_vector=("text_vector", q_text),
        query_filter=flt,
        limit=50,
        params={"hnsw_ef_search": 64},
        with_payload=True
    )

- **`must`** — обязательные условия (ACL, язык, раздел).
- **`must_not`** — отрицательные условия (soft-delete, черновики и т.п.).
- **`Range`** — фильтр по дате/числу (например, «только свежие»).


#### 3) ACL на практике: не доверяйте клиенту

- Строите `Filter` на бэкенде (по токену пользователя), а не принимаете «готовый» от фронта.
- Всегда добавляйте `org_id` и (если нужно) `user_id` в `must`; защищайте «публичные» данные флагом `is_public`.
- Проверяйте, что в ответ не попали payload, к которым нет прав (например, скрытые разделы).


#### 4) Борьба с дублями: ограничение «не более N фрагментов с одного doc_id»

Серверного «group by» может не быть — сделаем это на клиенте после поиска (и после fusion, если мультимодальность):

    def limit_per_doc(scored, max_per_doc=2):
        """
        scored: [(doc_id, point_id, score, payload), ...] в порядке убывания score
        """
        taken_by_doc, out = {}, []
        for item in scored:
            doc = item[0]
            cnt = taken_by_doc.get(doc, 0)
            if cnt < max_per_doc:
                out.append(item)
                taken_by_doc[doc] = cnt + 1
            if len(out) >= 10:  # например, собираем топ-10
                break
        return out

*Совместите* это с MMR (см. шаг 4): сначала MMR для разнообразия, затем ограничение по `doc_id` — или наоборот, если у вас много коротких фрагментов из одного документа.

#### 5) Soft-delete и безопасные обновления

- **Soft-delete**: помечаем запись и исключаем её фильтром, физическое удаление — в бэкграунде.

    client.set_payload(
        collection_name=COLL,
        payload={"is_deleted": True},
        points_selector=Filter(
            must=[FieldCondition(key="doc_id", match=MatchValue(value="kb-42"))]
        )
    )

- **Частичные обновления**: добавляйте новые именованные векторы (`ocr_text_vector`, `caption_vector`) *без* перезаписи остальных полей — через обычный `upsert` той же точки.


#### 6) Паттерны смешивания «публичного» и «частного» индекса

1. Делаем два поиска: в публичном и в приватном (с `org_id`), забираем по K кандидатов.
2. Складываем в общий пул, помечая происхождение (`source_index: "public"|"private"`).
3. Применяем нормализацию + fusion + MMR + *limit_per_doc*; при равенстве баллов чуть бустим «private».

    weights = {"text":0.5, "image":0.3, "ocr":0.2}
    cands_public  = search_named(..., coll="kb_public", ...)
    cands_private = search_named(..., coll="kb_multivector", query_filter=flt, ...)

#### 7) Быстрые рецепты фильтров

| Задача | Условие фильтра |
| --- | --- |
| Выдавать только русские «свежие» материалы | `lang == "ru"` и `created_at >= <ISO-дата>` |
| Исключить черновики и удалённые | `must_not: is_draft==true, is_deleted==true` |
| Ограничить разделом и организацией | `org_id == "<tenant>"` и `section in {"install","search"}` |
| Показывать только документы с OCR | наличие ключа `ocr` в payload → храните флаг `has_ocr=true` и фильтруйте по нему |

#### 8) Мини-практика (2–3 минуты)

1. Соберите фильтр: **org_id=acme**, **lang=ru**, **created_at ≥ 2025-01-01**, **не is_deleted**. Выполните поиск и верните топ-10 с *не более 2* фрагментов на `doc_id`.
2. Расширьте пайплайн до «публичный + приватный индекс»: верните общий топ-10, отметьте, из какого индекса пришёл каждый результат.


#### Чек-лист готовности

- Все запросы снабжаются серверным ACL-фильтром (`org_id`, `is_public`, опц. `user_id`).
- Есть фильтрация по языку/разделу/дате, soft-delete исключается через `must_not`.
- Включено ограничение «не более N фрагментов с одного `doc_id`» и MMR-диверсификация.
- Смешивание публичного/частного индекса реализовано через late-fusion c прозрачной трассировкой происхождения результатов.
