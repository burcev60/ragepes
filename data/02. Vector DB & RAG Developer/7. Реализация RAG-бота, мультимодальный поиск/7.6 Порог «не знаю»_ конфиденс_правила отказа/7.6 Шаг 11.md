## RAG: «Отвечай по PDF с цитатами»

**Бизнес-цель:** бот поддержки Shoply должен отвечать на вопросы о доставке и возвратах **строго по документам**, каждый ключевой факт подтверждать **цитатой** (источник + страница + фрагмент), а вне базы — честно говорить «не знаю» (fallback из М2).

## Что сделать (за 1 спринт)

1. **Собрать индекс** из 2 PDF (локально, без внешних БД).

2. **Сделать ретривер** (MMR/top-k) и цепочку «контекст → ответ».

3. **Вернуть структурированный ответ**:

  - `answer` — краткий ответ в голосе бренда (из М2),

  - `citations[]` — массив объектов `{source, page, snippet}`,

  - `confidence` — `low|medium|high`.

4. **Интегрировать в чат** из М1–М2 (команда `/order` должна остаться рабочей).

5. **Смоделировать автооценку**: прогнать 10 запросов и сохранить отчёт `reports/rag_eval.json` с метрикой pass-rate.

## Ограничения и требования

- **Документы:** использовать два PDF с политиками:

  - `policy_returns.pdf` (о возвратах),

  - `shipping_terms.pdf` (о доставке).  
Разрешено: взять свои реальные документы **или** сгенерировать PDF из следующего текста (без изменений по смыслу):

  - Возвраты: «Возврат возможен в течение 14 календарных дней после получения. Товар — в оригинальной упаковке, с чеком, без следов использования. Возврат средств — тем же способом оплаты в течение 7 рабочих дней после поступления на склад. Обратная пересылка не компенсируется, если дефект не подтверждён.»

  - Доставка: «Стандартная доставка — 2–5 рабочих дней. Экспресс — 24–48 часов в крупных городах. Изменить адрес можно до отгрузки. ПВЗ: хранение 5 дней.»

- **Эмбеддинги:** OpenAI `text-embedding-3-small` (или эквивалент по качеству/стоимости).

- **Ретриер:** k=4, допускается MMR; чанкование ~500–800 символов, overlap 100–150.

- **Стиль:** соблюдать tone из `style_guide.yaml` (Модуль 2).

- **Поведение вне базы:** использовать fallback-фразу из гайда М2, без «догадок».

- **Производительность:** среднее время ответа ≤ 3 сек на локальной машине (±), логировать длительность.

- **Логи:** писать JSON-логи в `logs/` (вопрос, ответ, citations, latency).

## Интерфейсы (контракты проверки)

- **CLI чат:** `python app_rag.py`

  - Вопросы на естественном языке → печатает `answer` и список цитат.

  - Команда `/order <id>` — должна работать, как в М1 (можно читать из `data/orders.json`).

- **Функция ответа:** `ask_rag(question) -> dict`  
Возвращает JSON-объект строго с полями:

    {
      "answer": <str>,
      "citations": [{"source": <str>, "page": <int>, "snippet": <str>}, ...],
      "confidence": "low|medium|high"
    }

   

- **Построение индекса:** команда `python src/build_index.py` создаёт/обновляет `vectordb/` и печатает количество чанков.

- **Отчёт по автооценке:** команда `python src/rag_eval.py` формирует `reports/rag_eval.json` вида:

    { "pass_rate": <number 0..100>, "items": [ { "q": <str>, "pass": <bool>, "oos": <bool>, ... }, ... ] }

   

## Набор проверочных запросов

Обязательные к покрытию (должны давать цитаты):

- «Сколько дней на возврат?» → цитата из *policy_returns.pdf*.

- «Сколько идёт стандартная доставка?» → цитата из *shipping_terms.pdf*.

- «Можно ускорить доставку? На сколько?» → *shipping_terms.pdf*.

- «Компенсируете обратную пересылку без подтверждённого брака?» → *policy_returns.pdf*.  
Вне базы (должен срабатывать fallback):

- «Принимаете криптовалюту?»

- «Есть ли доставка дронов?»
> В репозитории положите **ещё 4 своих** вопроса (2 в базе, 2 вне базы) в `data/eval_prompts.txt`.

## Критерии оценки

- ✅ **Функциональность (40%)**: ответы по документам, минимум 1 релевантная цитата, корректный fallback вне базы.

- ✅ **Качество ответов (20%)**: попадание в tone бренда из М2, краткость, ясность.

- ✅ **Надёжность (15%)**: логирование, обработка пустого индекса/ошибок, разумные значения `confidence`.

- ✅ **Производительность (10%)**: средняя латентность ≤ 3 сек, k/чанк-параметры задокументированы.

- ✅ **Автооценка (15%)**: `pass_rate ≥ 80%` на видимых кейсах; понятный `reports/rag_eval.json`.

**Бонус (до +10%)**

- Ререранк цитат (например, по длине/релевантности) с объяснением в README.

- Пороговое «не знаю» по числу/качеству цитат (например, если все сниппеты слишком короткие/неуверенные).

## Частые ошибки (подсказки)

- Слишком длинные чанки → «размазанные» цитаты и рост стоимости.

- Игнор `page` в цитатах — преподаватель не сможет быстро сверить факт.

- Fallback формулируется не по гайду М2.

- Отсутствует `eval_prompts.txt` → `rag_eval.json` нечем прогонять.
