**Шаг 3: Интеграция в LangChain Retriever**  
*Цель шага:* Научиться интегрировать гибридный поиск и реранк в инструментальный стек LangChain. Понять, как настроить кастомный **Retriever** в LangChain, который под капотом выполняет два вида поиска и использует кросс-энкодер для сортировки.

**Объяснение:**  
В экосистеме LangChain модуль извлечения знаний представлен интерфейсом **Retriever** (ретривер). Ретривер – это компонент, который по входному вопросу возвращает список релевантных документов. Обычно это оболочка над одной техникой поиска (например, вызов векторной базы или запрос в SQL-базу знаний). Однако LangChain позволяет создавать составные ретриверы, объединяющие несколько источников данных или этапов обработки.

Для реализации гибридного поиска есть два подхода:

1. **Комбинировать результаты нескольких ретриверов.** LangChain предоставляет класс `EnsembleRetriever` или возможность вручную вызвать несколько ретриверов и слить их результаты. Мы можем настроить два ретривера: первый – на основе векторного хранилища (например, FAISS/Qdrant), второй – на основе текстового поискового индекса (например, ElasticSearch с BM25). После получения списков документов их можно объединить (объединением множеств ID документов или конкатенацией списков с пометкой источника) и отсортировать. Сортировку можно выполнить либо простым чередованием (как RRF), либо вызвать третий компонент – **реранкер**. Например, можно использовать `ContextualCompressionRetriever` с `CrossEncoderReranker` как описано выше, чтобы переупорядочить объединенный список документов согласно релевантности.

2. **Использовать возможности векторной базы с гибридным поиском.** Некоторые современные векторные базы данных (Weaviate, Elastic, Qdrant) поддерживают **гибридные запросы** напрямую. Например, в Qdrant Query API можно одним запросом указать и фильтр по ключевому поиску, и векторный скор, получив взвешенную комбинацию. LangChain-интеграция таких хранилищ позволяет задавать параметры hybrid search. Если используемый стор (например, ElasticSearch) умеет сразу возвращать мешаный результат BM25+Vector, можно обойтись без двух отдельных ретриверов – достаточно правильно сконфигурировать запрос.

В нашем курсе, однако, ценность образовательная – поэтому мы реализуем явный pipeline: два поиска + явный реранк. Мы создадим свой ретривер, который внутри метода `get_relevant_documents(query)` сначала вызывает оба механизма, потом объединяет и ранжирует результаты. Этот ретривер можно зарегистрировать в LangChain как кастомный (через наследование от `BaseRetriever`). Тогда любую стандартную QA-цепочку (например, RetrievalQA) можно скормить наш гибридный ретривер вместо простого, и она прозрачно будет пользоваться улучшенным поиском.

**Пример интеграции:** допустим, у нас есть векторный индекс `vectordb` и текстовый индекс `text_index`. Мы можем написать:

    class HybridRetriever(BaseRetriever):
        def __init__(self, vectordb, text_index, reranker):
            # сохраним ссылки на два ретривера и объект реранка
        def get_relevant_documents(self, query: str) -> List[Document]:
            docs1 = vectordb.similarity_search(query, k=50)
            docs2 = text_index.search(query, k=50)
            candidates = merge_results(docs1, docs2)  # объединяем и удаляем дубликаты
            reranked = reranker.rerank(query, candidates)  # возвращаем, например, топ-5
            return reranked

Затем `qa_chain = RetrievalQA.from_chain_type(llm, retriever=HybridRetriever(...))`. Теперь `qa_chain` при каждом запросе будет использовать наш гибридный подход. Такой подход интегрируется в LangChain без изменений остального кода.
