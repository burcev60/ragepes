### Шаг 1. Ментальная модель и контракт QueryInterface

**Зачем нужен QueryInterface.** Это тонкий, фреймворк-агностичный слой между вашим приложением и векторной БД. Он стандартизирует: *(а)* как мы формулируем запросы, *(б)* что считаем «кандидатами», *(в)* как агрегируем/пересортировываем результаты, и *(г)* какой **trace** (объяснение) возвращаем для отладки и оценки.

#### 1) Контракт на уровне понятий

- **Query** — декларация задачи поиска. Примеры: *NearestQuery* (по одному вектору), *FusionQuery* (несколько каналов с весами), *FormulaQuery* (скор по формуле), *RecommendQuery* (похожие на X), *Sample/Discover* (исследование индекса).
- **CandidateSet** — объединённый пул кандидатов (обычно ≤ 200–1000), полученный из БД: `[{point_id, doc_id, score, vector_name, payload_subset}]`.
- **Postprocess** — операции над CandidateSet: нормализация по каналам, fusion, MMR, `max_per_doc`, сортировки/фильтры, бусты/штрафы по payload.
- **Trace** — подробный отчёт о том, *как* получился ответ: параметры запроса, фильтры ACL, ef_search по каналам, промежуточные списки, финальный топ, вклад каналов и формулы. Это база для дебага и урока 8 (оценка).


#### 2) Единый формат результатов

Любой запрос возвращает **Trace** со следующими ключами:

    {
      "query": {
        "type": "FusionQuery",
        "text": "экран входа с ошибкой ERR_1201",
        "has_image": false,
        "params": {
          "k_each": 50,
          "weights": {"text": 0.5, "image": 0.3, "ocr": 0.2},
          "ef_search": {"text": 64, "image": 32, "ocr": 48},
          "filters": {"org_id":"acme","lang":"ru","created_at": {">=": "2025-01-01"}}
        }
      },
      "candidate_sets": {
        "text": [{"point_id":"kb-42#p0","doc_id":"kb-42","score":0.74}, ...],
        "image": [{"point_id":"kb-42#img0","doc_id":"kb-42","score":0.31}, ...],
        "ocr":   [{"point_id":"kb-42#img0","doc_id":"kb-42","score":0.88}, ...]
      },
      "postprocess": {
        "normalization": "minmax",
        "fusion": [
          {"doc_id":"kb-17","fusion":0.500,"channels":{"text":1.000,"image":0.000,"ocr":0.000}},
          {"doc_id":"kb-42","fusion":0.442,"channels":{"text":0.370,"image":0.190,"ocr":1.000}}
        ],
        "mmr": {"lambda":0.7, "applied": true},
        "max_per_doc": 2
      },
      "final": [
        {"rank":1,"doc_id":"kb-17","point_id":"kb-17#p1","score":0.500,
         "payload":{"title":"Сбои при входе"}, "explain":"text=1.00 • image=0.00 • ocr=0.00"},
        {"rank":2,"doc_id":"kb-42","point_id":"kb-42#img0","score":0.442,
         "payload":{"title":"Ошибка ERR_1201"}, "explain":"text=0.37 • image=0.19 • ocr=1.00"}
      ]
    }

- `score` в `final` — это уже *после* всех нормализаций/весов/штрафов. Для интерпретации добавляем `channels` и текстовое `explain`.
- `payload` включаем *субсетом* полей (title/url/section/created_at) — чтобы не тянуть лишнее в сеть.


#### 3) Обязательные параметры в любом Query

- **Фильтры ACL/контента**: `org_id`/ `user_id`, `lang`, `section`, `created_at` — всегда на серверной стороне.
- **SLA-параметры**: `k`/`k_each`, `ef_search` по каналам.
- **Нормализация** (например, `minmax`) и политика пост-обработки: `mmr.lambda`, `max_per_doc`, `order_by` (например, по дате при равенстве скорингов).
- **fields** — список payload-полей, которые нужно вернуть (*минимальный набор* для UI/пакера контекста).


#### 4) Псевдокод интерфейса (минимальный каркас)

    # query_interface.py (скелет)
    from dataclasses import dataclass
    from typing import Dict, Any, List, Optional

    @dataclass
    class Query:
        type: str

        def run(self, client) -> Dict[str, Any]:
            "Вернуть Trace со всеми промежуточными шагами"
            raise NotImplementedError

    @dataclass
    class NearestQuery(Query):
        vector_name: str
        vector: list
        k: int = 50
        ef_search: int = 64
        filters: Optional[Dict[str, Any]] = None
        fields: Optional[List[str]] = None
        order_by: Optional[Dict[str, str]] = None  # например {"created_at": "desc"}

        def run(self, client):
            trace = {"query": {"type":"NearestQuery", "params": {
                "k": self.k, "ef_search": self.ef_search, "filters": self.filters}}}
            res = client.search(
                collection_name="kb_multivector",
                query_vector=(self.vector_name, self.vector),
                limit=self.k, with_payload={"include": self.fields or []},
                params={"hnsw_ef_search": self.ef_search},
                query_filter=self.filters
            )
            cand = [{"point_id": str(p.id), "doc_id": p.payload.get("doc_id"),
                     "score": float(p.score), "payload": {k:p.payload.get(k) for k in (self.fields or [])}}
                    for p in res]
            # вторичная сортировка (order_by) при равных score:
            if self.order_by:
                key, direction = next(iter(self.order_by.items()))
                cand.sort(key=lambda x: (x["score"], x["payload"].get(key)), reverse=(direction=="desc"))
            trace["candidate_sets"] = {"nearest": cand}
            trace["final"] = [{"rank":i+1, "doc_id":c["doc_id"], "point_id":c["point_id"],
                               "score": c["score"], "payload": c.get("payload")}
                              for i,c in enumerate(cand)]
            return trace

    def run(query: Query, client) -> Dict[str, Any]:
        return query.run(client)

*Заметки по контракту:* метод `run()` **детерминирован** при одинаковых входах и конфиге; не имеет побочных эффектов (только чтение); всегда возвращает `Trace` с `query`, `candidate_sets` (хотя бы одним), `final`.

#### 5) Инварианты и ошибки

- Каждый элемент в `final` обязан иметь: `doc_id`, `point_id`, `score`, а при запросе полей — `payload` (с только запрошенными ключами).
- При пустой выдаче: `final` — пустой список, `candidate_sets` — пустые; `trace.querynote` содержит причину (слишком жёсткие фильтры/малое `k`).
- Время и конфигурация (`ef_search`, веса каналов, фильтры) фиксируются в `trace` — это часть «договора» для дебага/оценки.

#### Чек-лист готовности шага

- Определены сущности: **Query → CandidateSet → Postprocess → Trace**.
- Есть единый формат `Trace` (минимальные обязательные поля) для всех типов запросов.
- Каркас `NearestQuery.run()` готов; предусмотрены фильтры ACL, поля `fields`, вторичная сортировка.
- Приняты инварианты: детерминизм, отсутствие побочных эффектов, обязательные поля в `final`, ведение `trace` даже при пустой выдаче.
