### Шаг 6. *Sample / Discover* и трейсинг для отладки

**Цель.** Научиться быстро «осматривать» индекс (рандомные выборки и простые агрегаты по payload)
и возвращать подробный *Trace*, который объясняет, почему система показала именно эти результаты —
с цифрами по каналам, фильтрам и пост-обработке.

#### 1) Когда это нужно

- **Проверка качества загрузки.** Всё ли индексировалось? Как распределены `lang`/`section`/`created_at`?
- **Диагностика перекосов.** Не «давит» ли один раздел? Хватает ли документов с OCR?
- **Объяснимость результата.** Почему этот документ — вклад каналов, формулы, фильтров, MMR.


#### 2) Контракты `Sample` и `Discover`

**Sample** — вернуть N случайных элементов под фильтрами (ACL/контент):

    {
      "type": "Sample",
      "params": {"n": 50, "filters":{"org_id":"acme","lang":"ru"}},
      "result": [{"doc_id":"kb-1","section":"howto","created_at":"..."}, ...]
    }

**Discover** — посчитать частоты/простые агрегаты по полям payload на сэмпле или по всему индексу:

    {
      "type": "Discover",
      "params": {"by":["section","lang"],"filters":{"org_id":"acme"}},
      "result": {"section":{"howto":1240,"faq":870,"deprecated":35}, "lang":{"ru":1810,"en":335}}
    }

*Правила:* 1) Всегда применять ACL-фильтры. 2) Для больших индексов считать по сэмплу `n=5k–50k`. 3) Возвращать и процент «пустых» значений — это индикатор проблем в ingest.

#### 3) Формат *Trace* — что логировать всегда

- **query:** тип запроса, вход (текст/есть ли картинка), `k/k_each`, `ef_search` по каналам, веса каналов, формула (если есть), ACL-фильтры.
- **candidate_sets:** по каждому каналу — top-K (doc_id, score).
- **postprocess:** нормализация, веса, MMR (λ), `max_per_doc`, тай-брейки.
- **final:** топ с `score`, `payload_subset`, вклад каналов (`channels{}`) и (если FormulaQuery) — `explain` с факторами.
- **timings:** латентности по каналам и общей пайплайн-стадии.


**Мини-шаблон Trace (с таймингами)**

    {
      "query":{"type":"FusionQuery","text":"ошибка ERR_1201", "params":{...}},
      "timings":{"encode_ms":3.4, "ch_text_ms":9.8, "ch_image_ms":6.2, "fusion_ms":0.5, "mmr_ms":0.2, "total_ms":21.1},
      "candidate_sets":{"text":[...], "image":[...], "ocr":[...]},
      "postprocess":{"normalization":"minmax","weights":{"text":0.5,"image":0.3,"ocr":0.2},"mmr":{"lambda":0.7},"max_per_doc":2},
      "final":[{"rank":1,"doc_id":"kb-17","score":0.50,"channels":{"text":1.0,"image":0.0,"ocr":0.0},"payload":{"title":"Сбои при входе","created_at":"..."}}, ...]
    }

#### 4) Псевдокод: `sample()` и `discover()`

    from typing import Dict, Any, List
    import random
    # Предполагаем, что есть клиент VectorDB с методами scroll/points и серверные фильтры.

    def sample(client, coll: str, n: int, filters: Dict[str,Any], fields: List[str]) -> List[Dict[str,Any]]:
        """Вернёт n случайных payload (под ACL/контент-фильтрами)."""
        out = []
        # В Qdrant можно использовать scroll с фильтром; ниже абстрактно:
        cursor = None
        while len(out) < n:
            batch, cursor = client.scroll(coll, limit= min(1000, n-len(out)), filter=filters,
                                          with_payload={"include": fields})
            out.extend([p.payload for p in batch])
            if not cursor: break
        random.shuffle(out)
        return out[:n]

    def discover(client, coll: str, by: List[str], filters: Dict[str,Any], n: int = 10000) -> Dict[str,Dict[str,int]]:
        """Частоты по полям на сэмпле из n элементов."""
        rows = sample(client, coll, n, filters, fields=by)
        freqs: Dict[str, Dict[str,int]] = {k:{} for k in by}
        for row in rows:
            for k in by:
                v = row.get(k, None)
                key = str(v) if v is not None else "__NULL__"
                freqs[k][key] = freqs[k].get(key, 0) + 1
        return freqs

#### 5) Диагностические «сигналы тревоги» и быстрые фиксы

| Симптом | Причина | Фикс |
| --- | --- | --- |
| В *final* почти все из одного раздела | Доминанта источника/раздела | MMR + `max_per_doc`, мягкий буст других `section` в FormulaQuery |
| OCR-канал «ничего не находит» | Нет OCR в payload, низкий `conf`, мусорные футеры | Проверить `discover(by=["has_ocr"])`, чистить футеры, фильтровать спаны по `conf` |
| Нестабильный порядок в топе | Нет тай-брейков / `order_by` | Стабилизировать сортировку по `(score, created_at, point_id)` |
| Пустая выдача при узких фильтрах | Слишком жёсткий ACL/дата | Ослабить `created_at` или убрать редкие секции из фильтра; логировать причину в `trace.querynote` |
| Высокая латентность на одном канале | Слишком большой `ef_search`/нет кэша | Снизить `ef` только там, включить кэш кандидатов, прогрев FAQ |

#### 6) Практические «рецепты» Discover

- **Качество загрузки:** `discover(by=["lang","section","has_ocr","has_caption"])`.
- **Анализ свежести:** вынесите `created_at` в «бакеты» (неделя/месяц) и посчитайте частоты — виден «устаревший хвост».
- **Покрытие OCR:** доля `has_ocr=true` по разделам — куда вложиться в OCR-пайплайн.
- **АВ-трассы:** сохраняйте Trace до/после изменения (веса, ef, формула) и сравнивайте топ-списки и тайминги.


#### 7) Безопасность и приватность

- В *Trace* не логировать чувствительные поля payload; используйте allowlist (`title,url,section,created_at`).
- Сохраняйте *хэш* текста запроса вместо полного текста — если политика компании этого требует.


#### 8) Мини-практика (2–3 минуты)

1. Выполните `discover(by=["section","lang"])` на сэмпле 10k. Что бы вы изменили в фильтрах/ингесте, если видите 40% `__NULL__` в `section`?
2. Дан Trace с пустым `final`. Назовите две вероятные причины и какие параметры вы смягчите в следующем запуске.
3. У вас p95 вырос с 60 до 95 мс после поднятия `ef_search` на `text_vector`, а nDCG@10 почти не изменился. Что зафиксировать/откатить и где это отразить в Trace?


#### Чек-лист готовности

- Реализованы **Sample** (рандомная выборка) и **Discover** (частоты по payload) с ACL-фильтрами.
- Единый **Trace** включает параметры запроса, канальные выдачи, пост-обработку, финальный список и тайминги.
- Есть процедура диагностики «тревожных сигналов» и понятные фиксы (MMR, max_per_doc, OCR-фильтрация, тай-брейки).
- Соблюдены требования приватности: логируется только allowlist payload и/или хэш запроса.
