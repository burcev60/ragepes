### Шаг 4. *FormulaQuery*: скор по формуле (бизнес-правила поверх похожести)

**Цель.** Научиться поверх базовой похожести (обычно из *FusionQuery*) добавлять бизнес-факторы: «свежесть», приоритет разделов, верификацию, популярность и штрафы. Всё это — в *одной прозрачной формуле* с понятным трейсом.

#### 1) Когда нужна FormulaQuery

- Нужно **поднять свежие** материалы при равной похожести.
- Нужно слегка **бустить приоритетные разделы** (`howto`, `faq`).
- Нужно учитывать **качество/верификацию** (`is_verified`).
- Нужно добавить **популярность** (CTR/клики) без убийства релевантности.
- Нужно ввести **штрафы** (дубликаты, слишком старые, низкая уверенность OCR).


#### 2) Сигналы и нормализация (рекомендуемые шкалы)

| Признак | Обозначение | Диапазон | Как получить |
| --- | --- | --- | --- |
| Похожесть (из Fusion) | `sim` | [0,1] | Нормированный fusion-скор (min–max или rank-fusion) |
| Свежесть (декей по дате) | `recency` | (0,1] | Экспоненциальный распад: см. ниже |
| Приоритет раздела | `boost_section` | {0,1} или [0,1] | Напр., 1 для `howto`, иначе 0 |
| Верификация | `verified` | {0,1} | Из payload: `is_verified` |
| Популярность | `pop` | [0,1] | CTR/клики → min–max по корпусу или per-section |
| Штраф за «сомнительный» OCR | `pen_ocr` | [0,1] | 1 − mean(conf) по спанам, клипнуть [0,1] |

*Правило:* все признаки приводите к сравнимым шкалам (обычно [0,1]) и **клипуйте** экстремумы, иначе любой «шумный» сигнал легко «забьёт» похожесть.

#### 5) Числовой пример (на тех же d1/d2/d3)

Возьмём fusion-скор из предыдущего шага и добавим свежесть с **полураспадом** `h=7` дней. Пусть:

- d1: `sim=0.442`, возраст 2 дня → `recency=2^{-2/7}≈0.8206`, `howto=0`
- d2: `sim=0.500`, возраст 10 дней → `recency=2^{-10/7}≈0.3716`, `howto=1`
- d3: `sim=0.378`, возраст 1 день → `recency=2^{-1/7}≈0.9057`, `howto=1`

#### 6) Псевдокод `FormulaQuery`

    from dataclasses import dataclass
    from typing import Dict, Any, List, Callable, Optional
    from math import exp, log

    def half_life_recency(delta_days: float, h_days: float) -> float:
        return float(exp(-log(2.0) * (delta_days / max(1e-9, h_days))))

    @dataclass
    class FormulaConfig:
        alpha: float = 0.7
        beta: float  = 0.2
        gamma: float = 0.1
        delta: float = 0.0
        rho: float   = 0.0
        lam: float   = 0.0
        half_life_days: float = 7.0
        section_boost: Optional[Dict[str, float]] = None  # например {"howto":1.0, "faq":0.5}

    @dataclass
    class FormulaQuery:
        base_query: Any  # обычно FusionQuery
        cfg: FormulaConfig
        fields: Optional[List[str]] = None
        limit: int = 10
        order_by_tiebreak: List[str] = None  # ["created_at","point_id"]

        def run(self, client, coll) -> Dict[str, Any]:
            trace = {"query":{"type":"FormulaQuery"}}
            base_trace = self.base_query.run(client, coll)
            cand = base_trace["final"]  # [{doc_id, score(sim), payload{...}}, ...]
            out = []
            for it in cand:
                pl = it.get("payload", {})
                sim = float(it["score"])  # уже [0,1] после fusion-нормализации
                days = self._days_since(pl.get("created_at"))
                rec = half_life_recency(days, self.cfg.half_life_days) if days is not None else 1.0
                bsec = (self.cfg.section_boost or {}).get(pl.get("section"), 0.0)
                ver  = 1.0 if pl.get("is_verified") else 0.0
                pop  = float(pl.get("pop_norm", 0.0))  # заранее положите [0,1] в payload
                pen  = float(pl.get("pen_ocr", 0.0))

                final = (self.cfg.alpha*sim +
                         self.cfg.beta*rec +
                         self.cfg.gamma*bsec +
                         self.cfg.delta*ver +
                         self.cfg.rho*pop -
                         self.cfg.lam*pen)

                out.append({**it, "score": final, "explain":
                            f"sim={sim:.3f}, rec={rec:.3f}, bsec={bsec:.2f}, ver={ver:.0f}, pop={pop:.2f}, pen={pen:.2f}"})
            # стабильная сортировка
            out.sort(key=lambda x: (x["score"],
                                    x["payload"].get("created_at"),
                                    x["point_id"]), reverse=True)
            trace["base"] = {"type": base_trace["query"]["type"]}
            trace["formula"] = self.cfg.__dict__
            trace["final"] = out[: self.limit]
            return trace

        def _days_since(self, iso: Optional[str]) -> Optional[float]:
            if not iso: return None
            try:
                from datetime import datetime, timezone
                t = datetime.fromisoformat(iso.replace("Z","+00:00"))
                delta = datetime.now(timezone.utc) - t
                return max(0.0, delta.total_seconds()/86400.0)
            except Exception:
                return None

#### 7) Советы по тюнингу

- **Начните просто:** только `sim` + `recency`. Остальные факторы добавляйте по одному, проверяя Δ nDCG/Recall.
- **Half-life вместо твёрдой отсечки:** гибко, интерпретируемо (например, «каждые 7 дней вес падает вдвое»).
- **Лёгкие бусты, не «молоты»:** 0.05–0.15 достаточно, иначе «бизнес-логика» заглушит релевантность.
- **Калибруйте на валидации:** grid-search по (α,β,γ,τ) или линейная регрессия/логрег на признаки.
- **В трейс добавляйте explain:** разбор «почему этот документ» снижает время дебага.


#### 8) Антипаттерны

- Суммирование *сырых* косинусов с бизнес-факторами без нормализации — потеря контроля масштаба.
- Бусты >= 0.5 поверх sim — релевантность исчезает.
- Отсечка по дате (жёсткий фильтр) вместо декея — «ломает» выдачу по редким темам.
- Не логировать вклад факторов — невозможно объяснить изменения топа.

#### Чек-лист готовности

- Все признаки приведены к сопоставимым шкалам (обычно [0,1]) и клипуются.
- Декей реализован через **half-life** или τ; параметры зафиксированы в трейс.
- Формула линейная и прозрачная; бусты малы и не ломают монотонность по похожести.
- В *Trace* есть вклад факторов (`explain`) и итоговый стабильный порядок с тай-брейками.
