#### Настройка CI-пайплайна (пример)

Рассмотрим конкретный сценарий: у нас проект на Python, и мы хотим, чтобы при каждом коммите в основную ветку автоматически проверялось, что все тесты проходят. Создаём файл `.github/workflows/tests.yml` со следующим содержимым (упрощённо):

     name: Run Tests on: [push] jobs:
    build:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    - uses: actions/setup-python@v4
    with:
    python-version: "3.10"
    - run: pip install -r requirements.txt
    - run: pytest

Разберём: workflow называется "Run Tests". Триггер `on: [push]` – то есть при любом пуше (в любую ветку, можно уточнить) он запустится. Один job `build`, выполняется на Linux-окружении (ubuntu-latest). Шаги: чек-аут – получает наш код; установка Python 3.10; установка зависимостей; запуск pytest. Если pytest завершится неудачно (код выхода не 0) – job завершится с ошибкой. GitHub отобразит в интерфейсе, что последний commit "красный", и покажет лог – какие тесты упали.

Вы можете добавить другие шаги: например, запуск линтера (`flake8` или `pylint`), сборку докер-образа и пуш его в регистр, деплой на сервер (через ssh или cloud CLI). Возможности GitHub Actions очень широки: workflows могут выполняться по cron (расписанию), параллельно на нескольких платформах (указываете `matrix` – набор ОС или версий языка). Они могут реагировать на открытие pull request – тогда удобно проверять вклад участников перед слиянием.
