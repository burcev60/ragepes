#### GitHub Actions: автоматизация на GitHub

Есть много CI/CD-систем (Jenkins, GitLab CI, CircleCI и др.). **GitHub Actions** – это встроенное решение от GitHub. Оно позволяет прямо в репозитории описать сценарии (workflow), которые будут запускаться на события. Например, «на каждый push в ветку main – запустить тесты» или «при открытии pull request – собрать проект и выполнить статический анализ».

Главный элемент GitHub Actions – **workflow**, описанный YAML-файлом в директории `.github/workflows` вашего репозитория. В этом файле вы указываете:

- **on:** когда запускать (событие: push, pull_request, schedule по расписанию и др.).
- **jobs:** какие задания выполнять. Можно параллельные несколько jobs (например, отдельные для разных ОС или разных этапов).
- **steps:** пошаговый сценарий внутри job: например, шаг «Checkout code» (специальный Action, чтобы вытащить код репо), шаг «Setup Python» (установка нужной версии Python), шаг «Install dependencies» (`pip install -r requirements.txt`) и шаг «Run tests» (`pytest`).


Все шаги выполняются в чистой виртуальной среде (например, Ubuntu). Если какой-то шаг завершается с ошибкой (например, тесты упали с non-zero exit code) – workflow помечается как failed, и дальше шаги можно не выполнять или выполнять блок пост-действий.

GitHub Actions предоставляет большой каталог готовых действий (actions) – например, action для чекаута кода `actions/checkout`, action для настройки Python `actions/setup-python`, action для кэширования зависимостей и т.д. Это упрощает написание workflow: можно подключить готовые шаги одной строкой.
