#### Зачем нужен контроль версий

Представьте, вы разрабатываете проект (например, нашего семантического чат-бота). Сначала всё просто: один файл, вы его редактируете и сохраняете. Но проект растёт, файлов становится много, вносятся изменения, возможно, в команде несколько человек правят код одновременно. Как отследить, кто что поменял? Как вернуться к предыдущей версии, если что-то сломалось? Как показать коллеге, над чем вы работали, и объединить ваши изменения с его изменениями?

Без системы контроля версий (VCS) разработчикам пришлось бы вручную копировать папки («project_old», «project_final_final», знакомо?). Это неудобно и ненадёжно. **Git** решает эти проблемы. Git – это распределённая система контроля версий, которая отслеживает изменения файлов, позволяет сохранять «снимки» состояния проекта (коммиты), переключаться между версиями, сливать параллельную работу нескольких авторов и многое другое. По сути, Git – как «история изменений» для вашего кода, с неограниченной глубиной и возможностью ветвления.
