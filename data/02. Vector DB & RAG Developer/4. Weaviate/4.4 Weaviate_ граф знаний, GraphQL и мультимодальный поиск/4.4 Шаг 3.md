**Сложные запросы GraphQL.** 

Weaviate предоставляет единый язык запросов – **GraphQL**. Первоначально GraphQL может выглядеть сложнее, чем привычный REST, но он очень выразителен. Все запросы идут на единый endpoint `/v1/graphql` с большим JSON, описывающим, что нужно. Главное – понимать синтаксис. Запросы делятся на `Get` (получить объекты), `Aggregate` (агрегации/статистика) и `Explore` (семантическое исследование без указания класса). Мы сосредоточимся на `Get`, так как он основной.

 

Простейший GraphQL-запрос: получить все объекты класса `Article` с полем `title` и `date`. В GraphQL это пишется как:

    {
      Get {
        Article {
          title
          date
        }
      }
    }

Weaviate вернёт список статей с этими полями. Заметьте, мы **должны явно перечислить, какие свойства хотим получить** – если свойство не указано, оно не вернётся (это особенность GraphQL: выбираешь нужные поля сам).

 

Теперь добавим условий. Например, хотим статьи, где `published = true`, и только те, что после 2023 года. В GraphQL для условий служит параметр **`where`**. Он принимает фильтр-объект с указанием поля, оператора и значения. В нашем случае: `where: { path: ["published"], operator: Equal, valueBoolean: true }` AND `path: ["date"], operator: GreaterThan, valueDate: "2023-01-01"`. Полный запрос:

    {
      Get {
        Article(
          where: {
            operator: And
            operands: [
              { path: ["published"], operator: Equal, valueBoolean: true },
              { path: ["date"], operator: GreaterThan, valueDate: "2023-01-01" }
            ]
          }
        ) {
          title
          date
          published
        }
      }
    }

Такой запрос вернёт только опубликованные после 2023 года статьи, с их заголовками, датами и статусом публикации. Можно заметить, что синтаксис чуть громоздкий (особенно для композитных условий), но очень гибкий: доступны операторы равенства, сравнений, полнотекстовый поиск, гео-координаты и т.д. По функциональности фильтры GraphQL аналогичны фильтрам Qdrant (включая поддержу **AND/OR** комбинаций и условий по различным типам).

 

Ещё более мощный сценарий – запрос с использованием **ссылок между объектами**. Предположим, у нас статьи связаны с авторами через `hasAuthor`. Можно спросить: «дай мне статьи и имена их авторов». В GraphQL для этого в теле запроса вкладывают поля ссылки. Например:

    {
      Get {
        Article {
          title
          hasAuthor {
            ... on Author {
              name
            }
          }
        }
      }
    }

Здесь мы в запросе `Article` указали вложенный блок `hasAuthor` и внутри него через конструкцию `... on Author` попросили поле `name` автора. Результат будет: список статей, у каждой поле `title` и поле `hasAuthor` (в котором массив авторов, обычно один автор), а у автора – `name`. В GraphQL синтаксисе `... on Author` называется **inline fragment** – он нужен, потому что поле-ссылка теоретически может ссылаться на несколько классов (например, если dataType ссылки содержит два класса, GraphQL требует указать, поля какого класса вы хотите). В нашем случае `hasAuthor` ссылается на `Author`, поэтому мы пишем этот фрагмент. Получается очень удобно: **в одном запросе** мы получили и статьи, и связанные с ними объекты других классов. В обычном REST для такого потребовалось бы сначала получить статьи, извлечь ID авторов, потом сделать второй запрос за авторами. GraphQL избавляет от этого: он как будто делает join и возвращает объединённый результат.

 

Заметим, что Weaviate разрешает задавать условия и по ссылочным полям тоже. Например, мы можем искать статьи, у которых автор находится в определённой стране, если у `Author` есть поле `country`. Тогда в фильтре можно использовать путь вроде `["hasAuthor", "country"]` с нужным значением. Weaviate сам пройдёт по связи и применит условие. Такие запросы могут быть тяжелее, но они отражают суть **графовых** запросов, которые комбинируют поиск по содержанию и по связям.
