### Multi-tenancy и резервное копирование: изоляция данных + S3-бэкапы

### 1. Зачем это нужно

- **Multi-tenancy** — хранение данных нескольких клиентов («тенантов») в одном кластере при полной логической изоляции. У каждого свои объекты, ACL и квоты, а инфраструктура общая.
- **Backup / Restore** — снимок коллекций на S3, GCS, Azure Blob или локальный диск. Можно быстро откатиться к сохранённому состоянию или мигрировать данные между кластерами.


### 2. Подготовка: включаем модуль бэкапа

В `docker-compose.yml` добавьте строку в `ENABLE_MODULES`:

    ENABLE_MODULES=text2vec-openai,generative-openai,backup-s3

А также переменные для S3 (minio, AWS или Yandex Object Storage):

    - BACKUP_S3_ENDPOINT=http://minio:9000
    - BACKUP_S3_ACCESS_KEY=minioadmin
    - BACKUP_S3_SECRET_KEY=minioadmin
    - BACKUP_S3_BUCKET=weaviate-backups

Перезапустите контейнер:

    docker compose down && docker compose up -d

### 3. Создаём multi-tenant коллекцию `ArticleMT`

    import weaviate
    from weaviate.classes.init import MultiTenancyConfig

    with weaviate.connect_to_local() as client:
        if "ArticleMT" in client.collections.list_all():
            client.collections.delete("ArticleMT")

        client.collections.create(
            name="ArticleMT",
            properties=[ ... ],                 # те же поля, что и раньше
            multi_tenancy_config=MultiTenancyConfig(enabled=True),
            vectorizer_config=weaviate.classes.init.Vectorizer.text2vec_openai()
        )

**Добавляем два тэнанта и по одной статье в каждый:**

    article_mt = client.collections.get("ArticleMT")

    # 1️⃣ Регистрация тенантов
    article_mt.tenants.create(["tenantA", "tenantB"])

    # 2️⃣ Импорт данных (по одному объекту)
    article_mt.data.insert(
        properties={"title": "LLM in prod", "content": "..."},
        tenant="tenantA"
    )
    article_mt.data.insert(
        properties={"title": "Vector search 101", "content": "..."},
        tenant="tenantB"
    )

Попробуйте поискать один и тот же запрос в разных изолированных средах:

    for t in ["tenantA", "tenantB"]:
        res = (
            article_mt.query
            .near_text("vector search", limit=1, tenant=t)
            .do()
        )
        print(t, res.objects[0].properties["title"])

### 4. Делаем бэкап в S3

    from weaviate.classes.backup import BackupStatus

    with weaviate.connect_to_local() as client:
        status: BackupStatus = client.backup.create(
            backend="s3",                   # s3 / gcs / azure / filesystem
            bucket="weaviate-backups",      # указан в env
            include_collections=["ArticleMT"],
            backup_id="articles_v1"
        )
        print(status.status)               # STARTED → SUCCESS

После `SUCCESS` в бакете появится папка `ArticleMT` с
HNSW-графом, JSON-метаданными и журналом.

### 5. Восстановление из бэкапа

1. Удалите коллекцию: `client.collections.delete("ArticleMT")`
2. Выполните `restore()`:

    client.backup.restore(
        backend="s3",
        bucket="weaviate-backups",
        backup_id="articles_v1"
    ).wait()
    print(client.collections.list_all())  # снова ['ArticleMT']

Метод `.wait()` блокирует поток, пока статус не станет `SUCCESS`. При асинхронной обработке можно опрашивать `.status()` или подписаться на webhook.

### 6. Мини-задания

1. Создайте третьего тенанта `tenantC`, импортируйте 100 объектов и убедитесь, что поиск с `tenant="tenantA"` их не видит.
2. Сымитируйте потерю контейнера: `docker compose down -v`. Поднимите новые контейнеры и выполните `restore()`. Проверьте, что все три тенанта на месте.
3. Измерьте время восстановления коллекции из бэкапа при `n=10 000` объектов. Сколько секунд на каждый объект?
