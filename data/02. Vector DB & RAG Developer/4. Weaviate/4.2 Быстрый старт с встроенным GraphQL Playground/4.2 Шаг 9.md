### `mutation`-операции и работа со схемой Weaviate

**Цель шага:** научиться *создавать* и *изменять* объекты, а также правильно описывать схему классов и свойств, чтобы дальнейшие GraphQL-запросы работали быстро и предсказуемо.

### 1 Почему схема важна?

Weaviate хранит не просто «документы», а объекты классов. Схема определяет:

- какие **типы** (Text, Number, Date, Boolean, GeoCoordinates…) имеют свойства;
- где строить инвертированный индекс (для фильтров `where`),
- какой модуль **векторизует** текст (по умолч. `text2vec-openai` — если не переопределите),
- будет ли класс *multi-tenant* и т.д.


### 2 Создаём класс (*CreateClass*)

    mutation {
      CreateClass(class: {
        class: "Article",
        description: "Tech articles and tutorials",
        vectorizer: "text2vec-openai",   # ← модуль векторизации
        properties: [
          { name: "title",  dataType: ["text"] },
          { name: "content", dataType: ["text"] },
          { name: "date",   dataType: ["date"] },
          { name: "rating", dataType: ["number"] },
          { name: "published", dataType: ["boolean"] }
        ]
      }) {
        class
      }
    }

💡 Если переменная `AUTOSCHEMA_DEFAULT` включена, Weaviate может создавать свойства «на лету» при *AddObjects*, но для продакшена **явно описывайте** схему: это ускоряет индексацию и избегает неожиданных типов.

### 3 Добавляем объекты (*AddObjects / AddObject*)

    mutation {
      AddArticle(objects: [
        {
          _id: "8f951…",          # (опц.) свой UUID, иначе сгенерируется
          title: "Intro to Vector DBs",
          content: "Weaviate, Qdrant и соседи…",
          date: "2025-07-25",
          rating: 4.7,
          published: true
        }
      ]) {
        numberObjects
      }
    }

- Массовая вставка быстрее, чем много одиночных *AddObject*.
- Нужно импортировать миллионы? Используйте REST-bulk-endpoint— он стримит JSON-Batch.


### 4 Обновляем объект (*Update*)

    mutation {
      UpdateArticle(
        id: "8f951…",
        data: { rating: 4.9 }    # передаём ТОЛЬКО поля, которые меняем
      ) {
        _additional { id }
      }
    }

Weaviate делает «partial update»: unspecified поля остаются без изменений.

### 5 Удаляем объект (soft vs hard)

    mutation {  # мягкое удаление (можно восстановить до compaction)
      DeleteArticle(id: "8f951…") { successful }
    }

    mutation {  # жёсткое удаление — исчезает из всех индексов сразу
      DeleteArticle(id: "8f951…", hardDelete: true) { successful }
    }

### 6 Добавляем reference-ссылку

    mutation {
      AddReference(
        from: { class: "Article", id: "8f951…", property: "hasAuthor" },
        to:   { class: "Author",  id: "b3d1e…" }
      ) { from { ... } }
    }

После этого в GraphQL-*Search* можно «прыгать» по `hasAuthor` → `wrote` (см. Шаг 7).

### 7 Практические советы

- **Batch-size**: при потоковой загрузке держите `batchSize ≈ 100-500`; большие батчи могут упереться в RAM.
- У числовых и дата-полей включайте `indexInverted` = true, если планируете многие фильтры `where`; иначе экономьте диск.
- Изменили схему (добавили свойство)? Weaviate перестраивает индекс *он-лайн*, но на коллекции 10M объектов это может занять минуты.
- При bulk-импорте можно временно выключить репликацию / консистентность, а после импорта — включить обратно.


### 8 Практика

1. **Импорт 100 JSON-статей.**  
Опишите класс `BlogPost` (fields: title / text / tags[] / date / views:number). Загрузите 100 записей одним *AddBlogPost*-батчем. Затем убедитесь через `Aggregate→meta.count`, что все объекты на месте.

2. **Обновление рейтинга.**  
Напишите *UpdateBlogPost*, который повышает `views` на 1, если дата старше «2025-01-01». Проверьте с фильтром `where`.

3. **Reference-каскад.**  
Создайте класс `Author`, добавьте связь `hasAuthor` к

  BlogPost

. Затем запросом выведите «имя автора → топ-3 самых просматриваемых поста».

**Итог:** теперь вы умеете полностью управлять данными — от описания схемы до масс-импорта, обновлений и reference-связей. В следующих уроках мы посмотрим, как *тюнить параметры индекса* (efConstruction / efSearch / m) и мониторить производительность запросов.
