### Сортировка, пагинация и агрегаты

**Цель шага —** научиться управлять порядком выдачи, объёмом результатов и получать сводную статистику по данным, используя стандартные возможности GraphQL-API Weaviate.

#### 1 Сортировка (argument `sort`)

В любом поисковом запросе (`Search`) можно добавить блок `sort`. Он принимает:

- `path` — массив имён полей, по которым сортируем (например, `["date"]` или `["rating"]`);
- `order` — `asc` или `desc`.

    {
      Search(
        class: Article
        nearText: { concepts: ["deep learning"] }
        sort: { path: ["date"], order: desc }
        limit: 10
      ) {
        title
        date
      }
    }

Сортировка может ссылаться как на обычные поля объекта, так и на значения, вычисленные во вложенном резолвере (напр. `_additional.score` — отсортировать «по релевантности»).

#### 2 Пагинация (limit, offset, cursor)

Weaviate наследует классическую логику GraphQL-страничной навигации:

- `limit` — сколько результатов вернуть;
- `offset` — сколько пропустить с начала;
- `after` (или `cursor`) — постраничная навигация без «дыр»: берём «курсор» последнего элемента предыдущей страницы и запрашиваем *следующую* пачку.

    {
      Search(
        class: Article
        nearText: { concepts: ["vector database"] }
        limit: 5
        offset: 5      # вторая страница
      ) {
        title
        _additional { id }
      }
    }

Пагинацию удобно комбинировать с сортировкой: например, отсортировать по дате «свежие сверху» и листать статью за статьёй.

#### 3 Агрегации (`Aggregate` API)

Отдельный корневой резолвер `Aggregate` позволяет быстро получать сводную статистику без сканирования объектов вручную.

    {
      Aggregate {
        Article {
          meta { count }          # общее число статей
          groupBy: { path: ["category"] } {
            value                 # название категории
            count                 # сколько статей в ней
          }
          date {                  # числовые/дата-поля поддерживают
            max                   #   min/max/mean/median/sum
            min
          }
        }
      }
    }

Полезные приёмы:

- **groupBy** — «раскидать» по уникальным значениям поля и посчитать частоты (часто применяют к тегам, авторам и т.д.);
- **topOccurrences** — вернуть N самых частотных значений (по умолчанию N = 10);
- Сочетание `where + Aggregate` — агрегировать только по подмножеству документов (например, «статьи 2024 года по категориям»).


#### 4 Комбинируем всё вместе

    {
      Search(
        class: Article
        where: {
          path: ["published"], operator: Equal, valueBoolean: true
        }
        sort: { path: ["_additional", "score"], order: desc }   # релевантность
        limit: 20
      ) {
        title
        date
        _additional { score }
      }
    }

Таким образом, в одном запросе мы:

1. отфильтровали только опубликованные материалы;
2. упорядочили их по убыванию «релевантности» (`_additional.score`);
3. вернули ровно 20 лучших результатов.


#### 5 Практика

1. Сделайте запрос: найдите 30 последних (по дате) статей про «graph embeddings» и покажите поля `title`, `author`, `date`.
2. С помощью `Aggregate` узнайте, сколько статей вышло *по годам* (groupBy `date.year`).
3. Попробуйте комбинировать `nearText` и сортировку по пользовательскому рейтингу — покажите топ-10 статей, близких к запросу, но отсортированных по `rating`.


После этого шага вы сможете не только «искать», но и строить полноценную аналитику непосредственно в Weaviate, экономя обращения к внешним сервисам и лишний код.
