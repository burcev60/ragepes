### Поиск `nearText` и `nearVector` в Weaviate

**Цель шага:** научиться формулировать два основных вида семантического поиска — по тексту (`nearText`) и по готовому вектору (`nearVector`). Поймём различия параметров *distance* и *certainty*, научимся ограничивать число результатов и запрашивать метаданные через `_additional`.

### 1 Быстрый чек-лист: когда какой оператор

| Оператор | Используйте, когда… | Обязательные поля |
| --- | --- | --- |
| `nearText` | есть текстовая строка запроса, а модуль сам сделает эмбеддинг | `concepts` (массив строк) |
| `nearVector` | у вас уже вычислен вектор запроса (например, в Python) | `vector` (массив float) |

Оба оператора можно дополнить:

- `distance` — максимальное косинусное расстояние (0 … 2).
- `certainty` — «уверенность» (1 → полное совпадение; 0.0 → всё подряд).
- `limit` — сколько результатов вернуть (дефолт задаётся в переменной окружения).


Weaviate «под капотом» превращает запрос в k-NN-поиск и возвращает объекты *только* указанного класса

### 2 Пример #1 — поиск `nearText`

    {
      Search(
        class: Article
        nearText: {
          concepts: ["Graph Neural Networks"]
          certainty: 0.6
        }
        limit: 5
      ) {
        title
        _additional { distance }
      }
    }

*Что происходит?*

1. Фраза `Graph Neural Networks` преобразуется в вектор встроенным модулем.
2. База ищет 5 ближайших статей с уверенностью ≥ 0.6 (чем выше, тем строже).
3. В ответе запрашиваем `distance` — реальное косинусное расстояние до запросного вектора.


### 3 Пример #2 — поиск `nearVector`

    {
      Search(
        class: Article
        nearVector: {
          vector: [0.12, 0.98, -0.34, …]   # 768-мерный эмбеддинг
          distance: 0.25
        }
        limit: 3
      ) {
        title
        date
        _additional {
          distance
          id
        }
      }
    }

Здесь мы передаём уже готовый эмбеддинг и указываем «радиус» `distance ≤ 0.25`; Weaviate вернёт максимум 3 документа, попавших в этот порог.

### 4 Когда использовать *distance*, а когда *certainty*?

- **distance** — численное ограничение, подходит для `nearVector`, когда вы знаете, какая метрика считается.
- **certainty** — более интуитивный «процент похожести»; удобен для `nearText`.


Официальная документация советует: если не знаете масштабы метрик, начинайте с `certainty ≈ 0.6 – 0.8`, а потом подбирайте значение экспериментально.

### 5 Добавляем метаданные через `_additional`

Поле `_additional` позволяет вывести сервисные данные (distance, score, id, вектор и др.) без влияния на поиск, что подчёркивается в теории курса.

    _additional {
      id          # UUID объекта
      distance    # косинусная метрика
      vector      # полный эмбеддинг объекта
    }

### 6 Мини-квиз для закрепления

1. Сформулируйте запрос, который ищет *пять* статей о «vector database», но только среди объектов, где поле `published = true`, и выведите `title` + `distance`.
2. У вас есть вектор `q`. Найдите ближайшие 10 объектов, но пропустите те, у которых `distance > 0.4`.


**Подсказки**

- Для п. 1 понадобится комбинация `nearText` + `where` (мы рассмотрим фильтры подробнее в следующем шаге).
- Для п. 2 используйте `nearVector` + параметр `distance`.

**Итог:** теперь вы умеете формулировать оба основных варианта семантического поиска и понимаете, как контролировать релевантность и объём результатов. В следующем шаге углубляемся в фильтры `where` — научимся ограничивать поиск по датам, числам, текстовым полям и комбинировать условия.
