### `_additional` — как извлечь score, distance, id, vector и другие метаданные

**Цель шага:** разобраться, какие служебные данные можно запросить вместе с результатами поиска и как это помогает строить аналитику, дебажить качество и объяснять пользователям, почему именно эти документы оказались в выдаче.

### 1 Что такое `_additional` в Weaviate?

Это виртуальное под-поле, доступное во всех операциях `Search` / `Aggregate`. Через `_additional` мы запрашиваем **служебную информацию**, которая не является частью объекта, но генерируется динамически: расстояние до запросного вектора, итоговый скор, id, сам вектор и даже *scoreExplanation*. Концепт описан в теории курса — Weaviate позволяет «достать» любые из этих значений по желанию пользователя.

### 2 Доступные поля `_additional`

| Поле | Тип | Когда полезно |
| --- | --- | --- |
| `id` | UUID | нужен, если в дальнейшем обращаемся к объекту через REST / клиент |
| `distance` | float | метрика косинусного расстояния (0 → идеально) |
| `score` | float | нормализованный скор (чем выше, тем лучше):contentReference[oaicite:2]{index=2} |
| `certainty` | float | альтернатива distance (1 → уверенное совпадение) |
| `vector` | array<float> | полный эмбеддинг объекта — пригодится для повторного k-NN локально |
| `scoreExplanation` | string | расшифровка, как считался итоговый скор (особенно полезно в hybrid-поиске) |

### 3 Базовый пример запроса

    {
      Search(
        class: Article
        nearText: { concepts: ["vector database"] }
        limit: 3
      ) {
        title
        _additional {
          id
          distance
          score
        }
      }
    }

Результат вернёт три статьи, где для каждой будут *id*, косинусная *distance* и нормализованный *score*. Если вы используете гибридный поиск (BM25 + вектор), *score* будет уже объединённым значением.

### 4 Расширенный пример с `scoreExplanation`

В hybrid-режиме Weaviate может показать вклад каждой части ранжирования:

    {
      Search(
        class: Article
        hybrid: {
          query: "graph neural networks"
          alpha: 0.4         # 40 % BM25 + 60 % вектор
        }
        limit: 5
      ) {
        title
        _additional {
          score
          scoreExplanation   # ⚡NEW
        }
      }
    }

*Пример ответа (сокращённо):*

    {
      "title": "GNN primer",
      "_additional": {
        "score": 0.83,
        "scoreExplanation": "bm25:0.31 vector:0.52 alpha:0.4"
      }
    }

Такой разбор помогает «дебажить» качество: видно, что документ попал в топ главным образом благодаря семантике.

### 5 Когда запрашивать `vector`?

- Нужно построить t-SNE / UMAP-график для визуализации ближайших статей.
- Хотите повторить поиск локально другими методами (например, сравнить с FAISS).
- Создаёте кеш популярных документов в стороннем сервисе.


Однако помните: полный вектор — это сотни-тысячи чисел, передаваемых по сети. Поэтому запрашивайте `vector` только при необходимости.

### 6 Практика

1. **Explain-mode.**  
Сформулируйте hybrid-запрос (alpha = 0.3) к классу `Tutorial` и выведите `title`, `score`, `scoreExplanation`. Что покажет объяснение? Как меняется баланс вкладов, если alpha = 0.8?

2. **Recall-check.**  
Запросите 50 ближайших объектов и сохраните поля `id` и `distance` в CSV. Затем построите гистограмму расстояний — где «провал»? (готовим почву для шага про метрики качества).

3. **Vector-export.**  
Скачайте векторы топ-10 результатов, чтобы локально применить алгоритм k-means и показать кластеризацию обучающих материалов.

**Итог:** теперь вы умеете запрашивать любые «внутренние» данные, которые Weaviate рассчитывает при поиске. Это открывает путь к **аналитике качества поиска**, **объясняемости** и **гибкому пост-обработочному ранжированию**. В следующем шаге рассмотрим сортировку, пагинацию и агрегации, чтобы делать полноценные «виджеты» статистики прямо в GraphQL.
