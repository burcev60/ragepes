### Гибридный поиск (BM25 + векторы) и переходы по связям

**Цель шага:** научиться комбинировать классический полнотекстовый BM25-поиск с семантическим k-NN и «прыгать» по графу знаний, вытягивая связанные объекты одной командой.

### 1 Что такое гибридный поиск в Weaviate?

У запроса появляется аргумент `hybrid`. Weaviate сначала вычисляет BM25-существование запроса в инвертированном индексе, затем — векторную близость. Итоговый *score* — взвешенная сумма:

`score = α·bm25 + (1 − α)·vectorScore`  
где `α` – доля «классики». При `α = 0` получаем чистую семантику, при `α = 1` — обычный BM25.

### 2 Базовый пример hybr > id-поиска

    {
      Search(
        class: Article
        hybrid: {
          query: "graph neural networks"
          alpha: 0.35          # 35 % BM25, 65 % k-NN
          vector:
            {                  # (необязательно) собственный вектор запроса
              vector: [0.12, …, -0.08]
            }
        }
        limit: 10
      ) {
        title
        _additional { score scoreExplanation }
      }
    }

*Разбор:*

- `query` — текст отправляется в BM25 + модуль векторизации.
- `alpha` балансирует вклад. 0.35 = «содержание слов» играет 35 % против 65 % семантики.
- `vector` (опц.) даёт свой эмбеддинг вместо автоматической векторизации строки.
- `scoreExplanation` покажет доли `bm25:` и `vector:` в итоговом `score`.


### 3 Весовые коэффициенты свойств (`vectorWeights`)

Если объект содержит несколько текстовых полей («*title*», «*content*», «*tags*»), можно задать, какое поле важнее:

    hybrid: {
      query: "vector database"
      alpha: 0.2
      vectorWeights: {
        title: 2.0         # удвоить вклад тайтла
        tags:  0.5         # ослабить вклад тэгов
      }
    }

### 4 Мульти-модальный гибрид (nearImage + text)

    {
      Search(
        class: Recipe
        nearImage: { image: $base64 },    # картинка блюда
        hybrid:   { query: "italian pasta", alpha: 0.5 }
        limit: 5
      ) { title score:_additional { score } }
    }

Weaviate объединит визуальный вектор (`nearImage`) и текстовый запрос.

### 5 Кросс-reference-переходы («прыгнуть к автору → взять его книги»)

Схема:

    Article  ---hasAuthor--->  Author  ---wrote--->  Book

#### Шаг-к-шагу:

    {
      Search(
        class: Article
        nearText: { concepts:["weaviate tutorial"] }
        limit: 3
      ) {
        title
        hasAuthor {                  # первая «ступень» ссылки
          name
          wrote(limit: 2) {          # вторая ступень: книги автора
            title
            year
          }
        }
      }
    }

Ключевые моменты:

- Любую reference-ссылку можно продолжить ещё одним блоком выбора.
- Под-запросы поддерживают `limit`, `where`, `sort` и даже `nearText`.


### 6 Практика

1. **Balanced α.** При каком `alpha` (0…1) гибрид-поиск для «vector db qdrant» выдаёт больше релевантных результатов в топ-10? Проведите A/B на ваших данных, сравните `scoreExplanation`.

2. **Короткий путь «автор → статьи 2025».** Сформулируйте запрос: найти авторов, у которых > 3 статей в 2025 г., и вывести их имена + названия этих статей.

3. **Поле-весы.** Настройте `vectorWeights` так, чтобы поле *tags* не влияло на выдачу (вес = 0). Сравните `score` до/после.

**Итог:** вы умеете объединять «словесное соответствие» и «семантическую близость» в одном запросе и проходить по графу, вытягивая связанную информацию. Дальше — *агрегации по связям* и *tuning HNSW-параметров* для скорости / точности.
