#### Мультимодальный поиск и гибридные возможности

Weaviate изначально задумывался не только для текста. Он поддерживает **мультимодальный поиск**. Это значит, что можно хранить и искать объекты по разным типам данных: текст, изображения, аудио и т.д. Например, вы можете добавить класс Image с полем image (картинка) и использовать модуль `img2vec`, тогда при добавлении изображений Weaviate сохранит их эмбеддинги. После этого можно делать запросы: `{ Search(class: Image, nearImage: { image: "base64-coded-image" }) { _additional { id } } }` – и получить id изображений, похожих на заданное изображение по визуальному содержанию. Также можно делать текстовый запрос по изображениям, если есть модель, связывающая тексты и картинки (например, CLIP). Weaviate как платформа позволяет подключать разные модели для разных модальностей.

Что касается **гибридного поиска** (комбинации текстовых слов и эмбеддингов): Weaviate имеет встроенную возможность объединять BM25 (классический алгоритм поиска по словам) и векторный поиск. Конкретно, в запросе GraphQL можно использовать оператор `hybrid`, указав, что текстовый запрос должен учитываться и как точное соответствие, и как семантическое. Например, `hybrid: { query: "deep learning", alpha: 0.5 }` – будет искаться баланс между обычным поиском "deep learning" и векторным сходством по этому же запросу, с весом 0.5 для каждого. Такие возможности избавляют от необходимости самостоятельно объединять результаты двух поисков.

Подводя итог, Weaviate – мощнейший инструмент, который выходит за рамки "просто nearest neighbors". Он хорош, когда вам нужна комбинация данных: и текст, и структура, и разные типы данных. Конечно, за универсальность расплачиваемся сложностью: GraphQL, настройка модулей, схему надо продумывать. Но для большого проекта (например, корпоративная база знаний) Weaviate может оказаться идеальным выбором.
